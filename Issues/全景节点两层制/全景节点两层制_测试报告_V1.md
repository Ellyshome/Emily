## 十、结论与遗留

**结论**：两层制重构已落地并通过实测。类型三层→两层完成收敛且结构自洽；状态语义改为「任务按完成量、里程碑按子节点聚合」并在实测中三层联动；系统侧进度计算已下线；工具层可带量建任务、上报门禁按设计放宽。**规格符合度 11/11（100%），用例 11/11 PASS，无高风险遗留**。

**待改进项**

1. **存量成果量纲普遍是「1 份」**（34 个成果大多 `target=1 / unit=份`），即当前的量只是"交没交文件"的开关。D5 的"按量推进"要等真实填报（如 100 棵乔木）铺开后才体现价值——这是数据口径问题，非代码问题。
2. `progress` 列存量全为 0，保留作兼容；若确认不再需要，可另立需求清理。
3. 前端 console 仅做静态同步（标签/CSS），未做浏览器点击级验证。

**遗留风险**

1. 本轮以「容器内真实 Service 层 + 真实库」实测替代 LLM 全链路对话验证；`create_task_node` 在 LLM 编排下的填参质量（模型是否主动追问目标量）尚未端到端验证，建议后续用 `emy-test` 补一轮对话测试。
2. 迁移脚本用原生 SQL 直接更新 `project_nodes`，未走 Service 层审计；已在脚本内提供 `--dry-run` 与幂等保证，且迁移属一次性运维动作。
