## 硬约束（违反即失败）

> 项目铁律直接引用 [宪法 §2](../_shared/constitution.md)，**不自行发明**。

1. **禁止修改已有接口签名**：仅在既有类/注册表中**新增**方法或条目，不改现有签名（`_reg_biz`、`console_resources` 路由、`registry.py` 现有调用一律不动）
2. **遵循宪法铁律 C0~C13**：本设计涉及的铁律及遵守方式：

   | 铁律 | 本设计如何遵守 |
   |------|--------------|
   | C1 业务内核独立 | 全部新增代码在 `emily_core` 内，不 import 任何 `astrbot.*` |
   | C2 分层不可跳 | 文件仓储（sync）← Service（sync 核心）← 工具/脚本/路由（async 包裹 `asyncio.to_thread`）；不跨层 |
   | C3 SOP 即路由 | 查阅 SOP 落 `emily-data/sops/`（M6），重启生效 |
   | C6 Sync repo + to_thread | 文件访问与入库核心为**同步**实现（M1/M2），工具层 async 用 `asyncio.to_thread()` 包裹 |
   | C9 ToolManager/ScriptManager 边界 | 入库脚本（subprocess）与查阅工具（进程内）**共享** M2 服务层，**互不调用** |
   | C11 功能注册接入 | 查阅/入库工具 → `tools/registry.py`；入库脚本 → `scripts_registry.yaml`；SOP → `sops/`；展示 → console 路由（复用能力） |
   | C12/C13 内核冻结 | **不改** `session/loop.py`、`workitem/langgraph_engine/`；认知注入走规则书（数据侧），不动装配代码 |
   | C13/C14 控制台=观察窗口 | 展示板块只读、复用 M1 列目录，不在路由层复刻业务逻辑 |

3. **每模块验收**：每模块验收检测必须通过，否则停止并报告
4. **遵循接口契约**：跨模块调用只走约定接口，不绕过接口直接操作对方内部数据
5. **不私自扩需**：发现规格缺陷**回退 req-review**，不在本设计里新增/改写需求
6. **接线闭合（宪法 §3 Q6）**：任何产出物必须有消费者（见"接线矩阵"）

## 数据流设计

### 核心流程

| 流程 | 触发条件 | 参与者 | 数据流向 | 异常路径 |
|------|---------|--------|---------|---------|
| 入库（脚本） | 运维 CLI / 控制台执行 | M4a→M2→M1→fs | 目录树 → 逐级索引写入 → 留痕 | dry-run 不写盘；越界路径拒绝；无权限拒绝 |
| 入库（对话） | 用户经 SOP 表达入库意图且 L5 | M6→M4b→M2→M1 | 同上传，含 L5 校验 | L5 不足 → 拒绝并提示等级 |
| 查阅（列目录） | 用户提问 / 控制台 | M5/M8→M1→fs | 根相对路径 → 首层条目列表 | 目录不存在 → 明确回报 |
| 查阅（下钻） | 列目录后按线索继续 | M5→M1→fs | 逐层读 `.emily.md` → 命中文件 | 索引缺失 → 提示"未入库" |
| 查阅（取文件） | 命中断言文件 | M5→M1→fs → 既有文件发送能力 | 文本内容 → 回复；不可读 → 如实说明 | L3 不足 → 拒绝 |

```
用户/运维 ──► 入口(M4a 脚本 / M4b 工具 / M6 SOP / M8 面板)
                    │
                    ├─(入库)─► M2 入库引擎 ──► M1 仓储 ──► fs: .emily.md
                    │                 └─► 既有留痕门面(audit)
                    └─(查阅)─► M5 查阅工具 ──► M1 仓储 ──► fs: 读索引/读文件
```

### 脚本交互关系

```

  │  argparse: --dir --root --operator-id --dry-run
  └── import KnowledgeLibraryIngestService.ingest()  → dict（系统/控制台调用通道）
```

## M2: 入库引擎（KnowledgeLibraryIngestService）

**依赖**：M1、M3

**实现的需求**：US-01（主实现）、US-02（消费手册）、US-09（写元信息）

**层级**：Service（sync 核心；上层 async 包裹）

**职责**：一次性遍历目标目录树，为**每一层目录**生成/更新 `.emily.md`；描述以文件名/文件夹名推断；dry-run 只出清单；写入前先读上级索引保证层级口径一致；通过既有留痕门面记录。

### 接口契约

#### 对外接口

| 接口/类 | 类型 | 签名 | 说明 |
|---------|------|------|------|
| `KnowledgeLibraryIngestService` | 类 | `__init__(fs: KnowledgeLibraryFs, playbook_path: str \| None = None)` | 注入仓储与手册路径 |
| `ingest(rel: str, dry_run: bool = False) -> dict` | 方法 | 输入目标目录相对路径，返回 `{ok, target, created:[], updated:[], skipped:[], stats:{}}` | 一次性遍历整树（US-01.10）；幂等（US-01.3） |
| `describe_file(name: str, parent_dir_name: str) -> str` | 方法 | 由文件名 + 所属目录名推断一句话描述 | 图片/二进制/压缩包**不解析内容**（US-01.8） |
| `_render_index(rel: str, entries: list[dict]) -> str` | 私有方法 | 按手册口径渲染索引文本（含 frontmatter 元信息） | 结构见 M1 数据模型 |

#### DTO 定义

| DTO | 字段 | 用途 | 流向 |
|-----|------|------|------|
| `IngestResult` | `ok: bool`, `target: str`, `created: list[str]`, `updated: list[str]`, `skipped: list[str]`, `stats: dict` | 入库结果 | M2→M4/M8 |
| `IngestInput` | `rel: str`, `dry_run: bool`, `operator_id: str` | 入库输入 | M4→M2 |

> 统一以 `dict` 返回（对齐 `scripts/ingest_knowledge.py::ingest()` 返回 dict 的既有范式），不新建 DTO 类。

### 核心算法/策略

| 算法/策略 | 用途 | 选型理由 | 备选方案 |
|----------|------|---------|---------|
| 自底向上 / 自顶向下逐级遍历 | 生成整树索引 | 用 `os.walk` 或递归；**先**父后子以便父索引能引用子索引首行 | 单层生成后二次合并（复杂，不选） |
| 名称推断描述 | 生成"每文件一句话" | 确定性、零依赖、可离线；符合 PRD R8 | LLM 逐文件摘要（成本高、依赖 LLM 可用性，本期不采用） |
| 幂等覆盖写 | 重复入库 | 直接覆盖同路径 `.emily.md`，不追加 | 追加行号（不幂等，不选） |
| 手册驱动渲染 | 口径统一 | 索引结构由手册（M3）规定，M2 只按手册填写字段 | 硬编码模板（口径无法统一，与 US-02 冲突） |

无 DB 数据模型变更；索引文件格式见 M1。

## 阶段反思指令

每完成一个模块的设计，在进入下一个模块之前，执行以下反思：

1. **检查设计完整性**：本模块的接口契约、数据模型、验收检测是否完整
2. **检查追溯闭合**：本模块声明的 US 是否都有接口/验收覆盖；对照追溯矩阵有无遗漏
3. **检查设计偏差**：是否有与规格（PRD）不符的设计？如发现规格缺陷，**回退 req-review**，不在计划内扩需
4. **判断是否继续**：
   - 偏差 ≤ 1 个接口调整 → 直接修改设计文档对应模块，继续
   - 偏差 2-4 个接口或模块职责调整 → 在文末追加 "v1.1 修订记录"，继续
   - 偏差 > 4 个接口或架构方向变化 → **停止**，报告给用户，等用户决定是否重新生成设计
