# Emily 测试用例库

> **用途**：把项目实施过程中沉淀下来的高价值测试用例，按「特性类别」归档成册。**业务一旦变更，按类别重跑，判断相关特性是否符合预期。**
> **建立日期**：2026-09-12
> **用例总数**：183 条（13 个类别文件）
> **设计原则**：每条用例只指向**一个具体特性**；每条用例自带**可执行操作**与**可判定的预期**；每条用例可**追溯到真实实现或真实执行记录**，不凭空构造。

## 二、什么时候用

| 场景 | 做法 |
|------|------|
| 业务规则变更（如密级规则、权限规则） | 打开对应类别文件（如 06 文件与密级管理），全量重跑该类 |
| 内核/编排层重构 | 先跑 12 内核编排专项（离线、快），再跑 01/02/03/04 联调类 |
| 接口或路由调整 | 跑 07/09/10 中的接口类用例，用「接口前缀以路由定义为准」核对 |
| 权限模型调整 | 05 全量 + 06 的 `CONF-*` + 07 的 `RAG-08~12` |
| 访客口径调整（话术 / 回复字数 / 可见能力 / MCP 权限 / 来源告知） | 05 的 `FR-G10~G12` + 07 的 `RAG-13` + 13 的 `MCP-06`、`MCP-10`；规则载入通道见 08 的 `FR-H6` |
| 规则书改动（`emily-data/rules/规则书.md` 章节与 `applicable_levels`） | 08 的 `FR-H6` + 受影响档位的业务用例（如访客 05 `FR-G11`、L5 称呼 05 `FR-G12`） |
| 对外回复格式规范（Markdown 禁用等） | 01 的 `FR-A9`（全档位适用） |
| MCP 工具接入/变更（增删 server、改 `category`/`permission_flag`/`write_mode`） | 13 全量 |
| 上线前回归 | 12（离线）→ 01/02/04（对话主干）→ 05/06/07（权限与数据面）→ 其余 |

## 三、执行通道

| 通道 | 适用用例 | 命令模板 |
|------|---------|---------|
| **A. 对话模拟（主）** | 所有「发消息」类用例 | `uv run python .claude/skills/emy-test/cli.py --managed --llm --message "<消息>" --sender "<真实用户名>"` |
| **B. HTTP 接口** | 接口/资源类用例 | `curl -X POST http://localhost:18080/api/v1/... -H "X-Emily-Token: $EMILY_API_TOKEN" -H "Content-Type: application/json" -d '{...}'` |
| **C. 内核离线回放** | `KRN-*`、部分 `FR-*` | `docker exec -e PYTHONPATH=/app -w /app emily-core python /app/scripts/session_graph_replay.py` |
| **D. 语料回放** | `GOLD-*`、批量断言 | `uv run python scripts/golden_session_loop.py --corpus emily-data/golden/session_loop_cases.yaml --path new --report emily-data/golden/report_new.json` |
| **E. 库核对** | 涉及写库的用例 | `docker exec emily-postgres psql -U emily -d emily -c "SELECT ..."` |
| **F. 归档取证** | 归档/上下文类用例 | 查 `emily-data/session_archives/` 最新 md |

## 四、判定口径

| 状态 | 含义 |
|------|------|
| **PASS** | 预期全部满足 |
| **FAIL** | 预期未满足，且可归因为系统缺陷 |
| **GAP** | 实现存在但默认关闭/未接线，属既定缺口 |
| **SKIP** | 因环境或取证条件不具备未执行（需说明原因） |
| **N/A** | 该特性已退役或已随架构变更消失，不再适用 |
| **需核对** | 用例依赖的开关/路径/数据可能已变，执行前先核对现状 |

**单条用例的通过标准以「预期」列为准。** 差异记入报告备注，不改预期。

### 断言字段（与 golden 语料同一套词汇）

| 字段 | 含义 |
|------|------|
| `reply_contains` | 回复包含指定文本 |
| `capability_hit` | 命中指定能力/SOP |
| `permission_block` | 越权诉求被拒绝，且无对应写操作 |
| `suspend_resume` | 挂起并成功续接 |
| `archive_completeness` | 归档段落完整（能力/参数/成果/触发者/成败） |
| `db_effect` | 库内可观测变化（行数、字段值） |
| `log_contains` | 日志包含指定行 |
| `llm_calls` | 模型调用次数 |

## 五、执行前置

1. **容器健康**：`emily-core` running；`GET /api/v1/health` 返回 `{"status":"ok","initialized":true,...}`；`emily-postgres` `accepting connections`。
2. **真实用户**（**禁止伪造 sender_id**，伪造会被自动建号并降级为访客，测试结果不可信）。
3. **基线快照**：记录 `messages` / `events` / `tasks` / `scheduler_jobs` 行数，测试后比对；写库类用例执行前登记，执行后清理。
4. **写操作窗口**：涉及节点写操作、规则演进、热加载的用例需单独窗口，避免与其它测试互相干扰。

## 六、维护约定

1. **编号不复用**：用例编号一经分配不再改变，便于跨版本追溯。
2. **来源可回溯**：每条用例在正文中给出「来源」列，指向原始执行记录或实现位置。
3. **业务变更时**：先改规格文档 → 定位受影响类别 → 更新该类别用例的「预期」→ 重跑 → 出报告。
4. **新用例归属**：新增用例放入最贴近的类别文件；若跨类，主用例放主类别，另一处仅做交叉引用。
5. **历史存档**：`需求/已完成需求文件/` 下的一次性项目测试计划仍作为历史归档保留，本库只收录**可重复执行的回归用例**。
