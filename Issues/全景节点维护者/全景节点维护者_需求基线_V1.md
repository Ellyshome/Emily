## 一、背景与问题

1. **业务诉求**：希望系统能根据上传的资料**自行构建/维护全景节点**，替代目前"人工逐条建节点、逐条挂归属"。
2. **核心难点不在技术而在组织口径**：节点怎么拆、可见文件范围给谁、参与企业怎么定、事件如何挂载，不同团队成员口径不一致。**这是人之间的问题，AI 不应"强制"收敛**。
3. **因此定位为"理性的中间人"**：显性化分歧 → 给提案 → 由人签认。Emilly 的机遇在于成为"组织架构共识"的载体，而不是规则的制定者。
4. **现状能力缺口**：
   - 节点创建、成果提交、依赖挂载等**原子能力齐全**（SOP-011 + 节点工具集），但**没有"该不该建 / 该挂哪里"的判断能力**——判断目前完全依赖操作人。
   - 现有"临时节点"只是一个兜底容器（`UNASSIGNED` 单节点，用于无归属事件），**不承载"未签认的新节点"**，也没有认领/迁正流程。
   - 节点状态机只有三态（`CONDITIONS_NOT_MET` / `IN_PROGRESS` / `COMPLETED`），**缺少"停用/废弃"这一人工出口**。
5. **结论**：需立一条独立需求线，把"判断 + 提案 + 收容 + 签认迁正"这套动作显性化为一个可注册的能力（Atlas），而不是继续往 Session 主循环或单个 SOP 里堆判断。

---

## 二、定位与形态

**Atlas = 一个可注册的能力，不是一个常驻 agent。**

- 形态：一纸 SOP 声明文件 → 经能力层注册通道接入 → agent loop 内多步完成「解析资料 → 读三书/模板库 → 推导 → 调既有节点工具落库」。
- **推导逻辑不写成代码**：走"声明 + 运行时推导"，符合 C3（SOP 即路由）与 C12（Session 主循环冻结）。
- 权限隔离：**通过 SOP 自己的能力边界 + 既有等级权限口径实现**，不引入 A2A、不引入独立进程。
- 触发：**由 session-agent 依其职责自主判断**是否调用（依据系统能力书对自身能力边界的描述），不新增独立触发器、不在文件归档主链路里硬编码判断。

---

## 三、目标

1. **G1 可判断**：新进信息（完工信息、归档文件）能自动判断归属，输出"挂到哪个节点 / 需要新建什么节点"的建议。
2. **G2 可沉淀**：能从往期项目节点图、团队成员手工改节点的记录中提炼管控规律，形成**可复用的规则候选**，经人确认后升级为标准。
3. **G3 可装配**：能从"人写的节点计划表 + 成果文件"产出整树级的增/删/改建议清单。
4. **G4 不越权**：Atlas 的全部分歧只做到"显性化 + 提案"，**改图与定规则的最终决定权始终在人**。
5. **G5 可信度可分辨**：Atlas 产出的节点入库即生效但**标为未签认**，检索时标注"暂不可信"；签认后才迁正为正式归属。

## 四、范围

- **纳入**：
  - Atlas 能力本体（SOP 声明 + 注册通道接入）；
  - 三类职能：信息归属判定、规律沉淀、资料驱动整树建议；
  - **两层临时节点**（收容无主信息与未签认节点）+ 认领 + 迁正；
  - 节点新增状态「**停用**」；
  - 三态流转触发条件的落地（激活两条件、完成两条件）；
  - 相对锚点（"取得施工许可证后 30 天"）的换算口径；
  - 节点编号策略、权重退役；
  - 签认可信度的复用（不新增签认机制）。
- **不纳入**（本轮明确不做）：
  - 常驻 agent、A2A、跨 session 主动找人对齐；
  - 跨项目高权限读取（行级隔离已按 Q9 关闭、不在本期范围，须另立需求；见 `Issues/权限矩阵/权限与能力缺口清单_V1.md` G-13 / Q9）；
  - 自动删除 / 自动废弃节点；
  - 邀请签认与待签认通知；
  - 权重推导与精细依赖计算；
  - 通用参考节点库的**新建**（现有模板库已具备参考系能力，仅消费）。

## 五、术语

1. **Atlas**：全景节点维护者的工作简称（取自"图谱集"，即掌管全景节点图谱者），指代本能力。
2. **信息**：本项目产生的、需要落到节点上的业务信息，典型为完工信息与归档文件。
3. **归属判定链**：见 §六 FR-2 的三档判定（命中已有任务 → 有里程碑归属 → 无归属）。
4. **临时节点**：无主信息与未签认节点的收容容器，分两层——根图下的**临时里程碑**、某里程碑下的**临时任务**。
5. **迁正**：临时节点经签认后，按节点组织办法改挂到正式归属位置。
6. **三书**：项目态势书 / 组织规则书 / 系统能力书（工程名：世界书 / 规则书 / 系统自我描述）。**"上岗手册"即其中的系统能力书**——描述系统当前能做什么。
7. **停用**：节点退出管控的人工操作（等价于废弃/冻结），非终态、可恢复。
8. **相对锚点**：以某个上游节点的时间为起点的相对时间描述（如"取得施工许可证后 30 天"）。

## 六、功能需求

### FR-1 能力载体与接入
Atlas 以**一份 SOP 声明文件**的形式落地，经既有注册通道接入；不得作为常驻服务、独立进程或 Session 主循环内的分支存在。关闭该 SOP 文件即能力不可用。

### FR-2 信息归属判定（职能一）
对新进信息执行三档判定，全程只出建议、不擅自改图：

| 档位 | 判定 | 处置 |
|------|------|------|
| A | 命中某个里程碑下**已有任务**已预定的内容 | 反馈目标节点，建议在该节点上录入信息（不新建节点） |
| B | 未命中已有任务，但**有明确的里程碑级归属** | 判断操作人是否有增加节点的权限：**有权** → 给出新节点创建建议并落库至临时节点，**签认后迁正**到该里程碑下；**无权** → 落库至临时节点，等待有权限者认领 |
| C | 连里程碑级归属都没有 | 落库至临时节点，标注「无归属」，等待认领 |

- 三档判定必须给出**依据**（命中的规则条目 / 参考的模板 / 来源文件），不得只给结论。
- 落库动作复用既有节点写入能力，**不新增节点存储逻辑**。

### FR-3 规律沉淀（职能二）
1. 输入：往期其他项目的全景节点图、团队成员手工改节点的记录。
2. 产出：**规则候选**（形如"某类专业节点必然包含某几个参与单位/共享文件"）+ 支撑样本。
3. 规则候选**不自动生效**，经人工确认后升级为标准，落入三书的对应资料中。
4. 提炼必须可追溯到样本，禁止无依据的"经验总结"。

### FR-4 资料驱动整树建议（职能三）
1. 输入：人写的本项目节点计划表、节点产出成果文件。
2. 动作：与现行架构标准（规则书 + 模板库参考系）做比对。
3. 产出：**增 / 删 / 改差异清单 + 每项理由与出处**，供责任人逐条确认。
4. 未采纳条目丢弃；采纳后才执行写入。

### FR-5 临时节点（两层）
1. 层级：**根图下的临时里程碑** + **挂在某里程碑下的临时任务**，取决于信息/新节点是否有里程碑归属。
2. 收容对象：无归属信息、未签认的新节点。
3. 可见范围：临时节点**L4 及以上人员可见**；**创建者本人始终可见自己的节点**。
4. 认领：各节点所有者可认领回自己的节点；**不设待认领超时**，长期挂起即可。
5. 迁正：认领/签认后按节点组织办法改挂到正式位置。

### FR-6 签认与迁正
1. 复用既有签认服务：节点签认门槛 **L4 及以上**，**幂等**，**不阻断入库**。
2. 未签认节点：检索结果须标注"（未签认，暂不可信）"。
3. 签认是**迁正的前置条件**（FR-5.5）。
4. 不引入草稿态、不做"确认后才落库"的对话闸口——**落库 + 临时节点 + 签认迁正** 即本基线的可信度方案。

### FR-7 节点停用
1. 新增节点状态「**停用**」，**仅 L4 及以上人员可操作**。
2. 停用后：不计入完成度汇总、不产生到期提醒、不得挂载新任务。
3. 停用需留痕（谁、何时、为何）。

### FR-8 三态流转触发条件
1. **激活**（`CONDITIONS_NOT_MET → IN_PROGRESS`）：
   - 已有任务级节点录入；或
   - 节点的**计划启动时间**到点自动激活。
2. **完成**（`→ COMPLETED`）：
   - 预期成果齐备且满足预定审核标准；或
   - 由 L5 / L6 人员签认。
3. 两者都不满足的，保持未激活（条件不足）。
4. 停用可作用于任意非终态节点。

> ⚠️ 现状差异：节点表当前**无"计划启动时间"字段**，且状态机无停用态，需在本需求内补齐（见 §十三）。

### FR-9 编号策略
1. **沿用现有编号规则**（`NODE-{hash4(node_name + project_id)}`），不另造一套。
2. 资料/文件已给出编号的，**以给定编号为准**。
3. 编码规则的解释权归执行该建议的 AI 工具，但其产物必须与现有规则一致（保证与模板库的编号映射不冲突）。

### FR-10 相对锚点换算
计划的时点若为相对描述（"取得施工许可证后 30 天"），**查询被锚定节点的时间计划**来推算本节点的时间，不凭空猜测年度/季度。

### FR-11 权限口径
一律沿用既有判定，Atlas **不新造权限规则**：

| 动作 | 门槛（现状口径） |
|------|-----------------|
| 节点创建 / 批量建树 / 节点管理工具集 | 管理员（L5+） |
| 节点签认 | L4+ |
| 节点参与单位/参与人维护 | L5+ |
| 成果提交等子流程 | L2 / L3+ |
| 临时节点查看 | L4+，或本人的节点 |

### FR-12 共识来源与参考系
1. 共识来源复用现有三书，不新建知识源：**组织规则书（应然）+ 项目态势书（实然）+ 系统能力书（能做什么）**。
2. 参考系消费现有通用参考节点库（模板库）：用于判断"某类项目大概率经过哪些节点"及该类节点的固定参与单位/共享文件/成果。
3. 模板中的「文件识别特征 / 典型文件名 / 流程位置」是**判定依据**，不作为硬规则。

### FR-13 权重退役
`权重` 概念退役，Atlas 不推导、不设置权重；依赖权重按既有默认值处理。若存在存量权重实现，一并退役。

### FR-14 留痕
Atlas 的每次建议、落库、签认迁正、停用均留痕（建议依据 + 操作人 + 结果），审计口径与手工操作一致。

## 七、非功能需求

1. **NFR-1 不阻断主链路**：资料归档、文件上传的正常链路不因分析失败而受阻；分析异步执行。
2. **NFR-2 不新增常驻成本**：无常驻进程、无 A2A 通道；不因本能力给普通对话引入额外 LLM 调用。
3. **NFR-3 可解释**：任何建议均可回答"凭什么这样建议"（规则条目 / 参考模板 / 来源文件 / 历史样本）。
4. **NFR-4 幂等**：同一份资料重复分析不产生重复节点、不重复更新。
5. **NFR-5 可关闭**：能力可整体下线（移除 SOP 声明），系统回落为现有手工路径。
6. **NFR-6 分歧不隐藏**：当资料与规则冲突时，**显性输出冲突**并交人裁决，不静默二选一。

## 八、约束

1. **经注册通道接入**：符合 C11（功能注册接入）；不得裸文件/硬编码接线。
2. **主循环冻结**：符合 C12——Atlas 的能力增长落在能力层，**不得为它修改 Session 主循环**。
3. **不新建重复层**：复用既有节点服务与工具链（单节点/批量建树/批量更新），不新增一套节点存储逻辑。
4. **权限判定单一来源**：沿用既有服务层判定，不得在能力内另写一套权限判断。
5. **不做 A2A、不做常驻 agent**：隔离子系统的诉求通过能力边界 + 权限口径达成。
6. **不引入新依赖**。
7. **资产复用**：三书 loader/builder、签认服务、模板库解析/映射链路均为既有资产，直接消费。

## 九、非目标

1. 常驻 agent、A2A 通信、跨 session 主动找人对齐。
2. 跨项目高权限读取（G-13 未立项前不做）。
3. 自动删除 / 自动废弃节点（由人决策）。
4. 邀请签认与待签认通知。
5. 权重推导、精细依赖权重计算。
6. 新建通用参考节点库（仅消费现有模板库）。
7. "专用强约束推导工具 + 专用 prompt"（作为演进项，见 §十二）。

## 十、验收方向（可执行、可判定）

| # | 场景 | 预期 |
|---|------|------|
| 1 | 移除 SOP 声明文件后重启 | 能力不可用，无残留触发器（证明经注册通道接入） |
| 2 | 归档一份"某节点完工单" | 命中已有任务 → 输出含**目标 node_id** 的录入建议，**不新建节点** |
| 3 | 归档一份有里程碑归属、但无对应任务的文件（有权限人操作） | 产出新建建议并落库至临时节点；签认后迁正到该里程碑下 |
| 4 | 同上但由**无权用户**触发 | 落库至临时节点等待认领，不报错、不静默丢弃 |
| 5 | 归档一份无任何归属的文件 | 落临时节点并标注「无归属」；L4 用户可见并认领 |
| 6 | 查询一个 Atlas 新建但未签认的节点 | 检索结果标注"（未签认，暂不可信）" |
| 7 | L4 用户对某节点执行停用 | 状态为「停用」，完成度汇总与提醒中排除；L3 用户执行同一操作被拒 |
| 8 | 给出"取得施工许可证后 30 天" | 产出时间 = 被锚定节点的计划时间 + 30 天，非猜测值 |
| 9 | 无编号的新节点 | 编号符合现有编号规则，且与模板库映射不冲突 |
| 10 | 分析过程抛异常 | 文件归档主链路仍成功；失败原因记录且可重试 |
| 11 | 重复归档同一份资料 | 不产生重复节点，无重复更新 |
| 12 | 复核任意一条建议 | 能追溯到依据（规则条目 / 参考模板 / 来源文件 / 历史样本） |
| 13 | 检查 Session 主循环文件 | 本需求的改动**未触及**主循环（C12） |

## 十二、暂缓项与演进触发

**暂缓**：A2A / 常驻 agent、跨项目高权限读取（G-13）、"LLM 自由推导质量兜底"的专用强约束工具、邀请签认。

- 推导可控 → 纯 SOP 方案足够；
- 推导不可控（乱拆、漏读规则书）→ 升级为"专用工具强约束推导"（专用工具 + 专用 prompt）。
