# 全景节点（模块）— 需求基线 V1

**一句话**：模板库是全景节点蓝图的唯一来源——由文件上传触发的节点自动补建，必须命中模板库已有 `ref_id` 并按其装配，匹配失败则不建节点、只出「缺模板」提案。
**一句话**：把模板从"文字预设"建成"对象装配说明书"，让节点的参与单位 / 成员 / 共享文件 / 前置成果按模板声明自动解析为候选，经人确认后落库。
**一句话**：把"该不该建、该挂哪里"的判断显性化为可注册能力 Atlas——三档归属判定 + 两层临时节点收容 + 认领后迁正，全程只出建议、不擅自改图。

> **性质**：需求基线（讨论稿），确认后转 PRD 与计划
> **日期**：2026-09-22
> **状态**：待评审（已定口径见 §十一；待定项见 §十二）
> **代码校对**：2026-09-22（§八、§十三 锚点均经实测核对）

## 一、背景与问题

1. **原子能力齐备、判断能力缺失**：节点创建、成果提交、依赖挂载等链路已有，但"该不该建 / 该挂哪里 / 建成什么样"完全依赖操作人。
2. **模板库有位置、无消费者**：模板目录已挂载且索引可读，但索引只扫顶层 `*.md`；没有 LLM 可调用的模板工具；SOP-011 未提及模板库；模板解析与装配逻辑目前内联在 console 路由层。
3. **文件与节点之间没有关联链路**：不存在成果匹配器，"上传一份文件 → 反推它属于哪个节点、该节点是否已完成"整条链缺失。
4. **没有可承载"未归属 / 未迁正"的容器**：现有 `UNASSIGNED` 仅是无归属事件的单节点兜底，不承载新节点，也没有认领与迁正流程。
5. **人工出口不全**：节点状态只有三态，缺少「停用」；节点表没有"计划启动时间"字段。
6. **阶段口径与数据结构脱节**：`project_nodes.stage_id` 已随迁移删除，但填报口径仍以"所属阶段入库"表达。
7. **结论**：需把"模板蓝图 + 对象装配 + 归属判断 + 收容迁正"作为一套模块能力落地，而不是继续往 Session 主循环或单个 SOP 里堆判断。

## 二、定位与边界

模块由三条能力线构成，缺一不可：

```
模板库（蓝图） → 装配（对象声明 + 采集器 + 落库编排） → 判断（Atlas 归属判定）
      ↑                                                        ↓
      └──────────── 三书（规则书 / 态势书 / 能力书）为共识来源 ──┘
```

- **判断落在能力层**：以 SOP 声明 + agent loop 运行时推导实现，推导逻辑不写成代码（符合 C3 / C12）。
- **不做常驻 agent、不碰 A2A**：隔离子系统的诉求通过能力边界 + 权限口径达成。
- **不新造规则制定权**：节点怎么拆是组织口径之争，系统只做"显性化分歧 + 提案 + 由人拍板"。

### 2.1 三种触发入口与闸口差异

| 入口 | 触发者 | 是否需模板锚定 | 落库闸口 |
|------|--------|---------------|---------|
| **文件上传自动补建** | 归档文件（异步分析） | **必须命中模板库已有 `ref_id`** | 直接落临时节点，认领/挂载后迁正 |
| **资料整树装配** | 人投喂计划类资料 | 以模板库为比对参考系（不强制命中） | 草案确认后才落库 |
| **人工建节点** | 控制台信息面板 / IM 对话 | 不强制 | 立即落库 |

> 前两条分层的原因：单文件补建影响面小、可收容；整树装配一次改动整层树，必须先出草案。

## 三、目标

1. **G1 模板可发现**：LLM 通过工具能列出模板清单、读取指定模板的清单、对象声明与附件清单。
2. **G2 装配可声明**：模板能结构化声明"要采集哪些对象"，系统按声明解析出**真实记录候选集合**（非单值），并保留可解释性。
3. **G3 节点可锚定**：文件触发的自动补建必须命中模板 `ref_id` 才建节点，落库携带 `template_ref_id`；模板缺失一律不建。
4. **G4 归属可判断**：新进信息能自动判断"挂到哪个节点 / 需要新建什么节点"，全程只出建议。
5. **G5 收容可控**：未归属信息与未迁正节点落入两层临时节点，由有权限者认领后迁正。
6. **G6 不阻断**：模板库缺失、分析失败、单项落库失败均不影响文件归档与节点创建主链路。

## 四、范围

**纳入**
- 模板库形态收敛、索引改造、存量迁移、容器挂载口径；
- 模板的**只读检索通道**（LLM 可调用工具 + SOP 声明）与解析逻辑下沉能力层；
- 模板的**对象声明**与四类采集器（参与单位 / 成员 / 共享文件 / 前置成果）；
- 装配链与节点草稿、创建期落库编排扩展；
- **模板锚定门禁**；
- Atlas 三档归属判定、文件 → 节点完成反推、两层临时节点、认领与迁正；
- 资料驱动整树装配（类型识别 / 抽取 / diff / 草案确认）；
- 节点「停用」状态、三态流转触发条件补齐；
- 编号策略、相对锚点换算、留痕、幂等、权限沿用。

**不纳入**
- 常驻 agent、A2A、跨 session 主动找人对齐；
- 跨项目高权限读取（G-13 未立项前不做）；
- 自动删除 / 自动废弃节点、自动推进节点进度；
- 邀请签认与待签认通知；
- 权重推导与精细依赖计算（`权重` 概念退役）；
- 模板库本体的业务内容扩写（模板由人维护，系统只消费）；
- **无模板命中时的兜底自动建节点**、依据文件自动生成新模板；
- 用 LLM 判断节点状态（状态是硬门禁，须可复现）；
- 从非计划类资料反推整树结构；
- 模板在线编辑 / 上传界面；
- "专用强约束推导工具 + 专用 prompt"（列为演进项，见 §十二-11）。

## 五、术语

1. **模板**：`emily-data/node_templates/` 下的一份行业参考蓝图，声明某类节点的名称、类型、成果清单、对象、前置条件，带 `ref_id`。
2. **模板锚定**：自动补建的新节点必须由模板库中一个已存在的模板（`ref_id`）装配而来，落库携带 `template_ref_id`。
3. **缺模板提案**：文件显示"此处应有节点"但模板库无匹配项时产出的建议——不落库任何节点，只说明缺哪个专业/名称的模板并附来源文件与匹配尝试依据。
4. **对象声明**：模板中声明"要采集哪类对象 + 匹配条件 + 是否必需"的结构化片段。
5. **采集器（Collector）**：把一条对象声明解析为**真实记录候选集合**的只读组件。
6. **装配（Assemble）**：采集器集合的编排；输入"模板 + 项目上下文"，输出**节点草稿**，不写库。
7. **节点草稿**：`{模板字段, 成果清单, 各类对象候选, 未解析项}`，只读、可反复调用。
8. **未解析项**：声明了但没匹配到真实记录的条目，必须回显，不得静默丢弃。
9. **归属判定三档**：命中已有任务（A）→ 有里程碑归属（B）→ 无归属（C）。
10. **临时节点**：无主信息与未迁正节点的收容容器，分两层——根图下的**临时里程碑**、某里程碑下的**临时任务**。
11. **迁正**：临时节点经**认领/挂载**后，按节点组织办法改挂到正式归属位置。
12. **三书**：项目态势书 / 组织规则书 / 系统能力书。
13. **停用**：节点退出管控的人工操作（等价于废弃/冻结），非终态、可恢复。
14. **相对锚点**：以某个上游节点的时间为起点的相对时间描述（如"取得施工许可证后 30 天"）。

> 面向业务同事的填报口径见 `Issues/资料驱动节点更新/全景节点填报格式约定_V1.md`。

## 六、功能需求

> 编号：`FR-{域}-{序}`。域：`NODE` 节点本体 / `TPL` 模板库 / `ASM` 装配 / `ATL` 归属判定与临时节点 / `DOC` 资料整树 / `COM` 共通。

### FR-NODE 节点本体

- **FR-NODE-1** 节点类型仅 `MILESTONE` / `TASK`；**任务必须是叶子节点**，里程碑可嵌套。
- **FR-NODE-2** 状态为**纯派生**、不可人工填写；判据 = 自身前置依赖满足 **且** 自身必需成果 `current_amount ≥ target_amount`；不做父子聚合。
- **FR-NODE-3** **每个节点至少 1 条必需成果**，创建与挂载时均校验。
- **FR-NODE-4** 新增节点状态「**停用**」：仅 L4+ 可操作；停用后不计入完成度汇总、不产生到期提醒、不得挂载新任务；需留痕（谁 / 何时 / 为何）。
- **FR-NODE-5** 三态流转触发条件补齐：**激活** = 已有任务级节点录入 **或** 计划启动时间到点；**完成** = 必需成果齐备（见 FR-NODE-2）。⚠️ 节点表当前**无"计划启动时间"字段**，需在本需求内补齐。

### FR-TPL 模板库

- **FR-TPL-1** **存储形态**：一个模板 = 一个单元，含**固定命名的结构化清单入口** + 附件（参考范例、成果约定）。清单文件承载入库所需字段（至少 `ref_id`、`node_name`、`node_type`）；"任意文本格式"只开放给附件，不开放给清单文件。
- **FR-TPL-2** **挂载与路径**：挂载点统一为 `/app/data/node_templates`，各 compose 变体口径一致、以只读方式挂载；索引在宿主机生成、容器只读消费。
- **FR-TPL-3** **索引改造**：扫描模板目录（支持子目录）而非顶层 `*.md`；`file` → `dir` + `entry_file`；新增 `attachments[]`；存量模板迁移后 `ref_id` / `node_name` / `node_type` / `summary` 输出保持一致（回归项）。
- **FR-TPL-4** **只读检索通道**：新增只读业务工具（进程内 async handler，登记进 `tool_registry`，带参数 schema）——列出模板清单（可按类型/关键词过滤）、读取指定模板（清单 + 对象声明 + 附件清单）。只读、幂等、不写库、失败不阻断。**不得**用 subprocess CLI 脚本作为 LLM 通道。
- **FR-TPL-5** **SOP 声明**：在节点管理 SOP 增补"参考模板库"一节——位置、发现方式、使用方式、权限口径，并声明"模板是判断依据/参考蓝图，不是硬规则"。仅增一节，不改既有触发条件、工具清单与权限映射。
- **FR-TPL-6** **解析逻辑下沉**：模板解析与装配逻辑下沉到能力层（service 层，供工具 / 控制台 / 批量脚本共用）；控制台路由层不再保留业务解析逻辑。
- **FR-TPL-7** **附件定位**：附件是给人看和给人下载的参考物，不要求 LLM 解析；索引只登记附件清单（文件名 / 大小 / 类型）；二进制附件（xlsx / docx / pdf）不走本模块解析链路。

### FR-ASM 装配

- **FR-ASM-1** **对象声明**：模板内设机器可读的对象声明区，按对象类型分节，每条含 `描述` / `匹配条件` / `是否必需`。匹配条件为**声明式**：参与单位 = 类型归一 + `scope` 关键词 + 名称关键词；成员 = 来源单位 + 可选角色；共享文件 = 文件名/类型关键词；前置成果 = 成果名关键词。声明**不进索引**，随模板正文按需读取；声明语法错误、类型越出词表、引用不存在的来源单位均产出告警而非静默忽略。
- **FR-ASM-2** **四类采集器**：
  - **参与单位**：候选池项目内参建单位优先、未命中退全局企业；`type` 经同义词表归一后等值匹配，`scope` 与名称按关键词包含匹配；**返回候选集合**，与既有单值解析语义并存、不改后者。
  - **成员用户**：由已确定的参与单位推该单位在职人员，候选带出所属单位。
  - **共享文件**：候选范围**必须限定在操作人可见文件集合内**；文件名/类型包含匹配。
  - **前置成果（依赖）**：在项目内已有成果中匹配，整句优先、无命中再退主体词；双向子串匹配，多命中取名称最长者；依赖只能指向已存在的成果，故落库须在节点创建之后。
- **FR-ASM-3** **模板锚定门禁**（核心）：
  1. **适用范围**：仅"由文件上传触发的节点自动补建"（FR-ATL-1 档 B / 档 C）。人工建节点不受限。
  2. **匹配强度**：必须命中模板库中**已存在的 `ref_id`**；不允许"类别近似 / 同专业派生 / LLM 软匹配"等降级命中。
  3. **命中后装配**：节点字段（名称 / 类型 / 说明）与成果清单、对象声明按该模板装配；落库携带 `template_ref_id`。
  4. **未命中处置**：**不创建任何节点**（含临时节点），出「缺模板」提案。
  5. **fail-closed 但不阻断**：模板库不可用、索引损坏、检索工具异常一律按"未命中"处理；文件归档主链路照常成功。
- **FR-ASM-4** **ID 由服务端生成**（硬原则）：LLM 只转述候选，绝不生成 ID；所有 ID 由服务端从声明解析得出，解析不出的丢弃并回报。
- **FR-ASM-5** **节点草稿**：装配产物为只读草稿，不写库、可反复调用；候选呈现给人可增删；**未解析项必须单列回显**；未经确认不落库。
- **FR-ASM-6** **创建期落库编排**：按依赖顺序写 节点 → 成果 → 参与单位 → 参与人 → 共享文件 → 依赖；服务端对每个 ID 做存在性与归属校验，越权/不存在的项丢弃并回报；**单项失败不阻断节点创建**。⚠️ 参与人 / 共享文件 / 依赖当前无创建期入参，需扩展链路或在创建成功后编排补写。
- **FR-ASM-7** **可解释**：每条候选能回答"依据模板的哪一条声明、匹配到什么、为什么命中"，且该信息在控制台与对话回复中均可见。

### FR-ATL 归属判定与临时节点（Atlas）

- **FR-ATL-1** **三档归属判定**，全程只出建议、不擅自改图：

  | 档位 | 判定 | 处置 |
  |------|------|------|
  | A | 命中某里程碑下**已有任务**已预定的内容 | 反馈目标节点，建议在该节点录入信息（**不新建节点，无需模板**） |
  | B | 未命中已有任务，但**有里程碑级归属** | ① 先过 FR-ASM-3 门禁：命中 → 按模板装配；有权限 → 落临时节点、认领/挂载后迁正；无权限 → 落临时节点等待认领。② 未命中 → 不建节点，出「缺模板」提案 |
  | C | 无里程碑级归属 | 同样先过门禁：命中 → 落临时节点并标「无归属」等待认领；未命中 → 不建节点，出「缺模板」提案 |

  判定必须给出**依据**（命中的规则条目 / 命中的模板 `ref_id` 及其具体条目 / 来源文件）。
- **FR-ATL-2** **文件 → 节点完成反推**：上传文件若被判定为某节点的必需成果，则提示归属并建议标记该节点完成（尤其里程碑），**询问有权限者批准**，不自动改状态。
- **FR-ATL-3** **两层临时节点**：根图下的临时里程碑 + 某里程碑下的临时任务；收容无归属信息与未迁正节点。可见范围为 L4+，**创建者本人始终可见自己的节点**；各节点所有者可认领；**不设待认领超时**；**迁正由认领/挂载动作完成**。
- **FR-ATL-4** **规律沉淀**：从往期项目节点图与人工改节点记录中提炼**规则候选**（+ 支撑样本），经人确认后升级为标准、落入三书；必须可追溯样本，禁止无依据的"经验总结"。
- **FR-ATL-5** **触发时机**：由 session-agent 依自身职责自主判断是否调用，不新增独立触发器、不在文件归档主链路硬编码判断。

### FR-DOC 资料整树装配

- **FR-DOC-1** **入口**：文件归档后异步挂载分析；或用户显式指定"按这份资料更新全景节点"。上传主链路不被阻断。
- **FR-DOC-2** **类型识别**：判定资料是否为计划/全景类，输出置信度；低置信度不进入装配。结论与文件记录关联、可追溯。
- **FR-DOC-3** **抽取与比对**：抽取节点树（名称 / 编号 / 截止时间 / 成果 / 前置依赖 / 父子层级），与现有节点比对产出**新增 / 更新 / 无变化**；比对键优先节点编号，无编号时用"名称 + 项目"；**不因资料未提及而删除**任何现有节点或字段。
- **FR-DOC-4** **人工确认闸口**：草案**暂不落库**，确认后才执行写入；呈现三类清单 + 每项依据的资料出处；支持部分采纳，未采纳的丢弃。
- **FR-DOC-5** **写入**：复用既有批量建树与批量更新能力，按项目隔离，携带操作人与来源文件身份。
- **FR-DOC-6** **参考系**：以模板库为比对参考系，能对应到模板的条目标注 `ref_id`；本入口逐条人工确认，**不适用 FR-ASM-3 硬门禁**。

### FR-COM 共通

- **FR-COM-1 编号**：沿用现有规则 `NODE-{hash4(node_name + project_id)}`；资料/文件已给出编号的，以给定编号为准。
- **FR-COM-2 相对锚点**：查询被锚定节点的时间计划来推算本节点时间，不凭空猜测年度/季度。
- **FR-COM-3 权限**：一律沿用既有判定，不新造规则（节点创建 / 批量建树 L5+；成果提交 L2/L3+；临时节点查看 L4+ 或本人节点；参与单位维护 L5+）。
- **FR-COM-4 留痕**：建议、落库、迁正、停用均留痕（建议依据 + 操作人 + 结果），审计口径与手工操作一致；自动补建的节点须留痕装配它的 `ref_id`。
- **FR-COM-5 幂等**：同一份资料重复分析不产生重复节点、不重复更新。
- **FR-COM-6 可关闭**：能力可整体下线（移除 SOP 声明），系统回落为手工路径。
- **FR-COM-7 分歧不隐藏**：资料与规则冲突时显性输出冲突并交人裁决，不静默二选一。
- **FR-COM-8 模板缺失不降级**：模板缺失一律落到「缺模板」提案，仅作用于文件触发的自动补建，不影响人工路径。

## 七、非功能需求

1. **NFR-1 不阻断主链路**：资料归档、文件上传的正常链路不因分析失败而受阻；分析异步执行。
2. **NFR-2 无新增常驻成本**：无常驻进程、无 A2A 通道；不因本能力给普通对话引入额外 LLM 调用。
3. **NFR-3 只读安全**：模板目录容器内只读挂载；装配链路全程只读。
4. **NFR-4 可解释**：任何建议均可回答"凭什么这样建议"（规则条目 / 命中模板及其条目 / 来源文件 / 历史样本）。
5. **NFR-5 零 schema 变更优先**：优先复用既有表与字段（如 `template_ref_id`）；确需新增字段时单独说明。
6. **NFR-6 注册通道接入**：新增工具须经 `tool_registry` 注册并带参数 schema；不得裸文件/硬编码接线。
7. **NFR-7 主循环冻结**：本模块改动**不得**触及 Session 主循环（C12）；能力增长一律落能力层。
8. **NFR-8 控制台同源**：控制台的动作与写库能力必须复用能力层（业务工具 / 服务层），不得在路由层复刻业务逻辑（C13）。
9. **NFR-9 数据质量可见**：企业类型越出同义词表、`scope` 缺失等情况应可巡检，不以静默降级掩盖。
