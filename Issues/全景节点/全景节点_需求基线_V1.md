## 一、整合说明

### 1.1 为什么合并

四条线本来就是同一个模块（全景节点）的四段，只是各自被立成了独立需求：

| 原线 | 原始诉求 | 在模块中的角色 |
|------|---------|---------------|
| 全景节点参考模板模块 | 把 `node_templates/` 从"空壳索引"建成可挂载、可检索的模板库 | **蓝图来源**（节点长什么样） |
| 模板驱动节点创建 | 模板从"文字预设"升级为"对象装配说明书" | **装配路径**（蓝图怎么变成真实记录） |

## 二、模块定位与边界

### 2.1 定位

全景节点回答两件事（源自填报格式约定 §一）：

1. **这个项目走到哪了**；
2. **别人上传一份文件，能不能认出它属于哪个节点、该节点是否已完成**。

模块由三条能力线构成，缺一不可：

```
模板库（蓝图） → 装配（对象声明 + 采集器 + 落库编排） → 判断（Atlas 归属判定）
      ↑                                                        ↓
      └──────────── 三书（规则书 / 态势书 / 能力书）为共识来源 ──┘
```

- **不新造规则制定权**：节点怎么拆是组织口径之争，系统只做"显性化分歧 + 提案 + 由人拍板"（Atlas 定位）。
- **不做常驻 agent、不碰 A2A**：隔离子系统的诉求通过能力边界 + 权限口径达成。
- **判断落在能力层**：SOP 声明 + agent loop 运行时推导，推导逻辑不写成代码（符合 C3 / C12）。

### 2.2 三种触发入口与闸口差异（本基线核心边界表）

| 入口 | 触发者 | 是否需模板锚定 | 落库闸口 | 实施状态 |
|------|--------|---------------|---------|---------|
| **文件上传自动补建** | 归档文件（SOP-004 链路后异步） | **必须命中模板库已有 `ref_id`**（FR-ASM-3） | **直接落临时节点**，认领/挂载后迁正 | 未实施 |
| **资料整树装配** | 人投喂计划类资料 | 以模板库为**比对参考系**（不强制命中） | **草案确认后才落库**（替代"自动直接改库"） | 未实施 |
| **人工建节点** | 控制台信息面板 / IM 对话 | **不强制**（沿用 SOP-011 既有口径） | 立即落库 | 已实施（console 侧） |

> 前两条的分层是**已拍板**口径（见 §十一 Q4）——它们面向同一目标但风险不同：单文件补建影响面小、可收容；整树装配一次改动整层树，必须先出草案。

### 2.3 非目标（合并四线，去重）

1. 常驻 agent、A2A 通信、跨 session 主动找人对齐。
2. 跨项目高权限读取（G-13 未立项前不做）。
3. 自动删除 / 自动废弃节点；自动推进节点进度。
4. 邀请签认与待签认通知（签认机制本身已退役，见 §七-1）。
5. 权重推导、精细依赖权重计算（`权重` 概念退役）。
6. 新建通用参考节点库 / 模板库本体的业务扩写（模板由人维护，系统只消费）。
7. **无模板命中时的兜底自动建节点**；依据文件**自动生成新模板**（一律不建，只出「缺模板」提案）。
8. 用 LLM 判断节点状态（状态是硬门禁，须可复现）。
9. 从非计划类资料（合同、证照、会议纪要）反推整树结构。
10. "专用强约束推导工具 + 专用 prompt"（作为演进项，见 §十-11）。
11. 跨项目高权限、模板在线编辑/上传界面。

## 四、统一术语（合并四线，去重）

1. **模板（参考模板）**：`emily-data/node_templates/` 下的一份"行业参考蓝图"，声明某类节点的名称、类型、成果清单、对象、前置条件；带 `ref_id`。
2. **模板锚定**：自动补建的新节点必须由模板库中一个**已存在的模板**（`ref_id`）装配而来，落库携带 `template_ref_id`。
3. **缺模板提案**：文件显示"此处应有节点"但模板库无匹配项时产出的建议——**不落库任何节点**，只说明缺哪个专业/名称的模板并附来源文件与匹配尝试依据。
4. **对象声明**：模板中声明"要采集哪类对象 + 匹配条件 + 是否必需"的结构化片段（参与单位 / 成员 / 共享文件 / 前置成果）。
5. **采集器（Collector）**：把一条对象声明解析为**真实记录候选集合**的只读组件（返回集合，不是单值）。
6. **装配（Assemble）**：采集器集合的编排；输入"模板 + 项目上下文"，输出**节点草稿**，不写库。
7. **节点草稿**：`{模板字段, 成果清单, 各类对象候选, 未解析项}`，只读、可反复调用。
8. **未解析项**：声明了但没匹配到真实记录的条目，必须回显，不得静默丢弃。
9. **归属判定三档**：命中已有任务（A）→ 有里程碑归属（B）→ 无归属（C）。
10. **临时节点**：无主信息与未签认/未迁正节点的收容容器，分两层——根图下的**临时里程碑**、某里程碑下的**临时任务**。
11. **迁正**：临时节点经**认领/挂载**后，按节点组织办法改挂到正式归属位置。
12. **三书**：项目态势书 / 组织规则书 / 系统能力书。
13. **停用**：节点退出管控的人工操作（等价于废弃/冻结），非终态、可恢复。
14. **相对锚点**：以某个上游节点的时间为起点的相对时间描述（如"取得施工许可证后 30 天"）。

## 六、功能需求

> 编号规则：`FR-{域}-{序}`。域：`NODE` 节点本体 / `TPL` 模板库 / `ASM` 装配 / `ATL` 归属判定与临时节点 / `DOC` 资料整树 / `COM` 共通。
> 标注"**沿用**"表示该口径已由归档件定稿且无冲突，本基线只做归位。

### FR-NODE 节点本体（多为已落地口径）

- **FR-NODE-1**（沿用，已实施）节点类型仅 `MILESTONE` / `TASK`；**任务必须是叶子节点**，里程碑可嵌套。
- **FR-NODE-2**（沿用，已实施）状态为**纯派生**、不可人工填写；判据 = 自身前置依赖满足 **且** 自身必需成果 `current_amount ≥ target_amount`；父子聚合已退役。
- **FR-NODE-3**（沿用，已实施）**每个节点至少 1 条必需成果**（创建与挂载均校验）。
- **FR-NODE-4**（**修订**）新增节点状态「**停用**」：仅 L4+ 可操作；停用后不计入完成度汇总、不产生到期提醒、不得挂载新任务；需留痕（谁/何时/为何）。——`VALID_STATUSES` 需扩枚举。
- **FR-NODE-5**（**修订**）三态流转触发条件补齐：**激活** = 已有任务级节点录入 **或** 计划启动时间到点；**完成** = 必需成果齐备（见 FR-NODE-2）。⚠️ 节点表**无"计划启动时间"字段**，需在本需求内补齐。

### FR-TPL 模板库（蓝图来源）

- **FR-TPL-1**（**待收敛**）模板存储形态：一个模板 = 一个单元，含**结构化清单入口**（形态见 §十-1）+ 附件（参考范例、成果约定）。清单文件承载入库所需字段（至少 `ref_id`、`node_name`、`node_type`）；"任意文本格式"只开放给附件。
- **FR-TPL-2**（沿用）容器挂载与路径统一为 `/app/data/node_templates`，三个 compose 变体口径一致、只读；索引在宿主机生成、容器只读消费。——**已实施**（§3.2）。
- **FR-TPL-3**（**修订**）索引改造：扫描目录（支持递归）而非顶层 `*.md`；`file` → `dir` + `entry_file`；新增 `attachments[]`；`--check` / `--auto` 语义不变。存量模板迁移后 `ref_id/node_name/node_type/summary` 输出保持一致（回归项）。
- **FR-TPL-4**（**合并自两线**）新增**只读业务工具**（`BusinessFlowTool`，进程内 async handler，登记进 `tool_registry`，带参数 schema）：列出模板清单（按类型/关键词过滤）+ 读取指定模板（清单 + 对象声明 + 附件清单）。**不得**用 `ScriptEntry`（subprocess CLI）作为 LLM 通道。只读、幂等、不写库、fail-open。
- **FR-TPL-5**（**合并自两线**）在 `SOP-011-SYS-node_manage.md` 增补"参考模板库"一节：位置、发现方式、使用方式、权限口径，并声明"模板是判断依据/参考蓝图，不是硬规则"。**仅增一节**，不改既有触发条件、工具清单与权限映射。
- **FR-TPL-6**（**新增，C13 整改**）模板解析与装配逻辑**下沉到能力层**（service 层，供 tools / console / 批量脚本共用）；`console_resources.py` 内联的 `_parse_*` / `_build_node_draft` 改为复用，不在路由层保留业务逻辑。
- **FR-TPL-7**（沿用）附件定位：附件是给人看/下载的参考物，不要求 LLM 解析；二进制附件（xlsx/docx/pdf）不走本模块解析链路。索引只登记附件清单。

### FR-ASM 装配（蓝图 → 真实记录）

- **FR-ASM-1**（沿用）模板内新增机器可读的**对象声明区**，每条声明含 `描述` / `匹配条件` / `是否必需`；匹配条件为声明式（参与单位：类型归一 + `scope` 关键词 + 名称关键词；成员：来源单位 + 角色；共享文件：文件名/类型关键词；前置成果：成果名关键词）。声明**不进 `index.yaml`**，随模板正文按需读取。
- **FR-ASM-2**（沿用）四类采集器：**参与单位**（项目内参建单位优先，`type` 同义词表归一 + `scope` 包含 + 名称包含，返回集合）、**成员用户**（由已定单位推在职人员，带出所属单位）、**共享文件**（限定操作人可见集）、**前置成果/依赖**（项目内已有成果，两级匹配键 + 尾词剥离 + 双向子串）。**与既有单值 `resolve` 语义并存**，不改前者。
- **FR-ASM-3**（**核心，硬门禁**）**模板锚定门禁**：
  1. **适用范围**：仅"由文件上传触发的节点自动补建"（FR-ATL-1 档 B / 档 C）。人工建节点**不受限**。
  2. **匹配强度**：必须命中模板库中**已存在的 `ref_id`**；不允许"类别近似 / 同专业派生 / LLM 软匹配"降级命中。
  3. **命中后装配**：节点字段（名称/类型/说明）与成果清单、对象声明按该模板装配；落库携带 `template_ref_id`。
  4. **未命中处置**：**不创建任何节点**（含临时节点），出「缺模板」提案（附来源文件 + 匹配尝试依据）。
  5. **fail-closed 但不阻断**：模板库不可用 / 索引损坏 / 检索工具异常一律按"未命中"处理；文件归档主链路照常成功。
- **FR-ASM-4**（沿用）**P1 硬原则：LLM 只转述候选，绝不生成 ID**——所有 ID 由服务端从声明解析得出；解析不出的丢弃并回报。
- **FR-ASM-5**（沿用）装配产物 = 节点草稿（只读、不写库、可反复调用）；**未经确认不落库**（人工入口）；未解析项必须单列回显。
- **FR-ASM-6**（沿用）创建期落库编排：按依赖顺序写 节点 → 成果 → 参与单位 → 参与人 → 共享文件 → 依赖；服务端对每个 ID 做存在性与归属校验，越权/不存在的项丢弃并回报；**单项失败不阻断节点创建**。⚠️ 参与人 / 共享文件 / 依赖当前**无创建期入参**，需扩展链路（§3.4）。

### FR-ATL 归属判定与临时节点（Atlas）

- **FR-ATL-1**（沿用 + 修订）**三档归属判定**，全程只出建议、不擅自改图：

  | 档位 | 判定 | 处置 |
  |------|------|------|
  | A | 命中某里程碑下**已有任务**已预定的内容 | 反馈目标节点，建议在该节点录入信息（**不新建节点，无需模板**） |
  | B | 未命中已有任务，但**有里程碑级归属** | ① **先过 FR-ASM-3 门禁**：命中 → 按模板装配；有权限 → 落临时节点、**认领/挂载后迁正**；无权限 → 落临时节点等待认领。② 未命中 → **不建节点**，出「缺模板」提案 |
  | C | 无里程碑级归属 | 同样**先过门禁**：命中 → 落临时节点（标「无归属」）等待认领；未命中 → **不建节点**，出「缺模板」提案 |

  判定必须给出**依据**（命中的规则条目 / 命中的模板 `ref_id` 及其具体条目 / 来源文件）。
- **FR-ATL-2**（**合并**）**文件 → 节点完成反推**：上传文件若被判定为某节点的必需成果，则提示归属并建议标记该节点完成（尤其里程碑），**询问有权限者批准**，不自动改状态。（合并自 Atlas 档 A 与《根据成果反推里程碑节点机制》；**代码未实现**，§3.5）
- **FR-ATL-3**（**修订**）**两层临时节点**：根图下的临时里程碑 + 某里程碑下的临时任务；收容对象为无归属信息与未迁正节点。可见范围 L4+，**创建者本人始终可见自己的节点**；各节点所有者可认领；**不设待认领超时**；**迁正由认领/挂载动作完成**（见 §七-1）。
- **FR-ATL-4**（沿用）**规律沉淀**：从往期项目节点图与人工改节点记录中提炼**规则候选**（+ 支撑样本），经人确认后升级为标准、落入三书；必须可追溯到样本，禁止无依据的"经验总结"。
- **FR-ATL-5**（沿用）**可解释性**：任何建议/命中/未命中结论都能回答"凭什么"（规则条目 / 模板 `ref_id` 及具体条目 / 来源文件 / 历史样本）。

### FR-DOC 资料整树装配

- **FR-DOC-1**（沿用）两个触发：文件归档后异步挂载分析；用户显式指定"按这份资料更新全景节点"。上传主链路不被阻断。
- **FR-DOC-2**（沿用）资料类型识别：判定是否为计划/全景类资料，输出置信度，低置信度不进入装配；结论与文件记录关联可追溯。
- **FR-DOC-3**（沿用）计划结构化抽取 → 与现有节点 diff（**新增 / 更新 / 无变化**）→ 产出变更草案；比对键优先节点编号，无编号时用"名称 + 项目"；"更新"只作用于资料明确写入的字段，**不因资料未提及而删除**。
- **FR-DOC-4**（沿用）**人工确认闸口**：草案**暂不落库**，确认后才执行写入；呈现新增/更新/无变化清单 + 每项依据的资料出处；支持部分采纳。
- **FR-DOC-5**（沿用）写入复用 `create_node_tree` / `batch_update_nodes`，不新增节点存储逻辑；携带操作人与来源文件身份。
- **FR-DOC-6**（**新增归位**）整树装配**以模板库为比对参考系**，能对应到模板的条目应标注 `ref_id`；本入口**不适用 FR-ASM-3 硬门禁**（因逐条人工确认）。

### FR-COM 共通

- **FR-COM-1 编号**：沿用现有规则 `NODE-{hash4(node_name + project_id)}`（`node_batch.generate_node_id`）；资料/文件已给编号的以给定编号为准。
- **FR-COM-2 相对锚点**：查询被锚定节点的时间计划来推算，不凭空猜测年度/季度。
- **FR-COM-3 权限**：一律沿用既有判定，不新造规则（节点创建/批量建树 L5+；成果提交 L2/L3+；临时节点查看 L4+ 或本人节点；参与单位维护 L5+）。**签认门槛条目随签认退役删除**。
- **FR-COM-4 留痕**：建议、落库、迁正、停用均留痕（建议依据 + 操作人 + 结果），审计口径与手工操作一致；自动补建的节点须留痕装配它的 `ref_id`；写入 `node_events`。
- **FR-COM-5 幂等**：同一份资料重复分析不产生重复节点、不重复更新（依据来源文件指纹/内容摘要判重）。
- **FR-COM-6 可关闭**：能力可整体下线（移除 SOP 声明），系统回落为手工路径。
- **FR-COM-7 分歧不隐藏**：资料与规则冲突时**显性输出冲突**并交人裁决，不静默二选一。
- **FR-COM-8 模板缺失不降级**（fail-closed，仅作用于文件触发的自动补建）。

## 九、验收方向（合并四线去重，按宪法 Q1 须可执行、可判定）

| # | 场景 | 预期 |
|---|------|------|
| 1 | 移除 SOP 声明文件后重启 | Atlas 能力不可用、无残留触发器（证明经注册通道接入，C11） |
| 2 | 人工在控制台新增节点 | **不触发模板门禁**，沿用 SOP-011 口径 |
| 3 | 归档一份"某节点完工单"（命中已有任务） | 输出含**目标 node_id** 的录入建议，**不新建节点** |
| 4 | 归档需补建节点、模板命中（有权限人） | 先命中模板 `ref_id`；按模板装配落库至临时节点（带 `template_ref_id`）；**认领后迁正** |
| 5 | 同上但**无权用户**触发 | 同 4 的门禁与装配；落临时节点等待认领，不报错、不静默丢弃 |
| 6 | 归档无归属文件、模板命中 | 落临时节点并标「无归属」；L4 用户可见并认领 |
| 7 | 归档需补建节点、**模板库无匹配** | **不创建任何节点**；产出「缺模板」提案（含来源文件与匹配尝试依据） |
| 8 | 模板库不可用 / 索引损坏 / 检索工具异常 | 一律按"未命中"处理：不建节点、出「缺模板」提案；文件归档主链路仍成功 |
| 9 | 复核一条自动补建的节点 | 能回指装配它的模板 `ref_id` 与具体条目 |
| 10 | 模板只读工具在 LLM 链路被调用 | 能列出模板、能读到指定模板的清单与附件清单；**装配调用后库行数不变**（只读） |
| 11 | 装配后落库 | 各类关联表行数与确认项一致；被移除项不入库；越权/不存在的 ID 被服务端丢弃并回报；单条失败不阻断节点创建 |
| 12 | 投喂一份计划类资料 | 产出变更草案、**暂不落库**；确认后落库；未采纳条目丢弃 |
| 13 | 重复归档同一份资料 | 不产生重复节点、无重复更新（幂等） |
| 14 | L4 用户对某节点执行停用 | 状态为「停用」，完成度汇总与提醒中排除；L3 用户执行同一操作被拒 |
| 15 | 给出"取得施工许可证后 30 天" | 产出时间 = 被锚定节点的计划时间 + 30 天，非猜测值 |

## 十、待拍板 / 开放问题（汇总四线未决 + 本次发现）

1. **模板存储形态收敛**（承 §五-2）：统一为"文件夹 + 固定命名清单文件 + 附件"（推荐，可承载对象声明与参考范例），还是沿用"单 `.md` + 段落锚点"？若统一，需一并定清单文件名（`template.yaml`？）与目录命名（`ref_id` vs `ref_id-node_name`）。
2. **阶段体系统一**（承 §七-2、节点状态自证化 §八）：四阶段（立项/规划设计/工程施工/交付结算）vs 三阶段主干（前期/设计/施工）——须定一套，并明确阶段是否只作模板/展示层分组。
3. **模板读取权限门槛**：列出/读取模板定 L3+ 还是 L5+？（建节点引用模板沿用 L5+）
4. **工具粒度**：`list_node_templates` + `read_node_template` 两个工具，还是合并为一个？装配预览是否与之一并？
5. **对象声明承载位**（承 §五-3）：独立小节（如 `## 对象声明`）vs 清单文件字段——须与 #1 一并定，避免同一信息两处。
6. **成员用户默认集**：模板声明"某单位应参与"时，是否默认把该单位**全部在职人员**加为成员？还是要求声明中显式指定角色？
7. **临时节点基础设定**（承节点状态自证化 §八）：按阶段/里程碑**预建** vs 按需（懒）创建。
8. **`UNASSIGNED` 伪节点处置**：与两层临时节点口径一并定（自证口径下它永不流转）。
9. **`acknowledged_*` 三列**：仅存量兼容保留，还是恢复一条最小写入路径使其成为"可写的纯标记"？
10. **无自有成果的叶子节点**（承节点状态自证化 §五-1）：是否要求**所有**节点（含任务）至少 1 条必需成果？（现运行时有两处创建路径不带成果）
11. **演进触发**：模板锚定门禁落地后，LLM 自由度只剩"把文件对到哪个模板"。跑 1–2 个真实项目收集**模板匹配质量**——若匹配不可控（常见文件对不上模板），**优先补齐模板库**（模板由人维护），而非放开自动建节点；必要时再评估"专用匹配工具 + 专用 prompt"。
12. **企业台账数据质量**：`CompanyInfo.type` 为自由文本且写法不统一，`scope`（承包范围 JSON）**全仓无代码读取**——对象采集器的召回质量依赖该台账规范化程度，需并行推动数据治理。
