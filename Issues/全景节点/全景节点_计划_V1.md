## 硬约束（违反即失败）

> 项目铁律直接引用 [宪法 §2](../.claude/skills/_shared/constitution.md)，**不自行发明**。

1. **禁止修改已有接口签名**：除本设计明确标注「修改接口签名」处外，只在已有类中新增方法、新增字段，不修改现有方法签名。本设计标注的签名变更仅 2 处：`determine_node_status`（新增入参）、`NodeService.create_node` 的落库编排顺序（不改签名，仅扩展命令字段）。
2. **遵循宪法铁律**（本设计涉及部分逐条自检）：

   | 铁律 | 本设计如何遵守 |
   |------|--------------|
   | C0 根治而非迁就 | 模板库形态一次收敛到「目录 + 结构化清单入口 + 附件」，不做双形态兼容分支；收容兜底由「无节点承载的标记」整体升级为真实节点，不留 `UNASSIGNED` 兼容；索引生成通路修正为「宿主机写 + 容器内只读校验」，不留静默跳过 |
   | C2 分层不可跳 | 模板解析/装配/判定全部落在 Service 层（新区块 `services/node_template_loader.py` 等），控制台路由只调用、工具层只搬入参、判定不经 LLM |
   | C3 SOP 即路由 | 模板库的位置/发现/使用/权限与工具声明写进 `SOP-011`，重启生效；移除声明即回落手工路径（见 §「AC-US-03.3 口径偏差」） |
   | C6 Sync repo + to_thread | 新增 repo 调用（`node_role` 过滤、容器查询、事件改挂）由 async Service 以 `asyncio.to_thread` 包裹 |
   | C9 ToolManager / ScriptManager 边界 | 模板索引与存量迁移属运维脚本（subprocess）；模板读取与装配属业务工具（进程内）；两者共享 Service 层但互不调用 |
   | C10 工具必须带参数 schema | 新增 `read_node_template` 等工具三步齐备：源文件 `_XXX_SCHEMA` → `registry.py` 注册 `params=` → `tools_consistency.py` 的 `TOOL_SCHEMA_MAP`（另同步 `REGISTERED_TOOLS`/`TOOL_META_MAP`/`TOOL_WRITE_MODE_MAP`） |
   | C11 功能注册接入 + Q6 | 新增能力逐一登记 §接线矩阵；新增「归档后处理器注册表」作为归档分析的注册点（禁止在归档收口散落业务逻辑）；「仅注册无调用 / 仅写入无读取」列入各模块静态可达性验收 |
   | C12 Session 主循环冻结 | 判断能力以 SOP 声明 + 运行时推导实现：门禁/判定/反推均落在 Service 层并被**工具**与**归档后处理器**调用，**不触碰** `session/loop.py`、`kernel/react_kernel.py`、`session/session_graph.py` |
   | C13 控制台 = 观察窗口 | 控制台模板/装配/迁正/停用面板全部复用本设计的能力层实现；路由层内联的模板解析（`console_resources.py:305-520`）**整体移除**，不在路由层保留第二份实现 |
   | Q5 无越界 | 不引入新依赖（仅用既有 `pyyaml` / `re` / `json`）；不顺带修复与本需求无关的既有不一致（`UpdateNodeCommand` 缺 `related_company_id`，见 §现有模块改动清单，登记为另案） |

3. **每模块验收**：每模块的验收检测必须通过，否则停止并报告。
4. **遵循接口契约**：跨模块调用只经约定接口，不绕过接口直接读写对方内部数据。
5. **不私自扩需**：发现规格缺陷**回退 req-review**，不在本设计内新增/改写需求。本设计发现 1 处规格张力（AC-US-03.3 与 AC-US-03.4 在既有 SOP-011 准入级别下不可同时满足字面），处理方式见 §「PRD 约束落实」与 §「待裁决项」。
6. **接线闭合（Q6）**：每个产出物声明消费者与接线点（§接线矩阵）；无消费者不得进入编码。

### AC-US-03.3 口径偏差（需裁决，详见 §待裁决项）

PRD 有两处 AC 在**既有权限口径**下不可同时满足字面：

- AC-US-03.3：移除 SOP 声明文件后重启 → 模板读取能力**不可用**且无残留触发器（证明经注册通道接入）
- AC-US-03.4：模板列出/读取门槛为 **L4+**；低于 L4 被明确拒绝
- 既有限制：`SOP-011` 的业务流版本信息声明「权限控制 admin（仅 L5+）」，且 PRD AC-US-03.2 要求**不改**既有权限映射

且 `fetch_available_tools._merge_sop_declared_tools` 的语义是**并集**（"即使级别层不放行，也并集进可见集"），因此「被 SOP 声明」不能成为工具不可用的**必要条件**——只要级别层放行，移除 SOP 后工具仍可调用。

**本设计选择**：满足 AC-US-03.4（门槛落级别层，L4+ 三入口可用），AC-US-03.3 改以下述三条判定替代字面：

1. 移除 `SOP-011` → 重启 → 能力目录（`SkillRegistry.list_skills`）不再含模板库声明，对话侧**无模板问答触发语义**；
2. 静态可达性扫描：无 SOP 外的裸引用/硬编码触发器（`grep` 注册点 vs 调用点）；
3. 归档后处理器注册表中的门禁处理器不受影响（其可用性由注册表决定，与 SOP 无关，属预期）。

> 替代方案（需回退 req-review）：把 `SOP-011` 准入级别由 L5 放宽到 L4。**不推荐**——该 SOP 声明了 14 个节点工具（含 `create_node`/`discard_nodes` 等 admin 级写工具），放宽准入会连带改变这些工具的会话可达性，波及面远大于本需求，且直接违反 AC-US-03.2。

## 数据流设计

### 主干流程

```
【一份文件上传】
  归档收口（archive_upload / handle_file）
    └─ asyncio.create_task → ArchiveHandlerRegistry.dispatch(file_id, project_id, actor)
         ├─ [M5] NodeTemplateGate.evaluate(file) ──┬─ 未命中 → 缺模板提案（零建节点）
         │                                          └─ 命中 → matched_ref_id
         ├─ [M6] NodeAttributionService.judge(file) → 档A / 档B / 档C（含依据）
         ├─ [M6] NodeCompletionInference.suggest(file) → 「像 X 节点成果」+ 询问批准
         └─ [M7] 档B/C 且命中 → NodeContainerService.get_or_create_*(project) → 落临时节点
              失败/异常 → 仅记录，不影响已完成的归档（fail-open）

【人工按模板建节点】
  三入口（控制台 / 对话工具 / 批量脚本）
    └─ [M2] NodeTemplateLoader.get_template(ref_id)
         └─ [M3] NodeAssemblyService.build_draft(template, project, operator) → 只读草稿
              （候选集合 + 依据 + 未解析项；不写库）
              └─ 人增删确认
                   └─ [M4] NodeService.create_node(cmd 含六类对象)
                        节点 → 成果 → 参与单位 → 参与人 → 共享文件 → 依赖
                        （节点必成功；其余逐项失败不阻断，进 failed[] 回报）

【未归类信息落点】
  事件/任务/文件写入（node_id 缺省）
    └─ [M7] NodeContainerService.get_or_create_sink(project_id) → 真实收容节点 node_id
         └─ project_events.node_id = 收容节点（不再是常量 'UNASSIGNED'）

【认领与归位】
  临时节点 → [M7] promote(node_id, target_parent) → node_role=BUSINESS + 挂正式父（编号不变）
  未归类事件 → [M7] reassign(event_id, target_node) → 改挂 + 留痕（改挂前/后归属 + 操作人）
```

### 核心流程

| 流程 | 触发条件 | 参与者 | 数据流向 | 异常路径 |
|------|---------|--------|---------|---------|
| 模板清单/详情读取 | 对话询问 / 控制台面板 / 装配链路 | M2→资产 | 读 `index.yaml` → 读 `{ref_id}/template.yaml` → 返回清单/附件/声明原文 | 模板库缺失 / 索引损坏 → 返回明确失败（不异常冒泡）；调用方不影响归档与建节点 |
| 对象装配（只读草稿） | 选中模板 + 项目 + 操作人 | M3→M2→既有 repo（只读） | 声明 → 四类采集 → 候选集合 + 依据 + 未解析项 | 声明语法错/类型越词表 → 输出 `warnings[]`，不静默；零候选不报错，进未解析项 |
| 确认落库 | 人确认草稿 | M4→既有 Service | 六类对象按依赖序落库 | 节点创建失败 → 整体失败；单项失败 → 进 `failed[]`，节点保留 |
| 文件归档后判定 | 归档收口异步触发 | M5/M6/M7→既有 repo | 文件 → 门禁 → 档位 → 建议/提案/临时节点 | 三步任一异常 → 仅日志，归档结果不变（fail-open） |
| 收容节点懒创建 | 首次出现未归类记录 / 档B·C落地 | M7→Repo→DB | 按 `project_id` 查容器 → 无则建 → 返回 `node_id` | 并发冲突 → 唯一索引报错 → 重查返回既有（幂等） |
| 迁正 / 归位 | 有权限者认领或改挂 | M7→Repo→DB | 改 `parent_node_id`/`node_role`（迁正）或 `project_events.node_id`（归位）+ 留痕 | 目标不存在/越权 → 拒绝并回报 |
| 整树装配 | 计划类资料归档 / 用户显式指定 | M9→M2/M4 | 识别（置信度）→ 抽取节点树 → 与现有比对 → 草案（运行时可读）→ 人勾选 → 复用批量能力写入 | 低置信度 → 不进入装配，仅归档；重复投喂 → 幂等不重复 |

## M1: 模板库形态收敛与索引改造

**依赖**：无（本模块为首建模块）

**实现的需求**：US-01（AC-US-01.1~01.6）、US-05（AC-US-05.1~05.3）

**层级**：资产层 + 脚本层

**职责**：把模板从「顶层单文件 md」收敛为**自洽单元**（固定命名的结构化清单入口 + 附件），索引递归覆盖子目录并登记附件清单；索引生成归属宿主机（模板目录只读），容器内只保留只读校验。

### 接口契约

#### 模板单元形态（资产契约）

| 项 | 约定 |
|----|------|
| 单元 | 目录 `emily-data/node_templates/{ref_id}/`（目录名 = `ref_id`，不一致 → 告警） |
| 清单入口 | 固定命名 `template.yaml`（机器可读；承载入库所需字段） |
| 附件 | 同目录任意格式（`*.xlsx` / `*.md` / `*.pdf` …）：仅登记，不解析 |
| 排除 | 根目录 `README.md` 不视为模板单元 |

`template.yaml` 字段（结构化清单）：

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `ref_id` | str | ✓ | 模板编号（前缀 `REF-CONST-*`） |
| `node_name` | str | ✓ | 节点名称 |
| `node_type` | enum | ✓ | `MILESTONE` / `TASK` |
| `stage_id` | int | — | 模板侧阶段分组（**展示层用，不入库**） |
| `summary` | str | ✓ | 摘要（迁移时取既有值，保证 AC-US-01.5） |
| `deliverables` | list | ✓ | 成果清单：`name` / `target_amount` / `unit` / `is_required` |
| `declarations` | 结构化块 | — | 对象声明（M3 定义与校验；**不进索引**，随内容按需读取） |
| `preconditions` | list | — | 前置成果文字描述（供 M3 匹配） |

#### 索引契约（`index.yaml`）

| 字段 | 类型 | 变更 | 说明 |
|------|------|------|------|
| `updated_at` / `template_count` / `stage_distribution` / `type_distribution` | — | 不变 | 顶层统计 |
| `templates[].ref_id` / `node_name` / `node_type` / `stage_id` / `summary` | — | 不变 | 保持既有字段名（减少下游改动）；`stage_id` 语义重述为模板侧展示分组 |
| `templates[].entry` | str | **新增** | 清单文件相对路径，固定 `{ref_id}/template.yaml` |
| `templates[].attachments[]` | list | **新增** | 附件清单：`{name, size, type}`（AC-US-01.3） |

**扫描口径**（`maintain_node_template_index.py`）：遍历 `node_templates/*/` 一级子目录 → 含 `template.yaml` 者为模板单元 → 递归登记该目录下除清单文件外的全部文件为附件。**不做双形态兼容**（C0）。

#### 对外接口（脚本）

| 脚本 | 入口 | 说明 |
|------|------|------|
| `scripts/maintain_node_template_index.py` | `main() -> int` | 0=一致/成功、1=`--check` 发现差异、2=只读目录写入失败 |
| `scripts/migrate_node_templates.py` | `migrate(ref_id="", dry_run=False) -> dict`、`verify() -> dict` | 可 import 供薄壳串联 |
| `scripts/node_template_release.py` | `main() -> int` | 聚合薄壳 |

### 数据模型

无 DB 变更（纯资产层）。资产变更见上「模板单元形态」与「索引契约」。
`emily-data/node_templates/README.md` 同步修正：删除不存在模块的映射说明、修正 `stage_id` 的过期入库映射。

## M2: 模板能力层与只读检索能力

**依赖**：M1

**实现的需求**：US-02（AC-US-02.1~02.5）、US-03（AC-US-03.1~03.4）；US-04 的能力侧（AC-US-04.1 的"由能力层提供"）

**层级**：Service（loader）+ 工具层 + SOP 资产 + 注册通道

**职责**：把模板解析从控制台路由层**整体下沉**到 Service 层，对外提供**一个**只读检索能力（列清单 + 读详情），经工具注册通道接入并由 SOP 声明其位置/用法/权限。

### 接口契约

#### 声明契约（模板内，承载位见 §附录 A-B1）

`template.yaml` 的 `declarations` 为**结构化块**，按对象类型分节；每条含「描述 / 匹配条件 / 是否必需」：

| 对象类型 | 匹配条件字段（**声明式**，非脚本） | 采集口径 |

## 阶段反思指令

每完成一个模块的设计，在进入下一个模块之前，执行以下反思：

1. **检查设计完整性**：本模块的接口契约、数据模型、验收检测是否完整（尤其"承接对方产出物"的接口是否已定义）。
2. **检查追溯闭合**：本模块声明的 US 是否都有接口/验收覆盖；对照 §追溯矩阵有无遗漏。
3. **检查设计偏差**：是否有与 PRD 不符的设计？如发现规格缺陷，**回退 req-review**，不在计划内扩需。特别复核三条红线：装配链路是否全程只读、判断链路是否只出建议、归档与建节点主链路是否始终不阻断。
4. **判断是否继续**：
   - 偏差 ≤ 1 个接口调整 → 直接修改设计文档对应模块，继续
   - 偏差 2–4 个接口或模块职责调整 → 在本设计末尾追加「v1.1 修订记录」，继续
   - 偏差 > 4 个接口或架构方向变化 → **停止**，报告给用户，等用户决定是否重新生成设计
5. **每次模块完工后必查（本设计特有）**：`git diff --name-only | grep -E "session/|kernel/"` 必须为空（C12 腐化判据）。
