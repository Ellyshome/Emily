## 关键架构变化

### 白名单软化

```
旧：Skill YAML tools 白名单 → 硬约束，"不在白名单直接拒绝"
新：Session 可见 API 集合 → 软约束，"不在 Session 可见 API 才拒绝"
         ├─ Skill 推荐工具（有 ParamMapping）→ 走原有参数解析
         └─ Session 元能力（无 ParamMapping）→ _llm_resolve_params() 动态推导
```

### Session 启动预载扩展

```
旧：Session 启动预载 项目 / 权限 / 记忆
新：Session 启动额外预载 4 类原子化能力：
    ├─ available_tools        → ToolRegistryRepo.get_available(permission_level, sop_allow)
    ├─ visible_schema_summary → db_perms 格式化为可读文本
    ├─ visible_files_count    → SessionAccessibleFileRepo.get_file_summary(user_id)
    ├─ visible_files_summary  → "共 N 个文件（类型分布）"
    ├─ rag_available          → RAG provider.is_available()
    └─ rag_collections        → RAG provider.collections
```

### 文件搜索双用途设计

```
search_files.py
├─ 作为 API  → register() 返回 BusinessFlowTool → SkillExecutor 调用
│               → handle_search_files() → SessionAccessibleFileRepo.search()
└─ 独立脚本  → uv run python -m emily_core.tools.scripts.search_files "精装" --user-id UUID
```

### 权限过滤链

```
ToolRegistryRepo.get_available(permission_level, sop_allow)
├─ category=base     → 全部用户可用（search_files, query_data, knowledge_search）
├─ category=business → 按 permission_flag 过滤（all/write/admin vs 6级权限）
└─ category=project  → 仅 L5-L6 管理员可用（node 操作 / email 等）
```

## 依赖关系

```
tool_registry 表 ← ToolRegistryRepo
    ↑
    ├── register_api.py（写入）
    └── _sub_fetch_available_tools()（读取 → SessionContext.available_tools）

session_accessible_files 表 ← SessionAccessibleFileRepo
    ↑
    ├── sync_for_user()（写入：Session 启动时 by SessionAgent）
    ├── get_file_summary()（读取 → SessionContext.visible_files_summary）
    └── search()（按需查询 → search_files 工具）

BusinessFlowTool.category/permission_flag
    → registry.py 注册时标记
    → ToolRegistryRepo.get_available() 权限过滤

SessionContext.available_tools
    → SkillExecutionContext.session_available_tools
    → SkillExecutor 白名单软化（Session 级可见性检查）
    → {available_tools} prompt 模板变量注入 LLM
```
