# Session 原子化能力重构 — 需求说明

> 日期：2026-07-05
> 状态：已确认（v2 — 根据意见修订）

---

## 1. 背景与问题

当前 SOP-Skill 根据设计定位，应只提供业务流程（步骤编排、前后步骤依赖、输出成果要求），不提供方法与数据。但 Session 缺乏自备的原子化能力，导致以下问题：

### 1.1 Skill 白名单约束死锁

如：SOP-005-QRY（数据查询）只声明了 `query_data` 工具，用户问"是否有精装施工图"时，搜索可见文件列表的一句话说明更合适，但 SkillExecutor 白名单校验会拒绝调用。

### 1.2 Session 不知道自己能干什么

SessionContext 只有 `available_skills: list[str]`（SOP ID 列表），没有：
- 可用工具清单（哪些工具、什么签名、什么权限）
- 可访问数据库 Schema（哪些表、哪些字段）
- 可见文件列表（项目范围内哪些文件、什么类型）
- RAG 访问能力（知识库是否可用、有哪些知识库）

### 1.3 工具与 Skill 强耦合

工具注册在 BusinessFlowToolRegistry 中，Skill YAML 通过白名单引用。Agent 无法独立获知"我能调哪些工具、什么签名、我有什么权限调"。

### 1.4 数据边界模糊

Agent 不知道自己能看到哪些表、哪些字段、哪个 RAG 库。权限过滤散落在各 handler 内部（如 query_data 的 `_session_scope`），不透明。

---

## 2. 需求

### 2.1 SOP-Skill 不记录工具白名单

SOP-Skill 只管业务流程，不限定可用工具。工具以 Session 能提供可访问的 API 工具为准——**能看到就能用**。Skill YAML 中的 `tools` 段降级为"推荐"或移除。

### 2.2 Session 自备原子化能力

Session 应自备以下原子化功能，作为 Agent 的元技能：

- **可用工具目录**：统一存放的工具集合，Session 可查询自己有权调用的工具列表
- **可访问 DB Schema**：Session 知道自己能查哪些表、哪些字段
- **可见文件列表**：Session 知道自己能看到哪些文件
- **RAG 访问 API**：Session 知道知识库是否可用、有哪些知识库

### 2.3 工具 API 注册表（DB 表）

建立统一存放的工具集合，对外只提供调用接口 API。数据库表至少存有：

| 字段 | 说明 |
|------|------|
| API 的 ID | 工具唯一标识，如 `search_files` |
| API 签名 | 函数签名（参数 + 返回值定义） |
| API 功能一句话说明 | 如"根据自然语言描述搜索可见文件" |

详细说明通过 API 的 `help()` 动态获取。

### 2.4 可见文件表（DB 表）

新建物理表记录用户→文件的可见关系，支持三种授权类型：

- **项目范围自动授权**（project_scope）：用户所属项目范围内的文件
- **节点关联授权**（node_linked）：通过全景节点关联的文件
- **显式授权**（explicit）：管理员/系统显式授予的文件访问权

### 2.5 工具脚本双用途

每个工具脚本应同时满足：
1. **作为 API 供系统调用**：注册到 BusinessFlowToolRegistry，被 SkillExecutor / Agent 调用
2. **作为独立脚本供测试或运维使用**：可直接 `python script.py --args` 运行

### 2.6 工具注册脚本

应有一套将脚本注册为 API 的脚本（注册器），一次执行同时完成：
1. API 注册（代码注册到 BusinessFlowToolRegistry）
2. 数据库 API 记录录入（写入 `tool_registry` 表）

### 2.7 本次交付范围：仅演示一个工具

本次只实现一个演示工具，验证完整链路：

> **search_files** — 根据自然语言描述，在可见文件中，通过关键词匹配文件名或一句话描述字段，查找最可能匹配的文件。

其他工具（query_data、knowledge_search 等已有工具的迁移）后续阶段编写。

### 2.8 元能力独立执行路径

Agent 的基本能力以原子化技能的形态，作为 Agent 的元技能出现。元能力有独立执行路径，不受 Skill 白名单限制。Session 可见的 API 工具，Agent 都能调用。

---

## 3. 设计约束

1. **Skill ≠ 能力**：Skill 只管流程编排，元能力是原子工具
2. **能看到就能用**：Session 可见的 API 工具即为可用，无需额外白名单
3. **工具注册 = 代码注册 + DB 记录**：注册器一次完成两件事
4. **工具脚本双用途**：既能被系统调用，也能独立运行
5. **本次只做一个工具**：search_files，验证链路
6. **一步到位实施**：不分阶段
