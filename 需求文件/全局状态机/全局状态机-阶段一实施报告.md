## 三、状态机引擎设计

### 3.1 节点状态转移矩阵

```
NOT_STARTED → IN_PROGRESS → COMPLETED (终态)
                          → BLOCKED → IN_PROGRESS
                                    → DELAYED
                          → DELAYED → IN_PROGRESS
                                    → COMPLETED
```

```python
class NodeStatus(Enum):
    NOT_STARTED = "NOT_STARTED"    # 未启动
    IN_PROGRESS = "IN_PROGRESS"    # 进行中
    BLOCKED    = "BLOCKED"         # 已阻塞
    DELAYED    = "DELAYED"         # 已延期
    COMPLETED  = "COMPLETED"       # 已完成（终态）

TRANSITIONS = {
    NOT_STARTED:  [IN_PROGRESS],
    IN_PROGRESS:  [COMPLETED, BLOCKED, DELAYED],
    BLOCKED:      [IN_PROGRESS, DELAYED],
    DELAYED:      [IN_PROGRESS, COMPLETED],
    COMPLETED:    [],  # 终态，禁止一切转移
}
TERMINAL_STATES = frozenset({COMPLETED})
```

### 3.2 前置条件满足度公式

```
satisfaction = Σ(前置节点状态系数 × 依赖权重)

状态系数：COMPLETED = 1.0, IN_PROGRESS(>80%) = 0.8, IN_PROGRESS(≤80%) = 0.5, 其他 = 0
强依赖约束：任何 required=True 的依赖非 COMPLETED → 满足度上限 99%
```

### 3.3 BFS 级联更新

节点 COMPLETED → 遍历所有下游节点 → 重新计算 `precondition_score` → 若达到 100 且 NOT_STARTED → 自动 IN_PROGRESS → 递归传播（最大深度 5）

### 3.4 关键异常类

| 异常 | 触发条件 |
|------|----------|
| `InvalidStateTransitionError` | 非法状态转移（如 COMPLETED → IN_PROGRESS） |
| `NodeNotFoundError` | node_id 不存在 |

## 五、节点导入

### 5.1 解析流程

`scripts/import_nodes.py` 解析 `emily-data/baseknowledge/全景节点.md`：

1. 正则提取 `## 阶段N：...` → 7 条阶段记录
2. 逐行扫描 `### N.N.N 节点名` → 提取 node_id + node_name
3. 读取后续字段行（`主责部门` / `前置条件` / `任务成果`）
4. 从 `前置条件` 行中正则匹配 `节点编号-《成果名》` → 建立依赖关系
5. 从 `任务成果` 行中正则匹配 `《xxx》` → 建立成果物
6. 按节点名关键词自动分类 `node_type`（design/construction/license/inspection 等）

### 5.2 使用方式

```bash
# 容器内执行（宿主机需通过 localhost:25432 连接）
docker exec emily-core python scripts/import_nodes.py --dry-run   # 预检不写库
docker exec emily-core python scripts/import_nodes.py              # 导入
docker exec emily-core python scripts/import_nodes.py --reset      # 清空再导入
```
