## 二、Session-Agent 能做什么

### 2.1 查询项目状态（query_sm_status 工具）

Agent 收到用户消息后，通过 LLM function-calling 调用 `query_sm_status`：

```
用户: "桩基做完了吗？"
  → LLM 调用 query_sm_status(keyword="桩基")
  → 返回匹配节点的状态、满足度、整体进度
  → LLM 基于结果自然语言回复
```

```
用户: "阶段二整体进度如何？"
  → LLM 调用 query_sm_status(stage_id=2)
  → 返回所有阶段二节点状态列表 + 进度百分比
```

```
用户: "施工许可证办下来了吗？"
  → LLM 调用 query_sm_status(node_id="4.14")
  → 返回节点 4.14「建筑工程施工许可证办理」的当前状态
```

### 2.2 自动完成后节点（try_match_and_complete）

当用户录入项目事件时，系统自动尝试匹配全景节点并推进状态：

```
用户: "帮我创建事件：样板段放线完成"
  → record_event 创建事件成功
  → try_match_and_complete("样板段放线完成") 自动匹配
  → 找到节点 5.1.1「施工测量放线」（相似度 > 0.35）
  → 自动将其从 IN_PROGRESS → COMPLETED
  → 级联更新所有下游节点的前置满足度
  → 回复追加："✅ 自动匹配：节点 5.1.1 已完成"
```

匹配使用 `difflib.SequenceMatcher`，阈值 0.35。仅匹配当前状态为 `IN_PROGRESS` 的节点。

### 2.3 级联传播示例

```
1.1 COMPLETED
  → 1.2 precondition_score: 0 → 100（1.1 已完成，权重 1.0）
  → 1.3 precondition_score: 0 → 100
  → 1.2、1.3 若 auto_start_enabled 则自动 IN_PROGRESS
  → 继续传播到 1.4（依赖 1.2）、1.5（依赖 1.3+1.4）
```

## 三、调用链路

```
用户消息 → IM → emily_agent 薄插件 → EmilyCore.handle_message
  → SessionPool.route → SessionAgent.handle
    → LLM 意图识别（路由 prompt 含 SOP 目录）
    → 命中 SOP → WorkItem → PipelineBUS 4 节点
      → node3: WorkItemAgent._real_execute()
        → BusinessFlowTool.handler(params)
          ├── record_event → 事件入库 + try_match_and_complete ← 新增
          ├── record_task
          ├── query_data → DB 查询
          └── query_sm_status ← 新增（LLM function-calling）
                → StateMachineService.query_sm_status()
                → sm_nodes/sm_stages 表查询
                → 返回状态摘要给 LLM
```
