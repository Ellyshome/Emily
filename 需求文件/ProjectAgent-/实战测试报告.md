## 🐛 发现的问题

### Issue 1: 用户 ID 没有被正确关联（emy-test 问题 ✅ 已修复）

**现象**:
```
docker 日志: Auto-created user xxx (王总) bound to simulator/xxx
```

**原因**:
- Emily Core 使用 `sender_id` 作为 `im_user_id` 查找用户绑定
- 但数据库中 `user_im_bindings` 表的 `im_user_id` 与测试用户 ID 不匹配
- 导致每次发送消息都创建新用户，原有的权限数据没有被使用

**修复方案**:
需要修改测试脚本或 SQL 数据，确保 sender_id 与 user_im_bindings 中的 im_user_id 一致。

### Issue 2: 权限系统尚未集成到消息处理（非 emy-test 问题，不修复）

**现象**:
- 所有权限级别的用户消息都被正常接收和处理
- 没有看到任何权限拒绝的日志
- `takeover=true` 对所有用户生效

**分析**:
- 当前版本 Emily Core 的权限模块（Permission Module）可能尚未集成到消息处理流程
- 权限检查应该在 `handle_message` 早期执行，但目前没有看到相关日志
- 属于架构设计问题，需要在 Core 层面集成

**备注**: 这不是 emy-test 技能的问题，按要求不修复，仅记录。

### Issue 3: company_info 插入失败（非 emy-test 问题，不修复）

**现象**:
```
ERROR: there is no unique or exclusion constraint matching the ON CONFLICT specification
```

**原因**:
- company_info 表没有唯一约束，导致 `ON CONFLICT DO NOTHING` 语法失效
- 需要在 models.py 中添加 `__table_args__` 定义唯一约束

**备注**: 不影响核心权限测试，仅影响单位归属显示。按要求不修复。

### Issue 4: ProgressHook 警告（非 emy-test 问题，不修复）

**现象**:
```
WARNING: ProgressHook[progress.processing] failed (non-blocking):
object NoneType can't be used in 'await' expression
```

**原因**:
- Emily Core 内部的 progress hook 实现问题
- 不影响消息主流程

## 🔜 后续改进建议（非 emy-test 范围）

### 对于 Emily Core

1. **权限集成点**
   - 在 `handle_message` 入口增加权限检查
   - 根据用户 permission_level 决定是否接管/拒绝

2. **用户绑定优化**
   - 支持通过 user.id 直接查找，不依赖 im_user_id
   - 或者在测试数据中正确关联 users 和 user_im_bindings

3. **权限审计日志**
   - 每次权限检查都应该记录日志
   - 包括：用户、操作、权限级别、检查结果

### 对于 emy-test

1. **对齐用户绑定**
   - 修改 SQL 脚本，确保 sender_id 与 im_user_id 一致
   - 或者修改 tester.py，支持使用 username 作为 sender_id

2. **权限验证增强**
   - 增加验证不同用户回复内容差异的功能
   - 自动检测权限是否生效（例如：管理员能看到什么，访客看不到什么）

3. **测试报告导出**
   - 支持导出结构化的测试报告
   - 包含每个用户的测试结果和响应时间
