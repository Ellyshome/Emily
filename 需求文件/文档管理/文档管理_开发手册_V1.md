## 1. 模块定位

### 1.1 一句话

为 Emily 已有的文件归档体系增加**业务分类维度**（`file_category`），使用户能通过 IM 对话按分类检索和管理文件。

### 1.2 不是什么

- **不是独立的"文档管理模块"** — 不新建 Service / Application / Repo，扩展现有 `FileService` / `FileRepository` 即可
- **不是文件管理器** — 不做文件夹树、目录层级、拖拽移动
- **不是版本管理** — 不改动 `files` 表已有的 `version` / `is_latest` / `parent_file_id` / `change_log` 版本链逻辑

### 1.3 架构决策：为什么是枚举字段而非文件夹树

Emily 是 IM 对话驱动的 AI 助手，用户通过"说一句话"查询文件而非浏览目录树。7 类分类是属性维度不是层级结构，一个枚举字段足以支撑，且与现有 `SessionAccessibleFileRepo.get_file_summary()` 的 `by_type` 统计逻辑天然兼容。

## 2. 整体架构

### 2.1 分层调用链

```
IM 消息
  │
  └─→ Tool 层 (file_tool.py)
        │  handle_record_file / handle_query_files / handle_update_file_category
        │
        └─→ Application 层 (file_app.py)
              │  handle_file / handle_list_by_category / handle_update_category
              │
              └─→ Service 层 (file_service.py)
                    │  create_file_record / list_by_category / update_file_category / get_category_summary
                    │
                    └─→ Repository 层 (file_repo.py)
                          │  create / query_by_category / update_category / count_by_category
                          │
                          └─→ DB (files 表, file_category 列)

Session 层（独立并行）：
  SessionDataFetcher
    └─→ fetch_visible_files.fetch()
          └─→ SessionAccessibleFileRepo.get_file_summary()  ← 含 by_category 统计
```

### 2.2 硬约束

| 约束 | 说明 |
|------|------|
| **禁止修改已有方法签名** | 只能新增方法，不改现有方法参数签名 |
| **分层不可跳** | Tool → Application → Service → Repository → DB，不允许 Tool 直接调 Repository |
| **Sync repo + `asyncio.to_thread`** | Repository 全 sync，async 层用 `asyncio.to_thread()` 包裹 |
| **枚举在应用层定义** | 不做 DB CHECK 约束，方便未来扩展 |
| **参照已有模式** | 新代码参照 WorkItemState 枚举、已有 FileRepository/FileService 的方法模式 |

## 3. 7 类分类体系

### 3.1 枚举定义

位置：`emily_core/infrastructure/database/models.py`，`FileCategory` 类

```python
class FileCategory:
    PROJECT_LICENSE    = "PROJECT_LICENSE"      # 项目证照
    CONTRACT           = "CONTRACT"             # 承包合同
    WORK_RECORD        = "WORK_RECORD"          # 工作记录
    PHASE_DELIVERABLE  = "PHASE_DELIVERABLE"    # 阶段成果
    PROCESS_DOC        = "PROCESS_DOC"          # 过程文件
    MANAGEMENT_SPEC    = "MANAGEMENT_SPEC"      # 管理规程
    OTHER              = "OTHER"                # 其他文件
```

### 3.2 枚举 API

| API | 说明 | 示例 |
|-----|------|------|
| `FileCategory.ALL` | 全部 7 种分类的列表 | `["PROJECT_LICENSE", "CONTRACT", ...]` |
| `FileCategory.DISPLAY_NAMES[val]` | 枚举值 → 中文显示名 | `"项目证照"` |
| `FileCategory.validate(val)` | 校验合法性，非法回退 OTHER | `validate("INVALID")` → `"OTHER"` |
| `FileCategory.display(val)` | 获取中文显示名 | `display("CONTRACT")` → `"承包合同"` |

### 3.3 分类规则

1. **7 类固定** — 枚举值定义在 Python 代码中，DB 无 CHECK 约束
2. **单值字段** — 一个文件只属于一个分类
3. **与 `file_type` 独立** — `file_type` 描述内容类型（自由文本），`file_category` 描述业务归属（枚举）
4. **默认 OTHER** — LLM 无法判断时默认归入"其他文件"
5. **分类可变更** — 用户可通过对话修改

## 5. 各层接口详解

### 5.1 Repository 层

**文件**：`emily_core/repositories/file_repo.py`

| 方法 | 说明 | 签名 | 新增/修改 |
|------|------|------|----------|
| `create()` | 创建文件记录 | `create(*, file_no, filename, ..., file_category="OTHER") -> File` | 修改：新增参数 |
| `query_by_category()` | 按分类查询文件 | `query_by_category(*, project_id=None, project_ids=None, file_category=None, limit=50) -> list[File]` | **新增** |
| `update_category()` | 更新文件分类 | `update_category(file_id: str, file_category: str) -> File \| None` | **新增** |
| `count_by_category()` | 按分类统计数量 | `count_by_category(project_id=None) -> dict[str, int]` | **新增** |

**`query_by_category()` 过滤逻辑**：按 `is_deleted == False` 过滤 → 可选 `project_id` / `project_ids` → 可选 `file_category` → 按 `created_at DESC` 排序 → 返回 limit 条。

**`count_by_category()` 注意事项**：采用应用层聚合（非 SQL GROUP BY），返回 `{"CONTRACT": 3, "PROJECT_LICENSE": 1, ...}` 格式。

### 5.2 Service 层

**文件**：`emily_core/services/file_service.py`

| 方法 | 说明 | 关键逻辑 |
|------|------|---------|
| `create_file_record(cmd)` | 创建文件记录 | 从 `cmd.file_category` 取分类（默认 "OTHER"）传入 repo |
| `list_by_category(project_id, file_category, limit)` | 按分类查询 | 透传 repo.query_by_category() |
| `update_file_category(file_id, file_category, operator_id)` | 更新分类 | **先调 `FileCategory.validate()` 校验**，再写入 repo |
| `get_category_summary(project_id)` | 按分类统计 | 调 repo.count_by_category()，返回 `{by_category: {中文名: 数量}, total: N}` |

**`get_category_summary()` 返回示例**：
```json
{
  "by_category": {"承包合同": 3, "项目证照": 1, "其他文件": 2},
  "total": 6
}
```

## 6. 权限模型

### 6.1 操作权限矩阵

| 操作 | 最低权限层级 | level 值 | 对应角色 |
|------|------------|---------|---------|
| 按分类查询文件 | all | ≥ 1 | 所有用户（含访客） |
| 修改文件分类 | write | ≥ 3 | 参建管理及以上 |
| 删除文件（软删除） | admin | ≥ 5 | 管理员 |

### 6.2 可见性隔离

`file_category` 是文件的元数据属性，不影响文件可见性判定。可见性仍由 `SessionAccessibleFile` 三级机制决定（project_scope / node_linked / explicit）。查询流程：

1. `SessionAccessibleFileRepo` 确定用户可见文件集合
2. 在可见集合内按 `file_category` 过滤
3. 返回结果

### 6.3 与保密级别的关系

`file_category` 与 `files.confidentiality` 是独立维度，查询时可组合过滤：

| 维度 | 字段 | 用途 |
|------|------|------|
| 业务分类 | `file_category` | 按文档用途检索（7 类枚举） |
| 保密级别 | `confidentiality` | 按密级过滤（0-公开/1-内部/2-机密/3-绝密） |

## 9. 扩展指南

### 9.1 新增分类

1. 在 `FileCategory` 类中添加新的枚举值
2. 将新值加入 `ALL` 列表
3. 在 `DISPLAY_NAMES` 中添加中文映射
4. 更新 Tool Schema 中的 `description` 字段（`file_tool.py`）
5. 更新 SOP prompt 中的分类决策规则
6. 更新本文档的分类表

**不需要**：DDL 变更（无 DB CHECK 约束）、索引变更。

### 9.2 与其他模块协作

#### 与全景节点模块

文件分类与全景节点（`NodeAccessibleFile`）是独立维度，互不冲突：

| 维度 | 字段/表 | 用途 |
|------|---------|------|
| 业务分类 | `files.file_category` | 按文档用途检索 |
| 节点关联 | `NodeAccessibleFile` + `files.source_module_type` | 按工程节点溯源 |

一个文件可同时有 `file_category="PHASE_DELIVERABLE"` 和 `source_module_type="NODE_DELIVERABLE_DOC"`。

#### 与 SOP 模块

文件管理 SOP（`emily-data/sops/`）需要注册以下意图路由：

| 用户意图 | 路由目标 |
|---------|---------|
| "查一下XX类的文件" | `query_files(file_category=...)` |
| "有没有XX文件" | `query_files(keyword=...)` |
| "项目有什么证照" | `query_files(file_category="PROJECT_LICENSE")` |
| "把XX文件改到XX类" | `update_file_category(...)` |

## 10. 常见问题排查

| 问题 | 可能原因 | 排查方式 |
|------|---------|---------|
| `file_category` 列不存在 | DDL 未执行 | `SELECT column_name FROM information_schema.columns WHERE table_name='files' AND column_name='file_category'` |
| 分类查询无结果 | 所有文件分类为 OTHER | 执行 DDL 后运行回填脚本 |
| Tool 不生效 | Tool 未注册 | 检查 registry.py 中是否有对应 `_reg_biz` 调用 |
| Session 中无分类信息 | `get_file_summary()` 未包含 by_category | 检查 `session_accessible_file_repo.py` 中 `get_file_summary()` 返回结构 |
| 权限未生效 | `update_file_category` 注册为 `all` 权限 | 确认 registry.py 中注册的 permission_level 为 `write` |
