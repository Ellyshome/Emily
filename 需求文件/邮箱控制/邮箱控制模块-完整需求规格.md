# 邮箱控制模块 — 完整需求规格

> **版本**：v1.0  
> **状态**：待评审  
> **关联需求**：`邮箱控制需求.md`  
> **目标**：为 Emily Core 提供模块化的邮件收发基座能力，供 SessionAgent 和 ProjectAgent 按需使用。

---

## 1. 模块定位

### 1.1 一句话

邮箱控制模块是 Emily Core 的**无状态能力层**——只提供 SMTP 发送 + IMAP 接收的实现，**不持有任何邮箱账号**。账号凭证由调用方（SessionAgent / ProjectAgent）自行提供。

### 1.2 设计原则

| # | 原则 | 说明 |
|---|------|------|
| P1 | **无状态** | 模块不存储凭证、不维护连接池、不持有会话。每次调用传入凭证 |
| P2 | **纯实现** | 模块是工具，不是服务。不主动做任何事，不启动后台任务 |
| P3 | **失败即反馈** | 调用失败直接返回错误信息，不做内部重试。重试策略由调用方决定 |
| P4 | **异步原生** | 基于 `aioimaplib` + `aiosmtplib`，全链路 async，不阻塞事件循环 |
| P5 | **分层一致** | 遵循项目分层：`Provider（抽象/实现） → Service（薄封装） → Config（配置入口）` |

## 2. 使用场景

### 2.1 ProjectAgent 场景

| 场景 | 触发条件 | 说明 |
|------|----------|------|
| **冷启动报告** | 系统启动完成 | ProjectAgent 用共享邮箱向管理员发送"Emily 实例已上线"通知 |
| **Order 轮询** | 定时任务，每 60 秒 | ProjectAgent 检查共享邮箱收件箱，查找管理员发来的 `subject=order` 邮件，解析正文作为系统命令执行 |
| **告警通知（未来）** | 系统异常事件 | 当 IM/SSE 通道不可用时，作为 fallback 通知管理员 |

### 2.2 SessionAgent 场景

| 场景 | 触发条件 | 说明 |
|------|----------|------|
| **用户发邮件** | 用户说"帮我发邮件给XX" | SessionAgent 从用户长期记忆中获取邮箱凭证，调用发送接口 |
| **用户查邮件** | 用户说"帮我查收邮件" | SessionAgent 用用户凭证调用收件接口，将结果纳入消息流 |

### 2.3 信息流约定

> Agent 收发的邮件，与一般通过 IM 入站的 message 走**同样的信息流**。只是信息来源标记为 `channel=email`。

这意味着：
- 收到的邮件正文作为消息内容进入 SessionAgent → WorkItem 处理链路
- 发送邮件的回复同样走 `chat_archive_service.record_outbound_reply()` 记录

## 3. 技术选型

| 层 | 选型 | 说明 |
|----|------|------|
| **SMTP 发送** | `aiosmtplib` | 原生 asyncio，支持 SSL/TLS/STARTTLS，轻量无依赖 |
| **IMAP 接收** | `aioimaplib` | 原生 asyncio IMAP4 rev1，支持搜索/获取/标记 |
| **邮件解析** | `email`（标准库）| 解析 MIME multipart、提取正文和附件 |
| **凭证注入** | 环境变量 `EMILY_EMAIL_IDKEY` / `EMILY_EMAIL_PASSWORD` | 与现有 Config 模式一致 |

### 4.2 Provider 抽象

```python
from abc import ABC, abstractmethod
from dataclasses import dataclass, field
from datetime import datetime
from typing import Optional

# ============ 数据对象 ============

@dataclass
class EmailCredentials:
    """调用者自备的邮箱凭证"""
    smtp_host: str          # 如 smtp.qq.com
    smtp_port: int          # 如 465 (SSL)
    imap_host: str          # 如 imap.qq.com
    imap_port: int          # 如 993 (SSL)
    username: str           # 邮箱地址
    password: str           # SMTP/IMAP 授权码（非登录密码）
    use_ssl: bool = True

@dataclass
class EmailAttachment:
    """邮件附件"""
    filename: str           # 展示文件名
    content: bytes          # 文件内容
    content_type: str       # MIME 类型，如 application/pdf

@dataclass
class EmailEnvelope:
    """一封收到的邮件"""
    uid: str                # IMAP UID（全局唯一递增），用于标记已读 / 去重
    message_id: str         # RFC 822 Message-ID 头
    sender: str             # From 地址
    recipient: str          # To 地址
    subject: str
    body_plain: str         # 纯文本正文
    body_html: Optional[str] = None   # HTML 正文（如有）
    date: Optional[datetime] = None
    attachments: list[EmailAttachment] = field(default_factory=list)
    is_order: bool = False  # 是否匹配 subject=order 约定

@dataclass
class SendResult:
    """发送结果"""
    success: bool
    message_id: Optional[str] = None  # SMTP 返回的 Message-ID
    error: Optional[str] = None

# ============ Provider 接口 ============

class EmailProvider(ABC):
    """邮件能力提供者抽象 —— 类比现有的 RagProvider（providers/rag/base.py）"""

    @abstractmethod
    async def send(self,
                   creds: EmailCredentials,
                   to: str,
                   subject: str,
                   body: str,
                   html: bool = False,
                   attachments: Optional[list[EmailAttachment]] = None,
                   ) -> SendResult:
        """发送邮件。"""
        ...

    @abstractmethod
    async def fetch_inbox(self,
                          creds: EmailCredentials,
                          subject_filter: Optional[str] = None,
                          from_self: bool = False,
                          unread_only: bool = True,
                          limit: int = 20,
                          ) -> list[EmailEnvelope]:
        """获取收件箱邮件列表。

        Args:
            subject_filter: 主题过滤关键词（None=不过滤）
            from_self: True=只查自己发给自己的邮件
            unread_only: True=只查未读
            limit: 最多返回数量
        """
        ...

    @abstractmethod
    async def fetch_orders(self,
                           creds: EmailCredentials,
                           since_uid: Optional[str] = None,
                           ) -> list[EmailEnvelope]:
        """获取 Order 邮件（ProjectAgent 专用便捷方法）。

        等价于 fetch_inbox(creds, subject_filter="order", from_self=True, unread_only=True)
        返回的 Envelope 已设 is_order=True。
        """
        ...

    @abstractmethod
    async def mark_read(self,
                        creds: EmailCredentials,
                        uids: list[str],
                        ) -> bool:
        """将指定邮件标记为已读。返回是否全部成功。"""
        ...
```

### 4.3 EmailService（薄封装层）

```python
class EmailService:
    """邮箱服务 —— 薄封装，组合 SMTP + IMAP Provider。

    不持有状态，不维护凭证，不启动后台任务。
    """

    def __init__(self, smtp: SMTPEmailProvider, imap: IMAPEmailProvider):
        self._smtp = smtp
        self._imap = imap

    async def send(self, creds, to, subject, body, **kwargs) -> SendResult:
        return await self._smtp.send(creds, to, subject, body, **kwargs)

    async def fetch_orders(self, creds, since_uid=None) -> list[EmailEnvelope]:
        return await self._imap.fetch_orders(creds, since_uid)

    async def mark_read(self, creds, uids) -> bool:
        return await self._imap.mark_read(creds, uids)
```

## 5. Order 邮件协议

### 5.1 约定

| 项 | 值 |
|----|-----|
| **用途** | 系统管理员 → ProjectAgent 的异步命令通道 |
| **发送方式** | 管理员用共享邮箱**自己发给自己** |
| **识别规则** | `sender == recipient == 共享邮箱地址` **且** `subject 包含 "order"`（大小写不敏感） |
| **轮询频率** | 每 60 秒（可通过 `email_poll_interval` 配置） |
| **已处理标记** | IMAP `\Seen` flag。标记后不再返回 |

### 5.2 正文格式

邮件正文为**自然语言**，由 ProjectAgent 的 LLM 解析意图并执行。示例：

```
主题: order: 查询项目进度

正文:
帮我查一下蓝天小区项目的当前进度，各个阶段完成情况。
```

```
主题: order: 创建任务

正文:
给张工安排一个任务：下周五前完成样板段消防验收。
```

```
主题: order

正文:
今天有哪些待处理的阻塞问题？
```

### 5.3 处理流程

```
PlanTaskScheduler 定时触发 (60s)
  → EmailService.fetch_orders(shared_creds)
    → IMAP 连接 → SEARCH SUBJECT "order" FROM "self" UNSEEN
    → 获取邮件列表 → 解析 MIME → 返回 EmailEnvelope[]
  → 对每封邮件:
      → 正文作为 message 注入 SessionAgent / ProjectAgent 处理链路
      → 来源标记 channel=email, source="order_mail:{uid}"
  → EmailService.mark_read(shared_creds, [所有已处理 uid])
```

### 5.4 幂等性

- **IMAP UID 天然去重**：同一 UID 只处理一次。`since_uid` 参数可跳过已处理的邮件
- **已读标记是边界**：`mark_read()` 成功后，后续 `fetch_orders()` 不再返回
- **Agent 端兜底**：如果同一封 order 因异常被重复注入，由 Agent 自身判断是否重复执行

## 6. API 接口规范

### 6.1 内部调用接口（Python API）

供 `EmilyCore`、`PlanTaskScheduler`、`SessionAgent` 内部调用。

```python
# ---- 发送 ----
result = await email_service.send(
    creds=EmailCredentials(
        smtp_host="smtp.qq.com",
        smtp_port=465,
        imap_host="imap.qq.com",
        imap_port=993,
        username="user@qq.com",
        password="授权码",
    ),
    to="recipient@qq.com",
    subject="会议通知",
    body="明天下午2点开会",
    html=False,
    attachments=None,  # 或 [EmailAttachment(...)]
)
# result.success → True/False
# result.error → 失败原因字符串

# ---- 收件（收件箱） ----
envelopes = await email_service.fetch_inbox(
    creds=...,
    subject_filter=None,  # 不过滤
    from_self=False,
    unread_only=True,
    limit=20,
)

# ---- ProjectAgent Order 专用 ----
orders = await email_service.fetch_orders(
    creds=shared_creds,
    since_uid=last_processed_uid,  # 增量拉取
)
```

## 7. 错误处理

### 7.1 错误分类

| 类别 | 示例 | 返回方式 | 调用方建议动作 |
|------|------|----------|----------------|
| **凭证错误** | 授权码过期、账号不存在 | `SendResult(success=False, error="AUTH_FAILED")` | 通知用户更新凭证，不重试 |
| **网络超时** | SMTP 连接超时 | `SendResult(success=False, error="CONNECTION_TIMEOUT")` | 可重试 1-2 次 |
| **协议错误** | IMAP SEARCH 语法错误 | 抛出 `EmailProviderError` 异常 | 记录日志，不重试 |
| **QQ 限流** | 发送频率过高 | `SendResult(success=False, error="RATE_LIMITED")` | 退避重试 |
| **附件过大** | QQ 邮箱附件上限 50MB | `SendResult(success=False, error="ATTACHMENT_TOO_LARGE")` | 提示用户缩小附件 |

### 7.2 模块职责边界

```
调用方                         邮箱模块                       外部
  │                              │                            │
  ├─ send(creds, ...) ──────────→│                            │
  │                              ├─ SMTP CONNECT ────────────→│
  │                              │←─ OK / ERROR ──────────────┤
  │←─ SendResult ───────────────┤                            │
  │                              │                            │
  │  （调用方自行决定重试/放弃）    │                            │
```

**模块不做的事**：
- ❌ 不重试
- ❌ 不排队
- ❌ 不死信队列
- ❌ 不缓存凭证

## 8. 安全设计

| 项 | 措施 |
|----|------|
| **凭证存储** | 共享邮箱凭证仅存于 `.env`（不入 git）。用户个人凭证存于长期记忆（`user_memory` 表），不在此模块 |
| **传输加密** | SMTP 465 SSL / IMAP 993 SSL，不降级明文 |
| **授权码隔离** | 使用 QQ 邮箱 SMTP/IMAP 授权码，非 QQ 登录密码 |
| **日志脱敏** | 日志中不打印 `password` 字段。打印 username 时截断为 `92****70@qq.com` |
| **输入校验** | `to` 字段校验邮箱格式；`subject` / `body` 长度限制（subject ≤ 998 字节，body ≤ 10MB） |

### 9.1 启动顺序

```

  ├─ 1. 加载 Config（含 email_* 字段）
  ├─ 2. 初始化数据库

  ├─ 5. NEW: 冷启动邮件报告（如果配置了共享邮箱）

```

### 9.2 PlanTaskScheduler 集成

在 `PlanTaskScheduler._main_loop()` 中新增一个 tick：

```python
async def _main_loop(self):
    while self._running:
        # ... 现有逻辑 ...

        # Order 邮件轮询（固定间隔）
        now = time.time()
        if now - self._last_email_poll >= self._config.email_poll_interval:
            await self._poll_order_emails()
            self._last_email_poll = now

        await asyncio.sleep(1)
```

### 9.3 SessionAgent 集成

```
用户消息 "帮我发邮件" 
  → SessionAgent.handle_message() 
    → LLM 意图识别 → chat_json 返回 {tool: "send_email", params: {...}}
      → ToolRegistry 路由到 email_tool.handler(params)
        → email_service.send(creds_from_memory, ...)
          → 返回 SendResult
        → 结果格式化为自然语言回复
```

## 10. 非功能需求

| 类别 | 要求 |
|------|------|
| **性能** | 发送单封邮件（不含附件）≤ 3 秒；IMAP 搜索 ≤ 5 秒 |
| **并发** | 模块无共享状态，支持多协程并发调用（各自独立凭证/连接） |
| **可用性** | 邮件模块失效不影响 IM/SSE 主通道 |
| **可测试性** | Provider 为 ABC，可 Mock 实现用于 smoke_test |
| **可观测性** | 每次 send/fetch 记录结构化日志（级别 DEBUG），含耗时、收件人域、邮件数 |
