> **日期**：2026-06-29
> **状态**：待实施
> **关联**：`SOP-012-FLOW-node_import.md` / `emily-data/baseknowledge/全景节点参考文档.md`

---

## 背景

当前 SOP-012（全景节点计划导入）承担了两项不同性质的职责：

1. **宏观**：从 Excel 文件解析阶段→节点树→依赖关系，构造全景节点图
2. **微观**：为每个节点填充完整的状态机细节（完成标准、责任人、监理单位等），生成节点实例文档

这两项工作在触发时机、数据量、核心困难上完全不同，应由两个独立 SOP 承担。

---

## 拆分方案

### SOP-012-FLOW：全景节点图构造（IMPORT）

| 维度 | 说明 |
|------|------|
| **业务目的** | 从 Excel 批量导入项目全生命周期节点计划，生成全景节点索引、Mermaid 图、依赖关系清单 |
| **触发时机** | 项目启动时一次性执行 |
| **输入** | 一个 Excel 文件（.xlsx，通常 2000+ 行） |
| **核心困难** | 列映射不确定、阶段名不标准、依赖关系缺失 |
| **产出物** | 全景节点索引.md / 全景节点图.mmd / 缺失依赖清单.md |
| **是否写 DB** | 可写 sm_nodes + sm_node_dependencies（--write 模式） |

**处理流程（概要）**：
```
Excel 文件
  ├── 读取 + 列映射（Agent 语义理解）
  ├── 识别阶段分类（以实际文件阶段名为准）
  ├── 解析 WBS 层级 → 节点树
  ├── 自动编号（阶段码-序号）
  ├── 依赖关系确认（主动询问用户 + WBS推断 + 阶段间推断）
  │     └── 缺失的生成缺失依赖清单
  ├── 输出全景索引.md + Mermaid .mmd
  └── 对每个节点，将基础数据传给 SOP-013 做实例填充
```

---

### SOP-013-FLOW：节点实例填充（DETAIL）

| 维度 | 说明 |
|------|------|
| **业务目的** | 针对单个节点，套用 V4 模板生成完整的节点实例文档。对缺失的关键字段主动向用户收集 |
| **触发时机** | ① SOP-012 批量调用（导入时）；② 用户独立触发（如"帮我把 SG-JG 的监理单位补上"） |
| **输入** | 节点编号 + 已知字段值（来自 Excel 解析或手工输入） |
| **核心困难** | 字段值不完整、不同阶段类型需匹配不同 L1 模板、需多轮对话补齐缺失字段 |
| **产出物** | 单个节点实例 .md 文件 |

**处理流程（概要）**：
```
输入：节点编号 + 已知字段值
  ├── 匹配 L1 模板（按阶段码：SJ→设计模板 / CB→成本招采模板 / SG→工程模板 / 其他→通用模板）
  ├── 区分字段状态：
  │     🔴 必有字段 → 检查是否已填充
  │            ├── 已填充 → 写入
  │            └── 缺失 → 主动向用户询问（每轮 ≤ 3 个问题）
  │     🟡 应有字段 → 尽量填充，缺失标注「【待补充】」
  │     🟢 如有字段 → 有则填充，无则省略
  ├── 输出节点实例 .md（套用 V4 模板：继承关系→继承字段→新增字段→状态流转→关联规则→变更记录）
  └── 回执：节点编号 + 文件路径 + 缺失字段提醒
```

**独立触发场景**：
> 「景观工程节点 SG-JG 的监理单位是中建监理，帮我更新」
>
> 「SG-015 节点缺少完成标准，我现在补充：...」


## 工具脚本拆分

与之配套的脚本也按 SOP 职责拆分为两个独立脚本：

| 脚本 | 对应 SOP | 功能 |
|------|:------:|------|
| `scripts/parse_nodes_tree.py` | SOP-012 | Excel → 结构化中间数据（节点树 + 依赖推断），不做文件输出 |
| `scripts/build_node_instance.py` | SOP-013 | 单节点数据 + V4 模板 → 一个节点实例 .md 文件 |

Agent 在 SOP 流程中按需调用脚本，脚本只做确定性操作，语义判断由 Agent 完成。
