# 节点状态自证化（含签认退役）— 需求基线 V1

**一句话**：把节点状态的事实收回节点自身——完成判定只认该节点自身的必需成果（退役父子聚合），签认不再构成完结路径并整体退役，里程碑被强制要求携带自有必需成果。

> **性质**：需求基线（口径已拍板，待转 PRD 与计划）
> **日期**：2026-09-21
> **状态**：口径已定；实施前需先解决 §二 D2 与 Atlas 基线的冲突（见 §二 注）
> **来源**：2026-09-21 讨论（节点成果判定口径 / 全景节点阶段主干 / 测试环境数据）
> **替代关系**：本基线**取代** [全景节点两层制_需求基线_V1.md](../../archived/全景节点两层制/全景节点两层制_需求基线_V1.md) 的 **D5 里程碑聚合口径**（该基线其余决策继续有效）
> **关联**：[全景节点维护者_需求基线_V1.md](../全景节点维护者/全景节点维护者_需求基线_V1.md)（Atlas，需随本基线同步修订）、[节点成果管控_需求基线_V1.md](../节点成果管控/节点成果管控_需求基线_V1.md)、[资料驱动节点更新_意向需求基线_V1.md](../资料驱动节点更新/资料驱动节点更新_意向需求基线_V1.md)

## 一、背景与问题

1. **现状口径**：Milestone 状态由**直接子节点三态聚合**产生——全部子节点完结才完结（两层制 V1 D5 原文："里程碑：由直接子节点的三态聚合，**不另写独立规则**"）。
2. **现状口径暴露的三个问题**：
   - **无自有成果的里程碑永不完结**：聚合退役前，里程碑自身成果不参与判定；一旦改为自证，无成果的里程碑会永久停在"条件不足"（`determine_node_status` 对空成果直接返回 `CONDITIONS_NOT_MET`）。
   - **状态是派生视图而非事实**：聚合让"父节点状态"成为子节点的函数，需要一条自底向上的级联重算链（`_recalc_ancestors`，8 个调用点），带来并发放大与"状态陈旧"类问题（两层制测试报告 B2 即此类）。
   - **完结有两个来源**：D4 方案 A 的判据是"成果量到位**或**签认通过"。签认与成果证据无关，等于给"完结"开了第二条不需要证据的路径，与"节点完成 = 成果达成"的业务语义冲突。
3. **结论**：节点状态回到**单一事实来源——节点自己的必需成果**。里程碑与任务同口径，不再逐层聚合；签认退出状态判定并整体退役；里程碑**强制**拥有自有必需成果（否则自证口径下无法完结）。

## 二、核心决策

| 编号 | 议题 | 决策 |
|------|------|------|
| **D1** | 状态计算 | **退役父子聚合**。`determine_node_status` 只按"自身前置依赖 + 自身必需成果"判定，**删除 children 分支**；节点有无子节点不再影响其状态 |
| **D2** | 完结路径 | **签认退役**。签认不再是完结路径；`SignoffService` 及工具/API/字段/标注链路整体退役（详见 §三） |
| **D3** | 里程碑成果 | **里程碑必须有自有必需成果**。创建与挂载时校验；存量数据补齐（含测试环境） |
| **D4** | 完成判据 | 唯一判据：**必需成果 `current_amount ≥ target_amount`**（比例口径沿用 `calc_deliverable_completion`） |

> ⚠️ **§二 注（实施前必须解决）**：Atlas 基线的可信度模型**建立在签认之上**——`FR-6 签认与迁正`、`FR-5.5 签认是迁正的前置条件`、`G5 未签认标为暂不可信`，以及 `Q3/Q6/Q7` 三条决策。D2 落地后这套口径失效，必须二选一并写入 Atlas 基线修订：
> - **（a）迁正改由"认领动作"承担**：临时节点 → 有权限者认领/挂载 → 迁正；可信度以"是否完成迁正"标记，不再依赖签认。
> - **（b）保留签认但降级为纯标记**：签认不再参与状态与迁正判定，仅作留痕。
>
> 本基线**不替 Atlas 做这个选择**，但要求 D2 实施前 Atlas 基线完成同步修订。

### D1 落地后的语义变更（对用户可见）

| 场景 | 现状 | 变更后 |
|------|------|--------|
| 任务全部完结、父里程碑自有成果未齐 | 父节点自动 `COMPLETED` | 父节点仍为运行中/条件不足 |
| 里程碑自有成果齐备、子任务未完结 | 父节点由子节点判（未启动） | 父节点 `COMPLETED` |
| 整体进度感（子节点全绿父仍灰） | 由状态机提供 | **由展示层自行聚合**，状态机不再承担 |
| 引用未签认节点 | 回复强制标注"未签认" | 不再有该标注 |

## 四、非目标

1. 不做父子进度加权聚合（`child_weight` 继续搁置，与两层制 D6 一致）。
2. 不用 LLM 判断状态（状态是硬门禁，须可复现）。
3. 不新增状态枚举；不改三态语义（`CONDITIONS_NOT_MET / IN_PROGRESS / COMPLETED`）。
4. 不改成果上报/匹配链路（`node_deliverable_matcher` 沿用）。
5. 不在本基线内处理"阶段主干（前期/设计/施工）"落地方案（见 §八 关联待定项）。
6. 不处理"未签认"退役后的检索可信度替代方案（属 Atlas 修订范围）。

## 五、开放问题（实施前需定）

1. **无自有成果的叶子节点怎么办**：D1 后，无成果的 TASK 同样永不完结（现状即如此）。是否要求**所有**节点（含任务）至少 1 条必需成果？当前运行时存在此类节点来源——`scheduler/jobs/periodic_node.py` 创建节点时不带成果；`create_task_node` 未传目标量时亦无成果。
2. **挂载校验的处置方式**（对应 C16）：拒绝挂载 / 自动补一条占位必需成果 / 允许成为"未定义工作的里程碑"并在展示层标记。三种代价不同，建议取"允许 + 展示标记"，避免因校验阻断既有操作。
3. **`acknowledged_*` 三列**：物理删除（需迁移）还是保留空列（与 `approver_id/approved_at` 同处理）。建议保留空列，与既有废弃字段口径一致。
4. **`child_weight` 与依赖权重**：聚合退役后 `child_weight` 仅剩"挂载权值"语义，是否一并退役。
