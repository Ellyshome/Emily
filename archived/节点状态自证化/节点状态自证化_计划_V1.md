## 数据流设计

```
建节点请求
  → 工具层（schema 校验 + 入参搬运）
  → NodeService.create_node
       ├── [M3] 必需成果声明为空？→ 拒绝（40003）
       ├── 权限/责任人/单位解析（现状不变）
       ├── 落库节点 + 落库声明成果
       └── [M1] 首次完成判定（0/目标 → 条件不足）

成果进度上报（现状不变）
  → NodeService.update_deliverable_progress
       └── [M1] _recalc_node_status(自身)  ← 不再向上传播

挂载关系请求
  → NodeService.mount_child
       ├── [M2] 层级校验：child=MILESTONE 且 parent=TASK → 拒绝（40004）
       └── 设置 parent_node_id（不改类型、不再向上重算）
```

### 核心流程

| 流程 | 触发条件 | 参与者 | 数据流向 | 异常路径 |
|------|---------|--------|---------|---------|
| 创建节点（带成果） | 用户/调度/批量建树 | 工具层 → M3 → M1 | 节点+成果一并落库 → 自身判定 | 无必需成果 → 拒绝并提示缺成果 |
| 成果进度更新 | 上报/进度更新 | M1 | 只重算本节点 | 节点不存在 → 失败返回 |
| 挂载子节点 | 拆解/批量建树 | M2 | 写 parent_node_id | 里程碑挂任务下 → 拒绝，且不改任何既有数据 |
| 调用签认 | — | M4 | 能力不存在 | 工具/端点/命令均不存在 |

## M1: 状态自证

**依赖**：无（首建模块）

**实现的需求**：US-01（覆盖 AC-US-01.1 ~ 01.5）

**层级**：Service

**职责**：把节点完成判定收敛为"只读自身成果与前置依赖"，并删除全部"由子推父"的状态写入路径。

### 接口契约

#### 修改的签名（标注：修改接口签名）

| 接口 | 变更前 | 变更后 | 说明 |
|------|--------|--------|------|
| `determine_node_status` | `(dependencies, deliverables, deliverable_file_status, children)` | `(dependencies, deliverables, deliverable_file_status)` | 去 `children`；判定逻辑只保留任务分支 |
| `NodeSnapshot` | 含 `children: list[ChildSnapshot]` | 去 `children` | 快照不再承载子节点 |
| `ChildSnapshot` | 类存在 | 删除 | 无消费者 |

#### 删除

| 对象 | 位置 | 原因 |
|------|------|------|
| `_determine_parent_status` | `node_state_machine.py` | 聚合判定退场后无调用者 |
| `NodeService._recalc_ancestors` | `node_service.py` | 唯一职责是向上传播状态，已无传播语义 |
| 8 处 `_recalc_ancestors(...)` 调用 | `create_deliverable` / `update_deliverable_progress` / `add_dependency` / `remove_dependency` / `submit_deliverable` / `confirm_deliverable` / `mount_child` / `unmount_child` | 同上 |

#### 保留（不得误删）

| 对象 | 说明 |
|------|------|
| `calc_deliverable_completion` | 唯一完成度算法；"无必需成果 → 1.0" 的既有语义保留（配合 M3 的创建把关，实际不会出现无成果节点） |
| `_recalc_node_status` | 节点自身判定入口，仍是成果变更后的唯一状态写入点 |
| `recalc_all_statuses` | 运维批量重算保留；**简化为不按深度排序**（聚合退场后顺序无关） |
