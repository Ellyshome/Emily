# 资料库入库手册（索引生成规范）

> 本手册是资料库索引生成的**唯一格式事实源**。任何索引（含根索引）都必须按本手册
> 规定的四要素结构与撰写口径生成；口径一经修改，已入库目录应重新入库以对齐。

---

## 一、适用范围

| 项 | 说明 |
| --- | --- |
| 适用对象 | 资料库（`emily-data/knowledge_library`，容器内 `/app/knowledge_library`）内的**全部受管目录** |
| 索引文件名 | 每个受管目录一份，文件名由系统常量统一规定（`INDEX_FILENAME`），**不得**改用其他名字 |
| 生成方式 | 由入库引擎一次性遍历整棵目录树，逐层生成；不解析资料内容，描述按名称推断 |
| 不适用范围 | 资料库之外的目录（如 RAG 检索源 `baseknowledge` / `company_policies`）一律不得写索引 |

---

## 二、索引的四要素

每个受管目录的索引必须包含且仅包含以下四要素：

| # | 要素 | 写什么 | 不写什么 |
| --- | --- | --- | --- |
| ① | **简介** | 本目录是什么、规模多大（子目录数 / 文件数）、按子目录名归纳的资料类型 | 不写具体结论、不写未从名称得到的信息 |
| ② | **文件目录** | 本目录的直接子目录与直接文件清单（子目录以 `/` 结尾）；每条附一句话描述 | 不列子目录内部的文件（那是下一层索引的职责） |
| ③ | **一句话描述** | 见「四、一句话描述口径」——按名称推断的**定位线索** | 不臆造内容、不猜测文档结论 |
| ④ | **其他备注** | 索引生成时间、时效提示、不可解析类型的说明等 | 不放业务判断、不放待办事项 |

> 四要素缺一不可；**备注**可为极简（至少含生成时间与时效提示）。

---

## 三、索引结构（机器可读）

以下 YAML 块是索引的**字段清单与内容模板**，入库引擎直接按它渲染索引。修改本块即修改索引格式。

<!-- INDEX_SPEC:BEGIN -->
```yaml
# 索引正文之前的前置元信息（frontmatter）字段，顺序即输出顺序
frontmatter:
  - generated_at      # ISO8601 生成时间（本地时区）
  - scope             # 本索引所辖目录的仓库相对路径（根目录写 /）
  - file_count        # 所辖目录规模：子树内文件总数（不含索引文件）
  - dir_count         # 所辖目录规模：子树内子目录总数

# 索引正文的 H1 标题行（{name} 为本目录名，根目录为「资料库」）
heading_line: "# {name}"

# 正文小节：key 决定填什么，title 决定标题怎么写，顺序即输出顺序
sections:
  - key: intro
    title: 简介
  - key: catalog
    title: 文件目录
  - key: notes
    title: 其他备注

# 简介：规模句 + 类型句（{types} 由直接子目录名归纳）
intro_template: "本目录「{name}」为项目资料目录，共 {file_count} 个文件、{dir_count} 个子目录。"
types_line: "资料类型：{types}。"
types_fallback: "以独立文件为主"

# 父层索引中的子目录条目说明（层级一致性：优先引用子索引的类型行）
subdir_desc:
  from_child_types: "含：{types}"     # {types} 取自子目录自身索引的类型行
  fallback: "{name}资料"              # 子目录无下级类型可引用（未入库 / 叶目录）时；
                                      # 目录名已以「资料/文件/文档/材料」收尾时只保留目录名，不重复后缀

# 文件目录条目的书写样式（{desc} 为一句话描述）
catalog:
  dir_line: "{name}/ — {desc}"
  file_line: "{name} — {desc}"
  unindexed_suffix: "（未入库）"

# 其他备注固定行（{generated_at} 生成时间）
notes_lines:
  - "索引按目录名与文件名自动生成，未解析文件内容；描述仅作定位线索，不作为内容依据。"
  - "生成时间：{generated_at}。目录内如有更晚的改动，本索引可能已过期，建议重新入库。"
```
<!-- INDEX_SPEC:END -->

## 四、一句话描述口径

**依据**：文件名（主）+ 所在文件夹名（辅）。文件名的编号、日期、专业词、版本号，都是可用的定位信息。

| 文件类型 | 描述写法 | 示例 |
| --- | --- | --- |
| 文本类（md/txt/csv/json 等） | 名称语义 + 类型 | `施工日志.md — 施工过程记录文本` |
| 合同/协议类 | 名称中的当事方、标的、阶段 + "合同/协议" | `黄湖景观工程施工合同（2024）.pdf — 黄湖景观工程施工合同文本` |
| 图纸类 | 专业 + 图纸类型 | `总平面图.dwg — 总平面布置图纸` |
| 周报/纪要/报告 | 周期 + 文种 | `第12期监理周报.docx — 第十一期监理工作周报` |
| 表格 | 字段主题 + 表 | `材料进场台账.xlsx — 材料进场记录台账表` |
| 图片 | 名称语义 + 图片 | `现场照片-基础施工.jpg — 基础施工阶段现场照片` |

**禁用写法**（不得出现）：

- 「内容涉及……」「主要说明了……」——**未解析内容，不得描述内容**
- 「可能包含……」「应该是……」——不得猜测
- 空描述、`—` 后留白——每条必须有一句描述

无法从名称得到任何语义时，如实写类型 + 所属目录，如：`未命名文件1.docx — 该目录下未命名文档（按类型标注，未解析内容）`。

---

## 五、目录树写法

1. **只写直接子项**：本层索引只列本层的直接子目录与直接文件；孙层内容由下一层索引承载（层级不越权）。
2. **子目录在前**：先列全部子目录，再列文件；各组内按名称排序（目录在前，名称升序）。
3. **子目录条目**：`子目录名/ — 一句话说明`。说明取自该子目录的用途（按名称推断）。
4. **文件条目**：`文件名 — 一句话描述`。
5. **未入库子目录**：某子目录尚无自身索引时，其条目后加「（未入库）」标注，**不**展开其内部文件——索引缺失即视为未入库。

---

## 六、不可解析类型的处理

图纸（dwg/dxf）、图片（jpg/png/gif/webp）、压缩包（zip/rar/7z）、二进制与已编译文件等，**一律不解析内容**（AC-US-01.8）：

1. 按**类型 + 所在文件夹名 + 文件名语义**给出描述；
2. 遇到此类文件**继续完成整目录入库**，不中断、不跳过、不报错；
3. 不得以「无法读取」为由省略条目；不得臆造内容。

---

## 七、层级一致性口径

本层索引中的**子目录描述**，与子目录自身索引的**简介**必须**不矛盾**（AC-US-02.3）：

1. 生成顺序：**先父后子**——父层索引先读子目录的既有索引（若有）取其简介要点，保证口径一致；
2. 子目录描述只做"用途定位"，不展开细节，细节留给子目录自身的简介；
3. 子目录重新入库后，若其简介变化，父层描述在父层下一次入库时对齐（同一口径）；
4. 上级描述与本级简介冲突时，**以本级简介为准**。

---

## 八、作业顺序（入库规程）

```
① 确认目录在资料库根之内（越界一律拒绝）
② 一次性遍历整棵目录树（不解析文件内容）
③ 逐层生成索引：先父后子，子目录条目引用子目录索引的简介要点
④ 逐层覆盖写；原索引被更新而非追加（幂等）
⑤ 原始资料文件不得改动、移动、删除
⑥ 预览（dry-run）只输出"将生成/更新的索引清单"，不写任何文件
```
