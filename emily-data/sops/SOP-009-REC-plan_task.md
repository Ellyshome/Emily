## 第2章 意图识别

### 2.1 触发此业务流的语义特征

**必须条件**：
- 下达任务、布置工作、创建任务
- 周期性任务、日报、周报、月报、定期上报
- 指派任务、分派工作
- 提交任务成果、提交报告、完成任务
- 上交、报送、上传成果
- 查看我的任务、待办任务、查询任务状态

**否定条件**：
- 查询已录入事件（应触发 SOP-005-QRY）
- 录入会议纪要（应触发 SOP-001-REC）
- 临时事件上报（应触发 SOP-002-REC）

### 2.2 示例对话

**应触发此业务流**：
> 「请给张三布置一个任务：本周五前完成S4地块铺装材料进场验收」
> 「创建周报任务，每周五17:00前提交，由李四负责」
> 「我提交S4地块铺装任务的成果，已完成验收」
> 「查看我待提交的任务」
> 「设定一个循环任务：每月20日前提交工程月报」

**不应触发此业务流**：
> 「查一下上周的事件记录」→ SOP-005-QRY
> 「记录一下今天的会议纪要」→ SOP-001-REC

## 第3章 业务流描述

### 3.1 目标数据库表

- `plan_task_templates` — 任务模板
- `plan_task_instances` — 任务实例
- `plan_task_logs` — 状态变更日志
- `plan_task_deliverables` — 任务成果

### 3.2 使用的系统工具/API

| 工具名 | 用途 |
|--------|------|
| `record_plan_task` | 创建计划任务（一次性或循环模板） |
| `submit_plan_task` | 提交计划任务成果 |
| `query_plan_tasks` | 查询计划任务列表 |

### 3.3 处理流程

```
用户请求
    │
    ├─ 创建任务？
    │     ├─ 一次性任务 → record_plan_task (is_recurring=false) → 创建实例 → WAITING
    │     └─ 循环任务 → record_plan_task (is_recurring=true) → 创建模板 → 激活
    │
    ├─ 提交成果？
    │     └─ submit_plan_task → WAITING → SUBMITTED
    │
    ├─ 查询任务？
    │     └─ query_plan_tasks → 返回任务列表
    │
    └─ 不匹配 → 兜底处理
```

## 第5章 异常处理

### 缺失处理
- 缺少截止时间：询问用户补充截止日期或循环规则

### 质量处理
- 截止时间已过期：提醒用户确认，记录过期任务
- 反向下达（执行者向主管下达任务）：标记 ANOMALY_PENDING_REVIEW，通知上级复核

### 系统处理
- 数据库写入失败：重试一次，仍失败则告知用户
