# 非友好格式资料加工（阅读笔记） — 业务流服务手册

> **适用对象**：AI Agent（MasterAgent / SOP 能力）
> **允许用户角色**：`admin`（入库与笔记生成属写操作）
> **业务目的**：把 PPT / 扫描件 / 图纸等"人能读、AI 难提取"的资料，加工成一份可被关键词检索命中的 Markdown 阅读笔记，并与源文件一并纳入资料库
> **文档风格**：地产企业内业文件管理规范，简洁明确，可执行

对非友好格式资料：**源文件保持原样只读**，在同目录生成一份伴生阅读笔记，再随目录一并入库。笔记只做定位、导航与原文摘录，不替代原文件。

## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

**必须条件（满足其一即可）**：

- 用户明确要求「入库」「纳入资料库」「放进资料库」，且所涉文件为 PPT / PDF / 扫描件 / 图纸 / 图片等非友好格式
- 用户要求「给这份资料做一份 AI 能读的笔记」「加工一下这份 PPT / 扫描件」「做成可检索的版本」
- 用户反馈某份资料「搜不到」「AI 读不了」「内容提取不全」，且该资料在资料库内

**否定条件（即使有上述关键词，也不应判定为此业务流）**：

- 只说「入库」，所涉文件是 md / txt / csv / json → 只需放文件 + 索引，走 SOP-013-QRY 的入库动作
- 明确说「RAG 入库」「进知识库」「建向量索引」→ 走 SOP-004-FILE 的 `embed_and_index`
- 只是查阅、要笔记内容或要看某页原图 → 走 SOP-013-QRY（`library_search` / `read_library_file` / `send_library_file`）
- 要求修改源文件内容、转成 Word/PDF 副本 → 属于文件处理，不在本流；本流不产生源文件的任何副本

### 2.2 示例对话

**应触发此业务流**：

> 「把这份《伟业景观红线》PPT 入库，做成 AI 好检索的样子。」[附 PPTX]

> 「这份扫描版制度 PDF 搜不到内容，帮我加工一下再入库。」

**不应触发此业务流**：

> 「把这份会议纪要 md 入库。」→ 友好格式，走 SOP-013 入库
> 「这份红线制度入到知识库里，以后做语义检索。」→ 明确 RAG，走 SOP-004 的 `embed_and_index`
> 「红线里关于封样的要求是什么？」→ 查阅，走 SOP-013

## 3. 业务流描述

### 3.1 术语口径：什么叫"入库"（🔴 本 SOP 的定义口径）

**自本 SOP 起，未特殊声明的"入库"一律指以下三步组合**：

| 步骤 | 动作 | 说明 |
| --- | --- | --- |
| ① | **放文件** | 把资料放入 `emily-data/knowledge_library`（容器内 `/app/knowledge_library`）的对应目录，按既有目录分层，不新建无意义层级 |
| ② | **做索引** | 对该目录及其上层逐级生成/更新 `.emily.md` 索引（按 `knowledge_ingest_playbook.md` 口径） |
| ③ | **生成阅读笔记** | **仅对非友好格式**：在同目录生成 `<源文件名>-阅读笔记.md` |

三条口径必须一起讲清：

1. **系统工具只覆盖第②步**：`ingest_knowledge_library` 只写索引，**不解析文件内容**、**不生成笔记**。因此对话中用户说"入库"时，Agent 不能只调该工具就回复"入库完成"。
2. **只有明确说"RAG 入库"才做向量化**：走 SOP-004 的 `embed_and_index`；本 SOP 全程不触碰向量库。
3. **第①③步当前无工具**：资料库内没有写入/复制文件的工具，源文件与笔记的落盘由管理员在宿主机（`emily-data/knowledge_library`）或容器内（`/app/knowledge_library`）完成；Agent 负责判定、提取、成稿并给出落位路径。工具缺口见 §6.1。

### 3.2 适用范围判定（🔴 先判定再动手）

| 格式 | 判定 | 处理 |
| --- | --- | --- |
| md / txt / csv / json / html | 友好 | 只做 ①②；不生成笔记 |
| pptx / ppt | 非友好 | 做 ①②③ |
| docx（含大量表格、文本框、修订） | 非友好 | 做 ①②③ |
| xlsx（多表、合并单元格、隐藏表） | 视情况 | 单表且结构清晰 → 只做 ①②；多表/含说明sheet → 做 ①②③ |
| PDF（有文字层） | 视情况 | 页数少且文本连续 → 只做 ①②；多栏/图表/跨页表格 → 做 ①②③ |
| PDF（扫描件、无文字层） | 非友好 | 做 ①②③，并标注 OCR 误差风险 |
| 图片（jpg/png，如拍照的制度、签字页） | 非友好 | 做 ①②③，仅转录可辨识内容 |
| dwg / dxf / 压缩包 | 不解析 | 只做 ①②；笔记只写用途与关联说明，不描述内容 |

**不做笔记的三种情况**（避免制造噪声）：内容已被 md 版本覆盖、文件为一次性过程稿且无复用价值、源文件本身残缺无法提取。

### 3.3 目标数据库表

**表决策结论**：本 SOP **不新建表**。产出物是资料库内的文件（源文件 + 笔记）与索引文件，均为文件系统实体。

| 表名 | 作用 | 关键字段 |
| --- | --- | --- |
| 不直接写表 | 产出物为 Markdown 笔记与 `.emily.md` 索引，存于资料库目录 | 源文件名、笔记文件名、生成时间、复核状态 |
| `files`（复用，可选） | 若该资料同时要进文件台账/参与节点共享，另走 SOP-004 归档 | `filename`、`storage_path`、`file_category`、`project_id` |

评估说明：现有表中 `files` 仅登记文件元数据，不承载"内容摘要/页码地图"，强行复用会把笔记正文塞进描述字段，故本 SOP 不写库；需要台账时再按 SOP-004 并行归档。

### 3.4 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `officeCLI`（mode=outline） | 列出幻灯片/段落的结构与标题 | 通读 pptx/docx 前先定位章节与页序 |
| `officeCLI`（mode=text） | 提取正文文本（工具侧受 `max_lines` 上限约束，默认 1000、最高 5000） | 逐段转录；大文件按页分段调用，避免整本截断 |
| `officeCLI`（mode=stats / issues） | 结构统计与格式问题检查 | 判断页数、文本框数量、提取风险 |
| `read_library_file` | 现读资料库内 Office 文件（内部调 officeCLI） | 资料已在库内时复核原文 |
| `parse_document` | 结构化解析（章节 + 表格） | PDF/docx 的章节与表格还原 |
| `ocr_document` | 图像文字识别（扫描件） | 无文字层 PDF、图片；结果须标注 OCR 风险 |
| `ingest_knowledge_library` | 逐层生成/更新 `.emily.md` 索引（**只写索引**） | 第②步；先 `dry_run=true` 预览再执行 |
| `library_search` | 关键词扫描资料库内 md/txt | 笔记生成后自检：关键问法能否命中 |
| `send_library_file` | 把库内文件/图片发到会话 | 需要展示原页、表单样张、签字照片时 |

权限参考：`read_library_file` / `library_search` / `send_library_file` 为 L3 及以上；`ingest_knowledge_library` 为 L5；`embed_and_index` / `rag_remove_document` 为 L5/L6（后者仅 RAG 入库场景使用，不在本流）。

### 3.5 阅读笔记格式手册（内嵌版）

> 本节即"笔记格式的唯一口径"。修改本节即修改笔记格式；后期拆分时整体移出为独立 playbook，正文不改。

#### 3.5.1 命名与落位

- 文件名：`<源文件名主名>-阅读笔记.md`（例：`伟业景观红线（0506）F-阅读笔记.md`）
- 落位：**与源文件同目录**。同目录才能被该层 `.emily.md` 索引列出、被 `library_search` 扫到、并带出同目录图片。
- 一份源文件对应一份笔记；**不得**覆盖或改写源文件，**不得**复制源文件生成"可读版"副本。

#### 3.5.2 必备头部（frontmatter）

```yaml
---
source_file: 伟业景观红线（0506）F.pptx   # 与磁盘文件名完全一致
source_version: 2024年版（2024-05 发布，2024-06 实施）
coverage: 全篇 P1-P90
note_version: v1.0
generated_at: 2026-10-22
review_status: 待复核        # 待复核 / 已复核
reviewer: -                  # 复核人（管理员）
---
```

`review_status` 与 `reviewer` 是回答可信度的依据：**待复核**的笔记，Agent 引用涉处罚、审批、时限、金额的条文时必须先说明"该笔记尚未复核"，并回原文核对。

#### 3.5.3 必备章节（顺序固定）

| # | 章节 | 写什么 | 不写什么 |
| --- | --- | --- | --- |
| 1 | 一句话定位 | 这份文件是什么、约束谁、解决什么问题（1–2 句） | 不写评价、不写建议 |
| 2 | 元信息 | 发布主体、版本、发布日期、实施日期、适用范围、文号 | 不臆造发文单位与文号 |
| 3 | 怎么用这份笔记 | 检索路径：命中笔记 → 答条文；需看原页/表单/照片 → 回原文件第几页 | 不写"AI 应如何思考"之类的元话术 |
| 4 | 术语与同义词 | 文件用词 ↔ 用户常用问法（如"红线＝设计红线＝否决指标"） | 不收录原文没有的概念 |
| 5 | 内容地图 | 页码导航表：主题 → 页码 → 该页性质（条文/流程/表单/示例） | 不逐页抄全文 |
| 6 | 原文照抄区 | 硬性条文：禁止事项、处罚标准、审批层级、时限、金额，**逐字**转录并标页码 | 不改写、不合并、不概括 |
| 7 | 改写区 | 流程图、审批表、空间排布页 → 线性文字（顺序 + 责任方 + 产出） | 不增删环节、不改变责任主体 |
| 8 | 必须回原页确认 | 只能看图才能确认的页码（表单样张、签字、封样照片、流程图细节） | 不猜图中文字 |
| 9 | 存疑与缺口 | 提取失败、OCR 不确定、版本冲突、缺失页，均标【存疑】并说明原因 | 不用推测填补空白 |
| 10 | 维护记录 | 笔记版本、生成时间、复核人、对应源文件版本 | — |

#### 3.5.4 保真规则（🔴 硬约束）

1. **硬信息照抄**：禁止性条款、红线行为、考核与处罚标准、审批层级、责任人、时限、金额、文号、版本日期——一律逐字照抄，标注页码，不做同义改写。
2. **软信息可改写**：流程图、组织关系、章节结构可改写为线性文字，但**不得增删环节、不得变更责任主体、不得改变先后顺序**。
3. **图片内文字不猜**：提取不到的文字列入第 8 节"必须回原页确认"，必要时用 `send_library_file` 把原页发给提问者。
4. **页码可回溯**：每条硬信息后写页码（pptx 用幻灯片序号，docx 用页码或章节号，PDF 用页号），页码口径在笔记开头声明一次。
5. **不产出原文没有的结论**：不写"因此建议…""这样做更好…"；不把行业常识当作该文件的条文。
6. **版本敏感信息显式提示**：原文含"以最新版本为准""如有更新另行通知"之类表述时，必须在第 2 节与第 9 节同时标出。

#### 3.5.5 分格式提取要点

| 格式 | 提取顺序 | 常见坑 |
| --- | --- | --- |
| pptx | `officeCLI` outline 定页序 → text 分段取正文；标题缺失时在宿主机用 `officecli view <file> annotated` 补层级 | 页眉重复导致标题失效；流程图页文本框乱序（必须归入改写区或"回原页"） |
| docx | `officeCLI` outline → `parse_document` 取章节与表格 | 文本框、修订痕迹、脚注易漏 |
| xlsx | 逐工作表取表头与结构 | 合并单元格、隐藏表、公式缓存值 |
| PDF（文字层） | `parse_document` | 多栏串行、跨页表格断裂 |
| PDF（扫描件）/图片 | `ocr_document` | 识别错字、表格错位，必须在第 9 节标注 |

### 3.6 处理流程

```
用户要求「入库 / 加工 / 做阅读笔记」，或上传非友好格式并表达纳入资料库意图
    ↓
[权限检查] → 读取第1章权限控制字段（以 DB min_level 为准）；非 L5 管理员 → 拒绝并说明，不进入后续步骤
    ↓
[口径确认] → 按 §3.1 向用户说明将做的三步：放文件 / 做索引 / 生成阅读笔记；
             如用户只想要索引，按否定条件转 SOP-013
    ↓
[格式判定] → 按 §3.2 判定友好 / 非友好 / 不解析：
             友好 → 只做 ①②，转 SOP-013 入库；
             不解析（dwg/压缩包）→ 只做 ①② 并在回执说明；
             非友好 → 继续
    ↓
[提取] → 按 §3.5.5 顺序提取；记录"提取成功 / 失败 / 需看图"三类页码清单
    ↓
[成稿] → 按 §3.5 生成笔记：硬信息照抄标页码，流程图改写，图片文字入"回原页"清单
    ↓
[复核闸门] → 涉处罚、审批层级、时限、金额、禁止事项的条文，交管理员逐条核对；
             未核对 → frontmatter 标 review_status=待复核；核对通过 → 已复核 + reviewer
    ↓
[落位] → 源文件与笔记置于同一资料库目录；不改写、不复制、不替换源文件
    ↓
[做索引] → ingest_knowledge_library(dir, dry_run=true) 预览
           → 确认将生成/更新的层级无误 → 实际入库（第②步）
    ↓
[自检] → library_search 用 2–3 个真实问法验证：笔记能否被命中、snippet 是否相关；
         未命中 → 调整笔记 H1 标题与术语表（索引只按文件名描述，无需重做索引）
    ↓
[回执] → 按 §4.3 返回：目录、笔记路径、覆盖范围、复核状态、未覆盖与存疑项、读取建议
```

流程要点：

- **三步顺序不可颠倒**：先落位再做索引，否则索引里的文件清单不含新笔记；笔记后续修订不需重做索引（索引只按文件名描述）。
- **索引可重生成，手工改动会丢**：`ingest_knowledge_library` 会整份重写 `.emily.md`，**不要**在索引里手工加"本目录有阅读笔记"之类的提示；可发现性靠 §3.5.1 的固定命名与 H1 关键词。
- **笔记不是原文替代**：命中笔记后，凡第 6 节条文、第 8 节图页，都应按需回原文核对或发送原页。

| 执行索引 | `ingest_knowledge_library` 内部门槛 L5，fail-closed |
| 复核签署 | 仅发起入库的管理员；不得由生成笔记的同一 Agent 自行签署 |
| 入库留痕 | 索引写入由服务层留痕；笔记的 `generated_at` / `reviewer` 即文件侧留痕 |

## 4. 输出成果要求

### 4.1 字段分级与约束

| 字段 | 级别 | 约束 |
| --- | --- | --- |
| **source_file** 源文件 | 🔴 必有 | 资料库相对路径 + 磁盘文件名，与源文件完全一致；不产生副本 |
| **note_file** 阅读笔记 | 🔴 必有 | 同目录 `<源文件名主名>-阅读笔记.md`，命名固定 |
| **入库目录** | 🔴 必有 | 资料库内相对目录，须已存在或与现有分层一致 |
| **页码地图** | 🟡 应有 | 主题 → 页码 → 性质；页码口径声明一次 |
| **原文照抄区** | 🟡 应有 | 硬信息逐字 + 页码；无硬信息时整节写"本文件无硬性条文" |
| **术语与同义词** | 🟡 应有 | 至少覆盖 3 个用户可能使用的同义问法 |
| **review_status** | 🟡 应有 | 待复核 / 已复核；未复核须在回执中明示 |
| **必须回原页清单** | 🟢 如有 | 有图页、表单页、签字页时必填 |
| **存疑与缺口** | 🟢 如有 | 提取失败、OCR 不确定、版本冲突时必填 |

### 4.2 格式要求

- 笔记正文中文书面语；表格用于页码地图、同义词、回原页清单；长段落不超过 150 字。
- 页码一律写 `P{序号}`；pptx 用幻灯片序号，docx 用章节号（无页码时）或页码，PDF 用页号。
- 硬信息引用格式：`> 原文……（P{页码}）`。
- 存疑统一前缀 `【存疑】`，并写明原因与建议核对方式。
- 不得出现"可能包含""应该是""大概"这类无据表述；不确定即入第 9 节。

### 4.3 回执格式

```
📋 资料加工完成
──────────────
源文件：{相对路径}
阅读笔记：{相对路径}
入库目录：{相对路径}
覆盖范围：{页数/章节}
复核状态：{已复核 / 待复核}
未覆盖 / 存疑：{若干条，无则写"无"}
索引：{新建 X 份 / 更新 Y 份}
──────────────
读取建议：
  · 条文类问题：命中笔记后按第 6 节页码回原文核对
  · 图页/表单类问题：用 read_library_file 或 send_library_file 看原页
  · 如源文件换版，本笔记需重做（见 §5 风险项）
──────────────
```

## 5. 异常处理原则

| 异常场景 | 处理建议 |
| --- | --- |
| **无权限**（非 L5） | 回复「资料加工与入库仅 L5 管理员可执行；查阅可走资料库检索」，不进入流程，记录日志 |
| **扫描件无文字层 / OCR 质量差** | 用 `ocr_document` 提取，第 9 节标注 OCR 风险与不确定字；不得据 OCR 结果改写硬信息，硬信息须回原页 |
| **提取结果为乱序（流程图页、多文本框页）** | 不强行成句；归入第 7 节改写（仅写顺序与责任方）或第 8 节"必须回原页"，并在第 9 节说明 |
| **整本超长、单次读取截断** | 按页分段提取；笔记声明覆盖范围（如 `P1-P90`）；未读部分不得写入 |
| **源文件版本不明 / 文件名为代号** | 第 2 节按文件内页信息填写；内页也无版本时写「文件名未体现版本，按内页为准」，并在回执提示重命名建议 |
| **原文有"以最新版本为准"等时效条款** | 第 2、9 节双处标注；回执中列为风险项，不默认为现行有效 |
| **笔记与原文表述不一致** | 以原文为准，立即修正笔记；涉硬信息的修正须重新复核 |
| **目录缺索引 / 未入库** | 先按 §3.6 落位并执行索引；不得跳过索引直接提供文件 |
| **重复加工同一文件** | 已有笔记且源文件未变 → 不重做，仅提示；源文件已变 → 新建 note_version，保留维护记录，旧笔记就地更新（不另建文件） |
| **用户要求"顺便转成 Word/PDF 便于阅读"** | 不属于本流；说明资料库以源文件为准，可发送原文件，不生成副本 |
| **落盘失败 / 路径越界** | 回复落位路径与所需权限，不写入资料库以外目录 |

**总原则**：宁缺勿猜（提取不到就列入回原页）、原文优先（笔记与原文冲突以原文为准）、不制造副本（避免双事实源）、未复核不引用（涉处罚/审批/时限/金额的条文）。

## 6. 建议补充内容

> 以下内容当前系统尚未实现，记录为后续优化方向，不影响本版执行。

### 6.1 资料库写入工具（高优先级）

当前 `read_knowledge_library` 仅支持 list / read_index / read_file，资料库内无写入与复制能力，导致"入库三步"中的第①③步必须管理员手工落盘。建议新增 `put_library_file`（受根目录越界保护、L5、`write_mode=append`，禁止覆盖同名源文件），使本 SOP 可由 Agent 端到端执行。

### 6.2 入库引擎识别伴生笔记（中优先级）

索引按文件名自动生成，会把 `xxx-阅读笔记.md` 与普通资料并列列出，Agent 需自行判断优先读笔记。建议入库引擎识别 `-阅读笔记.md` 后缀，在索引条目描述中追加「检索入口，优先阅读」，或在目录备注中单列一行。

### 6.3 笔记过期检测（中优先级）

现有索引服务已有"目录内容比索引新"的时效判定。建议扩展为"源文件 mtime 晚于笔记 `generated_at` 即标记笔记过期"，并在 SOP-013 查阅时提示重做。

### 6.4 格式手册拆分（后期）

本 SOP 复杂化后，将 §3.5 整体移出为 `prompts/knowledge_companion_note_playbook.md`，SOP 内仅保留引用与执行流程，口径单一事实源不变。

### 6.5 RAG 切块复用（后期）

做 RAG 时，笔记的第 4–7 节天然是带页码元数据的结构化切块底稿，可优先于原始文本切块使用，避免重复页眉与流程图乱序噪声。
