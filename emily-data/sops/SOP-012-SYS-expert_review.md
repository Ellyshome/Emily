# 专家方案审核 — 业务流服务手册

## 1. 业务流版本信息

| 字段 | 值 |
|------|-----|
| 业务流编号 | SOP-012-SYS-expert_review |
| 版本 | v1.0 |
| 业务名称 | 专家方案审核 |
| 业务类型 | SYS |
| 权限控制 | `Level1` `Level2` `Level3` `Level4` `Level5` `Level6` |
| 说明 | 当用户请求对方案/设计/文档进行专业审核时，系统自动匹配合适的审核专家，加载其职能手册与量化标准，由专家 LLM 完成逐项核查并输出评分报告。 |

## 2. 触发条件

### 2.1 触发语义特征

**必须条件（满足其一即可）**：
- 用户明确请求审核、评审、审查某份方案、设计说明、图纸或文档
- 用户提及"专家把关"、"专业审核"、"技术评审"、"质量检查"等审核请求
- 用户提交设计方案并要求核对是否达标、合规
- 用户提交植物配置表、景观设计说明、施工图等需要对照行业标准审核的文件
- 用户请求对苗木使用、种植方案、绿化设计等园林景观内容进行专业评估

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 用户只是在询问审核流程或审核标准，而非实际提交审核 → 应回退为普通对话
- 用户提交的是任务执行报告或工作日志，而非待审方案 → 应触发事件记录或任务管理 SOP
- 用户核心意图是查询而非审核 → 应触发数据查询 SOP

### 2.2 示例对话

**应触发此业务流的用户说法：**

> 「帮我审核星湖湿地公园的植物设计方案，看看苗木密度和换土深度是否符合规范。」

> 「这是景观施工图，请专家把关，重点检查种植间距和土壤参数。」

> 「审核一下这份植物配置表，我需要确认灌木面积比、成活率保证这些是否达标。」

> 「请用苗木使用审核标准，对这份设计说明做专业评审。」

**不应触发此业务流的用户说法：**

> 「审核流程是什么？」→ 询问而非提交审核

> 「昨天现场铺装完成了，记一下。」→ 事件记录

> 「查一下上次的审核结果。」→ 数据查询

## 3. 任务执行协议

### 3.1 前置合规理念

专家审核是一个系统自动化流程，不是用户可选的工具调用：

- **审核请求必须携带待审文件内容或附件**。无文件内容的审核请求，系统应引导用户补充文件。
- **审核专家由系统自动匹配**，依据：用户在消息中描述的领域 → SOP 绑定 → ACTIVE 状态专家。
- **审核结果必须包含**：评分（0-100）、维度得分明细、逐项问题列表（含严重程度和依据标准）、总体结论与建议。
- **审核输出标准化**：必须为结构化 JSON，包含 `status`、`score`、`score_dimensions`、`issues`、`conclusion`、`recommendation` 字段。

### 3.2 处理流程

```
用户发起审核请求（含待审文件）
    ↓
[意图识别] → 判定为专家审核请求 → sop_id=SOP-012-SYS
    ↓
[专家匹配] SessionAgent._match_expert() → 查找 ACTIVE 专家
    ↓
[路由分发] route_after_routing → expert_review 节点
    ↓
[手册加载] ExpertManualLoader → 职能手册 + 任务手册
    ↓
[文件加载] ExpertManualLoader.load_review_files() → 待审文件文本
    ↓
[Prompt 构建] build_expert_prompt() → 注入手册 + 文件 + 审核要求
    ↓
[LLM 审核] llm_client.chat_json() → 使用 expert_model
    ↓
[结果归一化] _normalize_expert_result() → 标准化 JSON
    ↓
[汇总] make_summarizing() → 将审核结果纳入最终回复
```

### 3.3 可调用工具

| 工具名 | 用途 | 调用场景 |
|--------|------|---------|
| `query_experts` | 查询可用专家 | 用户需要了解有哪些专家可审核时 |
| `approve_expert` | 激活专家 | 管理员激活新注册的专家（前置） |
| `toggle_expert` | 启停专家 | 管理员管理专家状态 |

专家审核流程本身是自动化的，不需要用户手动调用工具。上述工具仅用于专家管理。

### 3.4 审核维度（参考）

依据苗木使用审核专家（EXP-001）的职能手册，标准审核维度包括：

| 维度 | 权重 | 审核要点 |
|------|------|---------|
| 乔木密度合规 | 20% | 百平米密度在标准区间内 |
| 草灌面积比 | 15% | 各绿地类型草灌比合规 |
| 换土与种植穴 | 15% | 换土深度/直径满足标准 |
| 土壤理化参数 | 15% | 包含理化参数且数值达标 |
| 种植间距 | 15% | 株行距满足最小间距标准 |
| 苗木规格 | 10% | 进场规格达到最低要求 |
| 成活率保证 | 5% | 包含成活率保证条款 |
| 生物多样性 | 5% | 品种数、单一树种占比达标 |

> 其他领域专家（如结构审核、电气审核）将有各自独立的审核维度与职能手册。

### 3.5 异常处理

| 场景 | 处理方式 |
|------|---------|
| 无待审文件 | 提示用户补充文件或粘贴文件内容 |
| 无匹配的 ACTIVE 专家 | 提示当前无可用审核专家，建议联系管理员激活 |
| 专家 LLM 调用失败 | 尝试回退到主模型，仍失败则返回"审核异常" |
| JSON 输出不完整 | `status=partial`，降级处理已有内容 |
| 文件内容过长 | 分段加载，按章节/页码截取关键部分 |

### 3.6 输出成果要求

审核完成后，系统回复应包含：

| 分级 | 内容 |
|------|------|
| **必备** | 总体评分（0-100）、审核结论（通过/修改后通过/重做） |
| **必备** | 各维度得分明细 |
| **必备** | 问题清单（位置、严重程度、依据标准、说明） |
| **应有** | 改进建议（具体可操作的修改方向） |
| **如有** | 与历史审核结果的对比、行业标杆数据参考 |
