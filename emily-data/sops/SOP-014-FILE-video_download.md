# 视频下载 — 业务流服务手册

> **适用对象**：AI Agent（会话主循环 / SOP 能力）
> **允许用户角色**：参建管理（L3）及以上
> **业务目的**：把用户给出的公开视频页面地址，用 yt-dlp 下载为本地视频文件，归档后发送给当前会话用户
> **文档风格**：地产企业内业文件管理规范，简洁明确，可执行

按用户诉求下载**单个公开视频**：先确认地址属于支持站点，再调用 `download_video` 下载并归档，最后调用 `send_file` 把文件发给用户；不处理播放列表、直播、登录态、付费/DRM 内容。

## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

当用户消息同时满足以下条件时，判定为「视频下载」请求：

**必须条件（满足其一即可）**：
- 明确要求下载某个视频平台的视频（"帮我下载这个B站视频""把这条视频存下来"）
- 给出公开视频页面地址，并要求保存、下载、转存、发给自己
- 询问能否下载某平台的视频，并提供了视频链接

**否定条件（即使出现"下载/视频"等词，也不应判定为此业务流）**：
- 要求下载播放列表、合集、直播、付费课程、需要登录/会员的内容 → 不支持，如实说明
- 要求绕过平台限制、去水印、破解 DRM → 拒绝
- 只是询问视频内容、总结视频 → 不是下载动作
- 给出的是网盘链接、直链文件、内网地址 → 不属于本 SOP

### 2.2 示例对话

**应触发此业务流**：
> 「能不能帮我下载一段B站上的视频？」（用户随后给出链接）

> 「把这个视频存下来发我：https://www.bilibili.com/video/BV...」

**不应触发此业务流**：
> 「这个视频讲了什么？」→ 内容理解，不是下载
> 「帮我把这个合集全部下载」→ 播放列表不支持，如实说明
> 「下载这个内网地址的文件」→ 非公开视频/非支持站点，拒绝

## 3. 业务流描述

### 3.1 目标数据源

| 数据源 | 作用 |
| --- | --- |
| 用户提供的公开视频页面 | 下载来源；只接受 http/https 且属于支持站点的单个视频 |
| yt-dlp | 解析页面并下载可公开获取的视频流 |
| Emily 文件库 | 下载完成后的归档位置（`FileManager.archive_upload`） |
| 当前会话 | `send_file` 的投递目标（conversation_id） |

### 3.2 使用的系统工具

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `download_video` | 下载公开视频并归档，返回 `file_no`；写操作，L3+ | 用户给出支持站点的视频页面地址时；**核心工具** |
| `send_file` | 把已归档文件发送给当前会话用户 | `download_video` 成功返回 `file_no` 后 |

> 下载与发送分两步：`download_video` 只负责“拿到并归档”，`send_file` 负责“发给用户”。不要用下载工具直接生成外链或暴露本地路径。

### 3.3 处理流程（作业规程）

```
用户提出下载视频诉求
    ↓
[确认地址] 是否为 http/https、是否属于支持站点、是否为单个视频
    ↓
[调用下载] download_video(url="<页面地址>")
    ↓
成功：拿到 file_no / 标题 / 大小 / 时长
    ↓
[发送文件] send_file(file_no="<file_no>", caption="视频：<标题>")
    ↓
[组织回复] 说明已发送、视频标题与大小；不暴露本地路径
```

**失败时**：按工具返回的 `error_code` / `reply` 如实说明；不要改用其他工具下载，也不要编造“已发送”。

### 3.4 工具调用指引

**download_video**
- 必填 `url`：用户给出的公开视频页面地址；不要自行拼接、猜测或改写 BV 号。
- 单视频限制：≤30 分钟、≤200MB；超出时工具会拒绝并说明。
- 不支持：播放列表/合集、直播、需要登录或付费的内容、非支持站点、内网/本机地址。
- **先探测 metadata**：工具会先解析标题/时长（不下载），再按 `2×时长+90 秒` 设置等待上限（120–600 秒）；超时返回 `timeout`，提示换更短的视频。
- **证书校验**：演示环境默认 `nocheckcertificate=True`，避免 mitmproxy 代理 CA 导致 yt-dlp 失败；站点仍受 `ALLOWED_HOSTS` 白名单限制。
- 下载可能耗时（数十秒到数分钟）；先告知用户“正在下载”，不要重复调用同一地址。
- 成功后返回 `file_no` / `title` / `duration` / `wait_seconds`；不要把 `file_no` 当成最终回复，必须继续调用 `send_file`。

**send_file**
- 必填 `file_no`：直接使用 `download_video` 返回的值。
- `caption` 建议写“视频：<标题>”；不要附带内部路径、下载地址或调试信息。
- 发送失败（如文件未存档、无权限）时如实转述，不要重试到成功为止。

### 3.5 内容与合规边界

1. **只下载公开内容**：不绕过登录、会员、付费、DRM、地域限制；需要 cookies 的私有视频不支持。
2. **不做批量抓取**：一次只处理一个视频；播放列表/合集请用户提供单个视频地址。
3. **不改动原始平台内容**：不承诺去水印、二次剪辑、转码；只做原样下载与发送。
4. **不外发内部信息**：下载来源仅限用户提供的公开页面；不把 Emily 内部地址、文件路径、token 写入回复。
5. **版权提醒**：仅用于用户有权使用的场景；如用户要求下载明显侵权内容，提示其自行确认授权。

## 4. 输出成果要求

### 4.1 回复格式

- 下载完成并发送后，回复：视频标题、文件大小、已发送状态；控制在 100 字以内。
- 不出现“本地路径”“存储路径”“file_no”等内部字段；`file_no` 仅用于工具调用。
- 失败时给出原因与可执行的下一步（换单个视频地址 / 换支持站点 / 稍后重试 / 联系管理员）。

### 4.2 成果要素

| 场景 | 应含内容 |
| --- | --- |
| 下载并发送成功 | 视频标题 + 文件大小 + “已发送到当前会话” |
| 地址不支持 | 说明支持站点；请用户提供对应站点的单个视频地址 |
| 超时长/超大 | 说明 30 分钟 / 200MB 上限；建议提供更短的视频 |
| 需要登录/付费 | 如实说明不支持登录态/付费内容；请用户自行下载或提供公开版本 |
| 下载失败 | 概括原因（地址失效/平台不可用/网络失败）；建议稍后重试 |

## 5. 异常处理原则

| 异常场景 | 处理建议 |
| --- | --- |
| **权限不足** | 明确说明需参建管理（L3）及以上；不得绕过 |
| **非 http/https / 内网地址** | 拒绝并说明只支持公开视频页面 |
| **站点不支持** | 列出支持站点（B站 / YouTube / Vimeo），请用户更换地址 |
| **播放列表/直播/合集** | 说明只支持单个公开视频，请用户提供单条视频地址 |
| **超过时长/大小上限** | 说明 30 分钟 / 200MB 限制，请用户提供更短的视频 |
| **需要登录/付费/DRM** | 如实说明无法下载，请用户使用有权限的账号自行获取 |
| **下载失败/平台不可用** | 说明可能原因，建议稍后重试；不要连续重复调用 |
| **文件服务未就绪/归档失败** | 说明“已下载但归档失败”，建议联系管理员；不要编造发送成功 |
| **send_file 失败** | 如实说明发送失败；不要用其他通道绕过 |
