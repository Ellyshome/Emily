## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

当用户消息同时满足以下条件时，应判定为「事件记录」请求：

**必须条件（满足其一即可）**：
- 明确提及事件记录、事件录入、现场情况记录、工作日志
- 描述具体现场活动或工程进展（如"铺装完成"、"基坑渗水"、"材料到场"、"安全检查"）
- 用户以汇报口吻描述刚完成的现场工作或观察到的情况
- 提及具体的施工节点、质量问题、安全事故、材料验收等工程现场事件

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 用户在描述会议场景中的讨论内容而不是独立事件 → 优先会议纪要
- 用户消息核心意图是"创建待办/任务/提醒/安排/分派"，包含 deadline 或负责人分配 → 优先任务管理（SOP-003）
- 用户说"帮我记个待办"、"添加一个待办事项"、"提醒我..."、"安排..." → 这是任务管理，不是事件记录
- 只是询问某事件有没有发生过 → 属于查询，不是录入
- 单纯闲聊性质的"今天忙死了"等无具体业务内容的表述 → 普通对话

### 2.2 示例对话

**应触发此业务流**：
> 「科技城5号楼铺装完成了25平米，验收通过了，录一下。」

> 「今天下午基坑东侧发现渗水，大概2平米，已经通知监理了，先记上。」

> 「刚才钢筋检查完成了，3号楼12层，绑扎间距都符合要求。」

**不应触发此业务流**：
> 「上次基坑渗水那个事后来怎么处理的？」→ 查询  
> 「安排张三明天去处理渗水问题」→ 任务管理

## 3. 业务流描述

### 3.1 目标数据库表

| 表名 | 作用 | 关键字段 |
| --- | --- | --- |
| `events` | 事件主表 | `event_no`（事件编号）、`event_type`（事件类型）、`title`（标题）、`description`（描述）、`event_date`（日期）、`category`（分类）、`project_id`（关联项目） |

### 3.2 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `record_event` | 事件录入 | 核心工具 |
| `query_data` | 项目/上下文查询 | 推断项目归属时使用 |

### 3.3 处理流程

```
用户发起事件描述
    ↓
[意图判定] → 确认为事件记录
    ↓
[信息整理] 提取要素：
  ① 事件标题（title）[必有]
  ② 事件类型（event_type）[应有，语义推断]
  ③ 事件日期（event_date）[应有，默认今天]
  ④ 描述（description）[应有]
  ⑤ 关联项目（project_id）[应有，自动匹配]
    ↓
[拟录入确认] → 展示拟录入单，等待确认
    ↓
    ↓
[调用 record_event] → 写入 events 表
    ↓
[返回确认信息] → 事件编号 + 简要回执
```

### 3.4 Agent 调用指引（L3 agent loop）

1. **项目 UUID 解析**：若用户提供项目名称但不知 UUID，**必须先调 `resolve_project`** 解析 project_id，禁止将项目名称直接填入 project_id 字段
2. **工具失败自纠**：调用 `record_event` 返回错误时，分析 tool_result 中的 error 信息，调整参数后重试，不要原样重试
3. **信息不足**：缺少必须字段（如 title）时，调用 `ask_user` 工具向用户提问，不要猜测填充
4. **完成回复**：录入成功后给出最终文本回复（不调用工具），包含事件编号（如 EVT-xxx）

## 4. 输出成果要求

### 4.1 字段分级与约束

| 字段 | 级别 | 约束 |
| --- | --- | --- |
| **title** 事件标题 | 🔴 必有 | 简洁明了（≤ 50 字） |
| **event_type** 事件类型 | 🟡 应有 | construction_progress / quality_issue / safety_incident / material_arrival / inspection / decision / other |
| **event_date** 事件日期 | 🟡 应有 | YYYY-MM-DD，默认今天 |
| **description** 描述 | 🟡 应有 | 详细描述事件经过 |
| **project_id** 关联项目 | 🟡 应有 | 优先匹配已有项目 |

---

## 5. 异常处理原则

| 异常场景 | 处理建议 |
| --- | --- |
| **无事件标题** | 向用户询问事件简述 |
| **无关联项目** | 自动推断，失败时询问用户 |
| **用户无权限** | 终止流程，回复权限不足提示 |
