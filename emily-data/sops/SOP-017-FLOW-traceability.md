# 信息追溯与时间线 — 业务流服务手册

> **适用对象**：AI Agent（会话主循环 / SOP 能力）
> **允许用户角色**：参建管理（L3）及以上
> **业务目的**：把散落在评审意见、会议纪要、工作群、事件记录里的同一件事，串成一条可追溯的时间线，并明确指出未闭环项
> **所属框架**：资料查阅 / 信息追溯 → 跨源时间线（当前子项）
> **文档风格**：地产企业内业文件管理规范，简洁明确，可执行

对“这件事之前讨论过吗 / 谁提的 / 怎么议的 / 卡在哪里”这类问题，先确定项目，再用关键词检索资料库，按时间排序形成时间线；找不到后续记录时明确说“未闭环”，不要臆造。

## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

**必须条件（满足其一即可）**：
- 询问某件事“之前有没有讨论过 / 谁提的 / 怎么议的 / 议到哪一步 / 卡在哪里”
- 要求“追溯 / 时间线 / 来龙去脉 / 闭环情况”
- 针对某个具体部位、做法、尺寸、材料、节点，要求找历史评审、会议、群聊记录

**否定条件**：
- 只是问当前节点状态/进度 → 走节点查询（SOP-011 `query_nodes`）
- 只是问规范条文/制度 → 走知识库检索（`knowledge_search`）
- 只是要求记录一条新事件/会议 → 走对应记录 SOP

### 2.2 示例对话

**应触发**：
> 「鸿瑞府展示区入口台阶平台的尺度，之前有没有讨论过？」

> 「小市政和园林井盖点位这个事，谁提的、议到哪一步了？」

> 「帮我追溯一下这条评审意见的闭环。」

**不应触发**：
> 「鸿瑞府景观条线哪些节点超时了？」→ 节点状态查询
> 「把这次会议记一下」→ 会议纪要记录

## 3. 业务流描述

### 3.1 目标数据源

| 数据源 | 作用 |
| --- | --- |
| 资料库 `01_项目资料`（评审意见 / 会议纪要 / 工作群 / 变更） | **第一优先**：追溯的主证据 |
| 资料库 `02_材料与做法` / `节点做法` / `考察项目` | 做法与经验类追溯 |
| 结构化业务库 `meetings` / `events` / `tasks` | 补充时间点与责任人 |
| 群聊归档（`query_groups` / `chat_archive`） | 有追踪群时补充群内讨论；没有时如实说明 |

### 3.2 使用的系统工具

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `resolve_project` | 项目名称 → project_id | **第一步，必须做**；不要用 `project=None` 查业务库 |
| `library_search` | 关键词检索资料库备注/说明 | **第二步**，用“主题 + 评审/纪要/会议/群聊/变更”检索 |
| `read_library_file` | 读取命中的 .md/.docx/.xlsx 正文 | 命中文件后逐份读取 |
| `read_knowledge_library` | 列目录 / 读索引 / 读文本文件 | 需要补目录全景时 |
| `query_data` | 查 meetings / events / tasks | 资料库读完后补时间点；**必须带 project_id** |
| `query_groups` / `chat_archive` | 查已追踪群与归档消息 | 仅当目标群已加入追踪 |

> **禁止**：在没有 `project_id` 的情况下直接调用 `query_data`；不要用一次宽泛查询代替资料库检索。

### 3.3 处理流程（作业规程）

```
用户提出追溯问题
    ↓
[1. 定项目] resolve_project(project_name="<项目名>") → project_id
    ↓            找不到 → 让用户确认项目名，不继续猜
[2. 检索资料库] library_search(query="<主题> 评审 纪要 会议 群聊 变更", path="<可选>")
    ↓            命中 0 条 → 换关键词再试一次；仍 0 条 → 如实说“资料库无记录”
[3. 读正文] 对前 3–5 条命中逐份 read_library_file / read_knowledge_library(read_file)
    ↓            提取：日期、来源文件、提出人、问题/诉求、回复、结论/状态
[4. 补业务库] query_data(type="meeting"/"event", project_id=<id>, time="all")
    ↓            只作为补充；资料库已有记录时不重复展开
[5. 串时间线] 按日期升序排列，标注来源与状态
    ↓
[6. 结论] 已闭环 / 未闭环 / 资料不足，分别说明
```

### 3.4 证据提取口径

每一条记录至少提取：

| 字段 | 说明 |
| --- | --- |
| 日期 | 文件日期 / 会议日期 / 消息日期；缺失时标“日期不详” |
| 来源 | 文件名（如《景观施工图评审意见》第 47 条） |
| 提出方 | 谁提出的（业主 / 设计院 / 监理 / 施工） |
| 内容 | 问题、诉求或结论，一句话 |
| 回复 | 对方怎么回应 |
| 状态 | 已解决 / 待补充 / 未闭环 |

### 3.5 输出格式

```
已追溯「<主题>」：

1. 2026-09-20｜《景观施工图评审意见》第 47 条
   提出：展示区入口台阶平台尺寸偏小，要求整改。
   设计院回复：此处有锁口石，认为尺度适宜。

2. 2026-10-10｜《景观施工图评审会议纪要》
   再次讨论：会议未接受解释，要求设计院补充同类案例。

3. 2026-10-12｜项目工作群讨论摘录
   当前处理：设计院暂未找到支撑案例，拟调整附近高程。

当前状态：未找到后续闭环记录；景观施工图正式版是否已调整，需向设计院/项目负责人确认。
```

**纪律**：

1. 只写实际读到的内容；没读到的来源不猜测、不补全。
2. 没有后续记录时，明确写“未找到后续闭环记录”，不要用“应该已经解决”这类推断。
3. 群聊只有 Markdown 摘录时，写“群聊摘录文件”，不要宣称“实时群聊检索”。
4. 资料库和业务库都没有记录时，列出已检索的关键词与范围，再说明“未找到”。

## 4. 失败与降级

| 情况 | 处理 |
| --- | --- |
| 项目名无法解析 | 请用户确认项目全称；不要用空 project 查库 |
| 资料库命中 0 条 | 换 2–3 组关键词再试；仍 0 条则如实说明 |
| 只命中部分文件 | 按已命中内容给时间线，并标注“缺哪一段” |
| 业务库查询超时/报错 | 不影响已读到的资料库证据，如实说明 |
| 群聊未追踪 | 说明“该群未加入追踪，无法检索群消息” |

---

## 5. 与其他 SOP 的边界

- 节点状态/超时 → SOP-011 `query_nodes`；
- 规范条文/制度 → `knowledge_search`；
- 记录新事件/会议 → SOP-002 / SOP-001；
- 资料库目录查阅（不涉及时间线）→ SOP-013；
- 本 SOP 只负责“跨源串时间线 + 指出未闭环”。
