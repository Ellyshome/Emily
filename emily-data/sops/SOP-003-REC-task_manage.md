## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

当用户消息同时满足以下条件时，应判定为「任务管理」请求：

**必须条件（满足其一即可）**：
- 明确提及任务分派、工作安排、待办事项、任务创建
- 包含"安排XX做YY"、"让XX负责YY"、"指派XX去YY"等分派语句
- 用户说"帮我记个待办"、"把这个加到任务列表"、"添加一个待办事项"
- 用户说"提醒我..."、"设置提醒..."、"以后..."、"定期..."等涉及时效的长期要求（此时也可触发 SOP-007 长期记忆）
- 提及具体责任人 + 工作内容 + 时间要求的组合
- 包含"待办"、"任务"、"提醒"、"截止日期"、"deadline"、"安排"、"跟进"、"负责"等关键词

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 用户在会议纪要中顺带提到待办事项 → 优先会议纪要
- 只是询问任务状态或进度 → 属于查询
- 没有明确责任人或截止时间的笼统想法 → 普通对话，可引导但不强制录入

### 2.2 示例对话

**应触发此业务流**：
> 「安排张三下周五之前完成科技城外墙检查报告，优先级高。」

> 「帮我记个待办：明天提醒李工提交月报。」

**不应触发此业务流**：
> 「张三那个任务做完了吗？」→ 查询  
> 「我们可能需要做一次全面检查」→ 笼统想法，无明确责任人/时间

## 3. 业务流描述

### 3.1 目标数据库表

| 表名 | 作用 | 关键字段 |
| --- | --- | --- |
| `tasks` | 任务主表 | `task_no`（任务编号）、`title`（标题）、`description`（描述）、`owner_id`（责任人）、`status`（状态）、`due_date`（截止日期）、`project_id`（关联项目） |

### 3.2 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `record_task` | 任务创建 | 核心工具 |
| `query_data` | 查询现有任务/项目 | 检查重复、推断项目 |

### 3.3 处理流程

```
用户发起任务描述
    ↓
[意图判定] → 确认为任务管理
    ↓
[信息整理] 提取要素：
  ① 任务标题（title）[必有]
  ② 责任人（owner）[应有]
  ③ 截止日期（due_date）[如有]
  ④ 描述（description）[如有]
  ⑤ 优先级（priority）[可选]
  ⑥ 关联项目（project_id）[应有]
    ↓
[拟录入确认] → 展示拟录入单
    ↓
[调用 record_task] → 写入 tasks 表
    ↓
[返回确认信息] → 任务编号 + 简要回执
```

## 4. 输出成果要求

### 4.1 字段分级与约束

| 字段 | 级别 | 约束 |
| --- | --- | --- |
| **title** 任务标题 | 🔴 必有 | ≤ 100 字 |
| **owner** 责任人 | 🟡 应有 | 从语义提取姓名 |
| **due_date** 截止日期 | 🟢 如有 | YYYY-MM-DD |
| **description** 描述 | 🟢 如有 | 详细说明 |
| **project_id** 关联项目 | 🟡 应有 | 自动匹配 |

| **无责任人** | 询问或留空 |
| **重复任务检测** | 提示已有类似任务 |
