## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

当用户消息同时满足以下条件时，应判定为「守护审计」请求：

**必须条件（满足其一即可）**：
- 明确提及全面检查、巡检、审核、数据审计、综合分析
- 需要跨多个数据维度综合分析的请求（如"本周项目整体怎么样"）
- 需要主动探索数据关联（如"找出与渗水相关的所有信息"）
- 需要数据完整性巡检或信息审核（如"检查项目数据有无异常"）
- 多步骤推理需求（如"对比本月和上月活跃度变化"）

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 简单单表查询（如"今天几个事件"、"列出任务"）→ 用 query_data
- 单一事件/任务/会议的录入 → 对应录入类 SOP
- 闲聊性质的笼统问题 → 普通对话

### 2.2 示例对话

**应触发此业务流**：
> 「帮我全面审核一下科技城项目最近一周的数据。」

> 「检查一下有没有数据异常或矛盾的地方。」

> 「本周项目整体怎么样，做一次综合分析。」

**不应触发此业务流**：
> 「今天有几个事件？」→ query_data 简单查询  
> 「查一下张三的任务」→ query_data 简单查询

## 3. 业务流描述

### 3.1 目标数据库表

全部业务表均可访问。

### 3.2 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| 守护调查Agent | 框架自动唤醒并执行调查 | 核心能力 |
| `query_data` | 数据查询 | GuardianAgent 内部使用 |
| `write_notebook` | 写入笔记 | GuardianAgent 记录发现 |

### 3.3 处理流程

```
管理员发起深度调查请求
    ↓
[意图判定] → 确认为守护审计
    ↓
[框架自动唤醒 GuardianAgent] → 传递用户原始问题
    ↓
[GuardianAgent ReAct 循环] → 多轮查询分析
    ↓
[返回调查结果] → 汇总发现 + 建议
```

## 4. 输出成果要求

- 调查结果应包含：发现的问题、数据概况、改进建议
- 如有异常发现，自动写入笔记本
