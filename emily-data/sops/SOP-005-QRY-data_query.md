## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

当用户消息同时满足以下条件时，应判定为「数据查询」请求：

**必须条件（满足其一即可）**：
- 用户以疑问句形式询问项目/事件/任务/会议/文件相关信息
- 明确提及查询、查看、列出、统计、汇总等查询意图词
- 询问某个具体数据的状态或详情（如"XX事件怎么样了"、"张三有哪些任务"）
- 要求展示某时间范围内的数据概况

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 询问的同时表达了录入意图 → 优先录入类 SOP
- 需要跨多维度深度分析的复杂查询 → 使用 query_data 工具
- 纯闲聊性质的随口一问（如"你好吗"）→ 普通对话

### 2.2 示例对话

**应触发此业务流**：
> 「查一下科技城今天有哪些事件。」

> 「张三有哪些逾期任务？」

> 「最近一周会议记录列一下。」

> 「刚才聊了什么？」

**不应触发此业务流**：
> 「本周项目整体怎么样，帮我全面分析一下」→ 综合分析请求，需组合多个查询工具  
> 「帮我录一条事件」→ 事件记录

## 3. 业务流描述

### 3.1 目标数据库表

| 表名 | 作用 |
| --- | --- |
| `events` | 事件查询 |
| `tasks` | 任务查询 |
| `meetings` | 会议查询 |
| `files` | 文件查询 |
| `messages` | 通讯记录查询 |
| `conversations` | 会话查询 |
| `users` | 用户查询 |
| `projects` | 项目查询 |

### 3.2 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `query_data` | 结构化查询 | 核心工具，10 种 query_type |

### 3.3 处理流程

```
用户发起查询请求
    ↓
[意图判定] → 确认为数据查询
    ↓
[确定查询类型] → 从 10 种 query_type 中选择
    ↓
[调用 query_data] → 获取结构化结果
    ↓
[提炼摘要] → 将原始数据转换为自然语言回复
    ↓
[返回结果] → 简洁回复（≤ 150 字）
```

---

## 4. 输出成果要求

### 4.1 回复格式

- 查询结果必须先提炼摘要再用自然语言回复，严禁原文 dump 数据库记录
- 回复控制在 150 字以内
- 用自然口语，不要列清单

---

## 5. 异常处理原则

| 异常场景 | 处理建议 |
| --- | --- |
| **查询无结果** | 告知用户未找到相关数据 |
| **query_type 不确定** | 根据语义推断，不确定时选最相关的 |
