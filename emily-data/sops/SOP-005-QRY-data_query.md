## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

当用户消息同时满足以下条件时，应判定为「数据查询」请求：

**必须条件（满足其一即可）**：
- 用户以疑问句形式询问项目/事件/任务/会议/文件相关信息
- 明确提及查询、查看、列出、统计、汇总等查询意图词
- 询问某个具体数据的状态或详情（如"XX事件怎么样了"、"张三有哪些任务"）
- 要求展示某时间范围内的数据概况

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 询问的同时表达了录入意图 → 优先录入类 SOP
- 需要跨多维度深度分析的复杂查询 → 使用 query_data 工具
- 纯闲聊性质的随口一问（如"你好吗"）→ 普通对话

### 2.2 示例对话

**应触发此业务流**：
> 「查一下科技城今天有哪些事件。」

> 「张三有哪些逾期任务？」

> 「最近一周会议记录列一下。」

> 「刚才聊了什么？」

**不应触发此业务流**：
> 「本周项目整体怎么样，帮我全面分析一下」→ 综合分析请求，需组合多个查询工具  
> 「帮我录一条事件」→ 事件记录

## 3. 业务流描述

### 3.1 目标数据库表

| 表名 | 作用 |
| --- | --- |
| `events` | 事件查询 |
| `tasks` | 任务查询 |
| `meetings` | 会议查询 |
| `files` | 文件查询 |
| `messages` | 通讯记录查询 |
| `conversations` | 会话查询 |
| `users` | 用户查询 |
| `projects` | 项目查询 |

### 3.2 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `query_data` | 结构化查询 | 核心工具，10 种 query_type |
| `query_groups` | 群信息查询（列出在追踪群 / 检索群消息原文） | 用户问"系统在保存哪些群""群里说过什么"时使用；详见 3.5 节 |

### 3.3 处理流程

```
用户发起查询请求
    ↓
[意图判定] → 确认为数据查询
    ↓
[确定查询类型] → 从 10 种 query_type 中选择
    ↓
[调用 query_data] → 获取结构化结果
    ↓
[提炼摘要] → 将原始数据转换为自然语言回复
    ↓
[返回结果] → 简洁回复（≤ 150 字）
```

### 3.4 Agent 调用指引（L3 agent loop）

1. **项目 UUID 解析**：查询涉及特定项目时，若只有项目名称，**必须先调 `resolve_project`** 解析 project_id
2. **工具失败自纠**：调用 `query_data` 返回错误时，分析 tool_result 调整 query_type 或参数后重试
3. **查询无结果**：如实告知用户无结果，可建议调整查询条件
4. **完成回复**：查询结果必须提炼摘要后用自然语言回复（≤ 150 字），不要 dump 原始数据

### 3.5 群信息查询（`query_groups`）

**能力位置**：进程内只读业务工具 `query_groups`（登记在业务工具注册表，随 SOP 生效）。

**发现方式**：本 SOP 的 3.2 节声明；工具描述自带用法说明（两个动作 + 典型用途 + 权限口径），无需额外上下文。

**适用场景**——当用户的问题落在"群里说过什么"而不是"系统里登记了什么"时使用：

| 用户说法（示例） | 用法 |
| --- | --- |
| "系统在保存哪些群的信息" / "有哪些群可以查" | `action="list"`：列出在追踪群（备注名、平台、成员数、已留存消息数、最近活跃） |
| "某材料的进场时间" / "验收时间是什么时候" / "谁到场了" | `action="messages"` + `keyword`；这类信息常由某人在群里报备，取回原文由用户自行判断 |
| "查一下景观施工工程群" | `action="messages"` + `group="景观施工工程群"`——群可用**备注名 / 平台群名 / 群号**任一表达，不需要内部 ID |
| "最近一周群里关于变更的通知" | `action="messages"` + `keyword` + `time_range="week"` |

**调用约束**：

1. **不替用户下结论**：本工具只返回原文片段与出处（哪个群 / 谁说的 / 什么时候），**不做摘要、不做事件抽取**。若用户要的是结构化结论，走 `query_data`。
2. **群名匹配不上时如实回报**：返回"未找到"或"匹配到多个群 + 候选清单"时，请原样转述并向用户确认，**不得猜测或替换成相近的群**。
3. **空结果如实回报**：返回"没有匹配记录"时即如实告知，不得臆造原文。
4. **默认不含测试与运维流量**：检索默认排除测试/运维来源的消息；如用户明确要求排查测试数据，再传 `include_sources=true`。
5. **权限口径（不在 SOP 内自造）**：检索结果由服务层按发起者身份收敛 —— **建设主管（L4）及以上**可见全部群的群消息；**其余身份**仅可见其当前参与的（在群成员名册内在册的）群；名册数据缺失时一律不返回。权限判定在服务层单一实现，本 SOP 不重复判定，也不因"用户认为自己在群里"而放宽。
6. **越权与无权限一律回"没有匹配记录"**：不要在回复中透露"你看不到"或该群的存在状态。

**可下线**：移除本 SOP 的 3.2 声明与该工具的全部注册项后重启，本能力即不可用；群消息的留存不受影响（照常记录、只是没有查询入口）。

## 4. 输出成果要求

### 4.1 回复格式

- 查询结果必须先提炼摘要再用自然语言回复，严禁原文 dump 数据库记录
- 回复控制在 150 字以内
- 用自然口语，不要列清单

## 5. 异常处理原则

| 异常场景 | 处理建议 |
| --- | --- |
| **查询无结果** | 告知用户未找到相关数据 |
| **query_type 不确定** | 根据语义推断，不确定时选最相关的 |
