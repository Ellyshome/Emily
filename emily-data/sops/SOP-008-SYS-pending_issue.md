## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

当用户消息同时满足以下条件时，应判定为「待解决问题处理」请求：

**必须条件（满足其一即可）**：
- 管理员提及 PND 编号（如"处理 PND-xxx"）
- 管理员说"查看待处理问题"、"列出待解决问题"、"有哪些待处理"
- 管理员针对某个系统发现做出决策（"那个问题我决定..."、"这个不用管了"）
- 管理员要求关闭/解决某个待处理条目

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 普通用户（非管理员）提及 PND 相关词汇 → 权限不足，提示仅管理员可用
- 只是在讨论某个问题但没有做出决策 → 普通对话

### 2.2 示例对话

**应触发此业务流**：
> 「处理 PND-20260614-0001，决策是：重新测量后按实测数据录入。」

> 「列出所有待解决问题。」

> 「PND-20260614-0002 那个不用管了，数据是正确的，关掉。」

**不应触发此业务流**：
> 「PND 是什么意思？」→ 普通询问  
> 「帮我录一条事件」→ 事件记录

## 3. 业务流描述

### 3.1 目标存储

| 存储 | 作用 |
| --- | --- |
| `tem_log/待解决问题.md` | 待解决问题清单文件 |

### 3.2 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `manage_pending_issues` | 待解决问题管理 | 核心工具 |
| `record_event` | 决策事件录入 | 闭环处理时录入决策事件 |

### 3.3 处理流程

```
管理员发起待解决问题处理
    ↓
[意图判定] → 确认为待解决问题处理
    ↓
[操作类型判定]
  ├── 查看清单 → manage_pending_issues(action="list_pending")
  ├── 处理问题 → 完整闭环：
  │     1. record_event（决策事件）
  │     2. manage_pending_issues(action="resolve")
  └── 回复结果
```

## 4. 输出成果要求

- 查看清单：简洁列出 PND 编号 + 问题简述
- 处理完成：确认已闭环 + 决策事件编号
