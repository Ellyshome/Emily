# 苗木表审核（设计阶段）— 业务流服务手册

> **适用对象**：AI Agent（会话主循环 / SOP 能力）
> **允许用户角色**：参建管理（L3）及以上
> **业务目的**：对用户提交的苗木表做设计阶段预审，按《苗木表审核要点》逐条给出审核意见
> **所属框架**：资料审核 → 苗木表审核（设计阶段）（当前仅实现本子项）
> **文档风格**：地产企业内业文件管理规范，简洁明确，可执行

对用户当前提交的苗木表做设计阶段预审：先给信息分析，再按《苗木表审核要点》逐条给出审核意见；只读文件，不做成本、图纸、验收等延伸。

## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

**必须条件（满足其一即可）**：
- 用户提交 xlsx / pdf / docx 文件，并要求“审核苗木表 / 苗木清单 / 种植表”
- 用户要求“按公司要求看看这份苗木表”“给我逐条意见”
- 用户明确提到“苗木表审核 / 苗木表预审 / 苗木表自检”

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 只是要求读取文件、总结内容、提取字段 → 普通文件问答，不进入本 SOP
- 要求做成本估算、预算编制、询价 → 当前未开放（后续子项）
- 要求与图纸 / 工程量清单核对 → 当前未开放（后续子项）
- 要求做进场验收、封样、替换条件审查 → 当前未开放（后续子项）

### 2.2 示例对话

**应触发此业务流**：
> 「帮我审核这份苗木表。」

> 「按公司要求看看这个苗木表有没有问题，逐条给我意见。」

**不应触发此业务流**：
> 「这份苗木表里有哪些品种？」→ 普通文件问答，不做审核
> 「帮我根据苗木表做一下成本估算。」→ 当前未开放，说明只做设计阶段预审
> 「帮我跟图纸对一下数量。」→ 当前未开放，说明只审核用户提交的文件

## 3. 业务流描述

### 3.1 目标数据源

| 数据源 | 作用 |
| --- | --- |
| 用户当前提交的文件 | 唯一审核对象，支持 xlsx / docx（本次演示不做 PDF） |
| 会话中的文件信息 | 文件名、行数、品种数等基础信息 |

本 SOP **只读取用户当前提交的文件**；成本只读资料库中的《成本参考摘要》，不主动查询图纸或工程量清单；不写数据库、不生成文件。

### 3.2 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `officeCLI` | 读取 Office 文件（xlsx / docx / pptx） | **核心工具**，读取用户提交的 Office 文件 |
| `resolve_file_path` | 把文件编号解析为本地路径 | 当前消息附件清单只有 `file_no`、没有可用路径时 |
| `read_library_file` | 读取资料库内的文本/Office 文件 | 读取《成本参考摘要.md》或资料库参照文件时 |
| `ocr_document` | 对扫描件 / 图片做 OCR（如部署启用） | 扫描件 / 图片兜底；本次演示不做 PDF |

> `officeCLI` 随 emily-core 镜像构建安装（`/usr/local/bin/officecli`），启动时由 `TOOL_META_MAP` 自动种子到 `tool_registry`（base / all / meta）；工具 handler 内另有 L3 门禁（fail-closed），低于 L3 时返回权限不足。未启用时按第 5 章处理，不自行改用其他工具绕过。
>
> 文件路径由会话附件上下文提供；`officeCLI` 以 `file_path` 读取。若当前轮次拿不到本地路径，按第 5 章请用户重新上传，不自行拼接或猜测路径。

### 3.3 处理流程

```
用户提交文件并要求审核
    ↓
[权限] L3 及以上 → 否则拒绝并说明所需等级
    ↓
[文件检查] 确认文件已收到、格式为 xlsx/docx、可读取
    ↓
[附件确认] 从“当前消息附件”清单确认文件名、file_no、本地路径；多个 Office 文件先问“审哪一份”
    ↓
[读取] officeCLI 读取；大表先用 outline 确认 sheet/行数，再用 text/range 分段；扫描件走 OCR 兜底
    ↓
[信息分析] 统计行数、品种数、总绿化面积、草灌比、乔木密度、常绿比例等
    ↓
[成本参考] 用户问成本时 → read_library_file("成本参考/成本参考摘要.md") → 用区间/口径回答
    ↓
[逐条审核] 按《苗木表审核要点》逐条检查
    ↓
[输出] 先给信息分析，再给逐条审核意见和依据
```

### 3.4 审核要点（当前版本）

按《苗木表审核要点（设计阶段·基础版）》执行，逐条检查：

1. **字段完整性**：序号、苗木名称、规格、单位、数量、种植区域、常绿/落叶、土球/容器/苗龄、备注是否齐全。
2. **品种**：大类是否细分到品种群或具体品种；同物异名、别名是否统一。
3. **草灌比**：草本地被与灌木的面积比，参考 5:5，允许 ±5%。
4. **乔木密度**：每 100㎡ 绿地乔木株数，参考不少于 3 株。
5. **主景树**：胸径 30cm 以上的主景树，不宜超过乔木总量的 10%。
6. **规格**：胸径—高度—冠幅—分枝点是否匹配；土球、容器、苗龄是否注明。
7. **单位与数量**：株/丛/㎡/m 是否统一；数量与汇总是否能对上。
8. **备注**：花色、树形、分枝点、特殊造型、替换条件等是否写明。

**统计口径**：
- 草灌比 = 草本地被面积 : 灌木面积；
- 乔木密度 = 乔木总株数 ÷ 总绿化面积 × 100（株/100㎡）；
- 常绿品种比例 = 常绿品种数 ÷ 品种总数；乔木常绿总量比例 = 常绿乔木株数 ÷ 乔木总株数；
- 主景树占比 = 胸径 30cm 以上的乔木株数 ÷ 乔木总株数；
- 表中缺面积或汇总数据时，对应指标写“未提供，无法统计”。

**判定原则**：
- 只报能从表中核实的问题；不能核实的写“无法判断”，不臆测。
- 要点中的“参考 / 不宜”按提示处理，不直接判定为不合格。
- 表中缺少统计所需数据时，注明“未提供，无法统计”，不自行补值。
- 规格匹配、品种细分等需要专业判断的项，只提示明显问题；无法确定时写“需专业复核”，不替代设计负责人确认。

### 3.5 明确不做

- 成本只做同类项目参考（读《成本参考摘要》），不逐项匹配预算、不写死 245 元/㎡；
- 不与图纸 / 工程量清单比对；
- 不判断反季节、苗源、采购周期；
- 不做进场验收、封样、替换条件审查；
- 不生成审核报告文件、不写数据库、不外发文件；
- 不替代正式审图、合同验收和设计负责人确认。

### 3.6 成本参考（可选）

1. **只在用户问成本时执行**，不主动计算、不主动加成本段。
2. 用 `read_library_file("成本参考/成本参考摘要.md")` 读取摘要；读不到时如实说“成本参考未就绪”，不编数字。
3. 口径写清楚：**绿化分部分项 ÷ 整理绿化用地面积**；给区间（如“约 239–324 元/㎡”），不写死 245。
4. 预算是**宁牧同类项目**，不是当前苗木表的同项目预算；不逐项匹配、不表述为“本项目预算”。
5. 成本结构优先用预算原生的“乔木/灌木/其他”；要做“乔木/灌木/地被”三分，必须先定分类规则，不强行拆分。
6. 如果用户要求“最近版预算单”，先说明预算是宁牧同类项目、日期 2022-10-24，再给区间。

## 4. 输出成果要求

### 4.1 字段分级与约束

| 字段 | 级别 | 约束 |
| --- | --- | --- |
| 信息分析 | 🔴 必有 | 文件基本情况 + 可统计指标；无法统计的注明 |
| 逐条审核意见 | 🔴 必有 | 只列发现的问题，每条有定位和建议 |
| 审核依据 | 🔴 必有 | 引用《苗木表审核要点》对应条目 |
| 缺失项 / 无法判断说明 | 🟡 应有 | 表中缺字段、缺汇总数据时说明 |
| 问题数量 | 🟢 如有 | 一句话给出发现几个问题，不做总体评分 |

### 4.2 回复格式

```
已按《苗木表审核要点》完成预审。

【信息分析】
- 文件：xxx.xlsx（32 行 / 18 个品种）
- 总绿化面积：12,600㎡
- 草灌比：约 4:6
- 乔木密度：约 2.4 株/100㎡
- 品种数：18 个
- 常绿品种比例：8/18（约 44%）
- 乔木常绿总量比例：136/302 株（约 45%）
（未提供的数据注明“未提供，无法统计”）

【审核意见】
1. 品种（第 3 行）：只写“桂花”，建议至少明确到品种群（金桂/银桂/丹桂/四季桂）。
2. 草灌比：当前约 4:6，参考 5:5（允许 ±5%），建议调整。
3. 乔木密度：当前约 2.4 株/100㎡，参考不少于 3 株，建议补植或调整规格。

【审核依据】
《苗木表审核要点》第 1、2、3 条（品种、草灌比、乔木密度）。
```

### 4.3 格式要求

- 中文书面语，逐条列示，不做大段推演；
- 每条意见控制在 150 字以内；
- 不做总体评分、不做延伸建议、不做成本 / 图纸 / 验收推演；
- 没有发现问题时，回复“按当前要点未发现问题”，不写“审核通过”。

## 5. 异常处理原则

| 异常场景 | 处理建议 |
| --- | --- |
| **权限不足** | 明确拒绝，说明需参建管理（L3）及以上；不进入后续流程 |
| **未收到文件 / 文件无法打开** | 请用户重新上传；说明支持 xlsx/pdf/docx；不猜测内容 |
| **文件格式不支持** | 请用户转为 xlsx 或 pdf；不自行转换 |
| **扫描版 PDF / 图片识别质量差** | 说明识别质量有限，建议提供 xlsx 或清晰版；已识别部分仅供参考 |
| **表中缺字段 / 缺汇总数据** | 列出缺失项，注明“无法判断 / 无法统计”，不补值 |
| **文件过大 / 读取超时** | 请用户拆分文件或提供关键 sheet；不截断后假装完整 |
| **`officeCLI` 不可用** | 说明工具未就绪，请联系管理员检查部署注册；不自行改用其他工具绕过 |
| **用户要求超出当前范围（成本 / 图纸 / 验收）** | 说明当前仅做设计阶段苗木表预审，相关能力后续开放 |
