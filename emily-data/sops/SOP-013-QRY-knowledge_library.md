# 资料库查阅与入库 — 业务流服务手册

> **适用对象**：AI Agent（会话主循环 / SOP 能力）
> **允许用户角色**：查阅 `参建管理（L3）及以上`；入库 `管理员（L5）及以上`
> **业务目的**：指导 Agent 对用户发起的「查资料 / 资料入库」诉求进行标准化处理 ——
> 按既有资料库（数字资产档案库）的逐级索引查阅资料，或把新目录纳入资料库管理
> **文档风格**：地产企业内业文件管理规范，简洁明确，可执行

按用户诉求查阅资料库（数字资产档案库）内的项目档案：先读目录索引，再逐级下钻，命中后读取文件正文；用户要求把新目录纳入资料库时走入库动作（先预览、后确认，需 L5）。

## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

当用户消息同时满足以下条件时，应判定为「资料库查阅」请求：

**必须条件（满足其一即可）**：
- 询问资料库里有哪些项目 / 哪些资料 / 有哪些目录
- 按线索找一份具体资料（某项目的合同、某期的周报、某类图纸、某份清单台账）
- 询问某份资料的存放位置、是否已归档
- 明确提及「资料库」「资料」「档案」「找资料」「查资料」等词

**入库意图（本 SOP 的第二类触发）**：
- 要求把某个目录 / 一批资料纳入资料库（"把这个文件夹入库""生成索引""纳入管理"）
- 入库一律**先预览、后确认**，且受 L5 门槛约束

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 询问系统已登记的结构化数据（事件/任务/会议/文件记录）→ 数据查询类 SOP
- 询问企业规范、政策制度的条文内容（语义检索）→ 知识库检索（`knowledge_search`）
- 要求写入、修改资料文件本身 → 资料库不改动原始资料，如实说明并拒绝

### 2.2 示例对话

**应触发此业务流**：
> 「资料库里有哪些项目资料？」

> 「黄湖项目有哪些合同？」

> 「帮我找一下黄湖的监理周报。」

> 「把 H_Project/张村 这个目录纳入资料库。」

**不应触发此业务流**：
> 「科技城项目今天有哪些事件？」→ 数据查询（`query_data`）
> 「验收规范的条文是怎么写的？」→ 知识库检索（`knowledge_search`，语义检索通道）
> 「把这份合同的内容改一下」→ 资料库只读；如实说明不改动原始资料

## 3. 业务流描述

### 3.1 目标数据源

| 数据源 | 作用 |
| --- | --- |
| 资料库根目录（容器内 `/app/knowledge_library`） | 项目档案资料的结构化存放区（与知识库检索源**物理分离**） |
| 各层目录的索引文件 | 目录的唯一入口：简介 + 文件目录 + 每项一句话描述 + 备注（**先读索引，再读文件**） |
| 资料库内的资料文件 | 命中后的正文来源（仅文本类可按文本读取） |

### 3.2 使用的系统工具

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `read_knowledge_library` | 查阅资料库（`action=list` 列目录 / `read_index` 读索引 / `read_file` 读文件），只读 | **核心工具**，逐级查阅全流程；详见 3.4 节 |
| `ingest_knowledge_library` | 资料库入库（逐层生成/更新索引），写操作，需 L5 | 用户要求把目录纳入资料库时使用；**先 `dry_run=true` 预览并确认，再实际入库**；详见 3.5 节 |

> 两条通道均**不依赖**向量检索：查阅走资料库文件访问，入库走文件遍历 + 索引写入。

### 3.3 处理流程（作业规程）

**查阅（先读首层索引 → 按线索逐级下钻 → 命中后读取文件）**：

```
用户提出查资料诉求
    ↓
[意图判定] → 确认为资料库查阅（非结构化数据查询、非规范条文检索）
    ↓
[读首层目录] read_knowledge_library(action="list")          ← 缺省即资料库首层
    ↓
[读该层索引] read_knowledge_library(action="read_index", path="<目录>")
    ↓                                                        ← 索引给出子目录与文件的一句话描述
[按线索下钻] 命中子目录 → 回到上一步，path 指向下一层
    ↓
[读目标文件] read_knowledge_library(action="read_file", path="<文件>")   ← 仅文本类
    ↓
[组织回复] 给**目录制**结果（按层列出命中资料），并可据正文回答
```

**入库（先预览、后确认）**：

```
用户要求入库某目录
    ↓
[门槛判定] 管理员（L5）及以上 → 否则明确拒绝并说明所需等级（不静默失败）
    ↓
[预览] ingest_knowledge_library(dir="<目录>", dry_run=true)   ← 只出清单，不写任何文件
    ↓
[确认] 向用户列出将生成/更新的索引清单，请求确认
    ↓
[入库] ingest_knowledge_library(dir="<目录>", dry_run=false)  ← 逐层覆盖写索引（幂等）
    ↓
[回报] 新建/更新索引数、目录层数、文件数；原始资料未被改动
```

### 3.4 查阅工具调用指引

工具共三个动作（`read_knowledge_library`）：

| action | 用途 | 关键口径 |
| --- | --- | --- |
| `list` | 列某目录下的子目录与文件 | path 留空 = 资料库首层；回答"有哪些资料"先用它 |
| `read_index` | 读某目录的索引内容 | **每次下钻都要先读索引**，按索引里的描述决定进哪一层 |
| `read_file` | 读索引里列出的资料文件正文 | 仅文本类（md/txt/csv/json 等）；同目录**缺索引时拒绝**（视为未入库） |

**必须遵守**：

1. **先索引后文件**：目录缺索引即视为**未入库**，不得跳过索引直接读文件（工具会直接拒绝）；目录未入库时如实告知"该目录未入库"，并提示可由管理员入库。
2. **逐级下钻**：一次只进一层，逐层收敛（首层 → 项目 → 分类 → 文件）；不要凭猜测直连深层路径。
3. **路径范围**：只能传资料库范围内的相对路径（如 `H_Project/黄湖/合同类`）；越界路径一律被拒绝，不要重试越界路径。
4. **不可解析类型如实说明**：图片、图纸（dwg/dxf）、压缩包、PDF/Word 等不可按文本读取，工具会明确说明；**不得**编造其内容，改为说明该文件的名称、类型与描述。
5. **索引可能过期时会附提示**：出现"索引可能已过期，建议重新入库"时，照常按索引线索查阅，并在回复中如实提示。
6. **查不到就如实说**：目录/文件/索引不存在时明确回报原因，**不得**臆造资料内容或编造文件清单。
7. **敏感件不外发**：按用户权限等级作答；不因"用户追问"就获取其无权查阅的内容。

### 3.5 入库工具调用指引

1. **门槛**：`ingest_knowledge_library` 需**管理员（L5）及以上**；低于门槛时工具会明确拒绝并说明所需等级。此时如实转述，请用户找有权限的同事或管理员办理，**不得**改用其他工具绕过。
2. **两段式**：先 `dry_run=true` 出清单并请用户确认，确认后再 `dry_run=false` 实际入库；不要未经确认直接写盘。
3. **幂等**：同一目录重复入库不翻倍、不追加，只更新既有索引；重新入库用于对齐口径或更新过期索引。
4. **不改原始资料**：入库只写索引文件（每个受管目录一份），不修改、不移动、不删除任何原始资料。
5. **耗时与规模**：入库为一次性遍历，大目录（上千文件）耗时较长，事先向用户说明。
6. **运维通道**：同一动作另有脚本通道（`scripts/ingest_knowledge_library.py`，支持 `--dry-run`），供运维/控制台使用；两通道共享同一服务层，效果一致。

## 4. 输出成果要求

### 4.1 回复格式

- **目录制结果优先**：回答"有哪些资料"时按层级列出（项目 → 分类 → 文件），给出文件名与一句话描述，而不是零散片段或模糊概括
- 引用资料时说明来源文件（文件名 / 所在目录），不出现"系统记录""数据库"这类内部说法
- 只列**实际读到**的内容；未读到的层级不猜测、不补全
- 回复控制在 300 字以内，超过时先给结论与主要条目，其余请用户指定细化方向

### 4.2 成果要素

| 场景 | 应含内容 |
| --- | --- |
| 列目录 | 目录名 + 条目数（子目录/文件）+ 关键条目清单 |
| 读索引 | 按索引的四要素呈现（简介 / 文件目录与描述 / 备注中的时效提示） |
| 读文件 | 文件名 + 与用户问题相关的正文要点 |
| 入库预览 | 将生成/更新的索引清单 + 目录层数与文件数 |
| 入库完成 | 新建/更新索引数 + 目标目录 + "原始资料未被改动" |

## 5. 异常处理原则

| 异常场景 | 处理建议 |
| --- | --- |
| **权限不足（查阅）** | 明确拒绝并说明需参建管理（L3）及以上；建议找有权限的同事办理 |
| **权限不足（入库）** | 明确拒绝并说明需管理员（L5）及以上；不得绕过 |
| **目录未入库（缺索引）** | 告知"该目录未入库"，提示可由管理员执行入库；不跳过索引读文件 |
| **资料库不可达 / 为空** | 如实告知资料库当前不可访问或为空，建议联系管理员核查；不编造资料 |
| **不可解析类型** | 说明该文件类型无法按文本读取，给出名称/类型/描述线索，建议人工打开原件 |
| **索引可能过期** | 照常按索引查阅，同时提示"建议重新入库"；不阻断查阅 |
| **路径越界** | 被拒绝属正常保护；改为在资料库范围内按层级定位，不重复尝试越界路径 |
| **入库中断 / 部分跳过** | 如实报告已完成的索引数与跳过的目录，请用户复核后重试（幂等，可安全重跑） |
