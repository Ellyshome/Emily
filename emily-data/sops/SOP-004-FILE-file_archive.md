## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

当用户消息同时满足以下条件时，应判定为「文件归档」请求：

**必须条件（满足其一即可）**：
- 用户上传或发送了文件附件（图片/PDF/Word/DWG等）
- 明确提及文件归档、图纸归档、报告存档、资料上传
- 提到具体文件类型 + 归档意图（如"这份图纸帮我归档"）
- 消息附带附件且用户表达了保存/归档/上传意图

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 用户发送表情包或非业务图片 → 忽略，不归档
- 只是询问文件是否已归档 → 属于查询
- 文件是会议纪要附件 → 优先会议纪要流程

### 2.2 示例对话

**应触发此业务流**：
> 「这份图纸帮我归档一下，科技城3号楼的电气图。」[附带 DWG 文件]

> 「刚才发的那个PDF是上周的安全检查报告，归档到科技城项目。」

**不应触发此业务流**：
> 「上次发的那份图纸还在吗？」→ 查询  
> 「帮我查一下文件」→ 查询

## 3. 业务流描述

### 3.1 目标数据库表

| 表名 | 作用 | 关键字段 |
| --- | --- | --- |
| `files` | 文件主表 | `file_no`（文件编号）、`filename`（文件名）、`file_type`（文件类型）、`file_ext`（扩展名）、`project_id`（关联项目）、`storage_path`（存储路径） |

### 3.2 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `record_file` | 文件归档 | 核心工具 |
| `query_data` | 项目查询 | 推断项目归属 |
| `query_files` | 文件查询 | 查看已有文件避免重复 |
| `query_my_nodes` | 查询本人负责 / 参与的全景节点 | 确定文件归属节点时使用 |

### 3.3 处理流程

```
用户发送文件 + 归档意图
    ↓
[意图判定] → 确认为文件归档
    ↓
[信息整理] 提取要素：
  ① 文件名（filename）[必有]
  ② 文件类型（file_type）[应有，自动识别]
  ③ 关联项目（project_id）[应有]
  ④ 文件描述（description）[可选]
  ⑤ 文件分类（file_category）[应有，自动判断]
    ↓
[节点归属确认] → 按 §3.5 规则确定归属节点（node_id）
    ↓
[拟录入确认] → 展示拟录入单（含归属节点）
    ↓
[调用 record_file] → 写入 files 表（携带 node_id，文件绑定到节点）
    ↓
[返回确认信息] → 文件编号 + 归属节点 + 简要回执
```

### 3.4 Agent 调用指引（L3 agent loop）

1. **项目 UUID 解析**：若用户提供项目名称但不知 UUID，**必须先调 `resolve_project`** 解析 project_id，禁止将项目名称直接填入 project_id 字段
2. **工具失败自纠**：调用 `record_file` 返回错误时，分析 tool_result 中的 error 信息，调整参数后重试
3. **信息不足**：缺少必须字段（如 filename）时，调用 `ask_user` 工具向用户提问
4. **节点归属**：归档前按 §3.5 确定 `node_id`；填了归属节点，文件才会挂到该节点、节点内可见
5. **完成回复**：录入成功后给出最终文本回复，包含文件关键信息与归属节点名称

### 3.5 节点归属规则

参与节点建设的单位人员都应能在节点内留痕，归档文件尽量落到具体全景节点。

判定优先级（自上而下，命中即止）：

| 顺序 | 候选来源 | 采用方式 |
| --- | --- | --- |
| 1 | **承接本次成果的任务节点**：`query_my_nodes` 返回的节点中，`deliverables[].name` 与文件内容（部位/工序/成果）匹配的任务节点 | 直接采用，并在拟录入单中展示给用户确认 |
| 2 | 本人负责的节点（`role=responsible`，含未启动节点） | 能匹配上就采用为默认归属，展示给用户确认 |
| 3 | 本企业参与的全景节点（`role=participant` / 会话上下文授权节点） | 列出候选让用户选定后采用 |
| 4 | 以上均无匹配，或用户明确表示不知道该归哪个节点 | 留空 `node_id`：文件仅归项目、不绑定节点，回执中说明 |

对话口径要求：

- 不要向用户索要节点编号，直接给**节点名称**候选（如"这份资料挂到『硬质铺装与园路』下，可以吗"）
- **先查承接关系再列候选**：先判断有没有已预定该成果/工序的任务节点，命中即默认采用
- 归属节点必须与文件所属项目一致，跨项目节点不得采用
- 用户明确说不知道时不要反复追问

## 4. 输出成果要求

### 4.1 字段分级与约束

| 字段 | 级别 | 约束 |
| --- | --- | --- |
| **filename** 文件名 | 🔴 必有 | 原始文件名 |
| **file_type** 文件类型 | 🟡 应有 | 从扩展名推断 |
| **project_id** 关联项目 | 🟡 应有 | 自动匹配 |
| **file_category** 文件分类 | 🟡 应有 | 按分类决策规则自动判断，默认 OTHER |
| **node_id** 归属节点 | 🟡 应有 | 按 §3.5 规则确定；填了则文件绑定到节点（节点内可见） |

### 4.2 文件分类决策规则

归档时根据文件名和用户描述判断 `file_category`，规则如下：

| 分类枚举值 | 中文名 | 判定依据 |
|-----------|--------|---------|
| `PROJECT_LICENSE` | 项目证照 | 涉及政府许可、法律效力证书（施工许可证、预售证、土地出让合同等） |
| `CONTRACT` | 承包合同 | 涉及参建单位签约、合同文本、界面划分、预算清单 |
| `WORK_RECORD` | 工作记录 | 涉及完工确认、进场记录、巡检报告、验收单 |
| `PHASE_DELIVERABLE` | 阶段成果 | 涉及设计方案、施工图、专项施工方案 |
| `PROCESS_DOC` | 过程文件 | 涉及政府整改/通知、飞检评分、年终总结 |
| `MANAGEMENT_SPEC` | 管理规程 | 涉及操作手册、工艺规程、标准规范 |
| `PUBLICITY` | 外宣资料 | 涉及企业/项目对外宣传材料、品牌介绍、公开宣传册 |
| `OTHER` | 其他文件 | 无法归入以上分类 |

**分类依据是业务用途而非文件格式**。无法判断时默认 `OTHER`。

## 5. 异常处理原则

| 异常场景 | 处理建议 |
| --- | --- |
| **无附件** | 提示用户发送文件 |
| **不支持的文件类型** | 告知支持的类型 |
| **文件过大** | 提示大小限制 |
| **节点归属不确定** | 按 §3.5 逐档匹配（先看承接成果的任务节点），用户仍不确定则留空 node_id（不绑定节点），不得自行编造 |
