## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

当用户消息同时满足以下条件时，应判定为「长期记忆管理」请求：

**必须条件（满足其一即可）**：
- 用户表达了明显的长期或持续性要求（"随时跟踪..."、"每天检查..."、"以后..."、"今后..."）
- 用户设定了周期性行为偏好（"每周..."、"定期..."、"每次..."、"一直..."）
- 用户要求修改回答风格/称呼/格式（"以后用XX风格回答"、"叫我XX"）
- 用户指定了角色身份（"你是我的XX"、"你的身份是XX"）
- 其他明显表达长期意图的措辞

**否定条件（即使有上述关键词，也不应判定为此业务流）**：
- 一次性对话、临时查询、简单确认不需要写长期记忆
- "以后再说"等表示推迟但不涉及具体行为偏好的表述

### 2.2 示例对话

**应触发此业务流**：
> 「以后每周五提醒我审周报。」

> 「今后叫我老张就行。」

> 「每次查询结果按时间倒序排列。」

**不应触发此业务流**：
> 「今天天气真好。」→ 普通对话  
> 「查一下任务。」→ 临时查询

## 3. 业务流描述

### 3.1 目标存储

| 存储 | 作用 |
| --- | --- |
| `memory/{用户名}-长期记忆.md` | 用户长期记忆文件 |

### 3.2 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `write_user_memory` | 写入长期记忆 | 核心工具 |

### 3.3 处理流程

```
用户表达长期意图
    ↓
[检测触发条件] → 匹配触发关键词
    ↓
[提炼核心需求] → 提取 title（2-5字）+ content
    ↓
[调用 write_user_memory] → 写入记忆文件
    ↓
[新对话自动加载] → 注入 system prompt
```

---

## 4. 输出成果要求

- title: 2-5 字简短标题
- content: 提炼后的核心需求描述
- 严禁嘴上说"记住了"但实际没调用工具

---

## 5. 异常处理原则

| 异常场景 | 处理建议 |
| --- | --- |
| **内容提炼困难** | 诚实说明，不强行记录 |
| **写入失败** | 告知用户，日志记录 |
