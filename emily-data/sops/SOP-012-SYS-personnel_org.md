## 2. 触发条件

### 2.1 触发语义特征

**必须条件**：
- 消息涉及**人员权限等级**的调整（如"把张三调成参建管理""给他升到建设主管"）
- 消息涉及**人员企业归属**的调整（如"把李四转到中天建设""他换单位了"）
- 消息涉及**企业档案**的新增或删除（如"新增一家供应商：XX建材""把某单位从系统里删掉"）

**否定条件**：
- 纯闲聊问候
- 查询类需求（人员/企业清单查询应走 SOP-005-QRY 的 `query_data`）
- 与人员/组织无关的其他业务（事件、任务、文件、节点）

### 2.2 示例对话

**应触发此业务流的用户说法：**

> 「把马晓军的等级调成参建执行」

> 「张正宏换到中天建设了，帮他改一下所属企业」

> 「新增一家企业：苏州幕墙工程有限公司，类型是分包」

**不应触发此业务流的用户说法：**

> 「查一下公司有哪些人」 → 应触发 SOP-005-QRY 数据查询

> 「今天天气怎么样」 → 闲聊

## 3. 任务执行协议

### 3.1 前置合规理念

- **等级调整规则**（以服务层为准）：L6 可调至任意级别；L5 最高调至 L4；L4 最高调至 L3；L3 仅可调至**低于自身**的级别；L2 / L1 不可调整。
- **企业归属规则**：L4+ 可调整任意人员；L3 仅可管理**本企业**人员的进出；L2 / L1 不可。
- **企业增删规则**：**L4 及以上**可新增 / 删除企业；删除前须确认该企业**无在职归属人员**。
- **fail-closed**：取不到操作人等级时**一律拒绝**；**被拒也留痕**（含拒绝原因）——动作已开始后的权限/规则拒绝属"被拒"，按操作留痕治理的三态口径记录。
- 授权判定一律在**服务层**（`PersonnelService`），以操作人**实际等级**为准，不信任前端或请求自述之外的信息。

### 3.2 使用的系统工具 / API

| 工具名 | 功能 | 调用场景 |
| --- | --- | --- |
| `update_user_level` | 调整人员权限等级 | 用户要求升降某人的等级 |
| `update_user_company` | 调整人员所属企业 | 用户要求变更某人的企业归属 |
| `manage_company` | 新增 / 删除企业档案 | 用户要求新增或删除一家企业 |

> 三者均为 `sop_only`：不进 LLM 自由工具集，只能经本 SOP（+ 人工确认）执行。

### 3.3 处理流程

```
人员/企业维护诉求
    ↓
[意图判定] → 确认是人员等级 / 企业归属 / 企业增删
    ↓
[参数解析] → 目标人员（姓名或 UUID）/ 目标等级 / 目标企业 / 企业名与类型
    ↓
[工具调用] → update_user_level / update_user_company / manage_company
    ↓
[服务层判定] PersonnelService（按操作人等级 + 规则，fail-closed）
    ├── 通过 → 执行写库 + 留痕
    └── 拒绝 → 返回明确拒绝原因 + 留痕
    ↓
[结果反馈] → 告知执行结果；被拒时说明所需等级
```

### 3.4 权限映射

> 口径来源：`emily-core/emily_core/services/personnel_service.py`（服务层唯一判定点）+ 缺口清单决策 D3 / D6 / D8 / D8-b / Q11。

| 操作 | 工具 | 授权口径 |
|------|------|----------|
| 人员等级调整 | `update_user_level` | 服务层 `_can_adjust_level`：L6 任意（1–6）；L5 最高 L4；L4 最高 L3；L3 仅可调至低于自身；L2 / L1 不可；无操作人或取不到等级一律拒绝 |
| 人员企业归属调整 | `update_user_company` | 服务层 `_can_adjust_company`：L4+ 任意；L3 仅限本企业人员；L2 / L1 不可；fail-closed |
| 企业新增 / 删除 | `manage_company` | 服务层：**仅 L4 及以上**；删除前校验该企业无在职归属人员；fail-closed |
| 人员 / 企业清单查询 | 不属本 SOP | 走 SOP-005-QRY（`query_data`），只读 |

**已知取舍**：本 SOP 准入为 L3，而「企业增删」的业务口径是 L4+，因此 **L3 用户可见 `manage_company` 但调用会被服务层拒绝**（`权限不足：仅 L4 及以上可新增企业`）。这是为少动工具档位而接受的粗筛；如需"看不见"，可另立一份 L4 准入的企业维护 SOP 承载该工具。

### 3.5 留痕要求

- 全部动作经 `audit.record_action`（唯一挂载点）留痕，含操作人、目标、结果、拒绝原因。
- 被拒动作同样留痕（不得静默丢弃）。
