# 全景节点计划导入 — 业务流服务手册

> **适用对象**：AI Agent（Emily Agent，负责任务执行与语义理解）
> **允许用户角色**：`admin` / `project_owner`
> **业务目的**：将以 Excel 格式提供的地产项目全生命周期节点计划导入系统，自动生成全景节点清单及每个节点的独立实例文档
> **文档风格**：地产企业内业文件管理规范，简洁明确，可执行

## 2. 意图识别标准

### 2.1 触发此业务流的语义特征

**必须条件（满足其一即可）**：

- 用户上传或指定了一个 Excel 文件（.xlsx），并表达了将其作为项目节点计划导入的意图
- 用户要求"解析这份项目计划"、"导入节点计划"、"根据这份 Excel 生成全景节点"、"把项目计划转成节点文档"
- 用户发送了类似"这是 XX 项目的全生命周期计划，帮我导入"的消息

**否定条件（即使有上述关键词，也不应判定为此业务流）**：

- 用户只是询问"项目有哪些节点"、"XX 节点是什么状态" → 属于查询，走 QRY 流（SOP-005-QRY）
- 用户要求"修改某个节点的完成标准" → 属于状态机管理，走 SOP-011-SYS
- 用户要求"新建一个节点模板"或"起草新的 SOP" → 走 SOP-000-SYS

### 2.2 示例对话

**应触发此业务流**：

> 「这是我们生态城 26#地的全生命周期计划，帮我按 V4 模板拆成节点实例」

> 「H:\工作经验\全生命周期计划\生态城26#地.xlsx，帮我解析导入」

> 「这份 Excel 是项目甲方的节点计划，帮我生成全景节点索引和每个节点的实例文档」

**不应触发此业务流**：

> 「景观工程节点现在是什么状态？」→ 查询，走 SOP-005-QRY
> 「帮我把景观设计节点的完成标准改一下」→ 状态机管理，走 SOP-011-SYS
> 「全景节点图长什么样？」→ 查询，走 SOP-005-QRY

## 3. 业务流描述

### 3.1 产出物（不写入数据库表，产出为 Markdown 文件）

> **说明**：本 SOP 的产出物是文件系统中的 Markdown 文档，不直接写入数据库。产出物分三类：
> ① 全景节点索引（`.md`）— 项目节点树总览，供用户交互主界面使用
> ② 节点实例文档（每节点一个 `.md`）— 按目录层级存放，套用 V4 模板
> ③ 适配度报告（`.md`）— 对照 V4 模板，分析本次真实数据与模板的适配情况

| 产出物    | 格式                       | 说明                                                                |
| ------ | ------------------------ | ----------------------------------------------------------------- |
| 全景节点索引 | `{项目名}-全景节点索引.md`        | 阶段分块 + 节点 WBS 缩进树 + Mermaid 深色背景树状图 + 关键里程碑表 + 数据质量检查             |
| 节点实例   | `{阶段码}/{节点编号}-{节点名称}.md` | 每个节点独立一个文件，套用 V4 模板：继承关系表 + 继承字段清单 + 新增字段 + 业务表定义 + 节点状态流转 + 关联规则 |
| 适配度报告  | `{项目名}-模板适配度报告.md`       | V4 模板字段覆盖率、缺失字段、新增需求、模板改进建议                                       |

### 3.2 使用的系统工具 / API

| 工具                                  | 功能                            | 调用场景                               |
| ----------------------------------- | ----------------------------- | ---------------------------------- |
| `read_excel`（Agent 系统能力）            | 读取 Excel 文件内容，识别 sheet 结构和列映射 | 导入流程第一步：读取文件，理解数据结构                |
| `文件写入`（系统基础能力）                      | 将生成的 Markdown 文档写入指定目录        | 生成全景索引、节点实例、适配度报告后写入               |
| `parse_nodes.py`（辅助脚本）              | 确定性操作：生成 Mermaid 图、建目录、格式化输出  | Agent 完成语义判定后，调用脚本执行机械性输出操作        |
| `inspect_existing_tables`（数据库表结构检查） | 读取当前 `models.py` 的表全景         | 如需写入 DB，先检查 `sm_nodes` 等表是否存在且字段匹配 |

### 3.3 处理流程

```
用户上传/指定 Excel 文件 + 表达导入意图
    ↓
[文件读取] → Agent 读取 Excel：
  ① 识别所有 sheet
  ② 区分"签确版"sheet（含阶段条线 + 关键里程碑序号）和"节点计划"sheet（含完整 WBS 树）
  ③ 识别列映射：阶段列 / 级别列 / 节点名称列 / 完成标准列 / 责任部门列 / 时间列
    ↓
[语义理解] → Agent 理解数据结构：
  ① 阶段识别：从签确版或节点名中识别阶段分类（以文件实际内容为准，不强制映射标准阶段）
  ② WBS 层级：根据"一级/二级/…/八级"或缩进或序号格式判定节点间的父子关系
  ③ 关键节点：标记一级节点（和签确版中标注的节点）为关键节点
  ④ 时间解析：识别日期格式（datetime / Excel 序列数 / 纯文本），统一为 YYYY-MM-DD
    ↓
[节点编号生成] → 按规则自动编号：
  ① 阶段码映射：以 Excel 实际阶段名为准，优先匹配标准码（前期→QQ / 设计→SJ / 成本→CB / 工程→SG / 营销→YX / 交付→JF）
  ② 格式：阶段码-序号（如 QQ-001、SG-015）
  ③ 序号按阶段内 WBS 顺序递增
    ↓
[依赖关系确认] → **关键步骤，不可跳过**：
  ① 先向用户询问：「文件中未显式标注节点间依赖关系。我已根据 WBS 层级和阶段顺序做了初步推断。
     请确认：哪些节点之间有明确的前后依赖？例如"XX 节点完成前，YY 节点不能启动"。」
  ② 用户提供的显式依赖 → 标记为「已确认」，Mermaid 图中用**实线**
  ③ WBS 层级推断的依赖 → 标记为「推断」，Mermaid 图中用**虚线**（标注推断依据）
  ④ 阶段间推断的依赖 → 同上
  ⑤ 用户未回应或无法确认的 → 生成《缺失依赖清单》，待人工逐条处理
    ↓
[产出物生成] → 分四步生成文档：
  【第一步：全景节点索引】
    a. 阶段分块（用 ## 标题），每块下列出该阶段节点缩进树
    b. 末尾附关键里程碑表 + 数据质量检查（缺失字段数、异常数据条目）
    c. 依赖关系在索引中以文字描述（上/下游节点编号），不做大段依赖表格
  【第二步：Mermaid 流程图（单独文件）】
    a. 独立存放为 {项目名}-全景节点图.mmd
    b. 深色背景色板、阶段用 subgraph 包裹、关键节点用粗边框
    c. 已确认的依赖 → 实线；Agent 推断的依赖 → 虚线并标注推断依据
    d. 仅展示到三级节点；节点数 > 50 时只绘一级+二级
  【第三步：节点实例文档】
    a. 为每个节点生成独立 .md 文件
    b. 目录结构：{阶段码}/{节点编号}-{节点名称}.md
    c. 套用 V4 模板（参考 emily-data/baseknowledge/全景节点参考文档.md）
    d. 依赖异常节点在实例中显式标注 ⚠️ 标记
  【第四步：适配度报告】
    a. 统计 V4 模板字段在本次数据中的覆盖率
    b. 列出本次数据中有但 V4 模板中无的字段（如：双向考核部门等 Excel 特有列）
    c. 列出 V4 模板中定义了但本次数据无法填充的字段（如：监理单位、变更与作废机制等）
    d. 提出 V4 模板改进建议（哪些字段应该降级或新增）
    ↓
[输出目录确认] → 默认输出路径：
  {Excel同目录}/../解析结果/{项目名}/
  ├── {项目名}-全景节点索引.md
  ├── {项目名}-模板适配度报告.md
  ├── QQ/   （前期阶段节点实例）
  ├── SJ/   （设计阶段节点实例）
  ├── CB/   （成本阶段节点实例）
  ├── SG/   （工程阶段节点实例）
  ├── YX/   （营销阶段节点实例）
  └── JF/   （交付阶段节点实例）
    ↓
[展示与确认] → 向用户展示：
  ① 全景节点索引的概要（阶段数、节点总数、关键节点数）
  ② 询问是否需要写入数据库（--write 模式）
  ③ 如用户确认写 DB，调用 parse_nodes.py --write 执行
    ↓
[返回确认信息] → 产出物清单 + 文件路径 + 数据质量摘要
```

## 4. 输出成果要求

### 4.1 字段分级与约束

| 字段                               | 级别    | 约束                                            |
| -------------------------------- | ----- | --------------------------------------------- |
| **节点编号**（node\_id）               | 🔴 必有 | 格式：`阶段码-序号`，如 `QQ-001`、`SG-JG-015`。必须在所属阶段内唯一 |
| **节点名称**（node\_name）             | 🔴 必有 | 来自 Excel 原值，清理括号内阶段标注（如"（3月底前取得土地）"）          |
| **完成标准**（criteria）               | 🔴 必有 | 来自 Excel"完成标准"列，自由文本。若 Excel 中为空则标注"【缺失】"     |
| **责任部门**（owner）                  | 🟡 应有 | 来自 Excel"主办部门"列。若缺失则留空，但在数据质量检查中计数            |
| **计划级别**（plan\_level）            | 🔴 必有 | 一级/二级。一级为集团管控里程碑，二级为项目自管节点                    |
| **是否关键节点**（is\_milestone）        | 🟡 应有 | 一级节点默认 true；二级\~三级节点默认 true；更深层默认 false       |
| **计划开始时间**（planned\_start\_date） | 🟡 应有 | 格式统一为 YYYY-MM-DD。Excel 序列数需自动转换为日期            |
| **计划结束时间**（planned\_end\_date）   | 🟡 应有 | 同上                                            |
| **上游节点**（parent\_name）           | 🟡 应有 | 从 WBS 层级推导：每个节点的上游是其 WBS 上一级的节点               |
| **节点成果列表**（deliverables）         | 🟢 如有 | 如 Excel 中有成果物描述则提取；V4 模板的 L0 定义字段             |
| **前置条件列表**（preconditions）        | 🟢 如有 | 从依赖推断中自动填充                                    |
| **监理单位**（supervisor\_unit）       | 🟢 如有 | 工程阶段节点（SG）可能有，设计/前期节点通常无                      |
| **变更与作废机制**                      | 🟢 如有 | V4 模板定义了完整机制，本次导入暂不填充（由后续实操中补充）               |

### 4.2 格式要求

- **全景索引**：Mermaid 图使用 `%%{init: {'theme': 'dark'}}%%` 或等效深色配置，阶段用 `subgraph` 包裹，关键节点用粗边框样式
- **节点实例**：严格按 V4 模板的章节顺序（继承关系→继承字段→新增字段→业务表定义→状态流转→关联规则→变更与作废）
- **节点实例文件名**：`{节点编号}-{节点名称}.md`，如 `QQ-001-土拓.md`，中文允许，不包含特殊字符
- **目录层级**：`{阶段码}/` 下直接存放该阶段所有节点实例，不创建二级子目录
- **适配度报告**：表格形式呈现 V4 模板字段 vs 实际数据字段的对比矩阵

### 4.3 回执格式

```
📋 全景节点导入完成
──────────────
项目名称：{从 Excel 文件名或内容推断}
节点总数：{N}（一级：{n1}，二级：{n2}）
关键节点：{n3}
识别阶段：{阶段列表}
推断依赖：{d} 条
──────────────
产出物：
  · 全景索引：{路径}/{项目名}-全景节点索引.md
  · 节点实例：{路径}/{阶段码}/ 下 {N} 个 .md 文件
  · 适配度报告：{路径}/{项目名}-模板适配度报告.md
──────────────
[数据质量]
  · 完成标准缺失：{c} 个节点
  · 责任部门缺失：{o} 个节点
  · 计划时间缺失：{t} 个节点
  · 名称重复：{d} 处
──────────────
[下一步]
  · 查看全景索引确认节点树
  · 确认无误后执行：uv run python scripts/parse_nodes.py --file "{原Excel路径}" --write
  · 写入后可进入 sm_nodes 表查看
```

## 5. 异常处理原则

### 5.1 信息缺失类

| 异常场景                                       | 处理建议                                                                     |
| ------------------------------------------ | ------------------------------------------------------------------------ |
| **Excel 文件无法读取**（`file_read_error`）        | 向用户确认文件路径是否正确、文件是否被其他程序占用。提示：「文件 {路径} 无法读取，请确认路径正确且文件未被其他程序打开」           |
| **文件只有一张 sheet，缺少签确版**（`no_signoff_sheet`） | 不强制要求签确版。从节点计划 sheet 自身推断阶段分类和关键里程碑。在适配度报告中注明"本次无签确版 sheet，阶段分类由解析器自动推断" |
| **节点缺少完成标准**（`missing_criteria`）           | 不阻断流程。在节点实例中标注"【缺失】"，在全景索引数据质量中计数，在适配度报告中说明                              |
| **无法识别阶段分类**（`unknown_stage`）              | 使用 WBS 一级节点的名称前缀作为阶段码。如一级节点名为"土拓"，阶段码为"TT"。在适配度报告中注明使用非标准阶段码             |

### 5.2 信息质量类

| 异常场景                                      | 处理建议                                                                                                 |
| ----------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| **Excel 列名不标准**（`nonstandard_columns`）    | Agent 需通过语义理解推断列含义（如"节点名称"列可能叫"计划节点名称"、"工作项"、"任务名称"等）。推断成功的列名映射写入适配度报告的"列映射推断"章节。对无法确定的列，跳过并在报告中标注   |
| **日期格式混乱**（`mixed_date_formats`）          | 尝试按优先级解析：① datetime 对象 → ② Excel 序列数（>30000 的数字视为序列数）→ ③ YYYY-MM-DD 文本 → ④ 其他格式文本。解析失败的记录为空，在质量检查中计数 |
| **WBS 层级断裂**（`broken_wbs_hierarchy`）      | 如某层级中间缺失（如直接从三级跳到五级），Agent 应补充虚拟父节点（node\_name="【推断的父节点】"），使其层级连续。在报告中注明补充的虚拟节点数量和位置                 |
| **节点名称重复**（`duplicate_names`）             | 不重命名。在全景索引和报告中保留原样并标注警告。由人工决定是否需要区分                                                                  |
| **签确版的里程碑名称全为空**（`empty_milestone_names`） | 用阶段名 + "里程碑" + 序号自动生成名称（如"前期里程碑1"），在报告中说明签确版数据不完整                                                    |

### 5.3 系统异常类

| 异常场景                                     | 处理建议                                                                                 |
| ---------------------------------------- | ------------------------------------------------------------------------------------ |
| **输出目录创建失败**（`output_dir_create_failed`） | 检查目录权限。回退到当前工作目录下的临时文件夹                                                              |
| **节点实例文件写入失败**（`instance_write_failed`）  | 跳过该节点，记录到错误列表。全部处理完后向用户列出失败节点清单                                                      |
| **Mermaid 图生成失败**（`mermaid_gen_failed`）  | 全景索引中保留 Mermaid 图的占位符和注释说明，先输出其他内容。Agent 检查节点数是否超过 Mermaid 复杂度上限（约 50 个节点），超过则只绘一级节点 |

### 5.4 异常处理总原则

1. **宁慢不错**：列映射不确定时优先向用户确认，不盲目推断
2. **有据可查**：所有自动推断的决定（列映射、阶段分类、节点编号规则）写入适配度报告，留下追溯
3. **不替用户做判断**：用户提供的数据中如有明显矛盾（如日期顺序异常），标注警告但不修改原始数据
4. **不阻断流程**：单个节点的解析失败不阻断整体导入，在报告中汇总失败原因

## 6. 建议补充内容（系统增强方向）

> 以下内容当前系统尚未完全实现，记录在此作为后续优化参考，不影响当前业务流执行。

### 6.1 智能列映射学习

**问题描述**：当前每次导入都需要 Agent 重新理解 Excel 列的语义，不同项目/不同人写的 Excel 列名差异大。

**改进方向**：

1. 建立一个"列名同义词库"（如"节点名称" ↔ "计划节点名称" ↔ "任务名称" ↔ "工作项"），Agent 按同义词库匹配
2. 每次成功导入后将列名映射写入同义词库，逐渐积累

### 6.2 增量导入

**问题描述**：当前只有全量导入（--reset 清空重建），缺少对已有节点树的增量更新。

**改进方向**：

1. 解析器增加 `--merge` 模式：对比 Excel 与 sm\_nodes 表的节点编号，新增的 insert，变更的 update，删除的标记 is\_deleted
2. 保留人工对某些节点的手动修改（如额外添加的完成标准细化）
