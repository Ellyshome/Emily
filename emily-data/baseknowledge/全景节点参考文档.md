## 1. 节点模板继承体系

全景节点采用三层继承（L0 → L1 → L2）。每一层的定义文件在 `需求文件/全景节点图-梳理版V4/` 下。

### 1.1 L0：独立节点基础模板（共同基类）

定义文件：`单节点结构-手写需求.md`

**状态模型**：3+1 时态（未启动 / 运作中 / 完工归档 + 未追踪）。阻塞、延期记录在节点日志中，不纳入状态机流转。

**时态流转**：
```
未启动 → 运作中 → 完工归档
```
特殊状态「未追踪」需手动切换。

**核心原则**：所有状态变更须负责人手动确认，系统只做自动提醒。

#### L0 固有数据段（必含字段清单）

| # | 字段 | 类型 | 级别 | 从 Excel 导入时的数据来源 |
|----|------|------|:----:|---------------------------|
| 1 | 节点编号 | 字符串 | 🔴 必有 | 解析器自动生成（阶段码-序号） |
| 2 | 节点名称 | 字符串 | 🔴 必有 | Excel "计划节点名称"列 |
| 3 | 完成标准 | 自由文本 | 🔴 必有 | Excel "完成标准"列。若为空则标注「【待补充】」 |
| 4 | 计划级别 | 枚举（一级/二级） | 🔴 必有 | WBS 层级推断：一级=集团管控里程碑，二级=项目自管节点 |
| 5 | 是否关键节点 | 布尔 | 🟡 应有 | WBS ≤ 2 默认标记为 true |
| 6 | 计划开启时间 | 日期 YYYY-MM-DD | 🟡 应有 | Excel 开始时间列 |
| 7 | 计划结束时间 | 日期 YYYY-MM-DD | 🟡 应有 | Excel 结束时间列 |
| 8 | 实际启动时间 | 日期 | 🟢 如有 | 实操数据，导入时无 |
| 9 | 实际结束时间 | 日期 | 🟢 如有 | 实操数据，导入时无 |
| 10 | 状态最后更新时间 | 日期 | 🟢 如有 | 实操数据，导入时无 |
| 11 | 责任部门 | FK→建设单位部门 | 🟡 应有 | Excel "主办部门"列 |
| 12 | 完工确认岗位 | 字符串 | 🟢 如有 | 需业务指定，导入时无 |
| 13 | 前置条件列表 | 列表 | 🟡 应有 | 从依赖推断自动生成 |
| 14 | 节点成果列表 | 列表 | 🟢 如有 | Excel 中部分节点包含，未统一 |
| 15 | 节点日志 | 文本 | 🟢 如有 | 实操数据，导入时无 |
| 16 | 节点待解决卡点 | 文本 | 🟢 如有 | 实操数据，导入时无 |
| 17 | 通用文档表单索引 | 列表 | 🟢 如有 | 实操数据，导入时无 |

**表单审批流-基类**（所有业务表单继承）：
- 表单号（KEY）/ 提交时间 / 提交人 / 生效时间 / 批准人 / 审批意见 / 审批回复
- 作废：作废时间 / 作废批准人 / 作废原因 / 替代表编号
- 会签是审批前的内部确认步骤，不反映在状态机中
- 录入约束：节点完工归档后仅备注字段可追加

**异常处理**：三级升级（录入人自查 → 负责人判定 → 管理员介入）

### 1.2 L1：阶段状态机模板

继承 L0，按阶段类型追加专属字段。四种标准 L1 模板：

| L1 模板 | 追加的专属字段 | 阶段码 | 典型阶段名 |
|---------|---------------|:------:|-----------|
| 设计阶段 | 承包单位 / 设计部经理 / 甘特图 / 成果清单·施工图 / 设计文档索引 | SJ | 设计 |
| 成本招采阶段 | 测算咨询单位 / 设计部经理 / 成果清单·成本测算 | CB | 成本 / 招采 |
| 工程阶段 | 承包+监理+分包 / 工程部经理 / 甘特图 / 成果清单·工程完工 / 文档库 | SG | 工程 / 施工 |
| 通用（无匹配时） | 节点日志 / 节点待解决卡点 | XX | 前期 / 营销 / 交付 等 |

> **匹配规则**：按阶段名优先匹配。如 "设计"→SJ，"成本"→CB，"工程"→SG。无法匹配的（如"前期"、"营销"、"交付"）使用通用模板。**不以固定模板限制阶段分类**，以实际文件阶段名为准。

### 1.3 L2：节点实例

继承 L0 + L1，追加该节点专有的业务表定义和关联规则。参考实例：
- `节点实例-景观设计.md`：设计阶段实例，含地块分区+阶段N:N+评审会审批
- `节点实例-景观工程.md`：工程阶段实例，含四表（分解/计划/实现/确认）+关联规则+变更与作废

导入时生成的每个节点实例文件，按以下模板章节顺序：
```
# {节点名称}
## 继承关系（L0/L1/L2 三层表格）
## 继承字段（字段名 | 来源层级 | 本节点取值 的完整表格）
## 新增字段（如有）
## 业务表定义（工程/设计节点适用）
## 节点状态流转
## 关联规则（依赖关系 + 人员/时间/录入约束）
## 变更记录
```

## 2. 阶段映射规则

以传入 Excel 的实际阶段名为准，优先匹配标准阶段码。匹配规则：**子串匹配**（阶段名中包含标准关键词即匹配）。

| 关键词 | 阶段码 | 排序 |
|--------|:------:|:----:|
| 前期 | QQ | 1 |
| 设计 | SJ | 2 |
| 成本 / 招采 | CB | 3 |
| 工程 / 施工 | SG | 4 |
| 营销 / 市场 | YX | 5 |
| 交付 / 验收 | JF | 6 |

> 无法匹配的阶段名，使用缩写作为阶段码（取各字首字母）。如"投资拓展"→"TT"。在适配度报告中注明。

## 3. 节点编号生成规则

- 格式：`阶段码-序号`，如 `QQ-001`、`SG-JG-015`
- 序号在阶段内递增，从 001 开始
- 如果节点名称能匹配标准节点编号（如"景观设计"→SJ-JG），优先使用标准编号
- 二级及以下节点编号继承父节点前缀（如 `QQ-001` 的子节点为 `QQ-002`、`QQ-003`...）

## 4. 依赖关系约定

### 4.1 Excel 数据中可能缺失依赖关系

传入的 Excel 文件通常**不显式标注节点间依赖**。依赖关系需要通过以下方式获取：

| 优先级 | 方式 | 说明 |
|:------:|------|------|
| 1 | 用户显式说明 | **最优**。SOP 应主动询问：「文件中未标明节点间依赖关系，请说明：哪些节点需要等待其他节点完成后才能启动？」 |
| 2 | WBS 层级推断 | 同一父节点下的兄弟节点，默认后者弱依赖前者（weight=0.5, required=false） |
| 3 | 阶段间推断 | 后一阶段的首节点强依赖前一阶段的末节点（weight=1.0, required=true） |
| 4 | 标注为异常 | 若无法通过以上方式确定，标注为「依赖数据缺失」，待人工逐条处理 |

### 4.2 依赖数据缺失的处理

**这是 SOP-012 的核心职责之一**。当依赖关系无法自动推断时：

1. **不静默跳过**。在全景索引的数据质量章节中显式列出所有依赖缺失的节点
2. **生成待处理清单**。输出一个独立的 `{项目名}-缺失依赖清单.md`，逐条列出：
   - 节点编号 / 节点名称
   - 缺失类型（上游缺失 / 下游缺失）
   - 建议（可手动编辑填入依赖节点编号后重新导入）
3. **引导用户完善**。SOP 结束时在回执中提示：
   > 「检测到 {N} 个节点的依赖关系无法自动推断，已生成缺失依赖清单。请确认并补充后告知我，我将更新节点数据。」

### 4.3 依赖数据异常标记

对于确实无法确定的依赖关系，在节点实例中标记：
```
> ⚠️ **依赖数据异常**：本节点的上游依赖未在原始文件中标明，需人工确认后补充。
> 当前暂标记为「无上游依赖」。如发现有遗漏，请在变更记录中补充。
```

## 5. 产出物规范

### 5.1 全景节点索引

文件名：`{项目名}-全景节点索引.md`

章节结构：
1. 头部统计（节点总数 / 关键节点数 / 阶段列表 / 依赖数）
2. 阶段概览（表格）
3. 节点树（按阶段分块的缩进列表，每节点含：编号、名称、关键节点🔑标记、责任部门、计划时间）
4. 关键里程碑表
5. 数据质量检查（缺失字段数 / 异常数据条目）
6. 缺失依赖清单（如有）
7. 对 Mermaid 流程图的引用链接

> **Mermaid 图单独存放**：全景索引中的 Mermaid 图另存为独立文件 `{项目名}-全景节点图.mmd`，在全景索引中嵌入引用（如 `![全景节点流程图]({项目名}-全景节点图.mmd)` 或直接文本引用），不将大段 Mermaid 代码塞入索引文件中，避免索引文件过长。

### 5.2 Mermaid 流程图

文件名：`{项目名}-全景节点图.mmd`

**独立存放，不嵌入索引文件。** 包含以下内容：

```mermaid
%%{init: {'theme': 'dark', 'themeVariables': {...}}}%%
flowchart TB
    %% 样式定义
    classDef stageBox fill:#1a1a1a,stroke:#444444,stroke-width:2px,rx:6
    classDef milestone fill:#4a3728,stroke:#ffb74d,stroke-width:2px
    classDef normal fill:#2d2d2d,stroke:#555555,stroke-width:1px

    %% 阶段 subgraph + 节点定义
    %% ...

    %% 连线
```

**连线规则**：

| 连线类型 | 线型 | 适用场景 | 示例 |
|:--|:--|:--|:--|
| **实线** | `-->` | 已明确的前后关系。包括：用户显式指定的依赖、WBS 父子关系（子节点实线指向父节点）、签确版中标注的关键节点间顺序 | `QQ-002 --> QQ-001` |
| **虚线** | `-.-` | Agent 推断但未确认的关系。包括：阶段内顺序推断的弱依赖、阶段间推断的依赖、跨阶段但原始文件未标注的关系 | `SJ-001 -.-> QQ-101` |

推断关系的虚线旁应标注推断依据：
```
SJ-001 -.->|"推断：阶段间依赖"| QQ-101
```

> **Agent 职责**：在生成 Mermaid 图时，Agent 必须对每条边的类型做出判断——来自原始文件显式标注 → 实线；来自 WBS 推断 → 虚线并标注推断依据。所有推断的边在数据质量章节中汇总列出，供用户审核确认。用户确认后的虚线可升级为实线。

仅展示到三级节点以保证可读性。节点数超过 50 个时，只绘一级 + 二级节点及关键依赖。

### 5.3 节点实例文件

目录结构：按阶段码分目，每个节点一个 .md 文件。
```
{输出目录}/
├── {项目名}-全景节点索引.md
├── {项目名}-全景节点图.mmd          ← 独立存放，不在索引中内嵌
├── {项目名}-模板适配度报告.md
├── {项目名}-缺失依赖清单.md        ← 如有依赖缺失，必须生成
├── QQ/  → QQ-001-节点名.md ...
├── SJ/  → SJ-001-节点名.md ...
├── CB/  → CB-001-节点名.md ...
├── SG/  → SG-001-节点名.md ...
├── YX/  → YX-001-节点名.md ...
└── JF/  → JF-001-节点名.md ...
```

节点实例文件套用 V4 模板（见 §1.3），必含「继承字段」清单表，字段取值来源标注清晰。

### 5.4 适配度报告

文件名：`{项目名}-模板适配度报告.md`

至少包含：
- V4 模板字段覆盖率矩阵（字段名 / 本次有值 / 来源或缺失原因）
- Excel 特有字段（不需要纳入模板的列及原因）
- 数据质量统计（缺失数量 + 占比）
- V4 模板改进建议
