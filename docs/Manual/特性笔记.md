

# 工具管理
所有的工具在在toolmanager的管理下，可手动测试，AI友好。

### mitmproxy代理
用于APIkey的抓包工具，用来观察session调用API的实际输出内容

### 全景节点模板
全景节点配置模板，可用于支持用户创建节点做参考。也能用于根据文件建立节点

### rag数据库
使用TEI（Hugging Face 推出的高性能向量模型推理服务工具，行业标准 Embedding 部署方案）容器部署 BGE-m3，实现

## 核心架构

### 双容器架构
emily_agent 薄插件（~100行，仅做消息去重+标准化+HTTP转发+SSE监听）与 emily-core FastAPI 独立容器分离部署。业务核 `emily_core` 对 AstrBot 零 import，可独立开发、独立部署、独立扩展。

### Session主线 + WorkItem分解
SessionAgent 是每条消息的唯一 LLM 入口，单次 chat_json 调用完成意图识别，将一条用户消息分解为 0..N 个 WorkItem 执行单元，天然支持复合请求（如"查上周的变更单，再帮我约个协调会"）。每个会话持有独立 SessionAgent 实例，串行锁 + TTL 自动回收。

### 4节点 PipelineBUS
每个 WorkItem 按固定顺序流经 4 个总线节点：意图注入 → 规划 → 执行 → 总结。节点不可跳过，Hook 在节点前后声明式挂载，形成可审计、可追溯的完整执行链。

## 安全与治理

### 声明式 Hook 系统
4 类 Hook（Auth/Audit/Progress/Archive）通过 `hook_config.json` 声明式注册挂载点，三态决策 ALLOW/WARN/BLOCK。deny always wins——任一 before Hook 返回 BLOCK 则管道立即终止，异常视为 BLOCK。新增横切关注点无需改 Python 代码。

### 6级权限体系
访客(0) → 参建执行(1) → 参建管理(2) → 建设主管(3) → 管理员(4) → 系统管理员(5)。支持 SOP 白名单、单表 DB 读写权限、info 级别范围限制、granted/denied 代码覆盖。权限快照在会话创建时注入且只读，避免 AI 自我提权。

### Guardian 并发审计
步骤执行与 Guardian LLM 审核作为并发 asyncio Task 运行——执行先走、审计陪跑。Guardian 通过 GuardianNote 标记问题但不阻塞管道，结果在回复阶段汇总呈现。

## 智能执行

### M14 结构化输出优先
当 SOP/Skill 命中时，LLM 仅用于 NL→结构化参数提取（chat_json），框架直接调用 `BusinessFlowTool.handler(params)` 执行业务逻辑，完全绕过 ReAct function-calling，降延迟、减幻觉、省 token。ReAct 仅作为未匹配请求的兜底路径。

### 三梯次规划降级
规划器按三梯次自动降级：优先读取 Skill YAML 声明的步骤定义 → LLM 动态生成执行计划 → 硬编码 3 步通用兜底计划。系统自然降级，无 mock/real 模式切换，根据可用资源自适应。

### KnowledgeInjector + LRU 预算
每个 WorkItem 按需增量加载所需知识（SOP 全文、工具 schema、上下文），LRU 驱逐控制总上下文估计值 <32K tokens。不提前全量塞入 system prompt，避免大文档撑爆上下文窗口。

## 运维与可观测性

### 分布式调度引擎
基于 PostgreSQL advisory lock（`pg_try_advisory_lock`）的互斥锁 + croniter CRON 调度（北京时区解释）。多实例部署时自动互斥，内置定期节点创建 handler 和幂等性保障。支持 CRON 和 ONCE 两种作业类型。

### Session Markdown 存档
每轮对话增量写入人类可读的 Markdown 文件（命名格式：`日期_人员_会话ID前8位.md`），包含用户消息、意图识别细节、各节点执行记录、系统回复及 Guardian 警告。由 ArchiveHook 驱动，写入失败不阻断主流程。

### 工具一致性检查（V1-V13）
启动时多维度校验工具生态：工具 schema 与注册匹配、Skill YAML 引用有效（工具名 + 步骤参数名）、DB tool_registry 表与内存注册同步。支持独立脚本执行，退出码区分 fatal/warning，可集成 CI。

### LLM 流量代理
独立 mitmproxy 容器拦截 emily-core→DeepSeek 全部 HTTPS 流量。自定义 trace_addon 插件双格式输出——JSONL（机器可解析，逐行完整 request/response）+ Markdown（人类可读，含 reasoning_content 思维链），API key 自动脱敏。开关通过环境变量控制，无需改代码。

### 邮件集成
SMTP + IMAP 双 Provider 基于抽象基类 `EmailProvider`（send/fetch_inbox/fetch_orders/mark_read/is_available），每次调用独立建连不持有连接状态，不存储凭证，支持 HTML + 附件发送和主题过滤收取。

## 会话与上下文管理

### Session 池管理器
以 conversation_id 为 key 的活跃会话哈希表，TTL 后台自动过期清理（默认 10 分钟无消息）。同会话用 asyncio.Lock 串行执行、不同会话并发处理。新消息命中则直接路由，未命中则 SessionFactory 创建。

### 快速通道短响应
问候/感谢/告别等高频短消息硬编码匹配，毫秒级直接回复，完全跳过 LLM 调用。减少 token 消耗的同时提升响应速度。

### 对话历史自动压缩
message_history 超过 40 条时将最旧 20 条异步交给 LLM 压缩为 300 字以内摘要，插入对话历史头部。LLM 不可用时直接丢弃旧消息（fail-open），确保上下文窗口永不溢出。

### 会话上下文热更新
SessionContext 字段分三类：冻结字段（身份标识不可变）、可热更新字段（权限/工具/RAG/元认知）、运行时自维护字段（记忆/对话历史）。每 10 轮对话自动检测并增量刷新权限和项目上下文，20+ 字段细粒度热更新。

### 用户长期记忆
每个用户维护独立的长期工作记忆 Markdown 文件。Agent 通过工具写入（如"每天检查景观设计进度"），每次对话自动加载注入 prompt，每人最多 50 条，保持轻量。

## 认知与知识体系

### 元认知三书
WorldBook（项目世界书，七层结构化 JSON，偏差检测驱动增量更新）+ RuleBook（全局业务规则，从文件加载）+ SystemDescription（代码自描述的 ORM/权限/文件模型三域认知，SHA256 hash 比对检测代码变更）。纯数据驱动，无需 LLM。

### 四层项目初始化检查
23 项必备项分 T1-T4 四层模型：T1(7项基础配置) + T2(6项合作协议) + T3(5项可运转条件) + T4(5项充分运转条件)。每项有明确 DB 判定条件，LLM 零依赖，世界书的 initialization_tier 与其联动。

### Skill YAML 声明式技能
技能由三段式 `.skill.yaml` 文件声明——instructions（指令）、tools（白名单）、steps（执行步骤序列）。ParamExtractor 从 user_input/prev_step/fixed/context 四源解析参数，SessionContext 的 available_skills 联动注入 prompt。

## 进化与反馈闭环

### 自动进化闭环
完整五阶段闭环：洞察生成（周期性复盘，含健康评分/SOP命中率/异常标记）→ 规则归纳（从多日洞察归纳可复用规则）→ 补丁生成（配置文件变更）→ 审批应用 → 验证回滚（保留原始快照）。

### 晨报系统
定时生成个性化晨报推送：汇总节点进度、待办任务、昨日动态、截止临近项。管理员额外获得系统进化摘要（健康评分、待审批补丁）。

### 用户反馈信号检测
从交互模式隐式提取满意度信号——重复请求识别（repeat_request）、显式纠正（explicit_correction）、正向反馈（positive）、放弃（abandonment）等，写入 UserFeedbackSignal 表供进化分析，无需用户主动打分。

## 日志与可追踪性

### Agent 三层追踪日志
AgentReasoningLog（执行摘要：迭代次数、路由决策、结果）+ LLMInteractionLog（每次 LLM 调用的 token/延迟/模型/响应）+ ToolCallLog（工具名、参数、成功/失败、耗时）。全部 fail-open 不阻塞主流程。

### 进化版 LLM 交互日志
独立 evolution_llm_interaction_logs 表记录每次 LLM 调用的完整链路：pipeline_run_id 串联、call_category（intent/planning/execution/guardian/compression 等）、完整响应体及 reasoning_content（R1 类模型思维链）。

### Session 生命周期日志
追踪 Session 创建/刷新/压缩/归档/终止全生命周期事件，支持会话级回放和异常排查。

### 事件流水日志
追加模式 Markdown 项目日志文件，格式 `[日期] 姓名 操作摘要`。覆盖事件确认、任务/会议/文件创建、守护异常、启动体检、待解决问题处理等所有系统事件。

### 待解决问题清单
守护 Agent 自动维护 Markdown 格式待解决问题清单（编号 PND-YYYYMMDD-NNNN），分"待处理"和"已处理"区域，自动写入、标记已处理、列表查询。

## 基础设施与自动化

### 自动数据库迁移
启动时自动检查 ORM 定义与已有表的列差异，ALTER TABLE ADD COLUMN 补齐缺失列，同时确保 pgvector 扩展已安装。每次启动幂等执行，返回新增列清单用于启动报告。

### 冷启动邮件通知
系统启动完成自动向管理员邮箱发送详细报告：依赖连通性（DB/LLM/RAG/SMTP）、降级警告、系统快照（用户/项目/事件/节点数）、配置概要、基座工具就绪、数据库迁移详情、停机时长统计。

### 运维看板 API
只读运维 API：容器运行状态（Docker Engine API）、Session 池内存快照、全景节点列表、管控文件列表、人员列表、会话最近消息、IM 账号状态（QQ/微信/钉钉/飞书）。

### 工具注册表自动种子
启动时检查 tool_registry 表是否为空，空时从 TOOL_META_MAP 自动同步所有已注册工具的元数据（API ID、显示名、分类、权限标记），保证 DB 侧与内存注册始终同步。

## 消息与插件层

### 消息去重
插件层基于 SHA256(event_id) + LRU 双端队列（200 条）去重，防止 NapCat 重复事件被多次转发到 emily-core。

### SSE 出站事件流
异步推送四类出站事件——reply / progress / file_send / session_closed，断线自动重连。插件层维护 conversation_id→AstrMessageEvent 映射以定位异步回复目标。

### M4 回复合成层
SessionAgent 用主模型基于所有 WorkItem 的 structured_result 组织自然语言回复，而非简单拼串。Guardian 对最终回复再做一次安全性审核后才发送。

### 路由预填优化
意图识别阶段 LLM 直接提取 query_type 预填到 WorkItem，使查询类 SOP 的后续参数提取步骤可直接跳过 LLM 调用，节省一次 LLM 往返。

## 节点系统

### 四态节点状态机
NOT_ACTIVATED → CONDITIONS_NOT_MET → IN_PROGRESS → COMPLETED。前置条件满足度基于文件级依赖（不锁定节点，锁定具体成果文件）加权计算，支持成果完成度自动流转判定和父子进度加权汇总。

### 节点批量 YAML 操作
YAML 嵌套树定义自动展平、自动编号、按名称模糊解析依赖、幂等创建（已存在跳过）、dry-run 预览校验。creator_id 支持用户名转 UUID，无需硬编码 ID。

### BFS 循环依赖检测
节点依赖关系创建时进行 BFS 遍历检测循环依赖，阻止形成环形依赖结构，保障节点树为合法 DAG。

## 文件管理系统

### FileManager 统一 Facade
`FileManager` 聚合 FileService（元数据）+ FileStorageService（物理存储）+ SessionAccessibleFileRepo（可见性），作为 Application 层唯一入口。不替代底层 Repo，仅在 Service 层做权限校验 + 编排 + 统一出口，对外提供 `query_visible_files`、`link_to_module`、`create_version`、`soft_delete`、`list_versions` 五个核心方法。

### 权限可见性过滤
`query_visible_files(user_id, category)` 通过 INNER JOIN `session_accessible_files` 表过滤用户可见文件，实现会话级文件权限控制。不同用户查询同一分类可能看到不同文件子集，权限数据由会话创建时注入的快照驱动，不可被 AI 绕过。无权限用户查询直接返回空集（fail-closed）。

### send_file 文件推送
`handle_send_file(file_no)` 通过 FileManager 加载文件元数据，调用 `FileStorageService.get_local_path()` 解析物理路径，通过 SSE 出站事件流发布 `file_send` 事件推送到客户端。权限校验使用与查询一致的 `session_accessible_files` 链路，未授权文件拒绝发送。

### 异步附件自动下载
`AttachmentDownloader` 在核心启动时初始化，`handle_message` 后触发异步调度。收到带附件的消息时，通过 `urllib` 读取文件 URL 内容，经 FileStorageService 持久化到 `storage_root` 目录，同时在 `message_attachments` 表写入关联记录。URL 去重——相同 URL 只下载一次，避免重复落盘。

### 文件版本链
`new_file_version(parent_file_no)` 创建版本链：父文件 `is_latest` 置为 false，子文件 `parent_file_id` 指向父文件、`version` 设为新版本号、`is_latest` 置为 true。`list_versions(file_no)` 通过 `file_no = ? OR parent_file_id = ?` 查询完整版本历史，最新版本标记 `[最新]`。

### 文件关联与软删除
`link_to_module(file_id, module_id, module_type)` 将文件关联到业务模块（节点/事件/任务等），更新 `source_module_id` 和 `source_module_type` 字段。`soft_delete(file_id)` 执行软删除（`is_deleted = true`），删除后查询自动排除，可恢复。

### 工具注册与一致性
文件管理 5 个工具（`send_file` / `link_file` / `new_file_version` / `delete_file` / `list_file_versions`）全部注册在 tool_registry 表中，启动时通过 `_ensure_tool_registry_seed` 自动种子同步，`tools_consistency.py` 多维校验保证 schema 与元数据一致。
