## 架构概述

Emily V1.0 是双容器系统。**业务内核**（`emily-core` 容器，FastAPI + `emily_core` 包）拥有全部逻辑：分层架构 `adapters → session → workitem(pipeline) → application → services → repositories → infrastructure`。**AstrBot 插件**（`data/plugins/emily_agent/`）是薄通信垫片——它去重 IM 事件，转换为 `StandardMessage`，通过 HTTP 转发给 Core，并监听 Core 的 SSE 出站流将回复推回 IM。**插件中不含业务逻辑。**

一条消息的流转：AstrBot 事件 → `inbound_adapter` → `StandardMessage` → POST `/api/v1/message/send` → `EmilyCore.handle_message` → `DomainTakeoverService.decide` → `SessionPoolManager.route`（每个 `conversation_id` 一个 `SessionAgent`）→ `SessionAgent.handle` 做快回短路 / LLM SOP 意图识别 + WorkItem 拆分 → `SessionScheduler` 将每个 `WorkItem` 跑过全局单例 **`PipelineBUS`（4 固定节点）** → 回复通过 `OutboundEventBus` 发布 → SSE → 插件 → IM。

## emily-core/api/ — HTTP/SSE 协议层

| 文件 | 一句话说明 |
|------|-----------|
| `api/server.py` | FastAPI app 入口，lifespan 里调用 `bootstrap.init()` 初始化 EmilyCore，注册 health/message/session/outbound 路由 |
| `api/routes/message.py` | `POST /api/v1/message/send`：反序列化 `MessageIn` → `StandardMessage`，调用 `core.handle_message()`，返回 `ReplyOut` 或 204（异步 SSE） |
| `api/routes/session.py` | `POST /api/v1/session/terminate`：强制终止指定 `conversation_id` 的 Session |
| `api/routes/health.py` | `GET /api/v1/health`：返回 Core 健康状态（sessions/uptime 等） |
| `api/sse/outbound.py` | `GET /api/v1/events/outbound`：SSE 流，订阅 `OutboundEventBus`，15s 心跳 |
| `api/middleware/auth.py` | `AuthMiddleware` 占位：若设 `EMILY_API_TOKEN` 则校验 `X-Emily-Token` header（health 豁免），否则全放行 |
