## 1. 实验概述

### 1.1 实验目的

验证本文 3.7 节的核心主张——**一条指令在时间轴上留下多角色、多节点的留痕，串成可追溯记录链**。现有第 5 章验证均为"点"验证（单次消息 → 查库 → 看回复），本实验通过一个**连续过程案例**，验证五条设计原则组成的系统路线能否形成"多主体、跨时间的完整信息协同闭环"。

### 1.2 实验性质

- **层级**：E2 级（设计原则 / 路线闭环验证），非 E1 功能正确性。
- **零代码**：不改动系统任何代码，仅复用现有能力（事件录入 + `related_event_ids` 关联 + `build_trace` 溯源）。

### 1.3 验证三问

| # | 验证问题 | 对应原则 |
|---|---------|---------|
| 1 | 信息能否以低门槛（自然语言）进入系统？ | P3 |
| 2 | 信息进入后能否跨角色、跨时间持续沉淀并关联？ | P2 + P5 |
| 3 | 未参与全过程的用户能否低成本回溯完整过程 + 溯源到人？ | P1 + 3.7 节 |

## 4. 结果分析与原则落点

### 4.1 三问验证结果

| # | 验证问题 | 结果 | 结论 |
|---|---------|------|------|
| 1 | 低门槛进入（P3） | 5 次交互全部自然语言完成，无表单/固定格式 | ✅ 达成 |
| 2 | 跨角色跨时间关联（P2+P5） | 4 条事件由 3 名不同角色在连续时间点录入，`related_event_ids` 正确串链 | ✅ 达成 |
| 3 | 未参与人回溯 + 溯源（P1+3.7） | 未参与人一句查询还原完整时间线；溯源追问 2/2 命中 | ✅ 达成 |

### 4.2 关键发现

1. **显式关联稳定回填**：阶段 2/3/4 均显式带锚点编号，LLM 全部正确提取填入 `related_event_ids`，无一遗漏——证实了 PRD 第 5.3 节"显式关联下的可追溯能力"的可行性。

2. **关联链的自动扩展**：阶段 4 的录入中，系统**不仅**回填了用户显式给出的锚点 `EVT-20260814-0002`，还**自动**补充关联了中间事件 `EVT-20260814-0004`。这一"超出用户显式指令的关联补全"说明系统在结构化输出路径上具备一定的关联推理能力，是本实验的一个加分发现（但需谨慎表述，不夸大为"全自动知识链"）。

3. **溯源到人完整可用**：三类溯源（记录人 / 确认人 / 责任人）在追问时均返回姓名 + 岗位，命中率 100%，与 5.4.1 节既有实证一致。

4. **时间线由确定性数据链支撑**：回溯查询的结果来自 `related_event_ids` 的确定性数据链 + LLM 语义聚合，而非 LLM 凭空推理。日志证实查询走标准 `query_data` 链路，关联关系在数据库层可核验。

### 4.3 诚实边界声明

本实验展示的是**"显式关联下的可追溯能力"**，而非"全自动知识链"：

- 事件之间的关联**部分**依赖录入者在自然语言中显式给出锚点编号（阶段 2/3/4），系统在此基础上的提取与补全是可靠的；
- 系统**不自动判断**事件之间的因果真伪，最终闭环的判断仍由人完成（阶段 4 由项目经理确认定样）；
- 这一边界恰恰印证了 P1 原则"AI 增强、人做权威"的定位。

## 6. 局限与后续

- **局限 1**：本案例为单项目、单条问题主线的演示，样本规模有限，不构成统计意义上的结论，需与 5.2（功能正确性）、5.4（对比实验）共同构成多层次证据。
- **局限 2**：关联回填依赖用户显式带编号，未验证"用户不提编号时系统能否自动关联"（该能力边界需另行评估）。
- **局限 3**：本案例未触发守护核验异常，PND 待解决问题机制的"辅助展示"未能在本案例中体现。

**后续可探索**：① 用户不提编号时 LLM 的自动关联能力；② 跨项目多问题主线并行时的关联隔离；③ 触发守护核验异常时 PND 与事件链的联动闭环。

### A.2 关键 DB 断言

```sql
SELECT e.event_no, e.title, e.event_type, e.status, e.related_event_ids,
       u.username AS uploader, cu.username AS confirmer
FROM events e
LEFT JOIN users u ON u.id = e.user_id
LEFT JOIN users cu ON cu.id = e.confirmed_by
WHERE e.event_no IN ('EVT-20260814-0002','EVT-20260814-0003','EVT-20260814-0004','EVT-20260814-0005')
ORDER BY e.created_at;
```
