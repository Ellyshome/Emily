## 一、实验目的与立论拆解

### 1.1 要论证的立论

> **建立信息到人溯源纽带，搭建人员关联的基础**（审稿意见原话）

⚠️ **表述边界**：本实验只论证到"溯源纽带 + 关联基础"，**不**声称"已完整实现人与人关联"；主动消息推送、人员邀约联动属后续迭代。

### 1.2 立论拆解 → 三个可验证子命题

| 子命题 | 含义 | 验证方式 | 对应系统能力 |
|--------|------|---------|-------------|
| **P-A 信息→人（溯源纽带）** | 每条信息可追溯到"谁记录/谁确认/谁负责" | 定量：溯源命中率 | `trace` 字段（uploader/confirmed_by/responsible） |
| **P-B 人→人（关联基础）** | 第三人查询可获知"可向谁核实"，从而与信息源产生间接关联 | 定性：跨角色追问演示 | 追问时从 trace 提取姓名 |
| **P-C 克制性（基础而非终态）** | 第一轮不主动推送人员，追问才给 | 定量：第一轮克制率 | 提示词"默认不渲染、追问才展示" |

### 1.3 技术载体（本轮已实现并实测通过）

三层溯源的数据链路：

```
query_data 工具 → QueryService.build_trace()
  → 解析 user_id/confirmed_by/owner_id/host_id → username
  → 返回 trace: [{no, title, uploader{id,name}, confirmed_by{id,name}, responsible{id,name}}]
  → agent loop 提示词：默认不塞 summary，追问才从 trace 提取
  → session_reply 提示词：第一轮不列人员，追问才给
```

## 四、场景设计

### 4.1 场景四：跨角色信息溯源（验证 P-A + P-B + P-C）★ 核心

**业务叙事**：集团管控人员罗永强（L5）需要了解翠湖庭院近期现场情况。他先泛泛查询，再针对某条具体信息，追问"谁记录的、谁确认的、谁负责的"——验证系统能否在不主动打扰的前提下，把信息背后的"人"逐一揭示，从而建立"信息→人→可核实对象"的关联基础。

**技术链路预期**：
```
第一轮：SOP-005-QRY → query_data(event) → 回复列表（不含人员）  ← P-C 克制
追问1：query_data 返回 trace.uploader → 提取记录人姓名            ← P-A 上传人
追问2：trace.confirmed_by → 提取认证人姓名（若空，如实说明未确认）← P-A 认证人
追问3：跨表 query_data(task/meeting) → trace.responsible → 责任人  ← P-B 人→人
```

## 五、量化指标定义

### 5.1 溯源命中率（P-A）

**定义** = 正确返回人名的追问数 / 有效追问总数

| 子指标 | 样本 | 目标 |
|--------|------|------|
| 上传人命中率 | 追问 uploader 的次数 | ≥ 90% |
| 认证人命中率 | 追问 confirmed_by 的次数（含 pending 空值场景，正确返回"未确认"计为命中） | ≥ 90% |
| 责任人命中率 | 追问 owner/host 的次数 | ≥ 90% |

### 5.2 字段覆盖率（数据底座完整性）

**定义** = 数据层有溯源字段的记录数 / 总记录数

```sql
-- 事件：user_id 非空（应有 10/10）
SELECT COUNT(*) FILTER (WHERE user_id IS NOT NULL) AS has_uploader,
       COUNT(*) FILTER (WHERE confirmed_by IS NOT NULL) AS has_confirmer,
       COUNT(*) AS total
FROM events WHERE event_no LIKE 'EVT-TRACE-%';
-- 任务：created_by + owner_id 非空（应 3/3）
-- 会议：created_by + host_id 非空（应 3/3）
```

**目标**：100%（证明溯源能力建立在完整数据底座上，而非 LLM 硬凑）。

### 5.3 第一轮克制率（P-C）

**定义** = 第一轮未主动展示人员的查询数 / 总查询数

**目标**：100%（验证"基础而非终态"的克制性设计）。

### 8.2 写作要点（对齐审稿意见的红线）

## 九、注意事项

1. **sender 必须真实**（罗永强 123456008），伪造会被创建 level=1 用户
