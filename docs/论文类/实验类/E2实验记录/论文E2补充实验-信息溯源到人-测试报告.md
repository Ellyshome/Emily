## 一、实验目的

验证立论：**建立信息到人溯源纽带，搭建人员关联的基础**

拆解为三个可验证子命题：

| 子命题 | 含义 | 验证方式 |
|--------|------|---------|
| **P-A 信息→人（溯源纽带）** | 每条信息可追溯到"谁记录/谁确认/谁负责" | 定量：溯源命中率 |
| **P-B 人→人（关联基础）** | 第三人查询可获知"可向谁核实"，从而与信息源产生间接关联 | 定性：跨角色追问演示 |
| **P-C 克制性（基础而非终态）** | 第一轮不主动推送人员，追问才给 | 定量：第一轮克制率 |

## 八、关键发现与讨论

1. **三层溯源链路完整**：信息可追溯到 uploader（记录人）、confirmed_by（认证人）、responsible（责任人/主持人）三个维度，且角色分离清晰，证明"一条信息关联多个人"而非"一人包办"。

2. **空值诚实性强化可信度**：pending 事件的 confirmed_by 为空时，系统如实说明"没有确认人"，而非编造或回避——这是溯源可信度的重要体现，也是克制性设计的延伸。

3. **克制性设计符合"基础而非终态"**：第一轮泛查不主动暴露人员，追问才逐步揭示，既避免信息过载，又保留了溯源能力。主动消息推送、人员邀约联动属后续迭代方向。

4. **会议主持人的映射方式**：会议的 host_id 通过 trace.responsible 字段返回，LLM 做了语义解释（"按会议主持通常对应责任人字段"）。这是合理的映射，但如果后续要强化会议溯源，可考虑在 trace 中显式区分 host 与 responsible。

5. **表述边界**：本实验只论证到"溯源纽带 + 关联基础"，不声称"已完整实现人与人关联"。人与人的主动关联（消息推送、邀约联动等）属后续迭代。
