# “以团队公共认知为基础、嵌入日常信息流、跨部门理解项目过程并实际办事”的垂直行业系统
# 今天企业AI真正的分水岭，已经不是“AI能不能回答问题”，而是“AI能不能进入一个组织，拥有持续的公共上下文，并在明确的权责边界内真正把事情办完”。

AI技术深刻变革生产关系，但在住宅行业中，发挥效能的现状特征是单人单功能。本提出并实践了一套完整框架。让AI服务于以项目为对象的模式。
框架基于地产项目的需求特征，借鉴AI-harness工程实现的多项实用技术实现。如

- Agent Runtime 框架独立：模型、调度系统、tool、环境信息
- Session / Context 生命周期管理
- 上下文工程：Context Engineering
- 多信息源交叉验证
- 用户在团队中的访问权限控制
- 能力插件化扩展
- 自主规划选择-任务编排loop
- 可溯源行为轨迹

## 行业痛点
- 项目记忆与过程经验,随人员流动而流失。
- 企业信息沉淀量大难活化复用
- 传统数字化系统只擅长预设流程和结构化数据，对自然语言过程信息和非预设任务无力。培训成本高，跨企业难复用，无解释，可参与人少。
- 通用 AI 工具以个人单任务为中心，难以持续进入团队信息流并形成组织公共认知。
- 地产项目一线过程信息（现场/会议/IM 中的细节、试错经验、情境判断）不进入正式留档，造成「正式数据完整、过程认知分散」。 

## 技术路线
- 以IM作为入口，实现‘直达一线的、自然语言交互的、低门槛接入。
- 工作群'卧底'+ 有记忆的任务执行工具 = 经验收集 - 入库 - 复用：新sop，新全景节点，定制生成机制。
- LLM 增强有限状态机（FSM）：全景节点图，提供项目态势感知能力。提供图状相互关联互为输入条件-输出成果的关系图，通过图关联企业，通过企业关联人，实现鉴权、可见信息隔离
- 以 Skill 化 SOP 将业务流程封装为 Agent 可发现、可调用、可执行的能力单元。
- 智能体自主任务编排：以三智能体（SessionAgent / WorkItemAgent / GuardianAgent）分离任务组织、业务执行与责任核验。
- 以全景节点作为项目级信息可见性与鉴权的基本组织单元。
- **领域管理要素→Agent技术对象映射**：将地产项目的状态、信息、规则、流程、人员和系统能力分别映射为状态空间、公共认知对象、约束知识、能力单元和任务单元。
- 插件化提供能力

## 实践验证
`实例一：园路铺装验收（验证框架的预设执行链设计）`
三智能体分工设计：SessionAgent 拆解、WorkItemAgent 执行、GuardianAgent 核验三层各司其职，验证了「任务组织 / 业务执行 / 责任核验」三者分离的框架分工成立。
三书认知基座设计：态势书供状态、规则书供标准、能力书供 Skill，验证了「按需加载、非全文灌入」的认知组织方式成立。
Skill 化 SOP 设计：能力书语义匹配到验收 Skill 并调用，验证了「业务能力单元化 + 可发现可调用」的设计成立。
LLM 增强 FSM 设计：节点变更与整改须经人工确认，验证了「人定义状态空间、系统维护关系、LLM 仅辅助判断」的受控转移设计成立。
分层架构设计：三书（认知层）与三 Agent（执行层）在实例中分属不同层次被调用，验证了「认知组织与任务执行分离」的总体架构设计成立。
`实例二：跨部门软装品质追溯（验证框架的非预设组合设计）`
非预设能力组合设计：无专属 SOP 时组合 RAG/DB/事件日志/历史经验，验证了「能力组合 ≠ 新流程生成」这一边界设计成立。
渐进式发现设计：在无专属 SOP 的场景下仍能按「任务识别→按需探索→执行核验」运行，验证了「共享地图、按需探索」的联动机制设计成立。
全景节点可见性设计：涉密信息走权限控制 + 协作导航而非直接输出，验证了「节点级信息可见范围 + V_new ⊆ V_creator」的鉴权设计成立。
Guardian 边界核验设计：识别出成本壁垒、界面不清、签认缺位等信息流转缺口，验证了「执行与核验相分离」的职责隔离设计成立。
团队公共认知沉淀设计：原主管离岗后仍能还原完整过程链，验证了「以团队而非个人为认知主体」这一框架设计目标成立。
