# 1 引言

地产项目由投资、设计、成本、工程、营销等多专业条线在动态节点推进中协同完成，业务既包含标准流程，也包含大量情境化协调，不同信息还具有不同的权限与责任边界。团队日常运行中，大量细节信息、问题处理过程、试错经验和情境判断产生于现场、会议与即时通讯，往往仅通过人员沟通逐级流转，最终留档的通常只是加工后的结果性信息，形成"正式数据完整、过程认知分散"的现象，并随人员流动而流失。传统数字化系统擅长预设流程与结构化数据，对自然语言过程信息和非预设任务的关联处理能力有限。与此同时，AI技术正加速向各行业渗透，但在地产行业中其效能现状是"单人单任务"：通用AI工具以个人会话为中心，难以持续进入团队信息流并形成组织公共认知。从技术本质看，当前弱人工智能的核心能力是信息运算，适合承担信息检索、关联与分析工作，涉及责任归属的审核与决策仍应由人完成。因此，本文关注的核心问题是：如何针对地产项目管理结构，将通用AI Agent重构为能够持续组织团队公共信息、并在权责边界内支持受控业务协同的领域化框架？本文的贡献包括：一是建立地产管理要素向Agent技术对象的映射方法；二是据此构建信息协同型AI智能体框架并完成工程落地实践验证，为地产及相关垂直领域团队级AI的落地与系统框架搭建提供借鉴。

# 2 技术路线

## 2.1 总体技术路线

本文的总体路线是：提取地产行业协同管理要素，将其映射为Agent可处理的技术对象，在此基础上搭建面向团队的垂直领域Harness（即Agent公共运行支撑环境）。

## 2.2 地产行业Harness构建方法："六层一闭环"

围绕地产项目团队如何真实开展工作，构建AI的运行环境、协作机制与管理边界，可归纳为"六层一闭环"：组织层（Who）建立企业、项目、部门、专业、角色等组织关系，明确AI服务的团队边界；上下文层（Context）将项目、阶段、业务对象、历史决策与人员关系组织为持续上下文，使AI理解"当前是什么项目、处于什么状态"；状态层（State）将管理过程抽象为可感知的业务状态与全景节点，使AI能判断"进行到哪里、下一步应发生什么"；任务层（WorkItem）将自然语言需求转化为可创建、执行、暂停、恢复、交接和关闭的任务单元，实现多人多任务协同；能力层（Skill/Tool）将企业SOP、管理规则、专业方法和外部工具封装为可调用能力，使AI从"会回答"转向"会办事"；治理层（Permission & Audit）控制信息可见范围、操作权限、人工确认、责任归属与全过程证据。六层之上是业务执行闭环：感知→判断→任务→执行→协同→验证→留痕→更新状态。整体逻辑为：组织定义边界、上下文提供认知、状态决定时机、WorkItem承载任务、Skill完成执行、治理控制风险，闭环持续沉淀项目记忆。

## 2.3 管理要素与Agent技术对象映射

将地产项目管理中的主要信息对象抽象为七类：项目状态、过程事件、项目资料、组织规则、业务流程、人员关系和系统能力，并采用面向管理对象的分层映射（表1）。

表1 地产管理要素与Agent技术对象映射

| 地产管理要素 | Agent技术对象 | 核心机制 |
| --- | --- | --- |
| 项目状态/节点 | 状态空间 | LLM增强FSM |
| 过程事件/项目资料 | 公共上下文对象 | 项目态势书 |
| 组织制度/规则 | 约束知识 | 组织规则书 |
| 系统工具/接口 | 能力对象 | 系统能力书 |
| 业务流程/SOP | 能力单元 | Skill化SOP |
| 用户复合请求/交互上下文 | 工作项/会话任务 | WorkItem/SessionAgent |
| 具体业务任务 | 执行任务 | WorkItemAgent |
| 组织参与关系/权限 | 可见性与核验对象 | GuardianAgent |

该映射的基本逻辑是由地产管理对象反向决定Agent需要的技术对象：状态需要状态空间，过程信息需要公共认知，SOP需要能力单元，复合任务需要工作项，组织责任则要求执行与核验相分离。

## 2.4 与通用AI智能体的功能差异

通用AI智能体的组织方式可概括为Agent→Context→Tool→Loop→Memory，其上下文与记忆服务于当前用户。面向团队的地产行业垂直领域智能体则需具备：从"用户上下文"扩展到"项目—组织—角色—任务"的团队级上下文、多人协同与任务调度、项目状态感知、角色与权限控制、SOP流程执行、跨专业信息关联、事项闭环管理、证据链与可追溯性、主动提醒与催办、关键动作人工确认、企业规则沉淀与长期项目记忆。据此，地产领域框架还应具备五项要素：态势感知、团队共享记忆、按规办事、边界与核验、随实践成长。

# 3 实现方法

（1）领域上下文工程。以"三书"为三层上下文工件：项目态势书组织节点状态、过程事件与成果索引，回答"项目正在发生什么"；组织规则书组织制度、规范与合同约束，回答"应遵循什么规则"；系统能力书描述可调用的Skill、工具与数据接口，回答"系统能做什么"。三书采用"摘要先行、按需深入"的渐进式组织：会话建立时注入轻量摘要，任务执行中经RAG、DB与事件日志按需检索细节，避免全文灌入导致模型对长上下文中间信息利用不足的问题；并由偏差检测驱动的自维护闭环保证时效——系统定期比对工件与底层数据的差异并重建工件，规则书保持人工维护、热加载生效。

（2）全景节点与状态管理。以全景节点构建项目业务状态空间：将开发任务分解为有明确产出的子任务作为节点，以节点关联性组织项目全景图，节点按重要性分级并由操盘单位管理。状态变化采用"人定义状态空间、系统维护状态关系、LLM辅助语义判断"的LLM增强有限状态机：LLM从自然语言中提取状态证据并提出候选转移，实际转移受成果条件、业务规则与人工确认约束。

（3）SOP-Skill能力封装。将标准化业务流程封装为含任务描述、输入参数、前置条件、工具绑定、输出约束与权限要求的Skill，通过系统能力书进行语义发现与参数映射，使自然语言任务能够调用既定业务能力，并按业务稳定程度形成"Skill—专用Agent—既有能力组合"的分层能力组织。

（4）WorkItem驱动的任务协同。将复杂请求拆解为可独立执行的WorkItem，由三个智能体分工：SessionAgent负责会话组织与任务拆解，WorkItemAgent负责具体能力调用与业务执行，GuardianAgent负责责任核验，实现面向团队的异步任务协作。

（5）权限与执行边界控制。以全景节点作为信息可见性的基本组织单元，人员经企业、角色与参与节点形成节点级可见关系，新授权不得超过授权者自身可见范围（V_new⊆V_creator）。通过权限快照、执行前Hook、GuardianAgent二次校验及人工确认机制，对信息可见范围、业务规则与操作边界进行全过程约束；权限不足时选择拒绝、脱敏或协作导航。责任认定、关键状态确认与流程变更由人完成最终确认。

（6）非预设任务的能力组合。对缺少对应SOP的新型任务，若不涉及新增组织规则，可在权限边界内组合既有检索、数据库、事件记录和历史经验等基础能力完成。需严格区分"能力组合"与"新流程生成"，后者（新SOP、流程规则与状态空间变更）仍需人工审核。

（7）事件流与多源信息沉淀。以IM作为低门槛自然语言入口，将团队日常沟通中的过程信息经事件记录、结构化数据库与RAG检索持续沉淀，形成可追溯的项目过程记录，使项目记忆不随人员流动而流失。

# 4 案例验证

本文以实际业务实例说明框架的工程落点，不构成统计意义上的性能验证。

实例一（预设业务流程）：苏州某住宅项目景观工程阶段，园路铺装节点完成后项目主管经IM提出验收咨询。SessionAgent拆分流程匹配与成果定位两个WorkItem，WorkItemAgent经系统能力书发现验收Skill并从三书获取状态、成果与标准，GuardianAgent完成权限与规则二次核验；现场发现质量问题后，系统继续拆分规范比对、合同查询与材料溯源任务，经人工确认执行整改通知与节点变更。该实例验证了三智能体分工、三书按需加载、Skill化SOP与受控状态转移设计的成立。

实例二（非预设复合信息任务）：某已竣工住宅项目中，集团景观负责人追溯软装品质偏差。因原项目主管离岗且无专属SOP，系统按权限完成跨源查询后，由WorkItemAgent组合RAG、DB、事件日志与历史经验，还原招标、交底、采购、进场与验收5个阶段，形成跨5个部门、8类信息来源的事件演进链，并识别出成本信息壁垒、合约界面不清与程序签认缺位等信息流转缺口；涉密信息采用权限控制与协作导航。该实例验证了非预设能力组合、渐进式发现与团队公共认知沉淀设计的成立——原主管离岗后项目过程链仍可完整还原。

框架运行依赖项目数据、可检索规则与人员权限等数字化基础；跨载体深层关联仍依赖RAG与DB，LLM状态证据解析存在不确定性，需通过人工定义状态空间、规则与责任边界限制Agent自由度。

# 5 结论

本文从地产项目管理结构出发，提出领域管理结构驱动的AI Agent框架设计方法：将项目状态、过程信息、组织规则、业务流程、系统能力、复合任务与组织权责映射为状态空间、上下文工件（三书）、Skill能力单元、WorkItem与职责核验机制，以"六层一闭环"Harness组织为"认知—感知—执行—核验"的信息协同型框架。框架的核心不是增加行业知识，而是将管理结构本身转化为Agent的上下文、状态、能力、可见性与责任边界；两个业务实例表明，该框架能支持预设流程与非预设复合信息任务，并在受控边界内持续组织团队公共信息。本文为传统行业由管理结构反向驱动Agent架构设计提供了工程实践参考。后续可研究事件关系网络与RAG/DB双路径召回的结合、上下文工件的分层增量更新，并通过插件机制接入BIM、视觉多模态等专业能力，使业务能力随实践持续成长。
