# 图1：地产团队信息协同模式对比图

## 放置位置

建议放在：

> **第1章 1.4之后，或1.5之前**

也就是在讲完行业核心痛点之后。

## 图表达什么

核心表达：

> **传统项目团队的信息流 → 信息孤岛与层层过滤**
>
> 对比
>
> **AI信息协同模式 → 多源信息持续汇聚 → 团队公共认知 → 按权限服务团队**

我认为这张图非常重要，甚至优先级最高。

因为你整篇论文真正的研究价值，并不是：

> 三书、FSM、Skill、Multi-Agent。

而是：

> **改变信息在组织中的流动方式。**

图可以设计成左右对比。

### 左侧：传统模式

```text
                 集团管理层
                     ▲
                     │ 汇报
                     │
                项目负责人
                     ▲
                     │ 汇总/过滤
                     │
       ┌─────────────┼─────────────┐
       │             │             │
     工程部         成本部        设计部
       ▲             ▲             ▲
       │             │             │
   现场信息       合约信息       设计信息
       │             │             │
       └───── 分散、割裂、随人员流动 ─────┘
```

旁边可以标注：

* 信息分散
* 层级过滤
* 隐性知识流失
* 跨部门壁垒
* 过程不可见

---

### 右侧：信息协同型AI模式

```text
                集团 / 管理层
                     ▲
                     │
              ┌──────┴──────┐
              │  Emily AI   │
              │ 团队公共认知 │
              └──────┬──────┘
                     │
        ┌────────────┼────────────┐
        │            │            │
      工程部        成本部       设计部
        │            │            │
        └────── 日常自然语言 ──────┘
                     │
              项目过程信息
```

底部可以形成：

```text
IM沟通 / 会议纪要 / 文件 / 事件 / 数据库
                    ↓
             持续采集与关联
                    ↓
             团队公共信息环境
                    ↓
        按权限查询 / 任务支持 / 过程追溯
```

### 这张图的作用

它直接回答：

> **为什么需要这种AI？**

同时也把你的摘要里最重要的一句话视觉化：

> AI服务于团队，团队持续向AI提供信息，AI逐步形成团队公共认知。
