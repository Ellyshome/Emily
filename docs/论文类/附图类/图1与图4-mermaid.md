## 图 1 总体研究思路

**位置**：第 1 章 1.3 节 研究问题与研究思路
**尺寸**：单栏（约 7.5 cm × 10 cm），纵向排版

```mermaid
flowchart TB

    subgraph S1["① 问题识别（第1章 1.1–1.2）"]
        direction TB
        P1["地产项目管理特征"]
        P2["状态动态 · 信息多源<br/>流程标准化 · 权责明确"]
        P3["传统数字化与个人 AI<br/>的协同缺口"]
        P1 --> P2 --> P3
    end

    subgraph S2["② 管理要素抽象（第3章 3.1）"]
        E1["项目状态 · 过程事件 · 项目资料<br/>组织规则 · 业务流程 · 人员关系 · 系统能力"]
    end

    subgraph S3["③ Agent 技术对象映射（第3章 3.2–3.4）"]
        M1["状态空间 · 公共认知对象<br/>能力单元 · 工作项 · 核验任务"]
    end

    subgraph S4["④ 框架设计（第4章）"]
        F1["三书认知基座<br/>LLM 增强 FSM · Skill 化 SOP"]
        F2["Session / WorkItem / Guardian 协同"]
        F1 --> F2
    end

    subgraph S5["⑤ 工程应用说明（第5章）"]
        direction LR
        A1["预设业务流程<br/>（园路铺装验收）"]
        A2["非预设复合信息任务<br/>（软装品质追溯）"]
    end

    S1 -->|"提出研究问题 RQ1–RQ3"| S2
    S2 -->|"RQ1：管理要素 → Agent 技术对象"| S3
    S3 -->|"RQ2：组织为公共认知与受控执行框架"| S4
    S4 -->|"RQ3：保持流程、权限与人工责任边界"| S5
```

> 注：研究思路采用"问题识别—管理要素抽象—Agent 对象映射—框架设计—工程应用说明"五段式，由地产管理特征出发，识别传统数字化与个人 AI 之间的协同缺口，逐级收敛到信息协同型 AI 智能体框架，并以两个真实业务实例说明框架落地。

## 图 4 三书驱动的信息协同运行闭环

**位置**：第 4 章 4.7 节 信息协同运行闭环
**尺寸**：通栏（约 15 cm × 9 cm），纵向排版

```mermaid
flowchart TB

    ACT["团队日常业务活动"]
    SRC["IM · DB · 文件 · 事件记录"]
    ING["项目过程信息进入系统"]

    ACT --> SRC --> ING

    PB["📖 项目态势书<br/>项目正在发生什么"]

    ING --> PB

    TASK["Agent 业务任务<br/>Session 拆解 → WorkItem 执行"]

    PB --> TASK

    RB["📖 组织规则书<br/>当前应遵循什么"]
    CB["📖 系统能力书<br/>当前可以做什么"]

    TASK --> RB
    TASK --> CB

    EXEC["任务执行 / 信息支持"]

    RB --> EXEC
    CB --> EXEC

    CONFIRM["人工确认 / 业务结果"]
    NEWEVT["新的过程事件和业务记录"]

    EXEC --> CONFIRM --> NEWEVT

    NEWEVT -->|"回写项目态势书"| PB

    style PB fill:#e1f5fe
    style RB fill:#fff3e0
    style CB fill:#e8f5e9
```

> 注：项目过程信息构成持续更新的"热记忆"，组织规则书与系统能力书作为与热记忆关联的两个认知维度，共同形成 Agent 运行所需的信息交汇与架构地图。闭环起点为团队日常业务活动，终点以新的过程事件回写项目态势书，实现"业务活动 → 公共认知 → 任务支持 → 新的活动"的持续复用。
