# Emily 部署工具使用手册

## 一、概述

Emily 项目使用 **Task**（go-task）作为自动化部署工具，通过 `task` 命令管理容器的构建、启停、日志、备份等全部运维操作。

## 二、环境准备

### 2.1 前置依赖

| 依赖 | 版本要求 | 安装方式 |
|------|---------|---------|
| Docker | 24+ | `curl -fsSL https://get.docker.com \| sh` |
| Docker Compose Plugin | v2+ | 随 Docker 一起安装 |
| Task | 3.x | 见下方 |

> Docker Compose 必须是 **插件版本** (`docker compose`)，而非旧版独立二进制 (`docker-compose`)。

### 2.2 安装 Task

在 ECS（Linux）上执行：

```bash
sh -c "$(curl --location https://taskfile.dev/install.sh)" -- -d -b /usr/local/bin
```

验证安装：

```bash
task --version
# 输出示例: Task version: 3.41.0
```

### 2.3 配置环境变量

```bash
# 从模板创建 .env
cp .env.example .env

# 编辑 .env，至少填写 LLM API Key
vim .env
```

关键配置项：

```ini
EMILY_LLM_API_KEY=sk-xxxxxxxx          # 必填，DeepSeek API Key
EMILY_LLM_BASE_URL=https://api.deepseek.com
EMILY_LLM_MODEL=deepseek-v4-flash
EMILY_API_TOKEN=your-random-token      # 可选，API 鉴权 Token
```

## 三、部署场景

Emily 支持两种部署配置：

| 配置 | compose 文件 | 容器 | 使用场景 |
|------|-------------|------|---------|
| **minimal** | `docker-compose-minimal.yml` | core + postgres | 最小化运行，纯 API 调用，无 QQ |
| **napcat** | `docker-compose-napcat.yml` | 全部 6 个容器 | 完整功能，含 QQ 接入 + RAG + 代理 |

### 3.1 最小化部署

```bash
task deploy:minimal
```

- 启动 `emily-core` + `emily-postgres` 两个容器
- RAG 关闭，LLM 直连 DeepSeek（不走代理）
- API 端口：`localhost:18080`
- 监控看板：`http://<服务器IP>:18081`

**验证部署成功：**

```bash
# 健康检查
curl http://localhost:18080/api/v1/health

# 预期返回: {"status":"ok","version":"1.0",...}
```

### 3.2 完整部署（含 QQ）

```bash
task deploy:napcat
```

首次构建可能需要较长时间（下载镜像、编译依赖），后续启动只需：

```bash
task up PROFILE=napcat
```

### 3.3 部署流程图

```
task deploy:minimal / deploy:napcat
  │
  ├─ env:check       → 检查 .env 配置和 Docker 环境
  ├─ docker compose up → 构建并启动容器
  │
  └─ wait:healthy    → 轮询等待 emily-core 健康就绪
       │
       └─ 健康检查通过 → 部署完成
```

## 四、常用命令

### 4.1 服务生命周期

```bash
# 启动服务
task up                        # 默认 minimal
task up PROFILE=napcat        # 启动 napcat 配置

# 停止并移除容器（数据卷保留）
task down                      # 默认 minimal
task down PROFILE=napcat

# 重启服务
task restart
task restart SERVICE=emily-postgres   # 仅重启指定容器
```

### 4.2 状态与日志

```bash
# 查看所有 Emily 容器状态
task status

# 查看 compose 管理的容器
task ps PROFILE=minimal

# 查看 core 日志
task logs
task logs LINES=200           # 最近 200 行
task logs FOLLOW=true         # 实时跟踪
task logs SERVICE=emily-postgres   # 查看其他服务

# 查看多服务日志（compose 模式）
task compose:logs
task compose:logs FOLLOW=true
```

### 4.3 数据库操作

```bash
# 备份数据库 + 配置文件（输出到 backups/YYYYMMDD_HHMMSS/）
task db:backup

# 进入 psql 交互终端
task db:psql

# 从备份恢复（⚠️ 会覆盖当前数据）
task db:restore FILE=backups/20260101_120000/emily_db.sql
```

### 4.4 健康检查

```bash
task health
```

输出包括：
- 各容器运行状态
- Core API 可达性
- 数据库连接状态
- 磁盘使用率
- 最近错误日志

### 4.5 运维操作

```bash
# 进入 core 容器 shell
task shell

# 冷启动检查（世界书构建 + 启动报告）
task cold-start

# 停止服务并删除所有数据卷（⚠️ 危险，数据库数据会丢失）
task clean PROFILE=minimal

# 清理未使用的 Docker 资源
task prune
```

## 五、典型工作流

### 5.1 首次部署

```bash
# 1. 安装 Task
sh -c "$(curl --location https://taskfile.dev/install.sh)" -- -d -b /usr/local/bin

# 2. 配置环境
cp .env.example .env
vim .env    # 填写 EMILY_LLM_API_KEY

# 3. 最小化部署
task deploy:minimal

# 4. 验证
curl http://localhost:18080/api/v1/health
```

### 5.2 代码更新后重新部署

```bash
# 拉取最新代码后
task down
task deploy:minimal      # --build 会自动重新构建镜像
```

### 5.3 日常维护

```bash
# 每天检查一次
task health

# 出问题时看日志
task logs FOLLOW=true

# 定期备份（建议加入 crontab）
# 0 2 * * * cd /opt/emily && task db:backup >> /var/log/emily_backup.log 2>&1
task db:backup
```

### 5.4 紧急恢复

```bash
# core 挂了
task restart SERVICE=emily-core

# 还是不行，重建
task down
task deploy:minimal

# 数据库问题，从备份恢复
task db:restore FILE=backups/最新备份/emily_db.sql
```

## 六、目录结构

部署相关文件说明：

```
Emily/
├── Taskfile.yml                    # Task 任务定义（本工具）
├── docker-compose-minimal.yml      # 最小化部署 compose 文件
├── docker-compose-napcat.yml       # 完整部署 compose 文件
├── .env                            # 环境变量配置（需自行创建）
├── .env.example                    # 环境变量模板
├── emily-core/                     # Core 容器构建上下文
│   ├── Dockerfile
│   ├── emily_core/                 # 业务代码（挂载到容器）
│   └── api/                        # API 层代码
├── emily-data/                     # 持久化数据
│   ├── postgres_data/              # 数据库数据卷（minimal）
│   ├── db_seeds/                   # 数据库种子数据
│   ├── config/                     # 配置文件
│   ├── sops/                       # SOP 文件
│   ├── prompts/                    # Prompt 模板
│   ├── skills/                     # 技能定义
│   ├── logs/                       # 运行日志
│   ├── attachments/                # 附件存储
│   └── ...
└── backups/                        # 数据库备份输出目录
```

## 七、常见问题

### Q: `task: command not found`

Task 未安装或不在 PATH 中。运行安装命令后检查：

```bash
which task
task --version
```

### Q: 部署后 `curl http://localhost:18080/api/v1/health` 无响应

检查 core 是否正常运行：

```bash
task status
task logs LINES=50
```

常见原因：
- `.env` 中 `EMILY_LLM_API_KEY` 未配置或无效
- PostgreSQL 未就绪（等待 core 日志中出现 "Database connected"）
- 端口冲突

### Q: 想从 minimal 切换到 napcat 怎么办

```bash
task down PROFILE=minimal
task deploy:napcat
```

两个 compose 文件使用不同的数据卷路径，数据库数据不会冲突（minimal 用 `emily-data/postgres_data`，napcat 用 `emily-data/db_seeds`）。但建议切换前先备份。

### Q: docker compose 报 "unknown shorthand flag"

你用的是旧版 `docker-compose`（独立二进制），请升级到 Docker Compose Plugin：

```bash
docker compose version   # 确认是插件版本
```

### Q: 想在 Windows 上使用

Windows 下推荐使用 WSL2 或直接用 PowerShell。Task 提供 Windows 二进制：

```powershell
# PowerShell (管理员)
choco install go-task
# 或下载 exe: https://github.com/go-task/task/releases
```

但由于 compose 文件中的路径使用了 Linux 风格挂载（`/var/run/docker.sock`），建议在 WSL2 中运行。
