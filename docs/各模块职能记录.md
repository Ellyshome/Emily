## 一、LLM 模型使用点汇总

项目通过统一的 `LLMClient`（`infrastructure/llm/client.py`）封装 OpenAI SDK，提供三种调用方式：
- `chat()` — 单轮文本对话
- `chat_json()` — 单轮对话，强制 JSON 结构化输出（核心使用方式）
- `chat_with_tools()` — 多轮对话 + function calling

### 1.1 完整 Agent（含 LLM 调用链）

| # | Agent | 文件 | 调用方式 | LLM 职责 |
|---|-------|------|----------|----------|
| 1 | **SessionAgent** — 意图识别 + WorkItem 拆分 | `session/session_agent.py` | `chat_json()` | 加载 `session.md` prompt + SOP 目录，对每条入站消息做单次 `chat_json` 调用，输出 `{sop_id, confidence, is_compound, sub_tasks}` 的意图 JSON。**是所有消息的第一道 LLM 入口**。无 LLM 时降级为 fallback。 |
| 2 | **WorkItemAgent** — node2 执行规划 | `workitem/workitem_agent.py` | `chat_json()` | 加载 `planner.md` prompt + SOP 全文 + 可用工具列表，将用户输入规划为 `ExecutionPlan`（步骤、工具、验收标准）。LLM 失败时降级为 `MockPlanner`。 |
| 3 | **WorkItemAgent** — node4 回复合成 | `workitem/workitem_agent.py` | `chat_json()` | 加载 `workitem.md` prompt + 步骤执行结果，合成自然语言回复给用户。LLM 失败时降级为硬编码拼串。 |
| 4 | **RealGuardian** — step 审核 | `workitem/pipeline/real_guardian.py` | `chat_json()` | 加载 `guardian_step.md` prompt，审核每个步骤的 tool_call 输入/输出 + RAG 引用是否合理。通过 `asyncio.create_task()` 后台并发执行，不阻塞主链路。 |
| 5 | **RealGuardian** — reply 审核 | `workitem/pipeline/real_guardian.py` | `chat_json()` | 加载 `guardian_reply.md` prompt，审核最终回复草稿是否与 SOP 口径一致，输出问题标记后追加到回复末尾。只标记不拦截。 |

### 1.2 单次 LLM 调用工具/服务

| # | 调用位置 | 文件 | 调用方式 | 功能简述 |
|---|----------|------|----------|----------|
| 6 | **PlanTaskScheduler** — 当前周期推算 | `services/plan_task_scheduler.py` | `chat_json()` | 根据 deadline_rule（如"每周五"）推算当前周期的 period_key 和 deadline_at。失败抛 `LLMCalculationError`，不做兜底。 |
| 7 | **PlanTaskScheduler** — 下一周期推算 | `services/plan_task_scheduler.py` | `chat_json()` | 根据上一轮的 period_key + deadline 推算下一周期的信息。失败抛 `LLMCalculationError`。 |
| 8 | **NodeVoiceEntryTool** — 口述解析 | `tools/node_voice_entry_tool.py` | `chat_json()` | 解析用户自然语言输入的节点信息（名称/截止时间/部门），返回结构化提取 + 追问。**注意：此文件 import 路径 `from ..providers.llm_client import chat_json` 是遗留引用，实际 LLM 客户端应该是 `LLMClient` 实例**。 |

### 1.3 LLM 调用的 Prompt 文件体系

| Prompt 文件 | 加载方式 | 消费者 |
|-------------|----------|--------|
| `emily-data/prompts/session.md` | `load_prompt("session")` | SessionAgent 意图识别 |
| `emily-data/prompts/workitem.md` | `load_prompt("workitem")` | WorkItemAgent node4 回复合成 |
| `emily-data/prompts/guardian_step.md` | `load_prompt("guardian_step")` | RealGuardian 步骤审核 |
| `emily-data/prompts/guardian_reply.md` | `load_prompt("guardian_reply")` | RealGuardian 回复审核 |
| `emily-data/prompts/project.md` | `load_prompt("project")` | 项目级上下文注入（暂无直接消费者，预留） |
| `emily-data/prompts/flows/main.md` | `load_prompt("flows/main")` | LLM 流程定义（预留） |
| `emily-data/prompts/flows/unmatched.md` | `load_prompt("flows/unmatched")` | 未匹配处理流程（预留） |

### 1.4 LLM 调用模式总结

```
入站消息
  └─ SessionAgent._recognize_intent()          ← chat_json（意图识别，1次/消息）
      └─ WorkItemAgent.node2_plan()            ← chat_json（规划，1次/WorkItem）
          └─ WorkItemAgent.node3_execute()
              └─ RealGuardian.review_step()    ← chat_json（审核，N次/WorkItem，并发）
          └─ WorkItemAgent.node4_summary()
              ├─ WorkItemAgent._llm_synthesize_reply() ← chat_json（合成，1次/WorkItem）
              └─ RealGuardian.review_reply()   ← chat_json（审核，1次/WorkItem）

后台调度：
  └─ PlanTaskScheduler._calc_current_period()  ← chat_json（周期推算，定时触发）
  └─ PlanTaskScheduler._calc_next_period()     ← chat_json（周期推算，定时触发）
```

**总计：每消息链路 4+N 次 LLM 调用**（N = WorkItem 数，Guardian step 审核并发执行）。

## 附录：关键架构速查

### A. 分层架构

```
API 层（FastAPI routes）
  ↓
EmilyCore（惰性初始化所有子系统）
  ↓
SessionAgent（会话调度主脑）
  ↓
WorkItemAgent（全局单例，4 节点 handler）
  ↓
Application 层（event_app/task_app/meeting_app...）→ Service 层 → Repository 层 → DB
```

### B. 消息处理全路径

```
StandardMessage → DomainTakeoverService.decide()
→ SessionPoolManager.get_or_create()
→ SessionAgent.handle()
  → _try_fast_reply() 短路闲聊
  → _recognize_intent() LLM 意图识别（chat_json，1次）
  → _split_into_workitems() WorkItem 拆分
  → scheduler.enqueue_all() + run_all()
    → PipelineBUS 4 节点：
      1. node1_intent（验证+注入）
      2. node2_plan（LLM 规划，chat_json，1次）
      3. node3_execute（真实执行 + Guardian 并进审核，chat_json N次）
      4. node4_summary（LLM 合成 + Guardian 审核，chat_json 2次）
→ ReplyMessage → OutboundEventBus → SSE → 薄插件 → QQ
```

| 脚本 | 11 | smoke_test + 数据导入 + 迁移 + 测试 |
