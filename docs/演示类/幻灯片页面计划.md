# Emily公司试点汇报
- 风格定位：B站科普区UP叙事，节奏轻松、层层递进。叙述不过于学术化、沉闷。通过生动的比喻、流行梗等概念高效表达的手段，降低认知负担。
- 听众：地产公司高层；时长：20～25分钟
## 讲述计划：
1. 什么是企业AI中枢
    - 以去东站接人的经历作为钩子切入正题：知道车次（G1223），却不知道在哪个出站口出。
    - 先问通用AI（豆包）→ 得到一段"头头是道但没用"的回答（没有固定出站口、下至B1到达大厅…），拿不到有效信息。
    - 再看站内服务台的AI‘杭小东’→ 扫码接入，直接给出准确的出站口与导航路书。
    - 据此点题：**"它不是不聪明，而是它不在现场"**——通用AI与企业AI的分水岭，在于是否掌握私域（内部/现场）信息。（这里简化概念只以内部静态信息问答指代企业AI工具，emily的其他能力后续再补充，不在这里展开）
    - 对外形象展示窗口（可接入微信小程序）

2. 从个人视角讲述emily可解决的工作痛点：（先说个人，再说团队，循序渐进，以点带面）
    - 海量信息速查（项目信息、沉淀的历史项目资料）
    - 快速上岗手册（公司制度）
    - 管理一线员工（任务发放，自然语言引导按规范上报）

3. 延伸到企业团队视角使用emily可解决的工作痛点：
    
    - 蒸馏同事（企业经验技术资产数字化）
    - 团队‘养虾’（面向企业的AI工具的驯化）
    
4. 总结emily的本质。

## 具体PPT页面（一页一个概念）：

> 呈现方式：把它当**一期 B 站科普视频**来做——一个冷开场钩子 → 三章正片 → 片尾收束，总时长 20～25 分钟。
> 每页给三样东西：**画面**（屏幕/分镜上放什么）、**口播**（怎么讲，带比喻、带梗）、**花字**（屏幕大字/字幕，负责"一句记住"）。标 ⭐ 的是高能页，可放慢、留白。
> 篇幅预算：片头约 2.5 分钟｜第一章约 3.5 分钟｜第二章约 7 分钟｜第三章约 7 分钟｜片尾约 5 分钟。

### 片头（约 2.5 分钟）

**P01｜片头：一个还在长出来的东西**
- 画面：黑底淡入主标题「Emily · 企业记忆中枢」，副标题「一个给公司用的 AI 助理」；左下角小字"UP主：XXX"。
- 口播：今天不讲成果，讲个还在长出来的东西。你先别急着搞懂它是什么——我先讲一件我自己的小事，听完你大概就懂了。
- 花字：「这不是发布会，是一期科普」

**P02｜冷开场：同一趟车，问了两个 AI ⭐**
- 画面：左右分屏，两个聊天框同时回答"G1223 从哪个出站口出？"——左（豆包）一大段，右（杭小东）一句到位 + 一张导航路书。
- 口播：前几天去杭州东站接人，车次我有——G1223。可就这一个大活人，我得知道它从哪个口出来。我先问了豆包……你看它答得头头是道：没有固定出站口、由当天站台决定、下到 B1 到达大厅……逻辑满分，但对我一点用没有。后来我瞄见站里服务台有个二维码，叫"杭小东"，一扫——出口、路书，一步到位。
- 花字：「左边说了很多，右边说了有用」
- 转场：画面定格 + 悬念音效，"为什么？"

### 第一章｜什么是企业 AI 中枢（进度条 01/03，约 3.5 分钟）

**P03｜高能点题：它不是不聪明，而是它不在现场 ⭐**
- 画面：全屏大字「它不是不聪明，而是它不在现场」，下方小字"——差在一个词：私域信息"。
- 口播：我想了一下，豆包不是不聪明，它是——不在现场。它手里没有车站的实时数据。杭小东为什么行？因为它握着"现场"的信息。这一条，就是通用 AI 和企业 AI 的分水岭：有没有私域信息。
- 花字：「通用 AI vs 企业 AI，差在'在不在现场'」

**P04｜对比：就差在'在不在现场'**
- 画面：左右对照卡。
  - 通用 AI：知识来自公开互联网 → 同一个问题，给"正确但没用"的答案
  - 企业 AI：知识来自企业内部私域 → 给真名、真文件、真数据
  - 底部一行大字：企业里，"差不多对" = 不能用
- 口播：搬回公司你就懂了。你问"我们报销标准是啥""某个项目的负责人是谁"，通用 AI 只能给你一段模板话术；企业 AI 能告诉你——是谁、在哪份文件、第几条。企业场景里，"差不多对"等于不能用，要的是准。
- 花字：「准，是唯一的及格线」

**P05｜给公司配一个'杭小东' ⭐**
- 画面：定义句放大「企业 AI 工具 = 具备企业内部信息的问答智能体」；下方三个标签：内部信息 / 可溯源 / 用自然语言问。
- 口播：所以一句话：企业 AI 工具，就是具备企业内部信息的问答智能体。说人话——给公司也配一个"杭小东"。先划重点：这期只讲它最基础的一招，内部信息问答；别的本事后面慢慢放。
- 花字：「企业的'杭小东'」

**P06｜彩蛋：它还是'门面担当'**
- 画面：左侧客户头像 → 右侧 Emily，中间走一段客户问答（你们做什么 / 做过哪些项目 / 怎么合作）。
- 口播：顺手说个彩蛋：它不只对内，还能对外。接上小程序、官网，就是个 7×24 小时不打烊的商务接待。话术由公司审过，它只负责把话说准、说全。
- 花字：「对外的门面，也是它」

### 第二章｜一个人怎么用（进度条 02/03，约 7 分钟）

**P07｜转场：先看一个人的一天**
- 画面：章节卡「第二章 · 一个人怎么用」，副标题"先个人，后团队；先小痛，后大痛"。
- 口播：概念说完，上正菜。先看一个人——就我自己，一天里到底被什么卡住。

**P08｜扎心现场：1 万张照片，没人翻得动 ⭐**
- 画面：一整面"照片墙"糊满屏幕，角标"1 万+"；右侧一句反问"除了拍的人，谁知道它在这儿？"
- 口播：年中汇报，吴江林放了一万多张过程照片——别的项目其实特别需要。但说句实话，除了他自己，谁会去一万张里翻那几张"可能有用"的？考察报告也一样：写了、存了，需要的人根本不知道它存在，全靠人脑记、靠打听。问题不是没信息，是信息找不到人。
- 花字：「不是没信息，是信息找不到人」

**P09｜场景：一句话，把材料问出来**
- 画面：对话卡。Q"有没有项目在景观里用过'橡胶仿真草坪'？" A：命中"湖印晓庐"，附封样照片 + 厂家 + 报价。
- 口播：以前问这种问题得问一圈人、翻几个群。现在——一句话。而且它带着证据来：照片、厂家、报价，一次给全。不是"我印象里好像用过"。
- 花字：「带证据的回答」

**P10｜场景：答案藏在照片里，它也找得到**
- 画面：对话卡。Q"中式窄巷的景观雨水口有啥典型做法？" A：命中上虞"江南里"（2022）考察记录——导水槽 + 点式收水，附照片。
- 口播：这个问题你光打字搜不到，因为答案在照片里。它看得懂图，也记得住图。连"怎么做"这种经验，都能被翻出来复用。
- 花字：「图，也是知识」

**P11｜小结：海量信息，随问随有**
- 画面：三行标签。员工：流程制度 / 历史经验 / 工作手册；合作单位：统一资料 / 成果标准；所有人：资料列表 + 语义检索。
- 口播：一句话总结——通过语义识别，海量信息变成"随问随有"。谁能看到什么，跟着组织关系走，权限不越界。
- 花字：「语义识别 = 随问随有」

**P12｜名场面：一线师傅'说话就能上报' ⭐**
- 画面：对话流（黄湖项目 · 张师傅）。Q"铺装今天干了 10 平米"→ 系统主动推断部位、要远景+近景照片、复述确认、提醒找吴根林报验收。
- 口播：（放慢）这页我最想给你看。张师傅就一句大白话——"铺装今天干了 10 平米"。系统自己把它补齐了：是哪个部位、要什么照片、找谁验收。注意，对面说话的人，往往是语言表达一般的师傅。让他填表，等于让他放弃用。
- 花字：「他说大白话，系统补规范」

**P13｜拆解：这 5 步，系统都干了啥**
- 画面：表格（环节 / 它做了什么 / 背后逻辑），即提纲那 5 行。
- 口播：咱拆一下这五步……（快速过）核心就一句：每一个"体贴"，背后都是一次"降低认知负担"的设计。
- 花字：「体贴 = 降认知负担」

**P14｜高能点题：不是人适应系统，是系统适应人 ⭐**
- 画面：全屏大字。
- 口播：记住这句话——不是让用户适应系统，是让系统适应用户。能用大白话说明白的，就别让人填表。一个人的便利是这样，那……一整个团队呢？
- 花字：「系统适应人」
- 转场：第三章预告音效。

### 第三章｜一个团队怎么用（进度条 03/03，约 7 分钟）

**P15｜转场：从一个人的小确幸，到一群人的资产**
- 画面：章节卡「第三章 · 一个团队怎么用」，副标题"一个人的便利 → 一群人的资产"；埋两个词：蒸馏同事 / 团队养虾。
- 口播：一个人的便利，放大到团队，会变成什么？两个词先埋这儿——"蒸馏同事""团队养虾"。别急，往下看。

**P16｜概念：把同事'蒸馏'成资产**
- 画面：一个人 → 一张"经验卡" → 全公司复用，三步示意。
- 口播："蒸馏"是个玩笑说法：把优秀同事的管理技巧、怎么拆任务、子任务的活儿怎么要求，沉淀成能参考、能复用的东西。目的不是复制这个人——是不让一个人的离开，把公司的经验一起带走。
- 花字：「人走了，经验留下」

**P17｜场景：一个'潜水'在群里的同事**
- 画面：左项目群信息流 → 汇入 Emily；右两个结果：老员工走了信息还在 / 新人入职即上岗。
- 口播：项目群里的聊天，本身就是经验。它日常"潜水"收集，需要时随时翻出来。结果就是——老员工走了，经验没走；新员工来了，上手特别快。
- 花字：「老员工走了，经验没走」

**P18｜概念：一张图，看懂整个项目（全景节点图）**
- 画面：全景节点图缩略图（阶段 → 节点 → 子任务 → 成果要求）。
- 口播：每个项目都维护一张"全景节点图"，管理人员负责把节点拆开、给每个子任务定成果要求。它的价值在于——一个项目跑通，全项目可复用。标准被固化成图，而不是留在某个人的脑子里。
- 花字：「一项目跑通，全项目复用」

**P19｜名场面：一句话，生成一整个节点 ⭐**
- 画面：对话流 + 一张"节点信息卡"（编号 / 名称 / 责任人 / 参与人 / 资料 / 成果）。
- 口播：重点来了。有权限的人用大白话说一句"新建一个大区景观工程节点"——它先问你要不要套用标准节点，然后责任人、参与人、资料、成果，全自动规划好，最后汇总成一张卡，你确认，才生效。AI 提方案，人做决策。
- 花字：「AI 提方案，人做决策」

**P20｜场景：一个细节争议的'来龙去脉'**
- 画面：时间线。09.20 评审意见第 47 条 → 10.10 会议纪要 → 现状：图未出、无更新。
- 口播：壶园项目"船厅"入口台阶的尺度，之前到底议没议过？它顺着时间线一次讲清：谁提的、设计院怎么回的、后来怎么议的、卡在哪一步。以前这活儿得翻会议记录、问当事人，还不一定对得上。
- 花字：「一页看清来龙去脉」

**P21｜概念：养虾，还是团队养得好**
- 画面：左"一个人养虾" vs 右"团队养虾"；下方列出 SOP 内容：操作手册 / 公司制度 / 工艺标准。
- 口播：回到那个梗——通用 AI 就像养的电子宠物：一个人养，只适应你自己的习惯，换个同事就白养；团队一起养，习惯和标准才攒得下来。SOP 文件又多又常更新，交给它整合、匹配最新标准和流程，无损送到一线，学习成本压到最低。
- 花字：「一个人养 = 白养；团队养 = 资产」

### 片尾｜本质、落地与招人（约 5 分钟）

**P22｜升华：用大白话，跟复杂系统说话 ⭐**
- 画面：两个小故事并排。智能手机：把上网门槛降到"点一下" → 才有了网约车 / 电商 / 外卖；视窗系统：让普通人也能用电脑，此前只有命令行与专业领域。
- 口播：别小看"用大白话跟系统说话"这件事。当年智能手机把上网门槛降到"点一下"，才有了网约车、电商、外卖；视窗系统出现之前，电脑只有命令行，普通人都碰不了。Emily 干的是同一件事——把复杂技术的门槛打下来。
- 花字：「门槛降下来，行业才起来」

**P23｜幕后：它怎么搭起来的，怎么接入**
- 画面：上半=架构四块（静态知识库 / 动态全景节点图 / 标准工具套装 / 扩展能力 MCP·SKILL）；下半=三条接入通道（QQ / 微信小程序 / 企业微信），各标一行成本与优缺点；角落一行"以 DeepSeek 为例，四大名著体量的对话约 12 元"。
- 口播：掀开盖子看一眼：一套后端，多个入口。走哪条路——最低成本的 QQ 先跑通，还是直接上小程序、企业微信？这是要拍板的地方。顺便，成本真的不贵：一整部四大名著的对话量，大概十二块。
- 花字：「一套后端，多个入口」

**P24｜现状：软件已就位，就差'喂数据'**
- 画面：三块。① 已闭环、可上线 ② 已装黄湖 / 萧山宁牧 / 部分苏州资料，待授权清洗 ③ 沉淀路径 + 实践测试计划（苏州壶园景观工程，让 AI 当"观察者"跑一遍分项全流程）。
- 口播：坦白讲，软件这边已经闭环、能上线了。卡的从来不是技术，是数据——它是个记忆中枢，喂得越多越有用。所以这期不只是讲，也想请你一起：把各自的经验沉淀下来，蓝智讲堂、项目复盘、竣工资料，都能入网。
- 花字：「不缺技术，缺数据」

**P25｜片尾：我们自己的'杭小东'呢？**
- 画面：愿景句「项目与企业的记忆中枢全景控制台，让信息流转成本趋近于零」；小字"AI 给信息与参考，人负责决策与进化"；片尾留"讨论 / 提问"，末尾打一行"一键三连"字幕。
- 口播：最后回到最开始那个问题——车站都有"杭小东"了，我们自己的呢？它的价值不是某件事快了多少，是让地产的管理，从"高度依赖人"慢慢走到"以 AI 为中心"：AI 出信息，人做决策。这期讲到这儿，有问题咱们接着聊。
- 花字：「AI 出信息，人做决策」
- 片尾字幕：「点赞 / 投币 / 收藏——或者，直接来聊」

### 加更：评论区可能问到的问题（不上正片，随机应变）
- emily 是什么？——企业外置大脑；AI 驱动的企业记忆中枢。
- 价值在哪？——不在某项工作快多少、某项工艺省多少，而在把管理从"依赖人为节点"过渡到"以 AI 为中心"。
- 靠什么产生价值？——提高协作效率、提高信息利用率，让资产数字化、活化。
- 为什么是现在？——AI 正从互联网内部向各行业扩散。受众面大、人机互动标准化、不依赖人做最终交付的行业 AI 化快；地产独立性强、依赖人协调与实现，AI 化慢，**目前市场还没有对标项目**。
- 需要什么条件？——Emily 本质是记忆中枢，需要足够数据才能发挥价值；数据来自项目经验沉淀与应用反馈的迭代。
