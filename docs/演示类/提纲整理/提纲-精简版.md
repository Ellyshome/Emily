# Emily 演示提纲（精简版）

- 定位：B站科普区UP叙事 + 现场演示 + 企业价值提案
- 风格：轻松、层层递进、生动比喻、降低认知负担
- 听众：企业团队；形式：手机对话画面 + web幻灯片
- 切入：不用铺垫，直接从"杭小东"身边事切入

## 一、总纲：讲清楚一件事

- 不讲"AI有什么功能"，讲一个更简单的问题。
- 核心问题：AI真的进入一家企业，它应该知道什么、又能留下什么？
- 六步走：通用AI为什么"不知道" → 内部信息问答 → 信息整合速查 → 自然语言驱动工具 → 团队养虾 + 蒸馏同事 → 全景节点图 → 最后落到企业怎么接入、怎么跑试点。
- 技术放后面讲：故事没讲明白，讲Agent/RAG/状态机听众也不知为何存在。

## 二、开场：从"杭小东"说起

- 场景：去杭州东站接人，知道车次（G1223），但不知去哪个出站口等。
- 问通用AI"豆包"→ 答得泛泛，没给出关键信息。
- 原因：车站怎么走是公开信息；某车次今天从哪个口出，是车站当天的运营信息。
- 改用站内"杭小东"→ 精准查到出站口，还能给导航路书。
- 金句：**它不是不聪明，而是它不在现场。**
- 以此引出：与通用AI的区别——**内部信息问答**。

## 三、把杭州东站换成我们公司

- 对外的客户问："你们公司做过什么项目、有什么服务？"→ 通用AI答不了。
- 合作方问："这个项目现在推进到哪了？"→ 更不可能知道。
- 因为这是公司自己的信息、自己的项目、自己的规则。
- 金句：**企业缺的不是一个更聪明的AI，而是一个真正进入公司业务环境的AI。**

## 四、再进一步：信息整合速查

- 痛点：企业存了海量经验信息，但量一大了，人读不完，不知道里边有什么，成了死知识。
- 例1：年中汇报，吴江林展示了项目推进中收集的一万多张过程照片——很有价值，但除了他，其他人难以利用。
- 例2：老员工写PPT、做分享，当时这批人听了知道，新同事来还是不知道；就算翻文档，海量历史资料也读不完，真要用的时候还想不起在哪看过。
- 这些资料随着时间，沉积为休眠信息。
- 现在我们让AI去读、去标记、去组织，需要时一键检索出来。
- 金句：**很多公司的问题不是没有信息，而是信息只有"人肉搜索引擎"。**
- 而这个搜索引擎一旦换人，基本就掉线了。

## 五、本质升级：自然语言驱动复杂工具

- 以上功能，本质是给通用AI加了一个"企业内部信息背包"，很多开源项目稍改就能做。
- 但从更本质的角度看，关键是**自然语言理解能力**。
- 一方面：让个人能力有增幅。比如姚总用AI做出了很多让人眼前一亮的东西——AI时代之前，想做到类似程度要花极大精力学各种工具。
- 另一方面：让更多的人，可以在更广的维度上协作。
- 类比：DOS年代 vs 图形化界面。DOS年代只有专业人士能用电脑，图形化界面出现后，降低了接入门槛——网购、打车、自媒体、办公协作……哪怕只有小学文化，都可以纳入网络协作。

### 场景：一线员工自然语言上传完工报告

- 将更多人纳入系统，降低认知负担。
- 模拟黄湖项目，展示自然语言沟通弱的一般劳动者也能用。

## 六、"养虾"：一个人养，还是整个团队养？

- 养虾 = 养一个长期运行、会调工具、能持续干活的AI。
- 个人使用的AI工具有很多，但要自己花时间投喂数据、矫正工作模式。
- 个人养的局限：踩过的坑别人不知道，教的流程别人用不上，组织信息还是散的。
- Emily想做的：不要各养各的，整个团队一起养一个。
- 例：老员工教报销流程，新同事直接问；规则变了告诉一次，全员用新规则。
- 金句：**一个人的知识，开始变成团队可以共享的知识。**
- 本质：把知识沉淀的主体，从个人往团队移动。
- 个人养，复用性低；**团队养**，价值更大。

### 场景：下级单位使用标准业务流SOP

- 操作手册、公司制度、工艺标准，文件量巨大且持续更新。
- AI整合数据库，匹配最新流程要求、执行标准。
- 无损直达一线，极限降低学习成本。

## 七、"蒸馏同事"：最值钱的不是文件，而是经验

- 痛点：每个项目运转中，有大量的中间信息、工作经验、办事流程——不存在于正式记录中，散落在工作群讨论里、经手人的记忆里、或隐藏在大部头的经验文档里。
- 其他参与者了解情况，依赖询问与老员工的回忆。
- 员工的人事变动，意味着大量信息就此断线。
- 金句：**人把项目做完了，项目的经验却不一定留下来。**

### "蒸馏同事"是什么

- 前段时间有个AI概念叫"蒸馏同事"——让AI作为数字员工，参与讨论，保留项目集体记忆。
- 渠道：接入通讯软件，卧底工作群，收集沟通信息。
- 不是把一个人复制出来，而是把经验蒸馏成团队可调用的知识。
- 金句：**人可以离开项目，但经验最好不要一起离开。**

## 八、项目信息地图：全景节点图

- 行业难点：信息不是孤岛，是相互关联的。
- 每个项目维护一套全景节点图，管理人员负责节点分解与子任务成果约束。
- 文件语义读取，自动构建全景节点图。
- 节点复用：一项任务要拆解哪些子任务、各任务的完成标准、需要的条件与资源——一项目跑通，全项目可复用参考。
- 执行标准，直接传达到一线。

### 怎么让AI理解我们的行业

- 每个项目有全景计划。企业制定统一的、里程碑性质的节点（如"方案评审通过"、"取得施工许可证"、"二次结构完成"、"竣工验收"），给出成果约束条件、合理时间周期、负责人。
- 项目各专业管理人，根据任务分解子节点；所有材料进场、完工确认都由一线合作单位员工录入，管理人员确认。
- 每个里程碑节点分解成多少层、每个节点的成果约束（比如铺装完工的验测标准）都从对话中下发，直达一线。

## 十、从个人经验，到企业能力

- 链条：一个人做过一件事 → 事情进入项目记录 → 项目经验被团队复用 → 长期积累变成公司能力。
- 金句：**个人经验 → 项目经验 → 团队记忆 → 企业能力。**
- Emily不是凭空创造，而是帮公司把已存在、但容易散掉的东西留下来。

---

## 十一、"越用越强"到底是什么意思？

- 澄清：不是AI自己偷偷训练自己。
- 逻辑朴素：做项目多留数据；解决问题多留经验；发现共性问题整理成规则/SOP；发现重复动作做成工具。
- 下次遇到类似问题，就多一层可复用的东西。
- 本质：公司在用AI的过程中，也在给自己做数字化沉淀。

---

## 十二、为什么它能做到？（Emily背后的三样东西）

- 关键不是用了什么神奇大模型，而是准备了三类东西。
- 第一类 全景信息（知道现在发生什么）：项目、标段、节点、事件、人员、时间、状态——一张项目地图。
- 第二类 规则（知道应该怎么做）：制度、标准、规则、SOP——何时验收、谁负责、验什么、出问题怎么处理。
- 第三类 业务能力（知道能帮你做什么）：查资料、查项目、填表、生成报告、调用其他系统——通过插件/Skill增加。
- 公式：公司的数据 + 公司的规则 + 公司的业务能力。
- 模型只是大脑，让它成为"公司里的AI"的是周围这套业务环境。

---

## 十三、如果真的运行一年，会发生什么？

- 最值得期待的不是多答了多少问题，而是公司出现四个变化。
- 一、信息更容易找：过去找文件找人翻群，以后直接问。
- 二、项目过程更容易追：过去靠经办人回忆，以后沿项目事件去查。
- 三、管理信息更容易穿透：领导不必层层问，直接从项目过程找信息。
- 四、经验更容易留下：人员变化后不至于从头再来。
- 四句话：**信息不丢失、知识找得到、管理看得见、经验留得住。**

## 十四、现在Emily做到哪一步？

- 坦白：还不是成熟企业级产品，但也绝不是从零画PPT。
- 软件已经闭环，可上线。
- 当前装载了部分黄湖项目、萧山宁牧项目的经验资料，以及部分苏州项目资料。
- 最大瓶颈不再是"技术能不能做出来"，而是"能不能让它真正认识这家公司"。

## 十五、它现在缺什么？

- 最重要的投入不是继续堆代码，而是只有公司才拿得出来的东西。
- 第一，业务流：哪些专业、哪些阶段、按什么顺序走；每个动作谁发起、谁确认。
- 第二，项目全景节点：节点怎么分；何时开启/闭合；每个节点信息哪些角色可见。
- 第三，节点成果审核规则：谁审、审什么、依据什么标准、什么算通过。
- 这三套规则是Emily的冷启动数据，它以后所有的自我进化都从这里开始。
- 第四，公司过去发生过什么：历史资料、项目记录、过程信息和经验。
- 第五，一个真实项目：没有真实项目，永远只能讨论"AI应该可以怎么样"。
- 当前信息沉淀路径：提交各类经验技术文本、制作全景节点（成果约束）、贡献信息标注（数据标注、清洗）。
- 金句：**这三套规则不是给Emily的"资料"，是它的冷启动数据——它以后所有的自我进化，都从这套起点开始。**

## 十六、选择接入路径：企业微信、微信小程序，还是QQ？

- 后端同一套，前端入口可选，主要三条路。
- **第一条，企业微信。** 注册免费，认证按规模几百元/年；组织架构、身份、角色天然打通，最匹配分层鉴权；能主动推消息；边界是只覆盖公司内部的人。
- **第二条，微信小程序。** 注册免费，认证约300元/年，加备案开发维护投入最重；最容易落到一线（扫码就用）；也是对外窗口；代价是开发维护最贵、消息触达受限、离开微信就用不了。
- **第三条，QQ。** 成本几乎为零、接得最快、天然在群里干活；但适合自己先验证，不适合当企业正式入口（稳定性、留痕合规、对外公信力不够）。
- 建议：内部管理与集团穿透走企业微信；一线上报、参建协同、对外展示走小程序；QQ留给自己快速验证。

## 十七、我不建议一上来做"大项目"

- 不是来申请大而全的AI项目，恰恰相反——建议先小一点。
- 选一个真实项目，或先选一个相对集中的业务领域。
- 接进一套制度、一批历史资料，把一个真实项目跑起来。
- 只验证三个问题：一、能不能减少信息查找成本？二、能不能让项目管理过程更透明？三、能不能把项目经验真正留下来？
- 三个都能验证就继续：从一个项目扩到多个，从一个专业扩到更多专业，最后再考虑集团化。
- 这样风险最小，验证也最真实。

## 十八、实践测试：苏州壶园项目的景观工程管理任务

- 让AI作为观察者，观察一个分项的全流程信息。
- 信息收集：工程管理计划、工程日志、样品信息追踪、材料进场、日常巡检验收、工艺实践、完工确认等。
- 框架运转磨合：全景节点的子节点分解、节点成果完工标准测试等。

## 十九、最后：给Emily一个真实项目

- 一句话总结：不是申请现在就做大而全的AI项目，而是希望公司给Emily一个真实项目。
- 让它进去、跑起来，看它到底能不能真的帮项目团队干活。
- 公司需要提供：一个试点场景、一批真实数据、一套业务规则、基本运行条件。
- 剩下的开发和迭代，我来负责。
- 收尾金句：**如果一个AI真的开始记住我们的项目、理解我们的规则、留下我们的经验，一年以后，它能不能成为公司真正的一名"数字同事"。**

## 二十、现场问答备用（每问一句答）

- **Emily是什么？** → 企业外置大脑；AI驱动的企业记忆中枢。
- **Emily的价值？** → 不在于某项具体工作效率提升多少，而在于将地产行业现有管理，由高度依赖人为节点的模式，逐步过渡到以AI为中心的模式。AI提供信息与参考，人负责决策和进化。
- **产生价值的方式？** → 提高协作效率，提高信息利用率。资产数字化、活化。
- **与普通知识库的区别？** → 知识库解决"把文件找出来"；Emily更进一步——理解项目、理解规则、理解过程，并参与业务动作。
- **要不要把所有数据都给它？** → 不需要也不应该；按业务、权限、用途逐步接入，让AI在每个人的权限边界内工作。
- **AI答错怎么办？** → 关键业务不把AI自由回答当最终审批；重要回答要有来源依据；流程执行用企业规则和权限约束。AI负责理解/检索/辅助，企业制度负责约束。
- **会不会泄密？** → 企业内部部署+权限体系是基础；不是让所有人看到所有信息，而是让AI在用户权限边界内工作。
- **最大的成本？** → 冷启动阶段不是Token，而是数据整理、规则梳理、业务人员参与——也正是冷启动数据；软件运行成本反而容易计算。
- **还要不断开发吗？** → 会，但不是每次重做系统；新业务加Skill、新规则更新规则、新知识进知识库、新系统用插件接——形成可持续生长的业务内核。
- **最终能不能替代人？** → 没必要定成替代人；先替人做低价值信息工作（找资料、翻记录、整理过程、重复录入、生成基础报告），同时把人的经验留下来。人负责做完事，Emily负责尽量把做过的事留下来。
- **当前市场情况？** → AI的应用从计算机互联网内部开始，逐步向各行各业扩散。受众面大、人机互动标准化程度高的产业，AI化速度快。地产类独立性强、依赖人做最终实现与协调管理的行业AI化慢。当前市场还没有对标项目。
- **AI的能力边界？** → 有人用豆包指导去买榴莲，结果开出来的果肉达不到一般水准。不是AI做不了，而是挑榴莲这个专项任务没有专业技能训练。当前处于AI爆发起步阶段，优先蔓延到关联性强的数字领域、影响面大的领域，与自然关联强、依赖人实现的领域较慢。

## 二十一、演示时记住三个原则

- **原则1 让Emily说，少讲技术：** 架构最多讲几分钟，别让Agent/RAG/向量库/状态机抢主线；听众关心它能不能解决公司问题。
- **原则2 故意从"普通问题"开始：** 先问一个通用AI也能答的问题，再问"公司标准"，再问"项目发生过什么"——差异一层层出来。
- **原则3 最后一定落到真实试点：** 不要让听众觉得听了一个大研发规划，而要让他们觉得"这东西有基础，现在只需给一个真实项目验证一下"。

## 二十二、全程只保留这几句金句

- 它不是不聪明，而是它不在现场。
- 企业真正缺的，很多时候不是一个更聪明的AI，而是一个真正进入公司业务环境的AI。
- 不是让AI知道全世界，而是让AI真正知道我们公司。
- 很多公司的问题不是没有信息，而是信息只有"人肉搜索引擎"。
- 一个人的知识，开始变成团队可以共享的知识。
- 个人养，复用性低；团队养，价值更大。
- 人可以离开项目，但经验最好不要一起离开。
- 个人经验 → 项目经验 → 团队记忆 → 企业能力。
- 信息不丢失、知识找得到、管理看得见、经验留得住。
- 这三套规则不是给Emily的"资料"，是它的冷启动数据——它以后所有的自我进化，都从这套起点开始。
- 我们不是先做一个大项目，而是先给Emily一个真实项目，让它跑起来看看。

## 附：这版的节奏逻辑（递进关系）

- AI为什么不知道？→ 因为它没有进入我们的业务环境（杭小东 → 企业版杭小东）。
- 进入公司以后先知道什么？→ 先知道公司规则（内部信息问答：对外形象、合作方问答）。
- 再进一步能做什么？→ 信息整合速查，把沉睡的海量资料激活（查材料、查做法）。
- 本质是什么？→ 自然语言理解能力，驱动复杂工具，让更多人能参与协作（一线员工完工报告）。
- 从个人到团队？→ "养虾"：个人养 vs 团队养，知识沉淀主体从个人移到团队（SOP、规范要求）。
- 经验怎么留下？→ "蒸馏同事"：把散落在群聊和人脑中的经验组织成团队可调用的知识（事件追溯、管理复用）。
- 最高形态？→ 项目信息地图 / 全景节点图：信息不是孤岛，是相互关联的一张网（创建节点、状态查询）。
- 为什么它能做到？→ 数据 + 规则 + 业务能力。
- 现在缺什么？→ 公司手里的三套规则（业务流、全景节点、成果审核规则），这是冷启动数据也是自我进化起点。
- 从哪个入口进？→ 企业微信 / 微信小程序 / QQ。
- 所以别先做大，给它一个真实项目跑起来（苏州壶园试点）。
- 终点结论：企业缺的不是一个聊天机器人，而是一个真正进入业务、记住项目、理解规则、并且能把经验留下来的AI——企业的记忆中枢。
