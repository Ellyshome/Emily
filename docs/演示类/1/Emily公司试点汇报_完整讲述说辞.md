Emily公司试点汇报——完整讲述说辞与演示流程
定位：轻松科普式叙事 + 现场产品演示 + 企业试点提案
目标听众：地产公司高层管理团队
建议时长：20～25分钟
核心目标：让听众理解“为什么需要企业自己的AI”，相信Emily已经具备试点基础，并愿意提供真实业务场景、数据规则和基础经费进行试点。

==================================================
一、整体叙事主线
==================================================

不要按照传统“背景—产品—技术—预算”的汇报方式展开，而采用一条逐渐深入的认知路径：

生活小场景
→ 通用AI为什么有时“不知道”
→ 企业真正需要的是进入业务环境的AI
→ 最近为什么大家开始“养虾”
→ AI正在从一次性问答工具变成长期数字同事
→ Emily是什么
→ 现场问Emily一个真实地产项目
→ 从“会回答”到“记住项目”
→ 从个人助手到团队记忆中枢
→ 从知识沉淀到企业能力沉淀
→ 为什么它能做到：全景节点 + 企业规则/SOP + 工具/插件
→ Emily当前做到什么
→ 真正缺什么：公司的数据、规则和真实项目
→ 建议低成本试点
→ 请求公司提供试点条件

全程避免一开始堆砌“Agent、RAG、向量数据库、状态机”等技术名词。
技术只在听众已经产生兴趣之后，用来解释“为什么Emily不是普通聊天机器人”。

==================================================
二、开场：杭州东站出站口
预计2分钟
目的：用一个生活场景，让听众自己发现“通用AI也有不知道的东西”。
==================================================

【页面1：标题页】
说：
“今天不准备按照传统方式给大家汇报一个AI项目。
我想先从一个特别小的事情讲起。”

“而且这个事情可能大家都遇到过。”

切入下一页。

【页面2：去杭州东站接人】
说：
“假设我们去杭州东站接一个朋友。
朋友坐高铁过来，快到了，给我发消息：
‘我到了，你在哪接我？’”

“我可能第一反应就是问AI：
‘GXXXX这个车次，从杭州东站哪个出口出来？’”

“然后你会发现一个很有意思的事情——
普通通用AI，未必能准确告诉你。”

停顿。

“这就有点奇怪了。
现在的AI不是已经知道很多东西了吗？”

【页面3：为什么AI不知道】
说：
“后来你会发现，这其实不是它聪明不聪明的问题。”

“杭州东站有几个进站口、车站怎么走，这些都是公开信息。
但是某一个具体车次今天到底从哪个出站口出来，可能是车站内部根据当天实际情况实时调度的。”

“这个信息，不是一个固定知识。
它存在于车站自己的业务系统和现场运营里面。”

“而杭州东站其实已经有这样的企业AI入口——‘杭小东’。”

“我当时就是通过它，快速查到了这个车次实时的出站信息。”
“更有意思的是，它不只是告诉我一个出口，还可以结合我当时所在的位置，继续给我生成一段可以直接照着走的电子场景路书。”

“所以这里不是一个假设案例，而是一个已经发生的真实体验。”

“同样是AI，为什么一个通用AI回答不了，而站内这个AI却可以？
核心不是模型突然变聪明了，而是它进入了车站自己的信息环境，知道车站的实时业务状态，也知道这个场景下可以给用户提供什么服务。”

总结：
“这其实揭示了一个很重要的事情：

AI知道多少，和它有没有进入一个具体的业务环境，是两回事。”

三、从车站切到地产
预计2分钟
目的：让听众理解“行业垂直AI”的必要性。
==================================================

【页面4：如果换成地产公司】
说：
“我们把这个场景换成地产公司，其实完全一样。”

“比如问AI：
‘大树移栽需要注意什么？’”

“豆包、ChatGPT这类通用AI，完全可以回答，而且可能回答得还不错。”

“但是我换一个问题。”

“‘我们公司的乔木栽植验收标准是什么？’”

停顿。

“这时候它就不知道了。”

继续：
“如果再问：
‘我们XX项目今年5月份那次乔木移栽出现问题，当时是怎么处理的？’”

“这个问题，通用AI更不可能知道。”

总结：
“所以企业真正缺的，很多时候不是一个更聪明的AI。”

“而是一个真正进入公司业务环境的AI。”

四、全民养虾：引入时代背景
预计2分钟
目的：借当前AI热点降低技术理解门槛，引出“长期数字同事”概念。

【页面5：最近大家开始养虾】
说：
“这两年AI有一个很有意思的变化。
大家可能发现，最近突然很多人在‘养虾’。”

“这里的虾不是吃的，是OpenClaw这一类可以长期运行、持续调用工具的AI Agent。”

“为什么大家会觉得这种东西有意思？”

“因为它已经不太像一个搜索框了。”

“你不是问它一个问题，它回答完就结束。
而是可以把它放在身边，让它长期记东西、调用工具、完成任务、不断增加能力。”

“所以现在AI正在从：
‘我问你一个问题’
慢慢变成
‘我身边有一个数字同事’。”

【页面6：什么叫“蒸馏同事”】

“这里还有一个我觉得特别有意思的方向，叫‘蒸馏同事’。”

“一个项目经理干了五年项目。
他知道很多东西：

什么情况要提前处理，
公司习惯怎么做，
某个合作单位以前出过什么问题。”

“但是这个人离职以后，这些东西怎么办？”

“以前我们只能说：
‘可惜，经验没留下。’”

“现在我们可以换一个问题：

能不能把一个优秀员工长期工作过程中形成的方法、经验、判断标准，逐步沉淀成一个数字同事？”

停顿。

“这就是我理解的‘蒸馏同事’。”

【页面8：现场演示——先问一个普通问题】

“我们不先看系统架构。
直接问它几个问题。”

操作Emily：
“乔木移栽需要注意什么？”

“这个问题普通AI也能回答。”

“所以如果Emily只做到这里，它没有什么特别的。”

切换问题。

【页面9：问公司标准】
操作：
“我们公司的乔木栽植验收标准是什么？”

说：
“现在问题就发生变化了。”

“它回答的已经不是网上的通用知识，而是我们企业自己的标准。”

“而且我们希望它不仅告诉你答案，还能告诉你依据来自哪里。”

【页面10：问项目】
操作：
“XX项目最近有没有发生乔木移栽相关问题？”

说：
“现在再往前走一步。”

“它开始从‘公司知识’进入‘项目记忆’。”

“我们真正希望它记住的，不只是一个文件，而是：
什么时候发生了什么，
谁发现的，
怎么处理的，
最后结果怎么样。”

【页面11：连续追问】
连续问：
“是谁发现的？”
“什么时候发生的？”
“当时怎么处理？”
“最后解决了吗？”

说：
“这时候它已经不是一个文档搜索框。”

“它开始形成一条项目事件链。”

“这也是我们做Emily时非常看重的一件事情：
让项目过程本身成为可以被查询、被追溯、被复用的记忆。”

【页面12：集团管理视角】
操作：
“现在XX项目整体处于什么状态？”
“最近有哪些风险？”
“景观工程最近有哪些未完成事项？”

说：
“如果我是项目负责人，我可以这么问。”

“如果我是集团领导，我还可以继续问：
‘最近所有项目有没有类似问题？’”

“这时候视角就从一个员工的问题，变成了团队和集团的管理信息。”

八、从“会回答”上升到“项目团队记忆中枢”
预计2分钟
==================================================

【页面13：项目团队记忆中枢】
说：
“所以我后来给Emily一个定位：
项目团队的记忆中枢。”

“它记的不是简单的‘文件在哪里’。”

“而是：
发生过什么；
为什么发生；
怎么处理；
结果怎么样；
以后再遇到类似问题怎么办。”

“这样，一个项目结束以后，项目并不是‘结束了就结束了’。”

“项目过程中的信息和经验，还可以继续为下一个项目服务。”

“但这里还有一个非常现实、而且可能更高频的场景——新员工入职。”

“一个新人进入公司，真正困难的往往不是不会做某一项具体工作，而是不知道：
公司有哪些制度；
这个岗位有哪些要求；
自己参与的项目现在进行到哪一步；
以前发生过哪些事情；
遇到问题应该找谁、按照什么标准处理。”

“传统方法是什么？
培训、讲制度、发资料、让新人自己看文件，然后遇到问题再问老员工。”

“但地产公司的文件库往往非常庞大，也会有历史版本、重复文件和大量背景资料。
公司没有足够的人力把所有文件维护得非常精细，新员工也几乎不可能把这些东西全部读完。”

“最后就变成一种大家都很熟悉的方式：
用到哪儿，找到哪儿；
找不到，就问同事；
同事再靠自己的经验告诉你。”

“这其实也是一种人力成本。”

“如果Emily掌握企业制度、岗位要求，以及这个员工正在参与的项目和项目过往记录，它就可以变成一个‘入职陪练’。”

“新人不是先花大量时间把整个公司文件库读一遍，而是可以直接问：
‘我这个岗位最需要关注哪些制度？’
‘我现在参与的项目过去发生过什么？’
‘这个项目目前处于什么状态？’
‘按照公司的要求，这个节点我应该做什么？’
‘以前类似问题是怎么处理的？’”

“这时候，Emily实际上是在把原来依赖培训、翻文件和传帮带完成的一部分工作，变成一个可以随时使用的数字化辅助过程。”

“所以它解决的并不只是‘老人走了，经验怎么办’。
还有一个问题是：
‘新人来了，怎么更快成为一个真正懂公司、懂项目的人？’”

个人经验

“Emily要做的，本质上就是帮助这个过程发生。”

【页面15：越用越强】

“它不是说Emily自己偷偷训练自己。”

“真正的逻辑是：
每做一次项目，
就可能多留下一点数据；

再把这些经验整理成规则、SOP或者新的工具能力。”

“于是下一次Emily就比上一次更懂公司。”

“所以我把它戏称为：
‘越用越强的团队养虾。’”

十一、为什么Emily能够做到
预计3分钟
==================================================

【页面16：Emily为什么懂公司】
说：
“那么问题来了：
它凭什么知道这些？”

“其实不是因为我们用了一个特别神奇的模型。”

“真正重要的是，我们给它建立了三类东西。”

第一：
“第一类，是它知道‘现在发生了什么’。”

“比如项目、标段、节点、事件、人员、时间、状态。
我们把这些组织成项目的全景信息。”

“可以简单理解成：
让AI有一张‘项目地图’。”

第二：
“第二类，是它知道‘应该怎么做’。”

“这就是公司的制度、标准、规则和SOP。”

“比如什么情况下需要验收、谁负责、验收什么、出了问题怎么处理。”

第三：
“第三类，是它知道‘可以帮你做什么’。”

“例如查资料、查项目、填表、生成报告，甚至调用其他系统。”

“这些能力可以通过插件的方式不断增加。”

总结：
“所以真正让通用大模型变成公司AI的，不只是模型本身。”

“而是：

公司的数据
+
公司的规则
+
公司的业务能力。”

十二、价值：不要做传统功能清单
预计2分钟
==================================================

【页面17：如果Emily在公司里运行一年】
说：
“那么，如果Emily真的在公司里面运行一年，会发生什么？”

“我觉得可以看到四个变化。”

第一：
“对外，它可以成为一个新的企业服务入口。
客户、合作方、参建单位，不一定要知道系统在哪里，直接用自然语言问就可以。”

第二：
“对内，它可以成为一个新的知识入口。
过去是‘找文件、找人、问同事’，
以后逐渐变成‘直接问公司’。”

第三：
“对管理，它可以让项目过程更加透明。
领导不一定每次都要通过层层汇报才能了解项目状态，可以直接穿透到过程信息。”

第四：
“对组织，它最长期的价值，是让经验留下来。
人员变化以后，经验不至于全部跟着人一起消失。”

总结：
“所以我把它概括成四句话：

信息不丢失；
知识找得到；
管理看得见；
经验留得住。”

十四、真正需要公司提供什么
预计2分钟

【页面19：Emily现在缺的不是代码】
说：
“它现在最缺的东西，其实不是代码。”

“它缺的是公司的真实业务内容。”

第一：
“第一，公司怎么做。

“第三，让它进入一个真实项目。

第四：
“最后才是服务器、模型Token、小程序等基本运行条件。”

强调：
“所以这个项目真正需要投入的，可能并不是大量软件开发经费。”

“真正有价值的投入，是把公司原来已经存在、但分散在不同地方的知识和经验组织起来。”

【页面20：不要一开始做大，先做一个真实试点】

“所以我这次并不是想建议公司一开始就做一个很大的AI项目。”

十七、现场问答备用话题
==================================================

1. “它和企业微信AI、普通知识库有什么区别？”
答：
“普通知识库解决的是‘把文件找出来’。Emily希望进一步解决‘理解项目、理解规则、理解过程，并参与业务动作’。知识库是其中一个基础能力，不是最终形态。”

2. “是不是需要把所有数据都给它？”
答：
“不需要，也不应该。按照业务、权限和用途逐步接入。不同角色看到不同范围的信息，这是企业AI必须具备的基础能力。”

3. “AI答错怎么办？”
答：
“关键业务不能把AI自由回答当成最终审批。重要回答要有来源、有依据；涉及流程执行时由规则和权限控制。AI负责理解、检索和辅助，企业制度负责约束。”

4. “会不会泄密？”
答：
“企业内部部署和权限体系是基础。Emily的设计不是让所有人看到所有信息，而是让AI在用户权限边界内工作。”

5. “最大的成本是什么？”
答：
“冷启动阶段最大成本不是Token，而是数据整理、规则梳理和业务人员参与。软件运行成本反而比较明确。”

6. “以后是不是还要不断投入开发？”
答：
“会，但应该是插件式、模块化迭代。新业务增加新Skill，新规则更新规则，新知识进入知识库，而不是每次都重做整个系统。”

7. “新员工能不能直接靠Emily，不培训了？”
答：
“不能简单理解成取消培训。Emily更适合把培训从‘大量灌输资料’变成‘进入工作场景后的持续辅助’。基础培训仍然需要，但很多制度查找、项目背景熟悉和日常问题，可以随时问Emily，降低新人融入成本。”

8. “最终能不能替代人？”
答：
“不是这个目标。更现实的方向是替代大量低价值的信息查找、重复录入、过程整理工作，同时让人的经验更容易被组织复用。”

==================================================
十八、演示时的三个原则
==================================================

原则1：少讲技术，多让它现场工作。
技术架构最多用3分钟解释，不要成为主角。

原则2：故意先展示一个“普通问题”。
让听众先觉得“这不就是普通AI吗”，然后再通过企业标准和项目记忆逐层拉开差异。

原则3：最后一定落到“低成本试点”。
不要让高层感觉是在申请一个长期研发项目，而是申请一个可控、可验证的企业AI试验。

==================================================
十九、全程核心金句备用
==================================================

“AI知道多少，和它有没有进入一个具体的业务环境，是两回事。”

“企业真正缺的，很多时候不是一个更聪明的AI，而是一个真正进入公司业务环境的AI。”

“不是让AI知道全世界，而是让AI真正知道我们公司。”

“过去是找文件、找人、问同事；以后逐渐变成直接问公司。”

“人负责把事情做完，Emily负责把做过的事情留下来。”

“个人经验 → 项目经验 → 团队记忆 → 企业能力。”

“Emily不会凭空变聪明，它会把公司的经验不断变成自己的能力。”

“我们不是先做一个大项目，而是先给Emily一个真实项目，让它跑起来看看。”
