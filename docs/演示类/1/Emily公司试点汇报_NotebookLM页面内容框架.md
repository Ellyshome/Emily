Emily公司试点汇报——NotebookLM页面生成资料与内容框架
用途：将本文件整体提供给NotebookLM等生成工具，生成一套轻松、科普视频/B站UP主叙事感的企业演示文稿。
目标听众：地产公司高层管理团队；熟悉地产运营，对AI技术了解有限。
建议页数：22页。
建议风格：少文字、大图、强叙事、强转场；避免传统咨询汇报式密集文字。每页只表达一个核心意思。
核心视觉隐喻：从“一个生活问题”逐渐进入“公司自己的AI”，再进入“项目记忆—团队经验—企业能力”。
不要将页面做成技术白皮书，不要堆砌Agent、RAG、向量数据库、FSM等术语。

==================================================
一、总体视觉与叙事要求
==================================================

1. 整体气质
- 轻松、聪明、有一点幽默感。
- 接近优秀B站科技/商业科普UP主，而不是正式政府汇报或咨询公司PPT。
- 可以使用大字标题、漫画式插图、简单流程动画感、聊天气泡、手机界面、项目卡片等。
- 颜色建议克制，保持企业感；不要过度科技蓝、赛博朋克。

2. 页面原则
- 每页只讲一个核心观点。
- 标题尽量是“结论/问题”，而不是“第X章”。
- 少写定义，多用场景。
- 少写功能列表，多展示“一个问题如何逐渐深入”。
- 文字尽量短，完整解释留给现场讲述。

3. 技术内容原则
- 不主动展示复杂架构。
- 只有在“为什么Emily懂公司”一页中，用非常简单的三层结构表达：
  全景节点 / 企业规则与SOP / 工具与插件。
- 不使用复杂技术术语解释业务价值。

4. 演示原则
- 页面8～12为现场产品演示区，页面本身只做“问题提示”和“认知转场”，实际回答在Emily系统中完成。
- 页面16以后再回到系统原理、价值和试点。

==================================================
二、逐页内容框架
==================================================

【01 标题页】
标题：
“如果AI真的懂我们的公司，会发生什么？”

副标题：
“Emily——地产企业垂直领域AI智能体试点设想”

视觉：
不要使用典型机器人/大脑/代码背景。
建议使用“手机聊天界面 + 项目现场/住宅项目”的轻量组合。

核心目的：
不急于解释Emily，先制造问题。

--------------------------------------------------

【02 生活小场景：去杭州东站接人】
标题：
“先从一个很小的问题开始”

画面：
一个人在杭州东站接人。
手机聊天：
“GXXXX到了，从哪个出口出来？”

可以表现：
高铁站、手机、问AI。

核心目的：
让听众进入一个人人都能理解的生活场景。

--------------------------------------------------

【03 AI为什么不知道？】
标题：
“它不是不聪明，而是它不在现场”

画面左右对比：
公开信息：
- 车站结构
- 进站口
- 常规线路

内部实时信息：
- 某车次实时状态
- 当日调度
- 实际出站口

结论大字：
“通用知识 ≠ 业务现场信息”

--------------------------------------------------

【04 把杭州东站换成地产公司】
标题：
“换成我们公司，其实一模一样”

画面：
问题A：
“大树移栽需要注意什么？”
→ 通用AI可以回答

问题B：
“我们公司的乔木栽植验收标准是什么？”
→ 通用AI不知道

问题C：
“XX项目5月份那次乔木移栽问题，最后怎么处理的？”
→ 通用AI更加不知道

底部结论：
“企业需要的，不只是‘懂行业’的AI，而是‘懂我们’的AI。”

--------------------------------------------------

【05 全民养虾】
标题：
“最近，大家突然开始‘养虾’了”

内容：
用轻松方式解释OpenClaw/AI Agent现象。
不要详细介绍OpenClaw技术。

视觉：
一个拟人化的小虾/数字助手。
旁边用三个短词：
“记东西”
“调工具”
“长期工作”

结论：
“AI正在从‘问答工具’变成‘长期数字同事’。”

--------------------------------------------------

【06 蒸馏同事】
标题：
“如果一个优秀员工的经验，可以留下来呢？”

视觉：
左边：一个资深项目人员。
右边：一个数字同事。
中间：
“方法 / 经验 / 判断标准 / 项目经历”

底部：
“把个人经验逐步沉淀成组织可以复用的能力。”

可以小字标注：
“蒸馏同事”

--------------------------------------------------

【07 Emily正式出现】
标题：
“所以，我做了Emily”

中心定义：
“面向地产企业的垂直领域AI智能体”

下面三个标签：
“数字同事”
“项目记忆中枢”
“团队经验沉淀器”

一句话：
“不是替代员工，而是帮助员工做事，并把做过的事情留下来。”

--------------------------------------------------

【08 演示开始：先问一个普通问题】
标题：
“先问一个谁都会回答的问题”

屏幕中央模拟聊天气泡：
“乔木移栽需要注意什么？”

旁边小字：
“这一步，Emily和普通AI没有什么本质区别。”

目的：
故意降低期待，为后续差异做铺垫。

--------------------------------------------------

【09 第二问：公司的标准】
标题：
“那如果我问：我们公司怎么要求？”

聊天气泡：
“我们公司的乔木栽植验收标准是什么？”

右侧预留Emily实际回答区域。
建议回答区域展示：
- 标准名称
- 条款摘要
- 来源
- 适用条件

底部结论：
“从‘网上知识’进入‘企业知识’。”

--------------------------------------------------

【10 第三问：具体项目】
标题：
“再往前一步：它知道项目发生过什么吗？”

聊天气泡：
“XX项目最近有没有发生乔木移栽相关问题？”

画面：
从企业知识库切入一个具体项目。
展示项目名称、时间、事件等信息卡片。

结论：
“从‘企业知识’进入‘项目记忆’。”

--------------------------------------------------

【11 连续追问：形成事件链】
标题：
“真正有意思的是：可以继续追问”

连续聊天气泡：
“谁发现的？”
“什么时候发生的？”
“怎么处理的？”
“最后解决了吗？”

视觉：
四个问题串成时间轴/事件链。

底部：
“不是找到一份文件，而是还原一次真实发生过的事情。”

--------------------------------------------------

【12 从项目人员到集团领导】
标题：
“同一个Emily，换一个身份，问法就不一样”

左侧：
项目人员
“这个问题以前怎么处理？”

右侧：
集团管理者
“XX项目现在整体什么状态？”
“最近有哪些风险？”
“所有项目有没有类似问题？”

结论：
“从个人助手 → 项目信息入口 → 集团管理穿透”

--------------------------------------------------

【13 项目团队记忆中枢】
标题：
“所以，Emily真正想记住的不是‘文件在哪里’”

中心大字：
“发生过什么？”

周围五个词：
“为什么发生”
“谁处理”
“怎么处理”
“结果如何”
“以后怎么办”

底部：
“项目结束，记忆不结束。”

【14 新员工：从“翻文件”到“直接问公司】
标题：
“还有一种经验流失：新人根本不知道去哪里找”

画面建议：
左侧传统入职：
培训 → 发文件 → 翻文件库 → 找同事 → 传帮带

右侧Emily辅助：
岗位要求 + 企业制度 + 所参与项目 + 项目历史记录 + 当前状态
→ 随时提问
→ 快速进入工作场景

示例问题：
“我这个岗位最需要关注哪些制度？”
“我参与的项目以前发生过什么？”
“项目现在到哪一步？”
“这个节点按照公司要求应该做什么？”

底部结论：
“把新人熟悉公司、熟悉项目的一部分人力成本，变成持续可用的数字化辅助。”

【17 Emily为什么能懂公司？】

“它凭什么知道这些？”

① 全景节点

==================================================
三、建议NotebookLM特别注意的页面节奏
==================================================

第一阶段 01～04：
像科普视频，不像项目汇报。
目标：解释“为什么通用AI不等于企业AI”。

第二阶段 05～07：
像一个时代观察。
目标：借“全民养虾”和“蒸馏同事”让听众理解AI正在从工具变成长期数字同事，并正式引出Emily。

第三阶段 08～12：
整个演示的核心。
目标：不要解释Emily会什么，而是让听众看到“问法越来越深入，Emily能够越来越深入地回答”。

第四阶段 13～17：
把现场体验上升到系统原理，并加入“新员工快速融入”场景。
目标：解释“项目记忆”“团队经验”“新人上手”“全景节点、规则、工具”。

第五阶段 18～22：
从产品回到企业。
目标：讲价值、讲当前进展、讲缺口、讲低成本试点。

==================================================
四、不要出现的表达
==================================================

尽量避免：
“行业领先”
“赋能企业数字化转型”
“打造智能化新范式”
“基于先进的大语言模型技术”
“构建企业级AI中台”
“全面提升企业数字化水平”

这些词会迅速把轻松的科普叙事变成传统PPT汇报。

也不要在前半段出现：
RAG、向量数据库、Embedding、Agent编排、FSM、LangGraph等。

这些可以在被问到技术细节时再解释。

==================================================
五、整个PPT最终应该让听众记住的五句话
==================================================

1. “通用AI知道很多，但它不知道我们公司发生过什么。”
2. “企业真正需要的是一个进入自己业务环境的AI。”
3. “Emily不仅回答问题，还可以逐渐记住项目。”
4. “新人可以少一点翻文件、问同事，更快进入真实工作场景。”
5. “个人经验可以逐渐变成团队记忆，再变成企业能力。”
6. “现在不需要做一个大项目，先给Emily一个真实项目，让它跑起来。”

==================================================
六、NotebookLM生成时的最终调性
==================================================

这不是一套“AI产品说明书”。

它应该像一个懂AI、又懂地产的人，花20分钟给管理团队讲一个有意思的新东西：

先讲一个大家都能理解的故事，
让大家发现一个看似简单的问题，
再告诉大家这个问题背后其实是AI进入业务现场的问题，
然后借“养虾”“蒸馏同事”这些当下AI语境把认知拉近，
接着让Emily现场工作，
让听众自己看到它从“回答一个问题”变成“记住一个项目”，
最后再告诉大家：
这个东西已经做出来了，
现在真正需要的不是再写一个PPT，
而是给它一个真实项目试一试。

整体要有“发现感”，不要有“推销感”。
