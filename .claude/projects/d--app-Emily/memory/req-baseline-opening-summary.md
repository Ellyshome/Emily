- **规则**：所有「需求基线」文档（`{模块标识}_需求基线_V{N}.md`、`{模块标识}_意向需求基线_V{N}.md`）必须在**标题正下方**（元信息引用块 `> **性质** / **定位**` 之前）用"一句话"形式说明这份基线**做了什么**。
- **写法**：
  - 单主题：用一行 `**一句话**：…` 说清"做了什么"。
  - **多主题**：允许每个主题一句话（均以 `**一句话**：` 起行，每行一个独立主题），不必强行揉成一句。
  - 聚焦"做什么 / 改动了什么"，不写 Why、不写 How、不铺范围细节——那些留给后面的元信息块与正文。
- **示例（单主题）**：[节点成果管控_需求基线_V1.md](d:/app/Emily/Issues/节点成果管控/节点成果管控_需求基线_V1.md) 开头：`**一句话**：让任务级成果可配置"完工要带什么证据（如完工位置照片）"，并在完工录入时做软校验——缺证不拒绝，但必须由用户显式确认并留痕。`
- **示例（多主题）**：某基线同时包含「状态自证」「签认退役」「里程碑成果强制」三个并列主题 → 写三行 `**一句话**：…`，每行一个主题。

**Why:** 需求基线文档普遍很长（背景/取证/FR/数据模型/开放问题），评审者和后续 AI 需要在不读全文的前提下先知道"这份基线做了什么"，才能判断是否与当前任务相关；强行把多个并列主题揉进一句会导致句子臃肿、关键信息被淹没，多主题每主题一句反而更易快速扫读。
