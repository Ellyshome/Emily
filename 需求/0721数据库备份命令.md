# 数据库命令


## 备份

### 在项目根目录 d:\app\Emily 下执行
$ts = Get-Date -Format "yyyyMMdd_HHmmss"
$backupFile = "backups\emily_$ts.dump"

1. 容器内导出到 /tmp（避免 PowerShell 二进制重定向损坏）
docker exec emily-postgres pg_dump -U emily -d emily -Fc -f /tmp/emily_backup.dump

2. 拷出到宿主机
New-Item -ItemType Directory -Path "backups" -Force | Out-Null
docker cp emily-postgres:/tmp/emily_backup.dump $backupFile

3. 清理容器临时文件
docker exec emily-postgres rm /tmp/emily_backup.dump

Write-Host "备份完成: $backupFile ($([math]::Round((Get-Item $backupFile).Length/1KB, 1)) KB)" -ForegroundColor Green
---

#### 命令解释：
docker exec emily-postgres pg_dump -U emily -d emily -Fc -f /tmp/emily_backup.dump

-U emily
指定数据库登录用户名：emily
-d emily
指定要备份的数据库名：emily
-Fc
F = 自定义格式（custom format），c 代表压缩
特点：二进制压缩备份，支持单表恢复、选择性还原，pg_restore 专用格式，比普通 sql 文件高效
-f /tmp/emily_backup.dump
-f 指定输出文件路径
备份文件生成在容器内部的 /tmp 目录，文件名 emily_backup.dump
---

## 恢复（复现）

### 用实际备份文件名替换
$backupFile = "backups\emily_20260721_120000.dump"

1. 拷进容器
docker cp $backupFile emily-postgres:/tmp/emily_backup.dump

2. 干净恢复：先 DROP 再 CREATE 空库，再 pg_restore（最彻底，无残留）
docker exec emily-postgres psql -U emily -d postgres -c "DROP DATABASE IF EXISTS emily;"
docker exec emily-postgres psql -U emily -d postgres -c "CREATE DATABASE emily OWNER emily;"
docker exec emily-postgres pg_restore -U emily -d emily -v /tmp/emily_backup.dump

3. 清理
docker exec emily-postgres rm /tmp/emily_backup.dump

4. 重启 emily-core 让连接池重建（可选，建议做）
docker compose -f docker-compose-napcat.yml restart emily-core
---

⚠ PowerShell 二进制陷阱：
不要用 docker exec ... pg_dump -Fc > file.dump 的重定向写法——PowerShell 会按文本编码处理二进制流，损坏 .dump 文件。
务必用容器内 -f /tmp/... + docker cp 两步走。
