# 三书认知装配层与会话编排 — 概要设计（SD）

> **基于规格（PRD）**：[三书认知装配层_PRD_V1.md](三书认知装配层_PRD_V1.md)
> **宪法版本**：v1.0
> **设计版本**：v1.0
> **级别**：System Design（概要设计）
> **目标**：把三书摘要接回会话判断依据（摘要常驻 + 全文按需），并注入会话编排能力，使"先查后办"与"信息不足时只读补齐"可落地，且不拖慢简单诉求、不破坏前缀缓存。

## 硬约束（违反即失败）

> 项目铁律直接引用 [宪法 §2](../.claude/skills/_shared/constitution.md)，**不自行发明**。

1. **禁止修改已有接口签名**：除非设计明确标注"修改接口签名"，否则只能在已有类中新增方法/字段/返回键，不修改现有方法签名与语义
2. **遵循宪法铁律 C0~C11**——本设计涉及项及遵守方式：

   | 铁律 | 本设计如何遵守 |
   |------|--------------|
   | **C0 根治而非迁就** | 常驻摘要以"**当前操作者**"权限实时裁剪（根因：群聊多用户越权），不以会话创建者权限凑合 |
   | **C2 分层不可跳** | 裁剪为**纯函数**（落在会话层的数据采集/装配位置），数据读取仍经 Repository / Loader；不在 Service 直连 DB |
   | **C6 Sync repo + to_thread** | 按需查阅的 DB/文件读取全部经 `asyncio.to_thread()` 包装 |
   | **C8 唯一执行引擎** | 依赖序执行复用既有唯一执行路径（`_run_one` → `_run_graph` → `graph.ainvoke()`），不新建执行链 |
   | **C9 ToolManager/ScriptManager 边界** | 新增的 2 个开发者脚本走 subprocess CLI，不 import 运行时工具注册表；运行时工具不调脚本 |
   | **C10 工具必须带参数 schema** | 按需查阅工具三步齐备：源文件 schema 常量 → 注册时传 `params=` → `TOOL_SCHEMA_MAP` 映射 |
   | **C11 功能注册接入** | 按需查阅经 `tools/registry.py` 注册；编排开关/上限经 `config.py`；无孤儿实现 |

3. **每模块验收**：每个模块的验收检测必须通过，否则停止并报告
4. **遵循接口契约**：所有跨模块调用必须通过约定的接口，不允许绕过接口直接操作对方内部数据
5. **不私自扩需**：发现规格缺陷**回退 req-review**，不在本设计里新增/改写需求

## 数据流设计

### 核心流程

| 流程 | 触发条件 | 参与者 | 数据流向 | 异常路径 |
|------|---------|--------|---------|---------|
| F1 摘要注入 | Session 创建 / 刷新 / 每条消息渲染 | SessionDataFetcher → SessionContext → get_prompt_variables → session.md | DB / 文件 → 裁剪纯函数 → 3 类摘要 → 占位符替换 | 裁剪异常 → 空串（fail-open，渲染为"（无）"） |
| F2 全文按需查阅 | 执行层调用查阅能力 | tool_node → handler → Repo/Loader → 裁剪 → 关键词过滤 | 参数 → 全文裁剪 → 过滤 → 返回文本 | 无权限 / 无数据 → `success=false` + 友好提示 |
| F3 编排规划 | 每次入站消息（诉求拆分阶段） | SessionAgent → SessionOrchestrator → SessionScheduler | 路由结果 → `plan()` → 计划列表 → 入队 | LLM 不可用 / 解析失败 → 回退扁平拆分 |
| F4 依赖序执行 | 含先后关系的复合诉求 | SessionScheduler.run_dag | 拓扑层 → 逐层执行 → 完成后回调 → 动态追加 | 前置失败 → 后继标记跳过；超深 → 丢弃追加 |
| F5 摘要热更新 | 会话刷新 | SessionDataFetcher → SessionContext | 重取三书原文 → 覆盖字段 | 异常 → 保留旧值（fail-open） |

### F1 数据流向（摘要注入）

```
SessionContext.create() / refresh()
  └─ SessionDataFetcher.fetch(user_id, conversation_id, core)
       ├─ 世界书：文本摘要 + ★原文（供裁剪）
       ├─ 规则书：全文原文 + ★解析后章节（供裁剪）
       └─ 认知书：按会话权限预裁剪文本 + ★原文（供裁剪）
                     ↓ 灌注
SessionContext（★新增：世界书原文 / 认知书原文 / 规则书章节）
                     ↓ 每条消息（渲染阶段）
SessionAgent._build_rendered_system_prompt(actor_snapshot)
  └─ context.get_prompt_variables(actor_snapshot)   ★新增 3 键
       ├─ {project_brief} = 世界书裁剪(actor.可见节点)
       ├─ {rule_brief}    = 规则书裁剪(actor.权限等级)
       └─ {system_brief}  = 认知书裁剪(actor.数据访问权限)
                     ↓ 占位符替换（不进固定提示部分）
               路由 LLM system prompt
```

### F3/F4 数据流向（编排执行）

```
用户消息 → SessionAgent 诉求拆分
  ② 意图识别  → {目标业务流, 置信度, 是否复合, 子任务, 是否兜底}
  ② 编排规划  → orchestrator.plan(intent, context, actor)
       ├─ 简单 / 兜底        → [单计划]
       ├─ 并行复合           → [计划1, 计划2, ...]（无依赖）
       └─ 顺序复合           → [计划1, 计划2(依赖计划1)]
  ③ scheduler.run_dag(plans, ..., max_depth, on_wi_done)
       ├─ 分层：无依赖层并行执行 → 有依赖层等前置
       ├─ 每层完成 → on_wi_done(wi, done) → 追加只读计划（深度+1，≤上限）
       └─ 前置非成功 → 后继标记跳过（不执行、不抛异常）
  ④ 回复合成（不变）
```

## M1a: 世界书裁剪层

**职责**：让世界书结构化数据携带**按节点分段的骨架**，并提供按操作者可见节点裁剪的纯函数，产出常驻摘要（≤200 字）与按需全文。

### 接口契约

**职责**：为规则书引入**章节级适用等级标注**，使规则可按操作者等级裁剪；提供章节解析与摘要/全文渲染。

### 数据模型

**无数据模型变更**（规则书为文件，非 DB）。

#### 文件格式（章节级标注）

每个 `##` 章节可携带一段标注块，包含：

| 字段 | 类型 | 必填 | 默认值 | 说明 | 业务规则 |
|------|------|------|--------|------|---------|
| `applicable_levels` | list[int] | ✗ | `[1,2,3,4,5,6]` | 适用权限等级 | 缺失时按**全员可见**（fail-open，防条文静默失效） |
| `section_type` | str | ✗ | `""` | 章节语义标签 | 仅作标注，不参与裁剪 |
| `llm_inject` | bool | ✗ | `true` | 是否允许注入模型 | `false` 的章节不进摘要、不进按需查阅（落实"人读权威不注入"） |

### 核心算法/策略

| 算法/策略 | 用途 | 选型理由 | 备选方案 |
|----------|------|---------|---------|
| 章节级标注 + 按等级过滤 | 权限裁剪 | 一次性改造、维护成本低、支持精确过滤 | 取前 N 行（否决：无法按权限裁剪）；全文结构化重写（否决：改动过大） |
| 缺标注 → 全员可见 | 容错 | 规则书是"人读权威"，静默丢条文的风险高于多展示风险；越权风险由 `llm_inject` 与章节内容分级兜底 | 默认不可见（否决：改版后大面积失效） |

## M8: 依赖序执行

**依赖**：M7

**实现的需求**：US-02（覆盖 AC-US-02.2、AC-US-02.3）、US-05（覆盖 AC-US-05.4）、US-10（覆盖 AC-US-10.3）

**层级**：WorkItem（调度层）+ 状态机 + 配置

**职责**：支持带依赖的执行计划**按拓扑序执行**（无依赖层可并行），支持每层完成后的动态追加回调与深度保护。

### 接口契约

#### 对外接口

| 接口/类 | 类型 | 签名 | 说明 |
|---------|------|------|------|
| `SessionScheduler.run_dag` | 新增方法 | `(plans: list[WorkItemPlan], message=None, db_message_id: str = "", actor_snapshot=None, *, max_depth: int = 3, on_wi_done=None) -> list[WorkItem]` | 按拓扑层执行；返回全部执行单元（含跳过） |
| `SessionScheduler.run_all` / `run_all_with_message` | 方法（**不变**） | — | 保持兼容（简单场景仍走原路径） |
| `SessionScheduler._run_one` | 方法（**不变**） | — | 依赖序执行复用，不修改 |
| `WorkItemState.SKIPPED` | 枚举成员（新增） | `= "SKIPPED"` | 前置未成功导致的跳过（终态） |
| `Config.orchestrator_enabled` | 新配置 | `bool = True` | 编排总开关 |
| `Config.orchestrator_max_depth` | 新配置 | `int = 3` | 依赖链最大深度 |
| `Config.orchestrator_max_dynamic_wis` | 新配置 | `int = 2` | 单轮动态补齐上限 |

#### 执行规则

| 规则 | 说明 |
|------|------|
| 拓扑分层 | 按依赖关系分层：无依赖或依赖已完成的计划进入当前层，层内可并行 |
| 层内并发隔离 | 层内并行须使用**独立任务**（`asyncio.create_task`）以隔离执行上下文（既有执行路径依赖上下文变量传递执行态）；若实测存在上下文串扰，**降级为层内顺序执行**并登记偏差 |
| 前置失败 | 前置终态 ∈ {失败, 跳过} → 后继由 `CREATED` 转 `SKIPPED`，**不执行、不抛异常**，用户仍收到已完成部分 |
| 动态追加 | 每层结束后对本层成功项调用回调；返回的新计划深度 ≤ 上限则进入下一层 |
| 深度保护 | 超过上限的计划**丢弃并记日志** |
| 挂起透传 | 任一执行单元进入"等待用户输入"→ **立即停止后续层**，交由会话主脑处理多轮续接 |
| 依赖环 | 无可执行层且仍有剩余计划 → 剩余全部标记跳过（防死循环） |

#### 依赖接口

| 现有接口 | 来源模块 | 调用目的 |
|----------|---------|---------|
| `SessionScheduler._run_one` | 自身 | 单执行单元执行（复用，不改） |
| `SessionOrchestrator.on_wi_done` | M7 | 动态追加计划 |
| `WorkItem.transition_to` / `WorkItemState` | `workitem/` | 状态转换（含新增跳过态） |

### 数据模型

**无新增表。**

#### 状态机改动

| 当前状态 | 允许转换到 | 触发条件 |
|---------|-----------|---------|
| `CREATED` | `PLANNING`、`FAILED`、**`SKIPPED`（新增）** | 正常调度 / 规划失败 / 前置未成功 |
| `SKIPPED` | — | 终态（新增到终态集合） |

### 核心算法/策略

| 算法/策略 | 用途 | 选型理由 | 备选方案 |
|----------|------|---------|---------|
| 分层拓扑 + 层内独立任务并行 | 依赖序 + 并行 | 满足"无依赖可并行"；独立任务隔离执行上下文，避免执行态互相污染 | 全部顺序（否决：不满足并行要求；保留为异常降级路径）；全局线程池（否决：污染执行上下文） |
| 前置失败 → 显式跳过终态 | 失败隔离 | 跳过语义清晰，避免污染失败统计与重试逻辑 | 复用失败态 + 错误信息（否决：语义混淆）；不处理后继（否决：产生悬挂） |
| 深度上限 + 补齐次数上限 | 防无限派生 | 依赖链与补齐均有界（PRD R7） | 不限制（否决：存在无限派生风险，风险等级高） |

## M9: 只读补齐

**依赖**：M7、M8

**实现的需求**：US-05（覆盖 AC-US-05.1~AC-US-05.4）

**层级**：编排子能力（M7 内）

**职责**：执行结果不足以回答诉求时，动态追加**只读**检索计划；受原请求者权限约束、有次数上限、不递归。

### 接口契约

`on_wi_done(wi, done, *, depth=0) -> list[WorkItemPlan]`（M7 已定义，M9 实现追加逻辑）

#### 触发条件（规则化，不额外调 LLM）

| 触发条件 | 追加计划形态 |
|---------|------------|
| 结果为空且非知识检索类诉求 | 兜底类只读计划，目标为"补充相关规范 / 制度 / 背景"，`must_include=["依据","来源"]` |
| 项目态势类查询但缺节点进度信息 | 兜底类只读计划，目标为"检索项目态势全文，补充涉及节点与进度"，`must_include=["节点","进度"]` |

> 具体选用哪个只读能力，由执行层在**只读白名单**内自主决定（不新增工具钉选机制）。

#### 边界（硬性）

| 边界 | 规则 |
|------|------|
| 不递归 | 动态派生的计划**不再触发**派生 |
| 仅成功结果触发 | 执行项状态非"成功"不追加 |
| 只读 | 追加计划为兜底类；工具集由兜底只读白名单裁剪，写操作不可见 |
| 权限口径 | 追加计划以**原请求者**身份执行 |
| 次数上限 | 单轮追加 ≤ `orchestrator_max_dynamic_wis`（默认 2） |
| 深度上限 | 追加计划深度 ≤ `orchestrator_max_depth`（默认 3）；执行层二次校验 |
| 轮次隔离 | 每次规划开始时重置计数 |

### 数据模型

**无数据模型变更。**

### 核心算法/策略

| 算法/策略 | 用途 | 选型理由 | 备选方案 |
|----------|------|---------|---------|
| 编排器**主动检测**（完成回调） | 动态追加 | 编排器自主可控，会话主脑不关心内部机制 | 由执行结果携带"建议后续"字段（否决：需改执行层产出契约，耦合加深） |
| 规则化缺口判定（不调 LLM） | 控制延迟与成本 | 追加场景可枚举（结果为空 / 缺字段），规则判定足够 | LLM 判定（否决：每次完成都调 LLM，延迟与成本不可接受） |
| 只读 + 原请求者权限 | 安全 | fail-closed：越权不可追加；写操作永不动态追加 | 按计划自身业务流校验（否决：规格要求按原请求者） |

## 阶段反思指令

每完成一个模块的设计 / 实施，在进入下一个模块之前，执行以下反思：

1. **检查设计完整性**：本模块的接口契约、数据模型、验收检测是否完整
2. **检查追溯闭合**：本模块声明的 US 是否都有接口 / 验收覆盖；对照追溯矩阵有无遗漏
3. **检查约束落实**：本模块涉及的 PRD 约束是否仍在"PRD 约束落实"表中成立
4. **检查设计偏差**：是否有与规格（PRD）不符的设计？如发现规格缺陷，**回退 req-review**，不在计划内扩需
5. **判断是否继续**：
   - 偏差 ≤ 1 个接口调整 → 直接修改设计文档对应模块，继续
   - 偏差 2-4 个接口或模块职责调整 → 在设计文档末尾追加 "v1.1 修订记录"，继续
   - 偏差 > 4 个接口或架构方向变化 → **停止**，报告用户，等用户决定是否重新生成设计
