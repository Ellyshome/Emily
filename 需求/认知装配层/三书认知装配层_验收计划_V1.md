## 四、测试用户与权限矩阵

### 4.1 真实用户（宪法 Q3：禁止伪造身份）

```bash
docker exec emily-postgres psql -U emily -d emily -c "
SELECT u.id, u.username, u.level, u.company, u.project_id,
       (SELECT count(*) FROM node_participants np WHERE np.user_id = u.id) AS node_cnt
FROM users u WHERE u.status='active' AND u.is_deleted=false
ORDER BY u.level DESC LIMIT 20;"
```

> **注意**：`users` 表的权限列名是 **`level`**（非 `permission_level`），取值 1~6。

| 代号 | 要求 | 用途 |
|------|------|------|
| **U-L1** | `level = 1`，有项目、可见节点数为 0 或极少 | 越权封堵、摘要最小可见集 |
| **U-L3** | `level = 3`（执行级），有项目与多个可见节点 | 正常路径、摘要丰富度 |
| **U-L6** | `level = 6`（管理级）或 `is_management_unit = true` | 高级兜底档、全量摘要对照 |
| **U-NOJOB** | `project_id` 为空 | 无项目降级路径 |
| **U-G-A / U-G-B** | 同一群会话内、权限不同的两名成员 | 群聊多用户越权与固定部分稳定性（硬验收） |

> 若某档位用户缺失：优先用 env-test 环境重建脚本生成；仍缺则记为 SKIP 并注明原因（宪法 Q4，不留测试桩）。

### 7.1 里程碑制执行顺序

| 里程碑 | 用例 | 说明 |
|--------|------|------|

### 7.2 判定标准

| 结论 | 条件 |
|------|------|
| ✅ **通过** | **规格符合度 100%**（10/10 US 满足）；全部 TC PASS（SKIP ≤ 10% 且有合理原因）；无 🔴 高严重度 Bug；架构铁律与 **PRD §4.4 约束**均无违反 |
| ⚠️ **有条件通过** | 核心路径 US 满足，但存在 US 部分满足；或存在 🟡 中 / 🟢 低 Bug；或 SKIP > 10% |

### 7.3 单项 FAIL 判定锚点

| TC | FAIL 触发条件 |
|----|--------------|
| TC02 / TC07 / TC14 / TC18 | 出现任何越权内容（节点名 / 表名 / 他人信息） |
