# 强化文件分类识别(未来增强方向)

> **文档定位**:记录 purpose/file_category 识别能力的未来增强方向。当前阶段不实施,作为后续迭代 backlog。
> **当前基线**:见 [需求/文件管理系统.md](文件管理系统.md) §八 分辨策略 —— 当前用"文件名 + file_category 推断 + LLM 凭对话判断",**不读文件内容**
> **状态**:backlog,未排期

---

## 一、当前阶段(初始版本)的能力边界

| 能力 | 现状 | 依据 |
|------|------|------|
| 入站候选 purpose | 规则匹配文件名/扩展名 | 时机 1(M3 自动下载后) |
| 录入确认 purpose | LLM 凭文件名 + 用户对话 + 上下文 | 时机 2(record_file) |
| 历史数据迁移 | file_category → purpose 标签映射 + `purpose_confirmed=False` | 一次性迁移脚本 |
| **读文件内容判断** | **❌ 不做** | 成本高,初始阶段不启用 |
| **OCR 图片识别** | **❌ 不做**(OCR 工具已有,但不用于 purpose 判断) | 同上 |
| **LLM 二次确认** | **❌ 不做**(仅 Guardian 核验) | 同上 |

**初始阶段的设计哲学**:purpose 是"业务意图",文件名 + 用户说明通常够用。读内容留到后续按需启用。

---

## 二、何时启动增强(触发条件)

满足以下任一条件时,启动对应增强:

| 触发条件 | 增强动作 |
|----------|----------|
| 文件名不规范比例高(如 IMG_xxxx.jpg 占比 >30%)导致 purpose 误判 | 引入内容识别(层 4) |
| EVIDENCE 类误判影响合规审计 | EVIDENCE 候选强制读内容二次确认 |
| REFERENCE 入 RAG 后检索效果差 | 入库前读内容做摘要 + 标签 |
| 用户反馈"分类不准"累计超阈值 | 全量增强(规则 + 内容 + LLM) |

## 三、未来扩充方向(按优先级)

### 3.1 文件名规则引擎增强(低成本)

当前规则匹配较粗(关键词 ILIKE),未来可:
- 正则模式库(如 `^施工许可.*\.pdf$` → EVIDENCE)
- 文件名归一化(去日期/编号/版本后缀后匹配)
- 多信号加权(文件名 + 扩展名 + MIME + 大小 + 来源渠道)

### 3.2 内容识别(中成本,按需触发)

对 `purpose_confirmed=False` 或高价值 purpose(EVIDENCE)候选文件:
- 文档类:调 `parse_document` 工具提取文本 → LLM 判断 purpose
- 图片类:调 `ocr_tool` 提取文字 → LLM 判断 purpose
- 图纸类(dwg/dxf):暂不识别内容,维持文件名判断

**成本控制**:异步执行,限制每日处理量,失败不阻塞。

### 3.3 LLM 二次确认(中成本)

对 `purpose_confirmed=False` 的记录,在 query_files / record_file 触发时让 LLM 顺手复核:
- LLM 拿文件名 + file_category + 关联业务对象 + 用户对话历史
- 输出确认/修正建议
- 用户确认后 `purpose_confirmed=True`

### 3.4 主动学习(高成本,长期)

- 记录用户对 purpose 的修正历史
- 训练 purpose 分类模型(或调优 LLM prompt)
- 识别"高频误判模式"反哺规则引擎

### 3.5 多模态识别(高成本,远期)

- 图片:VLM(视觉模型)识别图片内容(如"这是施工许可证" vs "这是梗图")
- 图纸:图纸识别模型(如 CAD 内容解析)
- 语音:ASR 转文字后判断

## 四、与现有工具的衔接

未来增强时优先复用现有工具,不新建重复能力:

| 增强方向 | 复用的现有工具 |
|----------|---------------|
| 文档内容提取 | `parse_document`([parse_document_tool.py](../emily-core/emily_core/tools/parse_document_tool.py)) |
| 图片文字识别 | `ocr_tool`([ocr_tool.py](../emily-core/emily_core/tools/ocr_tool.py)) |
| 表格提取 | `extract_table`([extract_table_tool.py](../emily-core/emily_core/tools/extract_table_tool.py)) |
| 向量切片入库 | `chunk_text` + `embed_and_index`([chunk_tool.py](../emily-core/emily_core/tools/chunk_tool.py) / [embed_tool.py](../emily-core/emily_core/tools/embed_tool.py)) |
| VLM 识别 | `infrastructure/vlm/client.py`(已有 VLM 客户端) |

## 五、暂不实施的理由(初始阶段)

1. **成本**:全量读内容/OCR 成本高,初始阶段文件量不大时收益不显著
2. **准确率够用**:文件名 + 对话上下文在大多数场景下准确率可接受(预估 80%+)
3. **兜底机制**:`purpose_confirmed=False` 标记 + Guardian 核验 + 事后校正工具,误判可追溯修正
4. **优先级**:当前优先打通文件对象生命周期闭环(M1-M4),识别增强属于优化项,排在其后
