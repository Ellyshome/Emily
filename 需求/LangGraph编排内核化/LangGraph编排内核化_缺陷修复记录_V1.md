## 二、实现完成但默认关闭的两项（附原因）

上下文注入（第 2、3 项）已实现并以 `loop._context_injection_enabled` 为闸门，**默认关闭**。原因：注入块原文含「不要另起其他业务能力处理该内容」，若把它与系统提示词拼接，存在抑制业务能力调用的风险（该风险为推断，未取得有效实测证据——原因见第三节）。为不冒险，先保持关闭，待专项验证后再开。

后续正确做法（建议）：按旧路径语义，把注入作为**独立的 system 消息**插入消息列表，而不是拼接在系统提示词尾部（旧路径是前者，本次误做成后者）。

## 三、探针教训（重要，避免复发）

本轮出现过 4 次"看似系统故障"的假失败，全部为测试工具问题，**未对系统造成影响**：

| 现象 | 真因 |
|------|------|
| 接口返回空响应、日志 `mode=monitor` | 载荷字段名错误：`sender` 应为 `sender_name`，且缺 `platform`/`conversation_type`/`is_at_bot` |
| 回复是"看你发来一串问号"、不调用能力 | PowerShell `Invoke-RestMethod` 默认以 ISO-8859-1 发送请求体，中文变成 `??` —— 必须显式 UTF-8 编码字节 |
| 探针崩溃 `TypeError` | Python `%` 优先级：`"x-%s" % a % b` 应写 `"x-%d" % (a % b)` |
| 归档无能力调用段 | 同上（输入被破坏，模型自然不调能力） |

### 7.2 修复：检索端口死接线

`session/ports.py` 中我此前定义的 `retrieval`、`files` 两个端口全仓无消费方（宪法 Q6 断线）。经核验，检索与文件访问已由**能力通道（业务工具）**承载，端口属冗余设计，故移除该两字段；`GraphPorts` 现仅保留 `events` 与 `runtime`，并在文档串写明不设端口的原因。

**验证**：`py_compile` 通过；内核回放 11/11（端口用例输出变为 `{'events': False, 'runtime': False}`）；死端口残留检索 0 命中。

### 7.3 更正：`emily-embed` 并非故障

此前测试报告与本文第一节将该容器记为"重启循环缺陷（致工具数 44/45）"，**该判断有误**：`docker-compose-napcat.yml` 明确注释其为"临时停用，改用远程 SiliconFlow"，并说明原因是缺少 TEI 所需扁平模型目录 `/data/bge-m3-tei`。即：TEI 为**有意下线**，容器不存在属预期状态；`rag/backends` 报 `local.available=false` 也是预期。

至于当时的工具数 44（应 45），与本容器无关，需另行定位，不再作为该条目的理由。
