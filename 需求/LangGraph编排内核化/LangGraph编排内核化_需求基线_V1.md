# LangGraph 编排内核化 — 需求基线 V1

> **定位**：架构方向。把核心编排层从自研实现迁移到 LangGraph StateGraph，让会话与工单两条主循环共享同一执行形态；宿主外壳与领域资源留在图外，经端口调用。
> **状态**：草案（本次架构讨论收敛产物），待评审
> **性质**：内核形态升级，属内核自身的机制演进，不属业务功能增长。`CLAUDE.md` 约束 13 冻结的是"其他子系统开发期间不得动摇内核"，与本需求不是同一范畴；该约束适用范围的修订已获项目所有者授权（2026-09-11）
> **日期**：2026-09-11
> **上游**：本次架构讨论结论；现状证据见文末索引（无前版基线）
> **下游**：req-review 产出 PRD（规格）。本文只登记方向、决策与约束，不分配模块编号 `M{N}`，不定义表结构与函数签名
> **宪法版本**：v1.1

## 一、背景与问题

当前系统存在两套编排实现。WorkItem 侧已于 2026-07-28 换成 LangGraph StateGraph（`workitem/langgraph_engine/graph.py`，含 created → routing → executing → summarizing → done/failed 与 error_analysis 兜底），并有回退开关 `EMILY_WORKITEM_ENGINE`。Session 侧仍是自研：`session/loop.py` 的 `_run_loop` 是手写迭代循环，`_run_plan` 依赖 `session/capability_plan.py` 的 `PlanCursor` 手写分层调度。同一系统里两套形态并存，是本次要收敛的对象。

由此暴露的四个可验证问题：

| # | 问题 | 证据 |
|---|------|------|
| P1 | 任务级粗排只覆盖 SOP 能力，查询与写类工具因入参契约不同而被排除在计划之外，导致丢参 | `session/loop.py` 注释自认"只有 SOP 能力的入参契约与之匹配…塞进粗排会丢参（实测产生未命名事件）"，对应验证测试报告的缺陷 B2 |
| P2 | 挂起状态仅存会话内存，进程重启后未完成的能力调用即失效 | `session/suspend_registry.py` 的待办为进程内 list；该缺口被上游基线 D3 与 PRD 非目标第 8 条书面接受 |
| P3 | 进度与流式由多套自研通道承担 | `node_event_bus.py`、`outbound_bus.py` 与 SSE 三处并存 |
| P4 | 废弃编排代码仍留在主干 | `workitem/pipeline/` 下 PipelineBUS、BusContext、WorkItemPlan、confirm_queue 已无调用者，`CLAUDE.md` 约束 9 自认仅作历史参考 |

框架使用的历史伤痕也要计入决策依据。`.claude/plans/LangGraph执行引擎替换_非完美项分析_V1.md` 记录了 G1（state 持有 BusContext 导致不可 msgpack 序列化，checkpointer 被迫禁用，断点续传与中断能力同时失效）、G2（error_analysis 纠错闭环缺真实 LLM 触发验证）、G3（计划假定 langgraph `>=0.2.0`，实际安装 1.2.9，`add_node(retry=)` 已被移除）。

判断这份需求是否成立的依据是稳定性的三个来源：状态可序列化可恢复、执行有界可收敛、边界明确失败可结构化回吐。LangGraph 的价值在于把这三件事从团队自觉变成框架强制。一个补充事实是，项目已经完成过一次同类替换（WorkItem 引擎）并保留回退开关，路径可复制，不属于探索性方案。

## 二、目标与成功指标

| 目标 | 可度量指标 |
|------|-----------|
| 编排形态收敛为单一框架实现 | 会话与工单的核心编排均为 StateGraph；手写迭代循环与手写分层调度不再作为并列实现存在 |
| 挂起可跨进程恢复 | 进程重启后未完成的能力调用可被续接，上游 D3 缺口消除（e2e 用例判定） |
| 执行有界 | 任意节点异常或超时后用户仍收到可读回复；单条消息不产生无界循环 |
| 状态可序列化 | 图 state 仅含基础类型；检查点持久化全路径可用，不再出现 `checkpointer=False` 之类降级 |
| 可观测统一 | 进度与对外流式由单一框架事件通道产出 |
| 上下文有界 | 检查点内的对话历史有压缩策略，不随会话轮次无界增长 |
| 迁移安全 | 开关关闭时旧链路行为与现状一致 |

## 三、已锁定决策

| 编号 | 决策 | 要点 |
|---|---|---|
| **D1** | 核心编排层统一为 LangGraph StateGraph | 会话主循环与工单主循环同形态；自研编排不再作为并列实现长期存在。工单内部既有图保留为能力的实现载体，不重写业务能力本体 |
| **D2** | 领域对象一律不进图 state | state 只允许基础类型与 ID、摘要。会话上下文、消息、工单对象等经进程内上下文或按 ID 重建获取。依据是 G1 的实测代价 |
| **D3** | 能力调用契约显式化 | 每个能力（查询、写、SOP）声明参数 schema、读写模式、权限与兜底归属；废除"统一 `request` 字符串"作为万能入参。这是图化与外置的共同前置 |
| **D4** | 挂起与续接改用框架中断与检查点 | 挂起以图检查点承载，重启可恢复。上游基线 D3 的"挂起仅存内存"缺口在本需求内消除，不再作为书面接受的已知缺口 |
| **D5** | 明确出图范围，禁止第二编排器 | 宿主外壳（会话池、群聊多主体归属、推送、定时任务）与领域资源（全景节点、知识检索、文件）留在图外经端口调用。图外不得再造编排循环，也不得把执行权打包移交 |
| **D6** | 框架约束用满 | 迭代上限用框架的递归上限语义；进度与流式用框架事件通道；重试与超时用节点级策略；状态持久化默认走检查点，内存态仅作显式降级 |
| **D7** | 依赖纪律 | 以 LangGraph 为核心依赖并锁定版本上界；不引入 LangChain 主包（chain / agent / memory 全家桶）。需要生态能力时按单个子包引入并登记 |
| **D8** | 灰度双轨与可回退 | 新编排与旧路径并存；全局开关加按能力放开，关闭时行为与现状一致 |
| **D9** | 治理与资产不减 | 权限分级、行级可见范围、质量门、专家评审、分级兜底、审计与轮次归档全部保留，本次只改变编排形态 |
| **D10** | 专家评审（多专家 Agent）暂转休眠 | 由专家手册驱动的多专家 Agent 体系暂不启用，保留代码、数据与既有开关，不做删除、不改写、不作为本需求的推进目标。休眠期间：评审节点不进入执行路径；专家管理类能力移出会话可见能力集。后续由独立需求另行设计后启封。依据：项目所有者决定（2026-09-11） |

目标形态的依赖方向：

```
编排内核（LangGraph 图：会话主循环 + 任务级粗排 + 能力子图）
        │ 只依赖能力端口
能力层（SOP 能力、查询能力、写类工具）
        │ 只依赖领域端口
领域层（全景节点、三书与世界书、知识检索、文件）
宿主外壳（会话池、群多主体、推送、定时）——与图并列，不进图
```

## 四、特性清单

**F1 会话主循环图化**
消息进入后由唯一的图驱动至收敛并产出回复。零 LLM 快速短路（问候、感谢、告别、自我介绍）保留为前置分支，不进入模型调用。

**F2 任务级粗排图化并扩展到全部能力**
计划形态统一承载查询、写、SOP 三类能力，消除"只有 SOP 能力可被编排"的割裂，且任一能力都不丢参。层内并行、层间顺序、前置失败下游跳过、深度上限的语义保持不变。

**F3 能力边界统一**
能力对外只回传成果（结构化结果加可读文本），不向用户暴露工单实体与状态机词汇。

**F4 门禁与评审作为编排内判定**
权限过滤、分级兜底、质量门、专家评审在图中以判定分支表达，否决效力保留：评审不通过即不产出成果。

**F5 挂起与多轮续接**
挂起即待回答的能力调用；谁发起谁确认；重启后仍可续接。挂起成为对话的自然状态，不依赖自定义的内存登记表。

**F6 进度与流式统一**
一个事件通道同时服务对话内进度展示与对外流式，取代当前多套自研通道。

**F7 上下文预算与压缩进入编排**
对话历史在检查点内受预算控制并有压缩策略；权限可见范围的裁剪规则不变。

**F8 失败语义结构化**
能力结果区分成功、部分完成、失败三态；失败与超时不抛出循环之外，一律转为结构化结果回灌对话，如实回传部分完成状态。

**F9 宿主与领域端口化**
会话池、群聊多主体归属、推送、定时任务、全景节点、知识检索、文件访问保持在图外，图内只持有其 ID 与摘要。

**F10 灰度与回退**
新编排经全局开关与按能力 allowlist 放开，旧路径原样保留可随时回退。

## 五、非目标

1. 不重写业务能力本体：工具实现、SOP 内容、检索管线、全景节点四态状态机均保持现状。
2. 不改变权限模型与审计口径，本次只改编排形态。
3. 不引入 LangChain 主包与 Agent 生态。
4. 不新增第二套能力执行记录存储，沿用轮次归档内嵌加现有审计事件流。
5. 不做多租户。本系统是单租户形态：隔离边界是项目与企业参与关系，属权限与可见范围域，不是租户域。不落地多租户，也不预留租户字段——项目归属链本身是推导式，未来若出现多客户信号，可在企业实体上游加一层，无需重构归属链。
6. 不做多渠道抽象，不改变对外流式的语义契约。
7. 不启用专家评审（多专家 Agent），该体系休眠期间不作为验收对象，也不在本需求内改造。

## 六、实施约束

1. **契约先行**：能力 schema、读写模式与权限声明显式化未完成前，不进入图化编码。这是 P1 缺陷 B2 的系统性根因。
2. **领域对象不进 state**（D2）：评审以 state 字段类型做静态检查，出现领域对象即视为不合格。
3. **唯一执行引擎**（宪法 C8）：不得出现第二套编排引擎；`pipeline/` 下废弃代码不得复活为并列路径。
4. **分层不可跳**（宪法 C2）：图只调用能力端口与门禁端口，不直接访问 Repository；Repository 保持同步实现并由异步层包裹（宪法 C6）。
5. **工具必须带参数 schema 且经注册通道接入**（宪法 C10、C11）。
6. **失败不阻塞**：能力失败不阻断归档等主链路（承接上游基线四.4）。
7. **禁止前置分类**：不得引入"是否需要创建工单"的显式分类步骤（承接上游基线 D6）。
8. **无残留**（宪法 Q4）：迁移完成后自研编排代码与废弃路径必须清理，或显式标注保留原因。
9. **框架约束用满**（D6）：不得出现"引入框架但以内存态与自研事件通道为默认"的装饰性使用。
10. **治理文档同步**：`CLAUDE.md` 约束 13 的适用范围修订已获授权并落地；上游基线的 D3、D5 与 PRD 非目标第 7、8 条随本需求在 PRD 阶段一并修订，按宪法 §1.4 登记变更记录。

## 七、既有约定的变更

宪法 §1.3 规定铁律不被绕过，冲突必须显式提出并走变更。约束 13 的适用范围修订属于内核自身的机制演进，已获授权；其余事项随本需求一并处理。

### 7.1 约束 13 的适用范围（已获授权）

约束 13 原文的冻结对象是业务功能增长，其列出的合法改动也仅限对话行为语义、循环终止与超时、上下文管理三项。按项目所有者的说明，该条的立意是其他子系统开发期间内核不得被动摇，它约束的是功能开发不得侵入内核，而不是内核自身不得演进。内核的机制与形态升级需要独立立项与评审，本需求即属此列。

修订方向是重述适用范围，不放宽纪律：业务功能增长仍不得进入内核文件，腐化判据保留；内核自身的形态升级须以专项需求基线立项，实施后同步更新约束所指向的形态描述。

| 事项 | 变更 | 状态 |
|---|---|---|
| `CLAUDE.md` 约束 13 | 标题与正文重述为"对业务功能增长冻结"，明确内核形态升级为独立命题 | 已获授权并已落地（2026-09-11） |

### 7.2 随本需求处理的事项

| 现有约定 | 冲突点 | 变更请求 | 依据 |
|---|---|---|---|
| 上游基线 D3「挂起仅存内存，重启丢失为书面接受的已知缺口」 | 本需求 D4 直接消除该缺口 | 废除 D3，缺口从缺陷治理清单移除 | 本基线 D4 |
| 上游基线 D5「粗排留 Session 层自研、细排归 LangGraph」 | 本需求要求两级编排统一由框架图与子图表达 | 修订为：粗排与细排同为图形态，以子图区分层级 | 本基线 D1、D5 |
| 上游 PRD 非目标第 7、8 条「不做图检查点持久化 / 不做挂起落库」 | 与本需求 D4 直接相反 | 删除这两条非目标 | 本基线 D4 |
| `requirements.txt` 注释「不引入 langchain 主包」 | 与 D7 一致，维持不变 | 同时把 `langgraph` 从 `>=0.2.0` 收紧为锁定上界 | 非完美项分析 G3 |

## 八、验收与证据

验收项须可执行、可判定（宪法 Q1、Q2），不接受"功能正常"类描述。

| 编号 | 验收项 | 判定方式 |
|---|---|---|
| A1 | 挂起跨进程重启后可续接 | 构造挂起后重启容器，补充信息后能力调用完成并产出成果 |
| A2 | 同一主题重放不产生重复副作用 | 相同会话主题在恢复后重放，业务表无重复记录 |
| A3 | 节点异常或超时后用户仍收到可读回复 | 故障注入，检查回复文本与日志 |
| A4 | 开关关闭时旧链路行为不变 | 双轨对照回归 |
| A5 | 状态可序列化，检查点全路径可用 | 全路径运行时无降级到内存或禁用检查点的记录 |
| A6 | 粗排覆盖查询与写类能力且不丢参 | 复现 B2 场景，断言不再产出无标题的降级记录 |
| A7 | 长会话下检查点体积有上限 | 连续多轮对话后测量检查点增长曲线 |
| A8 | 语料四类断言全过 | 能力命中正确性、权限拦截、挂起续接、归档完整性 |
| A9 | 宪法合规 | 逐条核对 C0、C2、C6、C8、C10、C11，并以静态可达性扫描核验 Q6 接线闭合 |

## 十、前置条件与分期

前置条件是当前未收敛的变更先落地。2026-09-11 的 Session 主体化重构处于灰度关闭状态（`session_loop_enabled` 默认关，测试结论为有条件通过，尚有缺陷未修与测试数据待清理）。在此之前启动框架级迁移，会让两个未验证变更叠加，排障成本相乘。

| 阶段 | 范围 | 通过条件 |
|---|---|---|
| P0 | 收敛现状：开启灰度、跑完既有语料、修复遗留缺陷、清理测试数据 | 既有重构的验收项全部闭合 |
| P1 | 冻结契约：能力 schema、权限声明、挂起语义 | A6 通过 |
| P2 | 内核图化：按 Q1 结论迁移主循环与粗排 | A1 至 A5、A8 通过 |
| P3 | 领域与租户端口化 | A7、A9 通过 |
