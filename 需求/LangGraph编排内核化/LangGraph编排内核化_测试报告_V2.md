## 三、关键证据

**端到端（真实 HTTP 入站 → 内核分派 → 图式编排 → 出站）**

- 路由与形态：日志 `SessionLoopPool: graph path`、`session graph built: fast→understand→gate⇄execute→summarize, gate=True, checkpointer=True, max_iterations=12`。
- 第一轮问候：HTTP 200 直答「你好呀，林建辉！有什么需要帮忙的吗？」，零模型调用（图内快速短路）。
- 第二轮业务提问：HTTP 200 + SSE 出站，答复列出 5 条真实事件并按已确认/待确认分类，含「铺装 25 平米，验收通过」等真实字段，证明能力经既有工具通道执行且成果回灌。
- 事件分布：`{"progress": 4, "reply": 2}` —— 进度事件由节点迁移派生（单一来源）。

**灰度回退（US-09）**

- 关闭图开关（`EMILY_SESSION_GRAPH_ENABLED=false`，主循环开关保持 true）后实测：日志仅出现 `session loop path`、无 `graph path`，两轮消息均正常答复 → 回退可用，旧路径行为不变。

**跨进程挂起续接（US-04，D3 缺口）**

- 阶段 A：挂起节点建成、以追问收尾、中断负载写入检查点（含归属发起者），5/5。
- 阶段 B（新进程）：可从检查点读出挂起态、归属判定拒绝非发起者、续接后产出最终回复、挂起清空，6/6。

**M11 回放语料（容器内 10/10）**

快速短路零模型调用、工具回环、迭代上限收敛、门禁拒绝不执行能力、挂起与续接、计划层内并行、事件端口同源、端口装配降级、状态可序列化。

**M9 数据核对**

- `scheduler_jobs` 实际仅 3 行（每周进度汇报创建、每日晨报、文件过期提醒），**不存在自检作业行** → 此前「自检由调度作业定时触发」的判断不成立，自检实际未在定时运行，手动化无作业行可停用。
- 自检 T4-5 原判据查 `action_type="morning_report"`，而实际作业 action_type 为 `generate_morning_report`，该判据**永远不可能通过**；已解耦为「调度能力可用（存在 ACTIVE 作业）」，实测 ACTIVE 作业数 2 → 判据转为通过。
