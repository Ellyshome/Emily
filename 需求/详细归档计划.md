# 增强 Session 归档文件的过程记录详细度

## Context

用户查看 [emily-data/session_archives/2026-07-23_刘大勇_12345600.md](emily-data/session_archives/2026-07-23_刘大勇_12345600.md) 后，询问归档是否只记录了 LLM 结果而无过程。调研确认：归档**已记录**过程骨架（4 节点轨迹 + 每次 LLM 调用的元数据/响应摘要 + Prompt 模板与变量摘要 + 工具调用 + Guardian 审核），但所有过程数据都是**摘要级**，且 Guardian Prompt 标「（未追踪）」。用户选择「增强过程记录详细度」。

三个具体短板（均经代码确认）：
1. **LLM 响应三层截断到 200 字**：client.py `content[:500]` → DB `String(500)` → 归档 `summary[:200]`。长回复（如 Node4 最终回复合成）被严重截断。
2. **Prompt 变量值截断 80 字**：存入时已是摘要/`[:80]`，渲染时 `_render_prompt_info` 再 `[:80]`。
3. **Guardian Prompt 未追踪**：[real_guardian.py](emily-core/emily_core/workitem/pipeline/real_guardian.py) 内部构建 prompt 但不回传字符数，[workitem_agent.py:439](emily-core/emily_core/workitem/workitem_agent.py#L439) 写死 `rendered_chars=0`，归档显示「（未追踪）」。

目标：让归档呈现更完整的过程——LLM 完整响应、更长的 Prompt 变量值、Guardian Prompt 渲染字符数。保留 `response_summary` 作为快速摘要不变，新增完整版本字段，向后兼容。

---

## 改动方案

### 增强点 1：LLM 完整响应（新增 `response_full` Text 字段）

**数据链路**：client trace_callback → `LLMInteractionLogger` → `EvolutionLogWriter.write_sync` → `evolution_llm_interaction_logs` 表 → 归档 `_render_llm_log_line` 读取。

**改动文件**：

1. [models.py:1334](emily-core/emily_core/infrastructure/database/models.py#L1334) — `EvolutionLLMInteractionLog` 新增列：
   ```python
   response_full = Column(Text, default="")   # 完整响应（截断到 5000 字），response_summary 保留作快速摘要
   ```

2. [session.py:61](emily-core/emily_core/infrastructure/database/session.py#L61) — `_PENDING_COLUMNS` 加映射（该表当前不在映射里，不加则新列不会自动 ALTER 建出）：
   ```python
   "evolution_llm_interaction_logs": [
       ("response_full", "TEXT", "''"),
   ],
   ```

3. [log_writer.py:29](emily-core/emily_core/infrastructure/logging/log_writer.py#L29) — `_LONG_FIELD_NAMES` 元组追加 `"response_full"`，使其走 `TEXT_LIMIT=5000` 而非默认 `STRING_LIMIT=500`。

4. [client.py](emily-core/emily_core/infrastructure/llm/client.py) — trace callback 两个分支的 data dict 各加一个不截断的完整字段：
   - text/json 分支（~L195）：`"response_full": content`
   - tool_call 分支（~L165）：`"response_full": f"{tc.function.name}({arguments})"`
   - `response_summary` 保持原样（快速摘要仍有用）。

5. [llm_logger.py:113](emily-core/emily_core/infrastructure/logging/llm_logger.py#L113) — `EvolutionLogWriter.write_sync(...)` 调用追加参数：
   ```python
   response_full=(data.get("response_full", "") or ""),
   ```
   （`write_sync` 用 `**kwargs` 透传到 ORM 构造，无需改签名。）

6. [session_archive_writer.py:455](emily-core/emily_core/services/session_archive_writer.py#L455) — `_render_llm_log_line` 优先用完整字段，回退摘要，并用代码块包裹提升可读性：
   ```python
   full = getattr(log, "response_full", "") or ""
   summary = getattr(log, "response_summary", "") or ""
   # 主行不变（category/model/latency/tokens）
   display = full or summary
   if display:
       lines.append(f"    摘要: {display[:2000]}{'…(共%d字)' % len(display) if len(display) > 2000 else ''}")
   ```
   归档显示上限 2000 字（比当前 200 字增强 10 倍，又避免无限膨胀；完整 5000 字在 DB 可回查）。同步更新 `_render_workitem` 中 LLM 调用明细的同逻辑（L408）保持一致。

### 增强点 2：Prompt 变量值放大（80 → 300 字）

**改动文件**：

1. [workitem_agent.py](emily-core/emily_core/workitem/workitem_agent.py) — Node2/Node3/Node4 存 `variables` 时，把 `[:80]` 放大到 `[:300]`：
   - Node2（~L319）：`user_input`、`sop_text`（`sop_text` 超长，保留「N字」摘要不动；`user_input` 放到 300）
   - Node3（~L440）：`output`/`tool_info`/`rag_info` 保留「N字」摘要（这些是聚合字数，非值本身，不动）
   - Node4（~L780）：`user_input`、`step_results` 等 `[:80]` → `[:300]`
   - Node4 guardian（~L678）：`draft_reply`、`user_input` 放到 300

2. [session_archive_writer.py:495](emily-core/emily_core/services/session_archive_writer.py#L495) — `_render_prompt_info` 的 `val_str[:80]` → `val_str[:300]`；`session_vars` 的 `[:40]` → `[:120]`。

### 增强点 3：Guardian Prompt 追踪（消除「未追踪」）

**时序已确认**：Node3 在 `asyncio.gather()` 汇合后才存 prompt_info（[workitem_agent.py:423-447](emily-core/emily_core/workitem/workitem_agent.py#L423)），Node4 的 `review_reply` 是 await 的——两处此时同步调用 RealGuardian 取 prompt 字符数无时序问题。

**改动文件**：

1. [real_guardian.py](emily-core/emily_core/workitem/pipeline/real_guardian.py) — 新增两个公开方法（内部复用现有 `_build_step_prompt`/`_build_reply_prompt`，纯字符串 format 无 I/O，开销可忽略）：
   ```python
   def step_prompt_chars(self, sr: Any) -> int:
       """返回 step 审核 prompt 渲染后字符数（供归档追踪，不暴露 prompt 内容）。"""
       try:
           return len(self._build_step_prompt(sr))
       except Exception:
           return 0

   def reply_prompt_chars(self, draft: str, wi: Any) -> int:
       """返回 reply 审核 prompt 渲染后字符数。"""
       try:
           return len(self._build_reply_prompt(draft, wi))
       except Exception:
           return 0
   ```

2. [workitem_agent.py:439](emily-core/emily_core/workitem/workitem_agent.py#L439) — Node3 存 prompt_info 时：
   ```python
   "rendered_chars": self._guardian.step_prompt_chars(sr) if self._guardian else 0,
   ```

3. [workitem_agent.py:677](emily-core/emily_core/workitem/workitem_agent.py#L677) — Node4 存 `prompt_info_node4_guardian` 时：
   ```python
   "rendered_chars": self._guardian.reply_prompt_chars(draft, wi) if self._guardian else 0,
   ```
   （`draft`/`wi` 在该作用域已有，需确认变量名与 Node4 合成逻辑对齐。）
