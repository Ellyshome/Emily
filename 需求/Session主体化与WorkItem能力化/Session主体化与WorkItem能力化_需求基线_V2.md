# Session 主体化与 WorkItem 能力化 — 需求基线 V2

> **定位**：架构调整方向。Session 连续对话（瀑布流）为**唯一会话主体**；WorkItem 降级为**可插拔能力**，向对话提供执行手脚（写/操作）与查询服务（读）。
> **状态**：基线已评审（继承 V1，沉淀评审结论，进 PRD）
> **本版变更**：在 V1 基础上锁定五条新决策（D3–D7）、关闭全部开放问题、补齐验收与实施约束。
> **上游文档**：`Session主体化与WorkItem能力化_意向需求基线_V1.md`（现状差距、证据索引仍以 V1 为准，本文不重复引用）。

---

## 一、已锁定决策

| 编号 | 决策 | 要点 |
|---|---|---|
| **D1** | 一个 SOP 一个能力 | 每个启用中的 SOP 暴露为独立能力工具，不用通用 `run_flow` |
| **D2** | 编排器保留在 Session 层 | Session 层产任务级执行计划（DAG），对象为能力调用 |
| **D3** | 挂起仅存内存，重启丢失为书面接受的已知缺口 | 不为挂起做落库；缺口写入运维口径，非回归缺陷 |
| **D4** | 审计以 Session 为锚点 | 能力执行结果与审计/评审意见作为 Session 参考意见；归档锚定 Session 轮次，轮次归档段内嵌能力调用清单；评审/质量门的**否决效力保留**（"参考"仅指呈现方式，不是决策权重） |
| **D5** | 两级编排：粗排/细排 | Session 编排器 = **任务级粗排**（调哪些能力、依赖顺序）；WorkItem 内部 LangGraph = **工具级细排**（能力内工具使用计划）。细排失败以结构化结果向上冒泡，由 Session 循环决定重试/换能力/放弃；粗排只在能力边界间重排，**不进入能力内部** |
| **D6** | 是否创建 WorkItem 是循环内的**隐式判断** | 禁止回合开始的前置分类步骤；能直答则直答，需要执行则调能力工具，由每次工具调用决策自然体现。任何形式的"要不要建工单"显式分类器均为还原被废弃的旧路由器，禁止 |
| **D7** | 任务包是**执行依据**，不是**交付物** | Session 掌握**能力目录**（含查询能力）与对话上下文，将需求规划为能力调用计划（`CapabilityPlan`，即"任务包"）；由 Session 循环**逐项调用、成果逐步回灌、按结果随时重排**，而非打包移交第三方"组合执行"。**执行权与纠错权始终在 Session 循环手里，永不随任务包移交**——"打包扔给 workitem-agent 自主组合执行"即派发范式复辟，禁止。数据资源不经 Session 直接持有，一律经能力访问（保权限过滤 fail-closed） |

## 二、特性清单

### F1 Session 会话主循环（唯一对话主体）
- Session 持有 `chat_with_tools` 循环：LLM → 工具执行 → tool_result 回灌 → 循环至收敛。
- 取消"渲染结构化结果 → LLM 二次合成"中间层，回复由循环直接产出。
- 保留零 LLM 快速短路（问候/感谢/告别/自我介绍）作为前置分支。
- 循环终止：沿用 `agent_loop_max_iterations=12`，另加**单次能力调用超时上限**（超时以失败 tool_result 回灌，由循环收敛，具体值 PRD 定）。

### F2 SOP 能力化（D1）
- 能力入参：用户请求原文 + SOP 声明的可选参数。
- 能力内部保留现有 LangGraph 执行：SOP 全文、质量门、专家评审、分级兜底、审计。
- 对外只回传成果（结构化 + 可读文本），不暴露 WorkItem 实体与状态。

### F3 能力目录与工具集装配
- Session 可见工具集 = 查询能力 + 执行手脚 + SOP 能力 + 控制工具。
- 权限过滤复用 `build_tool_specs`（fail-closed），单条消息按当前操作者裁剪。
- 能力目录由 SkillRegistry 与 `tools/registry.py` 合成。

### F4 查询服务直达对话
- 查询类能力直接暴露给 Session，不经 SOP；只读，不受写操作门禁约束。

### F5 执行手脚与写操作护栏
- 写类能力保留：权限过滤 + 分级兜底门禁（`FallbackPolicy`，fail-closed）。
- 覆盖/编辑/删除等高危诉求不进入自由工具集，仍走对应 SOP 能力。

### F6 两级编排（D2 + D5 + D7）
- Session 编排器产出 `CapabilityPlan`（任务级粗排）：层内并行、层间顺序、前置失败下游跳过、动态追加、深度上限，沿用 `run_dag` 语义。
- 计划由 Session 循环**照单执行**：逐项调用能力、成果逐步回灌对话、发现计划不成立时按 D5 规则重排（D7）。
- WorkItem 内部循环为工具级细排，独立运转；两级通过"结构化失败结果冒泡"衔接（D5）。
- 编排计划在对话中可见（简版进度），编排器同时作为进度可见性来源。

### F7 控制工具语义换位
- `complete_work`：改为"结束当前能力调用，成果回灌对话"。
- `ask_user`：改为"工具返回 `need_input` → Session 提问 → 下轮用户回答作为 tool_result 回填"。挂起成为对话自然状态，不依赖图检查点。

### F8 挂起与多轮续接
- 挂起 = 对话中待回答的能力调用；续接判定沿用 `continuation` 语义；多能力并发挂起按"谁发起谁确认"归属。
- **已知缺口（D3）**：挂起状态仅存会话内存，进程重启后未完成调用即失效，需用户重新提出。此缺口书面记录于运维口径与缺陷治理清单，不计为回归。

### F9 确认 / 取消归位为对话行为
- `SYS-confirm` 由 WorkItem 特例改为 Session 循环内交互；确认存储复用 `EventApplication.handle_confirmation`。

### F10 审计、归档与溯源（D4）
- 归档锚定 Session：扩展现有 `_append_archive_turn_*`，轮次归档段**内嵌能力调用清单**（能力名、入参摘要、成果摘要、触发者、成败），一条记录同时满足审计与溯源，**不新增 `CapabilityExecution` 表**。
- 专家评审、质量门产出作为 Session 参考意见回灌对话，但**否决效力保留**：评审不通过即不出成果。
- 能力执行仍写现有审计与事件流；权限按当前操作者鉴权（`actor_snapshot`）。

## 三、非目标

1. token 级流式输出。
2. 会话树 entry / 分叉。
3. Pi 式"内核零内建 + 扩展生态"。
4. 删除或弱化 SOP、权限分级、质量门、专家评审、分级兜底。
5. 重写 WorkItem 内部执行引擎。
6. 多渠道 Channel 抽象。
7. 图检查点持久化（新路径已不依赖图挂起）。
8. 挂起状态落库（D3，书面接受缺口）。

## 四、开放问题处理结果（V1 全部关闭）

| 编号 | V1 问题 | 结论 |
|---|---|---|
| Q1 | 工具命名 | **工具名 = SOP 编号**（如 `SOP-002-REC`），可枚举、审计友好、与工具粒度权限裁剪一致 |
| Q2 | 工具集膨胀 | **当前全量暴露**；设阈值（能力数 > 20）触发两段式（目录摘要 → 按需加载 schema），PRD 中记录阈值，现在不实现 |
| Q3 | 计划数据结构 | **新增 `CapabilityPlan`**，不沿用 `WorkItemPlan`，避免换位半途而废 |
| Q4 | 循环终止 | 沿用 `agent_loop_max_iterations=12` + 单次能力调用超时（值 PRD 定） |
| Q5 | 进度回灌 | 编排器作为进度来源，对话中简版展示（F6） |
| Q6 | 审计落库口径 | **归档内嵌调用清单（D4）**，不新增执行记录表 |
| Q7 | 旧派发路径删除时机 | **Phase 2 验收后删除**，不长期双轨 |
| Q8 | 计划对用户可见 | **显示（简版）** |

## 五、分期与验收

| 阶段 | 范围 | 验收要点 |
|---|---|---|
| Phase 1 | 独立模块实现 Session 主循环（`session/loop.py`，开关控制）+ 查询能力直达 + SOP 能力工具（D1），只读能力先行 | ① 同批业务问题上新路径体验 ≥ 现状；② **闲聊类消息平均 token/延迟不劣于现状**；③ 权限与兜底不破 |
| Phase 2 | 主循环转默认；编排器产出 `CapabilityPlan`（D2/D5）；控制工具/挂起/确认换位（D6 生效） | 旧派发路径下线删除；SOP、质量门、审计仍生效；粗排/细排边界不越界 |
| Phase 3 | 归档与审计闭合（D4）；进度回灌；成本优化 | 轮次归档可回答"调了哪些能力、产出什么、谁触发" |

**验收语料**：复用仓库 repro/harness 脚本体系建 golden set，覆盖四类断言：能力命中正确性、权限拦截、挂起续接、归档完整性。

## 六、实施约束

1. **新循环独立模块**：主循环以 `session/loop.py` 独立实现、组合 `SessionContext`，不原地改造 `session_agent.py`——灰度双轨要求旧路径原样保留，并行模块是开关干净的前提。
2. **灰度粒度**：全局开关 + 按 SOP allowlist；迁移顺序 = 查询能力 → 写类 SOP 逐个放开。
3. **治理文档同步**：改写 `CLAUDE.md §6` 约束 #3（"SOP 即路由"→"SOP 即能力"）、#5（M14 措辞）；SOP 能力经注册通道接入（约束 #12）；分层关系不变（约束 #2）。
4. **失败不阻塞**：能力失败不阻断文件归档等主链路；能力失败语义为结构化失败 tool_result，不支持原子性声明（部分完成状态如实回传对话）。
5. **禁止前置分类**：任何回合开始的"是否需要 WorkItem"显式分类步骤均违反 D6，代码评审按此把关。
