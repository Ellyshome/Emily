# 检索通道治理 — 计划（概要设计）V1

> **模块标识**：检索通道治理
> **版本**：V1
> **日期**：2026-09-12
> **基于 PRD（规格）**：[检索通道治理_PRD_V1.md](检索通道治理_PRD_V1.md)
> **基于需求基线**：[检索通道治理_需求基线_V1.md](检索通道治理_需求基线_V1.md)
> **角色声明**：以 Emily 开发者资深架构师视角编制；叠加"系统集成"与"可观测性"两个视角
> **定位**：本需求属**治理层**，不改内核图结构（PRD 约束 11）

## 一、设计目标与边界

1. 让通道**可登记**：元数据双处存储，工具描述由其生成。
2. 让选择**有规则**：分工与升级目标外置为策略表，运维可改。
3. 让选错**可自愈**：实体解析前置 + 空结果确定性升级（默认开）。
4. 让结果**可解释**：出处标注 + 全通道日志 + 正确率指标。
5. **不做**：改写内核图、全量并发、替换搜索引擎、启封休眠通道。

## 二、模块划分

| 模块 | 职责 | 覆盖 US |
|------|------|---------|
| **M1 通道元数据注册** | 七项元数据的双处存储（配置文件承载静态字段与默认策略，数据表承载启用状态与优先级等可运营字段）；由元数据生成工具描述 | US-01、US-10 |
| **M2 策略表** | 承载三张表：分工表（问题类型→首选→备选）、升级目标表、并发白名单；外置配置 + 热加载 | US-02、US-09 |
| **M3 实体解析前置** | 覆盖登记的全部业务实体；判定存在性与标识；产出路由建议 | US-03 |
| **M4 升级与融合引擎** | 空结果判定、按升级目标改道、跳数上限、升级阶段并发 2~3 路并去重按来源排序；常态单通道 | US-04、US-05 |
| **M5 出处标注** | 回答标注来源通道与对象；多源可区分 | US-06 |
| **M6 全通道检索日志与指标** | 记录通道、跳数、命中数、是否被采用、耗时、权限过滤结果；计算通道选择正确率 | US-07 |
| **M7 可见性统一接入** | 所有通道复用既有可见性唯一权威来源；失败即拒 | US-08 |
| **M8 注入通道治理** | 会话期注入类通道的元数据登记与注入形态（独立系统消息）；防工具调用被抑制的回归 | US-01（注入通道部分）、非功能 4 |
| **M9 回归语料与度量** | RAGENV 扩展为「通道选择」语料（标注期望命中与期望不命中通道）；RAG-04／RAG-11 回归题；正确率基线采集 | 第七节验收全部 |

## 三、模块接口契约

| 模块 | 输入 | 输出 | 失败处理 |
|------|------|------|---------|
| M1 | 通道定义（配置）、运营字段（数据表） | 通道元数据列表；按通道生成的描述文本 | 元数据缺失时该通道不参与路由，并记日志（fail-closed） |
| M2 | 配置文件 | 分工表、升级目标、并发白名单、跳数上限 | 配置非法或缺失 → 回落内置最小默认（单通道、不升级），并告警 |
| M3 | 用户问题、实体登记表 | 实体类型、存在性、标识、路由建议 | 解析异常按"不存在"处理并允许转入文档检索 |
| M4 | 首选通道、路由建议、策略表 | 检索结果集合（含来源标记）、跳数、每跳命中数 | 全部为空则产出"未找到 + 已查范围"结论；超跳数上限即停止并如实告知 |
| M5 | 结果集合 | 带出处的回答片段 | 出处缺失时降级为"来源未标注"提示，不编造 |
| M6 | 每跳检索事实 | 日志记录与指标 | 写日志失败不得影响检索主流程 |
| M7 | 通道标识、用户身份 | 可见范围判定结果 | 判定失败即拒（fail-closed） |
| M8 | 注入内容、消息列表 | 独立系统消息形态的注入 | 注入异常不得影响工具调用可用性 |
| M9 | 语料文件 | 通过／失败清单与指标 | 用例失败即报告，不得静默跳过 |

## 四、依赖图与构建顺序

```
M1 ──┬─> M2 ──┐
     │        ├─> M4 ──┬─> M5
     └─> M3 ──┘        └─> M6
M7 ────────────────> M4（每跳均过可见性）
M1 ──> M8（注入通道登记）
M9 ───────────────（全程并行，最后统一验收）
```

**构建顺序**：M1 与 M7 并行 → M2 与 M3 并行 → M4 → M5 与 M6 并行 → M8 → M9 收口。依赖关系为有向无环图。

**分阶段落地**：

- **P0（不改检索逻辑）**：M1 元数据 + M2 策略表 + M5 出处标注 + M8 注入形态。此阶段只做"把隐性知识显性化"，工具描述与提示词分工表即在此阶段生效。
- **P1（引入自愈）**：M3 实体解析前置 + M4 升级兜底。RAG-11 类现象在本阶段被修复。
- **P2（可观测与收窄）**：M6 日志与指标 + M7 可见性统一接入。
- **P3（调优）**：M9 语料回归与正确率基线，据此决定白名单与目标值。

## 六、与现有系统的接线

| 接线对象 | 方式 | 校验 |
|---------|------|------|
| 业务工具注册表 | 元数据按通道登记，与既有工具一一对应 | 无孤儿：元数据中的通道必须在注册表存在，反之亦然 |
| 工具描述 | 由元数据生成后传入提示词构建 | 抽样比对描述与元数据一致 |
| 既有可见性权威来源 | M7 直接复用，不新建 | 与现有 `query_files` 等通道的可见性口径一致 |
| 检索日志 | M6 落点（扩展或新建）在实现前确定 | 新表/新列必须有读写双方 |
| resolver 体系 | M3 复用既有解析器并按实体类型扩展 | 每个实体类型有唯一解析入口 |
| 内核图 | **不接入**（治理层包装） | 内核图文件无改动 |

**断线自查（Q6）**：新增配置项必须有读取方；新增元数据列必须有读写双方；新增指标必须被采集并可见；字符串开关必须至少两处引用（定义 + 读取）。

## 七、验收与组装验证

| 验收项 | 方式 | 通过标准 |
|--------|------|---------|
| 通道元数据完整性 | 列表核对 | 六条通道七项元数据齐备 |
| 描述与元数据一致 | 抽样比对 | 完全一致 |
| 实体解析前置 | 定向用例 | 实体不存在时自动转入文档检索 |
| 空结果升级 | 定向用例 | 主通道空 → 改道；全空 → 明确告知已查范围 |
| 常态单通道 | 日志核对 | 常态跳数为 1（白名单外） |
| 出处标注 | 对话检查 | 回答含来源通道与对象 |
| 全通道日志 | 库核对 | 六条通道均有日志记录 |
| 正确率指标 | 指标查看 | 可计算、可展示 |
| **RAG-11 回归** | emy-test 复现原问题 | 不再"解析失败即终止"，能改道检索 |
| **RAG-04 回归** | emy-test 复现 | 通道选择与期望一致（或按策略表明示） |
| 内核无改动 | 版本比对 | 内核图文件无新增改动 |
| 权限不放宽 | 权限回归 | 机密文档对不同等级的可见性与改动前一致（密级已简化为 3 级） |
| 既有功能不回归 | 内核回放 | `session_graph_replay.py` 11/11 通过 |

## 八、组装验证与断线模式自查

1. **接线矩阵**：每个新增产出物（元数据、策略表、日志列、指标）均已指定消费方，无"仅定义无使用"。
2. **半截交付自查**：若 P0 完成后 P1 未做，必须明确告知"升级能力尚未生效"，不得默认其已可用。
3. **失败可读**：任何通道全空时必须给出"未找到 + 已查范围"，不得静默。
4. **开关可回退**：策略表整体关闭后，行为回到模型自选且检索功能不受影响。
5. **注入安全**：M8 完成后必须回归验证工具调用未被抑制（历史实测坑）。

## 九、反思与停损规则

1. 若 P1 上线后**平均跳数 > 2 且通道选择正确率未提升**，回退到 P0 方案（仅提示词分工表），重新评估是否值得引入升级引擎。
2. 若 M8 的注入改造**再次引发工具调用抑制**，立即回退该变更，并改为"仅在用户表达确认意图时注入"的收窄形态。
3. 若实体的解析失败率高（超过阈值）导致频繁误升级，改为**先文档检索再台账**的顺序，并复查实体登记表。
4. 若 M6 的日志写入影响检索延迟，降级为异步写并保留关键字段。
5. 任一阶段发现需要改动内核图才能实现，**停止并回报**，交由规格变更处理（PRD 约束 11）。
