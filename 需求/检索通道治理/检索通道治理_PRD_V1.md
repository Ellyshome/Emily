# 检索通道治理 — PRD（规格）V1

> **模块标识**：检索通道治理
> **版本**：V1
> **日期**：2026-09-12
> **基于需求基线**：[检索通道治理_需求基线_V1.md](检索通道治理_需求基线_V1.md)（六项议题 Q1~Q6 已全部确认）
> **状态**：待评审
> **与本项目其他需求的关系**：与「LangGraph 编排内核化」为两条独立需求线；本需求属治理层，不改内核形态

## 一、概述

**问题**：模型在"去哪里找信息"上没有依据。实测中 L6 用户问「节点A的投标报价」，模型连调节点台账与文件台账三次、知识库一次未触发，`rag_retrieval_logs` 对该查询 0 行；卡点在**通道选择**，不在密级、不在检索过滤。

**目标**：为信息获取建立治理层，使通道可登记、选择有规则、选错能自愈、结果可解释。

**范围**：六条可调用检索通道与会话期注入类通道的元数据登记、选择规则、升级兜底、日志与指标。
**不范围**：写入类能力；文档解析与 OCR；休眠通道的启封。

## 二、用户故事与验收标准

### US-01 通道元数据可登记、可查询
**AC-US-01.1** 每个通道登记七项元数据：所属域、回答对象、参数、权限维度、是否含正文、空结果语义、升级目标。
**AC-US-01.2** 元数据同时存在于配置文件与数据表（配置管静态字段与默认策略，数据表管可运营字段与审计引用）。
**AC-US-01.3** 工具描述由元数据生成，抽样比对时描述与元数据一致（不得出现手写副本）。

### US-02 通道分工可读、可配
**AC-US-02.1** 存在「问题类型 → 首选通道 → 备选通道」的分工表，且模型可读到。
**AC-US-02.2** 分工表内容来自配置，修改后无需改代码。

### US-03 实体解析前置
**AC-US-03.1** 实体解析覆盖登记的全部业务实体（节点、项目、文件、人员、企业、任务、事件、会议等）。
**AC-US-03.2** 实体存在时走对应台账通道；实体不存在时**自动转入文档检索**，不得停在原地。
**AC-US-03.3** 现状回归：本次 RAG-11 现象（实体解析失败即终止）不再复现。

### US-04 空结果确定性升级
**AC-US-04.1** 主通道返回空结果时，按该通道的升级目标改道。
**AC-US-04.2** 全部候选通道均为空时，明确告知"未找到"并说明已查范围。
**AC-US-04.3** 升级行为默认开启，且可整体关闭（关闭后回到模型自选）。

### US-05 多路融合受策略表约束（四档）
**AC-US-05.1** 常态为单通道调用。
**AC-US-05.2** 升级阶段允许并发 2~3 路，结果去重并按来源排序。
**AC-US-05.3** 常态并发默认关闭，仅对策略表白名单的问题类型开启。

### US-06 出处标注
**AC-US-06.1** 回答标注来源通道与对象（文档名、记录类别等）。
**AC-US-06.2** 多源融合时，标注可区分各来源。

### US-07 全通道检索日志与指标
**AC-US-07.1** 每次检索记录：通道、跳数、命中数、是否被采用、耗时、权限过滤结果。
**AC-US-07.2** 覆盖全部通道，不限于知识库。
**AC-US-07.3** 可计算「通道选择正确率」并在监控中可见。

### US-08 权限收窄贯穿
**AC-US-08.1** 所有通道复用既有可见性唯一权威来源，不各自实现。
**AC-US-08.2** 任一通道判定失败即拒（fail-closed），不得因通道不同而放松。

### US-09 规则可配置、可回退
**AC-US-09.1** 路由规则外置为配置，运维修改后生效，不需发版。
**AC-US-09.2** 关闭策略表后行为回到当前"模型自选"，且检索功能不受影响。

### US-10 不改变内核形态
**AC-US-10.1** 路由规则不进入内核图代码，图仅作执行者。
**AC-US-10.2** 通道调用仍经既有能力（工具）通道，不新增编排主体。

## 三、术语

| 术语 | 定义 |
|------|------|
| 通道 | 一次信息获取的入口（工具或会话期注入） |
| 命中 | 通道返回可用内容 |
| 升级 | 主通道空结果后按规则改走备选通道 |
| 业务实体 | 系统内可被引用的对象（节点、项目、文件、人员、企业、任务、事件、会议等） |
| 策略表 | 承载分工、升级目标、并发白名单的外置配置 |

## 四、约束（约束型技术决策）

纳入本需求范围的约束型技术决策共 11 条：

1. 通道元数据必须**双处存储**（配置文件 + 数据表），不得只存一处。
2. 工具描述必须**由元数据生成**，不得手写副本。
3. 升级策略**默认开启**，且必须提供整体关闭能力。
4. **常态并发默认关闭**，白名单之外不得并发。
5. 实体解析必须覆盖**登记的全部业务实体**，不得只覆盖部分类型。
6. 路由规则必须**外置且运维可改**，不得写死在代码或提示词模板正文之外。
7. 通道可见性必须**复用既有唯一权威来源**，失败即拒（fail-closed）。
8. 不得引入**第二编排器**（与内核图化的 D7 一致）。
9. 不得**全量并发**检索。
10. 「通道选择正确率」必须**纳入监控指标**。
11. **不得为落实本需求改写内核图结构**：本需求属治理层。

**触碰的架构铁律**：C2（分层不可跳）、C10（能力注册接入）、C11（功能注册接入）。
**触碰的质量红线**：Q4（无残留，规则与元数据不得留孤儿）、Q6（接线闭合，新增配置必须有读取方）。

## 五、非功能需求

1. **常态成本不增**：默认单通道；仅在空结果时产生额外开销。
2. **可观测**：每次检索可回溯（日志与会话归档）。
3. **可回退**：策略表可整体关闭。
4. **注入方式安全**：会话期注入必须以独立系统消息参与消息列表；历史上把注入内容**拼接在系统提示词尾部**曾导致工具调用被抑制（本项目实测），此坑必须在实现约束中规避。
5. **升级跳数设上限**：串行升级不得无界，需设最大跳数。

## 六、非目标

1. 不替换全文搜索引擎。
2. 不做排序与重排算法研究。
3. 不做跨库联邦查询。
4. 不启封休眠通道（专家名册按 D10 保持休眠）。

## 七、验收与度量

1. **语料**：以现有 RAGENV 测试集扩展「通道选择」语料，每题标注**期望命中通道**与**期望不命中通道**。
2. **回归题**：本次两处现象作为必通过回归——RAG-04（节点进度被台账抢占）、RAG-11（实体不存在即终止）。
3. **判定三件事**：通道是否选对；空结果是否升级；来源是否标注。
4. **指标**：通道选择正确率 = 选对通道的请求数 ÷ 需检索的请求数；并统计升级触发率、升级成功率、平均跳数。
5. **权限回归**：不同等级用户对机密文档的可见性不得因本次改动而放宽（文件密级已简化为 3 级，取消绝密）。

## 八、风险与开放问题

| 风险 | 说明 | 缓解 |
|------|------|------|
| 元数据与实现漂移 | 描述手写会落后于实现 | 约束 2（描述由元数据生成） |
| 规则过拟合 | 策略表只覆盖已知问题 | 用评测语料回归，逐题标注期望通道 |
| 升级导致延迟叠加 | 串行多跳 | 非功能 5（跳数上限） |
| 注入抑制工具调用 | 本项目已有实测教训 | 非功能 4（独立系统消息 + 回归验证） |
| 通道选择正确率无基线 | 目标值未知 | 先建基线数据，再定目标（见开放问题） |

**开放问题**：
1. 「通道选择正确率」的目标值定为多少？建议先跑一轮建基线再定。
2. 白名单问题类型的初始名单包含哪些？
3. 检索日志是扩展现有表还是新建统一表？属方案问题，交 req-plan。
4. 会话期注入类通道是否也纳入元数据登记（当前以可调用通道为主）？

## 附录 B 交接给计划阶段的方案型问题

以下属实现方案，不在本规格内求解：

1. 元数据表的表结构与列定义；是否复用现有表。
2. 策略表的格式、加载时机与热更新方式。
3. 升级引擎的实现位置（治理层包装 / 图内节点），及与既有能力通道的衔接。
4. 检索日志的数据落点（扩展现有表或新建统一表）。
5. 实体解析复用的既有 resolver 范围与扩展方式。
6. 会话期注入的注入点与消息形态（须满足非功能 4）。
7. 「通道选择正确率」的计算口径、采集点与上报方式。
8. 分工表初版的条目内容与白名单初版名单。
