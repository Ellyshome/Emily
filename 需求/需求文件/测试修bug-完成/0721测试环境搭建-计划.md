### 1.2 现有 `reset_emerald.ps1` 的三个核心问题

| # | 问题 | 根因 | 后果 |
|---|------|------|------|
| 1 | **重置不彻底** | 脚本用 `docker compose down -v`，但 PostgreSQL 数据目录是 **bind mount**（`emily-data/db_seeds:/var/lib/postgresql/data`，见 [docker-compose-napcat.yml:104](../docker-compose-napcat.yml#L104)）。`down -v` 只删 named volume，**不删 bind mount**。 | 数据库内容跨重置残留，不是真正的空库。 |
| 2 | **无磁盘文件生成** | 脚本只写 `files` 表记录，不在磁盘创建实际文件。`storage_path` 指向 `/mock/project-emerald/...` 但该路径不存在。 | 文件类 SOP（SOP-004 `search_files`、文件下载）测试时找不到文件，`get_local_path()` 返回的路径无效。 |
| 3 | **`storage_path` 绝对路径 bug** | 现有种子数据 `storage_path = '/mock/project-emerald/...'`（带前导 `/`）。`FileStorageService.get_local_path()`（[file_storage_service.py:276](../emily-core/emily_core/services/file_storage_service.py#L276)）执行 `self._storage_root / f.storage_path`，Python 中 `Path("/app/attachments") / "/mock/..."` 结果是 `/mock/...`（绝对路径覆盖基路径）。 | 文件永远解析到 `/mock/...` 而非 storage_root 下，路径彻底错乱。 |

## 三、功能一：一键重置数据库（空库）

### 3.1 正确的重置方式

**不用 `docker compose down -v`**（对 bind mount 无效），改用 SQL TRUNCATE：

```
流程：
  1. 确认 emily-postgres 容器在运行（没运行则 docker compose up -d emily-postgres）
  2. 执行 000_reset_all.sql → TRUNCATE 全部业务表（保留 schema）
  3. 验证：表数 ≥ 54，所有数据表行数 = 0
```

### 3.2 核心实现

```powershell
function Invoke-ResetDatabase {
    Write-Host "[重置] TRUNCATE 全部业务表（保留 schema）..." -ForegroundColor Yellow

    # 确保 postgres 容器在运行
    $pgState = docker inspect -f '{{.State.Running}}' emily-postgres 2>$null
    if ($pgState -ne 'true') {
        docker compose -f docker-compose-napcat.yml up -d emily-postgres | Out-Null
        Start-Sleep -Seconds 3
    }

    # 执行 TRUNCATE 脚本（000_reset_all.sql 已按 FK 依赖顺序排列）
    Get-Content "emily-core/emily_core/infrastructure/database/scripts/000_reset_all.sql" |
        docker exec -i emily-postgres psql -U emily -d emily 2>&1 | Out-Null

    # 验证空库
    $tableCount = docker exec emily-postgres psql -U emily -d emily -t -c `
        "SELECT count(*) FROM information_schema.tables WHERE table_schema='public';"
    $dataRows = docker exec emily-postgres psql -U emily -d emily -t -c `
        "SELECT coalesce(sum(cnt),0) FROM (
            SELECT count(*) cnt FROM users UNION ALL
            SELECT count(*) FROM projects UNION ALL
            SELECT count(*) FROM files UNION ALL
            SELECT count(*) FROM messages UNION ALL
            SELECT count(*) FROM project_nodes
        ) t;"

    Write-Host "  [OK] 表数: $($tableCount.Trim())，关键表行数: $($dataRows.Trim())" -ForegroundColor Green
}
```

### 3.3 关键约定

- **保留 schema**：`000_reset_all.sql` 用 `TRUNCATE ... CASCADE`，不 DROP 表。emily-core 无需重启。
- **幂等**：TRUNCATE 空表不报错，脚本可重复执行。
- **不动容器**：不需要 `down`/`up`，emily-core 保持运行（其 ORM session 连接池自动适应）。
- **清附件目录**：重置时同时清空 `emily-data/attachments/mock/` 下旧文件（见功能二重新生成）。

### 4.3 磁盘空文件生成（`New-MockFiles`）

#### 4.3.1 核心逻辑

```
1. 从 DB 查询所有 files 记录：SELECT file_no, filename, storage_path, file_category, project_code
2. 对每条记录：
   a. 计算规范化相对路径：mock/{project_code}/{category}/{filename}
      例：mock/EMERALD-01/PHASE_DELIVERABLE/主体结构分部验收报告.pdf
   b. UPDATE files SET storage_path = <相对路径> WHERE file_no = ...  （修复绝对路径 bug）
   c. 在宿主机 emily-data/attachments/<相对路径> 创建空文件（0 字节）
3. 同步修复 message_attachments.local_path（如有）
```

#### 4.3.2 路径映射

| 项 | 值 |
|----|----|
| 容器 storage_root | `/app/attachments`（env `EMILY_STORAGE_ROOT`） |
| 宿主机对应目录 | `d:\app\Emily\emily-data\attachments`（bind mount，见 [docker-compose-napcat.yml:64](../docker-compose-napcat.yml#L64)） |
| DB `storage_path` 存储格式 | **相对路径**：`mock/EMERALD-01/PHASE_DELIVERABLE/主体结构分部验收报告.pdf` |
| `get_local_path()` 解析结果 | `/app/attachments/mock/EMERALD-01/PHASE_DELIVERABLE/主体结构分部验收报告.pdf` ✅ |
| 宿主机实际文件 | `d:\app\Emily\emily-data\attachments\mock\EMERALD-01\PHASE_DELIVERABLE\主体结构分部验收报告.pdf` ✅ |

#### 4.3.3 实现伪代码

```powershell
function New-MockFiles {
    Write-Host "[文件] 生成磁盘空文件 + 修复 storage_path..." -ForegroundColor Yellow

    $attachmentsRoot = "emily-data/attachments"
    # 清旧 mock 文件（只清 mock 子目录，不动其他真实附件）
    if (Test-Path "$attachmentsRoot/mock") { Remove-Item "$attachmentsRoot/mock" -Recurse -Force }

    # 从 DB 拉文件清单（含 project_code）
    $rows = docker exec emily-postgres psql -U emily -d emily -t -F "|" -c "
        SELECT f.file_no, f.filename, f.file_category, p.code
        FROM files f JOIN projects p ON f.project_id = p.id
        WHERE f.is_deleted = false;"

    foreach ($line in $rows) {
        $parts = $line.Trim() -split "\|"
        if ($parts.Count -lt 4) { continue }
        $fileNo, $filename, $category, $projectCode = $parts

        # 规范化相对路径（用正斜杠，DB 存储统一格式）
        $relPath = "mock/$projectCode/$category/$filename"
        $fullPath = "$attachmentsRoot/$relPath"

        # 创建目录 + 空文件
        $dir = Split-Path $fullPath -Parent
        New-Item -ItemType Directory -Path $dir -Force | Out-Null
        New-Item -ItemType File -Path $fullPath -Force | Out-Null

        # 修复 DB storage_path（去前导 /，改用相对路径）
        $escaped = $relPath -replace "'", "''"
        docker exec emily-postgres psql -U emily -d emily -c `
            "UPDATE files SET storage_path = '$escaped' WHERE file_no = '$fileNo';" | Out-Null
    }
    Write-Host "  [OK] 磁盘文件已生成，storage_path 已修复" -ForegroundColor Green
}
```

## 八、注意事项

1. **PowerShell 编码**：文件名含中文（如"主体结构分部验收报告.pdf"），脚本需设 `$OutputEncoding = [System.Text.Encoding]::UTF8` 且 `$env:PYTHONIOENCODING="utf-8"`，避免 GBK 乱码（见 CLAUDE.md 踩坑速查）。
2. **`manage_nodes.py` 的 `creator_id`**：需传真实用户 UUID。008 YAML 中用 `creator: admin_wang` 用户名，`manage_nodes.py` 会自动解析（见 [测试.md:71](环境布置/测试.md#L71)）。
3. **幂等性**：所有 SQL 脚本应可重复执行。现有 002 已 `DELETE` 旧数据再插入；010 需同样模式（`DELETE FROM scheduler_jobs WHERE job_no IN (...)` 再插入）。
4. **不清 `emily-data/attachments` 全目录**：只清 `mock/` 子目录，避免误删真实运行时产生的附件。
5. **`pipeline_run_id` 关联**：010 脚本的 `user_feedback_signals` / `rag_retrieval_logs` 需从现有 `pipeline_execution_logs` 反查真实 `pipeline_run_id`，不能编造。
6. **不修改现有种子脚本**：007 的 `storage_path` 绝对路径 bug 由 `New-MockFiles` 函数在运行时修复，不改 007 原文（保持现有脚本稳定性）。
