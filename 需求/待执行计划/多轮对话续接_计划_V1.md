### 架构决策

**为什么选 SessionAgent 内聚判题，而非 LangGraph checkpoint 跨轮次续跑？**  
LangGraph checkpoint 的 thread_id 机制虽然支持断点续跑，但需要持久化 checkpointer（PostgresSaver）且不改变当前 MemorySaver 架构。更重要的是，LangGraph 图本身没有"用户是在继续还是换话题"的语境——这必须由拥有完整 message_history 的 SessionAgent 来判断。当前方案：SessionAgent 判断 continuation，WorkItem 只执行，职责清晰且改动量小。

**为什么在 _recognize_intent 同次 LLM 调用产出 continuation，而非额外调一次？**  
节省 ~500ms + token 成本。续接判断和意图识别共享同一个 prompt 上下文（message_history + 项目背景 + 用户记忆），天然适合同一次调用。

# 在 _handle_impl 中，焦点切换检测之后、_split_into_workitems 之前追加

        # ── 多轮续接：检查是否有挂起的 WorkItem ──
        paused_wi = getattr(self, "_paused_workitem", None)
        if paused_wi and paused_wi.state == WorkItemState.WAITING_FOR_INPUT:
            # 需要先识别意图才能判断 continuation
            intent = await self._recognize_intent(message)
            await self._append_archive_intent(intent)
            
            if intent.get("continuation"):
                # ★ 续接模式：复用挂起的 WI，注入新输入
                paused_wi.additional_input = content
                paused_wi.state = WorkItemState.EXECUTING  # 恢复执行
                self._paused_workitem = None
                
                # 将同一个 WI 重新入队执行
                self.scheduler.enqueue(paused_wi)
                done = await self.scheduler.run_all_with_message(
                    message, db_message_id=db_message_id,
                    actor_snapshot=getattr(self, "_current_actor", None)
                )
                self._last_turn_workitems = done
                
                # 检查是否需要再次挂起
                for wi in done:
                    if wi.state == WorkItemState.WAITING_FOR_INPUT:
                        self._paused_workitem = wi
                        return self._reply(message, wi.question)  # M5: 直接返回问题
                
                final_reply = await self._synthesize_final_reply(message, done)
                return self._reply(message, final_reply)
            else:
                # 用户切换话题，放弃旧 WI
                try:
                    paused_wi.transition_to(WorkItemState.ABANDONED)
                except ValueError:
                    paused_wi.state = WorkItemState.ABANDONED
                self._paused_workitem = None
                logger.info("Session[%s] abandoned paused WI %s (user switched topic)",
                            self.conversation_id, paused_wi.id)
                # 继续走正常流程
```

**注意**：这需要把 `_recognize_intent` 调用提前到分叉处。为避免重复调用，需要调整原有 `_split_into_workitems` 的调用逻辑——当从续接分叉恢复时跳过第②步。最简单的方式是把续接分叉放在第②步**之前**完整覆盖：

            return self._reply(message, fast)

        # ①b 焦点切换（不变）
        if FocusLock.wants_switch(content):
            self.focus.clear_focus()

        # ★ 续接分叉：检查挂起的 WI

        continue_wi = None
        if paused_wi and paused_wi.state == WorkItemState.WAITING_FOR_INPUT:

            await self._append_archive_intent(intent)
            if intent.get("continuation"):
                continue_wi = paused_wi
                continue_wi.additional_input = content
                continue_wi.state = WorkItemState.EXECUTING
                self._paused_workitem = None
            else:
                try:
                    paused_wi.transition_to(WorkItemState.ABANDONED)
                except ValueError:
                    paused_wi.state = WorkItemState.ABANDONED
                self._paused_workitem = None

        # ② LLM 意图识别 + WorkItem 拆分（续接模式跳过）
        if continue_wi:
            work_items = [continue_wi]
        else:
            work_items = await self._split_into_workitems(message)
            if not work_items:
                return self._reply(message, "我暂时不太确定你的意思...")

        # ②b 设置焦点（不变）
        self.focus.set_focus(work_items[0].id)

        # ... 后续不变（SYS-confirm、BUS 执行、回复合成）
```

## 阶段反思指令

   - 如果偏差 2-4 个文件或步骤顺序调整 → 在计划文档末尾追加 "v1.1 修订记录"，继续
   - 如果偏差 > 4 个文件或架构方向变化 → **停止**，报告给用户，等用户决定是否重新生成计划
