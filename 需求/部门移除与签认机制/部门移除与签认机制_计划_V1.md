# 部门移除与签认机制 — 概要设计（SD）

> **基于规格（PRD）**：[部门移除与签认机制_PRD_V1.md](部门移除与签认机制_PRD_V1.md)
> **宪法版本**：v1.0
> **设计版本**：v1.0
> **级别**：System Design（概要设计）
> **目标**：把"部门"从权限维度与业务对象中移除，用"签认"替代"审批"，使信息先记录、后认可、不阻断入库。

## M1: 权限去部门化

**依赖**：无

**实现的需求**：US-01（AC-US-01.1~01.3）、US-02（AC-US-02.1~02.3）

**层级**：Service / Permission

**职责**：把 `department` 从权限快照、SOP 白名单计算、三维鉴权、会话上下文中彻底移除，使权限仅由 `level`（等级）+ `company_type`（单位性质）唯一确定；并消除"引用不存在的用户部门"导致的运行时异常。

### 接口契约

#### 对外接口（修改签名，显式声明）

| 接口/类 | 类型 | 签名（改后） | 说明 |
|---------|------|------------|------|
| `PermissionService.build_permission_dict` | 方法 | `(user_id: str) -> dict` | 返回 dict **不含** `department` 键 |
| `PermissionCache.get_user_whitelist` | 方法 | `(user_id: str, user_level: int, company_type: str) -> tuple[list[str], list[str]]` | **删除** `department` 形参（修改接口签名） |
| `PermissionAuthEngine._check_sop_matrix` | 方法 | `(perms: dict, sop_id: str) -> Optional[AccessCheckResult]` | 移除 3.5 部门匹配 |
| `SessionContext` | dataclass | 删除字段 `department` | 变量映射删除 `{user_department}` |

#### 依赖接口

| 现有接口 | 来源模块 | 调用目的 |
|----------|---------|---------|
| `PermissionRepository.get_user/get_company` | Permission | 取 level / company_type |
| `PermissionCache.get_matrix` | Permission | L1 权限矩阵 |
| `.level.can_access` | Permission | 树形等级判定 |

### 数据模型

无表结构变更（M1 只改逻辑）。存量部门列的清空由 M6 处理。

## 阶段反思指令

每完成一个模块的设计，在进入下一个模块之前，执行以下反思：

1. **检查设计完整性**：本模块的接口契约、数据模型、验收检测是否完整
2. **检查追溯闭合**：本模块声明的 US 是否都有接口/验收覆盖；对照追溯矩阵有无遗漏
3. **检查设计偏差**：是否有与规格（PRD）不符的设计？如发现规格缺陷，**回退 req-review**，不在计划内扩需
4. **判断是否继续**：
   - 偏差 ≤ 1 个接口调整 → 直接修改设计文档对应模块，继续
   - 偏差 2-4 个接口或模块职责调整 → 在设计文档末尾追加 "v1.1 修订记录"，继续
   - 偏差 > 4 个接口或架构方向变化 → **停止**，报告给用户，等用户决定是否重新生成设计
