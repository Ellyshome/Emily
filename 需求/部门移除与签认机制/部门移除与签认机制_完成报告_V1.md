# 部门移除与签认机制 — 完成报告

> **日期**：2026-09-11
> **基于 PRD**：[部门移除与签认机制_PRD_V1.md](部门移除与签认机制_PRD_V1.md)

---

## 一、总体目标

1. **去掉"部门"这个没有事实基础的中间概念**：让权限归口回归「单位性质 + 人员等级」两个有数据支撑的维度，并消除"引用不存在的用户部门"导致的运行时报错。
2. **用"签认"替代"审批"**：把"能不能入库"（阻断）改为"可不可信"（标注），实现"信息先记录、后认可"。
3. **存量干净与概念收敛**：清空业务对象上的部门标识与审批阻断态，全系统不再新增部门维度。

## 四、验收结果（真实环境）

| 目标 | 证据 |
|------|------|
| 权限去部门 | 快照无 `department` 键；同单位性质同等级用户 `sop_allow`/`db_perms` 一致 |
| 入库不阻断 | 非管理员建节点返回"已创建并入库（状态：条件未满足）"，无"待审批"；`owner_dept_id` 为空 |
| 签认等级门槛 | L3 签认返回 `403 等级不足（当前 L3，需 L4）`；L4 签认成功并留痕三项；重复签认幂等 |
| 未签认标注 | 用户可见回复出现"全部节点「未签认」"；已签认不带标识；未签认信息正常展示 |
| 存量迁移 | 预览不写库；执行后部门标识残留 `0`、阻断状态 `0`；二次执行 `0` 变更 |
