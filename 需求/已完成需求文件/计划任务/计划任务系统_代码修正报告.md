## P0 修正方案

### P0-1: 同步/异步混合调用 → `asyncio.to_thread()` 包裹

**根因**：Repository 全部使用同步 `with get_session()`，Project 其他模块也是如此（EventRepo、TaskRepo 等均同步）。改动整个项目为 async engine 工作量过大。

**方案**：在 Service 层方法的公共入口处，将 Repository 调用包裹进 `asyncio.to_thread()`，让同步 I/O 在线程池中执行：

```python
import asyncio

async def create_template(self, cmd):
    return await asyncio.to_thread(self._create_template_sync, cmd)

def _create_template_sync(self, cmd):
    template_no = PlanTaskTemplateRepo.generate_template_no()
    return PlanTaskTemplateRepo.create(...)
```

同时也修复 UserRepository 的调用（当前 Service 中对 `self._user_repo.get_by_id()` 使用了 `await`，但 UserRepository 同样是同步的）。

### P0-2: instance_no → instance_id 解析

**根因**：`handle_submit_plan_task` 和 `handle_review_plan_task` 接收 `instance_no`，但传给 Command 的 `instance_id=""`。

**方案**：在两个 Tool Handler 中，先调用 `PlanTaskInstanceRepo.get_by_instance_no(instance_no)` 获取 instance_id，再构建 Command。

### P0-3: 添加 UniqueConstraint

**根因**：`PlanTaskInstance` 缺少 `__table_args__`。

**方案**：在 models.py 的 `PlanTaskInstance` 类中添加：
```python
__table_args__ = (
    UniqueConstraint("template_id", "period_key", name="uq_pti_template_period"),
)
```

### P0-4: User 模型添加 permission_level

**根因**：`User` 模型没有 `permission_level` 字段，鉴权逻辑读到的是默认值 0。

**方案**：在 `User` 模型中添加字段：
```python
permission_level = Column(Integer, default=0)  # 0=访客 1=参建 2=主管 3=一般管理员 4=系统管理员
```

### P0-5: Scheduler 调用 self._service.find_by_status（不存在的方法）

**根因**：`_auto_archive_confirmed` 调用 `self._service.find_by_status("CONFIRMED")`，但 Service 没有 `find_by_status` 方法。

**方案**：改为调用 scheduler 自己的 `self.find_by_status("CONFIRMED")`。

### P0-6: 分布式锁改为会话级持有

**根因**：`_acquire_distributed_lock` 中 `with get_session()` 离开时锁即释放。

**方案**：使用一个单独的持锁 session，在整个 `_tick()` 期间保持打开：
```python
async def _tick(self):
    # 获取持锁 session（不在 with 块中）
    lock_session = get_session_raw()
    acquired = lock_session.execute(text("SELECT pg_try_advisory_lock(...)"))
    if not acquired:
        lock_session.close()
        return
    try:
        ...  # 执行所有调度逻辑
    finally:
        lock_session.execute(text("SELECT pg_advisory_unlock(...)"))
        lock_session.close()
```

## P1 修正方案

### P1-1: LLM 失败标记移到 Template 级别

在 `PlanTaskTemplate` 添加 `llm_calculation_failed` 和 `llm_failure_notified` 字段。Scheduler 推算失败时在模板上标记，通知模板发起人而非实例发起人。

### P1-2: 计划外事件匹配接入 Pipeline Hook

在 `AuthHook` 或新建 `PlanTaskMatchHook` 中，对 `record_event` / `record_task` 执行前调用 `match_or_create_unscheduled()`。

### P1-3: 事务边界统一

实例创建和日志写入合并到同一个 session 中。在 `PlanTaskLogRepo` 方法中增加 `session` 参数（可选），传入时复用 session，不传时自建。

class InvalidStateTransitionError(ValueError): ...
