# 分级兜底（Fallback Tiering）— 概要设计（SD）

> **基于需求**：会话讨论结论（2026-09-09，本会话逐轮确认；正式需求文档另行补录时以本设计为准）
> **设计版本**：v1.0
> **级别**：System Design（概要设计）
> **目标**：将"无 SOP 命中的自由兜底（fallback agent loop）"由"全员同等开放"收敛为**两级授权**——普通用户仅享最小安全工具集；管理员/管理单位人员获得受节点边界约束的"自由检索 + 追加式写"，实现能力可控、越权可视、写入可审计。

## 需求基线（本计划依据的逐条结论）

| # | 已确认结论 |
|---|-----------|
| R1 | 兜底分两层：**基础兜底**（全员）与**高级兜底**（资格人群） |
| R2 | 高级兜底资格 = `level >= 4`（建设主管/管理员/系统管理员）**或** `is_management_unit == True`（企业被标记为管理单位） |
| R3 | 基础兜底工具集 = `{knowledge_search, chat_archive}`；`chat_archive` 覆盖**私聊（本人）**与**群聊（用户已加入的群，仅入群时间之后的记录）** |
| R4 | 高级兜底可访问范围**仍受用户参与的全景节点约束，不得越界**；放开读写权，但**写以"追加式（append-only）"为主** |
| R5 | 写能力分级：**追加型（create）放开**；**状态迁移型（transition）半放开（走合法状态机迁移，其余需确认）**；**覆盖/编辑已有内容、删除/批量不放**（走对应 SOP + 人工确认） |
| R6 | RAG（`knowledge_search`）视为**普惠基座能力**，进入基础兜底；其更高级形态（自由组合检索/交叉分析）属高级兜底 |
| R7 | 写工具永远不因"高级兜底"绕过 SOP 门禁框架约束之外的校验；任何兜底写都先解析目标节点并在 `authorized_node_ids` 内校验 + 写后审计回告 |
| R8 | 硬性范围安全（不属分级、任何档位都成立）：`chat_archive` 的私聊/群聊作用域必须收敛（见 M0） |

## 硬约束（违反即失败）

1. **禁止修改已有接口签名**：除设计明确标注"修改签名"的点（仅 `build_tool_specs` 扩展关键字参数、`ToolDefinition`/`_tool()` 增字段、WorkItem 增字段）外，一律在已有类中新增方法/参数，不改现有方法行为与返回。
2. **分层不可跳**：`API → EmilyCore → Session → WorkItem → Application → Service → Repository → DB`。兜底策略属 Session/WorkItem 编排层逻辑；不跨层直接操作 DB。
3. **不引入孤儿代码**：新增能力必须挂到既有注册/调用点（工具 → `tools/registry.py`；脚本 → `scripts_registry.yaml`；SOP → `sops/`；调度 → handler registry）。禁止"实现文件无人调用"。
4. **工具必须带参数 schema**：本次不新增业务工具；仅给既有工具登记"写类型元数据"，仍满足 schema 三步入库。
5. **根治而非迁就**：作用域收敛（M0）在工具/服务层根治，不在提示词层靠"请模型自觉"。
6. **安全默认（fail-closed）**：新增档位白名单默认为空集；任何未显式登记为"基础/高级可用"的工具默认对兜底不可见。权限判定失败一律降级为基础档（最低权限）。
7. **写不放**：高级兜底的"写"绝不包含覆盖/删除/批量；追加/状态迁移写仍须通过既有 resolver/service 的节点与字段合法性校验。
8. **每模块验收**：每个模块验收命令必须通过，否则停止并报告。
9. **遵循接口契约**：跨模块调用只走约定接口；`fallback_policy` 是唯一"档位判定/白名单"事实源，禁止在多个文件里硬编码第二份名单。

## 数据流设计

### 核心流程：一条无 SOP 消息的档位化处理

```
用户消息 → SessionAgent
  ├─ 命中 SOP ──────────────→ WorkItem(sop) ──→ 执行引擎（现状不变）
  └─ 未命中（fallback）─────→ M3: wi.fallback_tier = Policy.gate(actor)
                                 │ basic / advanced
  M4 created 节点:
    tier=basic    → tool_specs = 基础白名单 ∩ session_api_ids（仅 knowledge_search/chat_archive，零写）
    tier=advanced → tool_specs = (高级只读白名单 ∪ 追加写白名单) ∩ session_api_ids
                          写工具每次调用 → 节点边界校验(authorized_node_ids) → 合法状态迁移/append
                          → 审计 + 回复回告编号
  agent loop → 结构化结果 → session_reply 合成（M5 话术按档位/拒绝原因给用户）
```

### 核心流程表

| 流程 | 触发条件 | 参与者 | 数据流向 | 异常路径 |
|------|---------|--------|---------|---------|
| 档位判定 | 创建 fallback WorkItem | M3→M1 | actor→tier | actor 缺失→基础档（fail-safe） |
| 基础兜底执行 | tier=basic | M4→M1→registry | 消息→仅 2 工具→回复 | 无权限工具→fail-closed 不暴露 |
| 高级追加写 | tier=advanced 且调用 append 工具 | M4→resolver→Service | 参数→节点校验→append→审计 | 越界节点→拒绝并提示；非法状态迁移→拒绝 |
| 普通用户越权请求 | tier=basic 但意图需自由检索/写 | M4/M5 | 消息→无对应工具→引导话术 | LLM 空工具返回→合成"走对应 SOP / 找管理员"话术 |

## M0: chat_archive 作用域收敛

**依赖**：无（首建模块，独立验收）

**层级**：Service + 工具

**职责**：把 `chat_archive` 从"全局可见/靠命名检索"收敛为"仅可见本人有权看到的会话"：
- 私聊：仅本操作者（actor）参与的会话；
- 群聊：仅本操作者**已加入**的群，且仅**其入群时间之后**产生的消息。

### 接口契约

#### 对外接口

| 接口/类 | 类型 | 签名 | 说明 |
|---------|------|------|------|
| `ChatArchiveService` | 服务 | — | 在既有查询方法上叠加作用域过滤 |
| `search_messages(actor_user_id, keyword, ..., scope_guard=None)` | 修改签名（标注） | 输入操作者 + 查询参数；返回过滤后消息 | 追加操作者参数，强制作用域 |

| 作用域解析 | 内部 | `resolve_allowed_conversations(actor_user_id) -> set[(conversation_id, visible_from)]` | 私聊=本人会话；群聊=已加入群 + 入群时间 |

## M1: fallback_policy（档位策略唯一事实源）

**依赖**：无

**层级**：编排层策略（置于 `emily-core/emily_core/workitem/langgraph_engine/agent/fallback_policy.py`，与 tool_adapter 同层）

**职责**：集中定义"档位判定"与"两级白名单"，全系统唯一事实源。

### 接口契约

#### 对外接口

| 接口/类 | 类型 | 签名 | 说明 |
|---------|------|------|------|
| `FallbackTier` | Enum | `BASIC="basic"`、`ADVANCED="advanced"` | 档位 |
| `FallbackPolicy.gate(actor: dict) -> FallbackTier` | 静态/类方法 | `actor={level:int, is_management_unit:bool}` | `level>=4 or is_management_unit → ADVANCED`；否则/字段缺失→BASIC（fail-safe） |
| `FallbackPolicy.basic_tools() -> frozenset[str]` | 静态 | — | `{knowledge_search, chat_archive}` |
| `FallbackPolicy.advanced_read_tools() -> frozenset[str]` | 静态 | — | 现 `FALLBACK_SAFE_TOOLS`（只读集） |
| `FallbackPolicy.advanced_append_tools() -> frozenset[str]` | 静态 | — | 高级追加写工具白名单（见 M2 语义，默认空，逐工具登记） |
| `FallbackPolicy.resolve(tier, *, with_write=False) -> frozenset[str]` | 静态 | — | 单一口径取白名单 |

#### 依赖接口

| 现有接口 | 来源 | 调用目的 |
|----------|------|---------|
| `PermissionLevel.OWNER_SUPERVISOR.value` | `emily_core/permission/level.py` | 阈值 4（不 magic number） |
| `PermissionLevel` 中 `is_management_unit` 语义 | 权限快照 | gate 输入字段 |

### 核心策略

| 策略 | 用途 | 选型理由 | 备选 |
|------|------|---------|------|
| 集中单一口径 | 档位判定+白名单唯一源 | 杜绝多份名单漂移；M6 可脚本校验 | 多文件散落（否决：违反硬约束 9） |
| fail-closed 默认空集 | 白名单 | 未登记工具对兜底不可见 | 默认全量再排除（否决：易漏） |

### 模块验收检测

```bash
uv run python scripts/check_fallback_policy.py --check
→ 预期输出：
  gate 矩阵（level 1-6 × is_management_unit T/F）全部正确；
  basic_tools == {knowledge_search, chat_archive}；
  advanced_append_tools 默认空集；退出码 0
```

**失败处理**：矩阵不符 → 检查谓词实现；多份名单 → 收敛回 policy 后重跑。

## M2: 工具写类型元数据（write_mode）

**依赖**：无

**层级**：工具注册层

**职责**：给所有工具登记"写语义类别"，作为高级追加写门禁的基础，并使一致性检查可自动校验。

### 接口契约

#### 对外接口

| 接口/类 | 类型 | 签名 | 说明 |
|---------|------|------|------|
| `WriteMode` | Enum | `READ` / `APPEND` / `TRANSITION` / `OVERWRITE` / `DELETE` | 写语义 |
| `ToolDefinition.write_mode` | 字段 | 默认 `READ` | 工具自声明 |
| `_tool(... , write_mode: WriteMode=READ)` | 修改签名（标注） | registry 注册参数 | 注册点注入 |
| 一致性映射 | 常量 | `TOOL_META_MAP` 增补列 | `check_tools_consistency.py` 复用 |

**归类口径**（实施时由注册处逐个核对登记）：
- `APPEND`（create/追加）：`record_event`、`record_task`、`record_meeting`、`record_file`、`new_file_version`、`send_file`、`link_file`、`create_*`/记忆新增 等"新建即留痕"类；
- `TRANSITION`（状态迁移）：节点/任务状态推进等"合法迁移即留痕"类（其余状态操作需确认队列）；
- `OVERWRITE` / `DELETE`：既有内容的编辑/软删/批量（**高级兜底一律不开放**）；
- `READ`：全部查询/检索/文件列举。

### 数据模型

无新增表。仅代码元数据（ToolDefinition + registry + tools_consistency 映射）。

### 模块验收检测

```bash
uv run python scripts/check_tools_consistency.py --dry-run   # 扩展项：write_mode 缺失即 error
→ 预期输出：全部业务/基座工具均有合法 write_mode；无 error
uv run python scripts/check_fallback_tools.py --dry-run
→ 预期输出：APPEND/TRANSITION 工具清单与高级白名单登记一致；未登记工具不会出现在高级白名单
```

**失败处理**：schema 三步缺失或 write_mode 缺失 → 对照 CLAUDE.md §6-11 补全后重跑。

## M4: 执行裁剪接线（工具按档位暴露 + 高级追加写门禁）

**依赖**：M1、M2、M3

**层级**：WorkItem 引擎（`tool_adapter.py`、`nodes.py` created 节点）

**职责**：
1. `build_tool_specs` 按 `fallback_mode + fallback_tier` 计算可见工具：基础档仅 `basic_tools`；高级档 = `advanced_read_tools ∪ advanced_append_tools`；
2. 追加写门禁：写调用仍走既有 `resolver`/Service 第二层权限与节点校验；新增"写语义门禁"（非 APPEND/TRANSITION 不得经兜底写）+ 写后审计 + 回复回告。

### 接口契约

#### 对外接口

| 接口/类 | 类型 | 签名 | 说明 |
|---------|------|------|------|
| `build_tool_specs(business_tools, resolvers, session_api_ids, *, fallback_mode=False, fallback_tier="basic")` | 修改签名（标注，向后兼容默认值） | 见左 | 兜底可见集 = `FallbackPolicy.resolve(tier, with_write=...) ∩ session_api_ids` |
| created 节点 | 修改 | 读取 `wi.fallback_tier`，透传 | 保持"拉起时固化一次"不变 |

#### 追加写调用链门禁（新增接口，位于 agent loop 写工具执行前）

| 接口 | 说明 |
|------|------|
| `assert_write_allowed(tool_name, tier)` | write_mode ∈ {APPEND, TRANSITION} 且 tool ∈ 对应白名单，否则拒绝 |
| 节点边界校验 | 复用现有 resolver/权限层：工具参数解析出目标节点须在 `authorized_node_ids` 内 |
| 写后审计 + 回告 | 复用现有 AuditHook/Trace/事件日志，落一条"fallback 高级写"，并把 `business_object_no` 回填回复 |

## 阶段反思指令

每完成一个模块的设计/实现，进入下一个之前执行：

1. **检查设计完整性**：接口契约、数据模型、验收检测是否完整；
2. **检查设计偏差**：是否与需求基线 R1-R8 不符，记录差异；
3. **判断是否继续**：
   - 偏差 ≤ 1 个接口调整 → 直接修正，继续；
   - 偏差 2-4 个接口/模块职责调整 → 在本设计文末追加"v1.1 修订记录"，继续；
   - 偏差 > 4 个接口或架构方向变化 → **停止**，报告用户决定是否重新生成设计。
