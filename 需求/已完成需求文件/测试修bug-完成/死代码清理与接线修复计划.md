## 2. Module D1：AgentTraceService 接线 + trace 查询 API

### 2.1 问题

`AgentTraceService` 从未实例化，`get_complete_agent_trace` 零调用方、无 API 路由。M4 删除 TraceHook 后，其写入方法（`create_reasoning_log` 等）已无消费者，但**查询方法 `get_complete_agent_trace` 是 trace Bug 验收的必要入口**，必须接线。

### 2.2 修复方案

**两步**：①在 EmilyCore 初始化时实例化并存为 `self._agent_trace_service`；②新增 `api/routes/trace.py` 暴露 `GET /api/v1/trace/{message_id}`，参照 [monitor.py](../emily-core/api/routes/monitor.py) 的 lazy `_get_service` + `set_xxx_service` 注入模式。

### 2.3 代码骨架

**① 实例化服务** — `emily-core/emily_core/__init__.py`（`_ensure_initialized` 内，建议紧跟 `_init_monitor_module()` 后）

```python
# ── Agent 追踪查询服务（D1：接线，供 trace API 查询）──
try:
    from .services.agent_trace_service import AgentTraceService
    self._agent_trace_service = AgentTraceService()
    logger.info("AgentTraceService initialized (trace query ready)")
except Exception as e:
    logger.warning("AgentTraceService init failed: %s", e)
    self._agent_trace_service = None
```

**② 新增 API 路由** — `emily-core/api/routes/trace.py`（新建文件）

```python
"""Agent 追踪查询 API —— 全链路回溯。

端点：
    GET /api/v1/trace/{message_id}  — 获取一条消息的完整 Agent 执行追踪
                                       （推理 + LLM 调用 + 工具调用）

参照模式：api/routes/monitor.py（lazy _get_service + set_xxx_service 注入）。
"""

from __future__ import annotations

import asyncio
import logging

from fastapi import APIRouter, HTTPException

logger = logging.getLogger("emily.api.trace")

router = APIRouter(prefix="/trace", tags=["trace"])

# 延迟初始化（与 monitor 路由同模式）
_service = None


def set_trace_service(service) -> None:
    """由 EmilyCore 注入 AgentTraceService 实例。"""
    global _service
    _service = service


def _get_service():
    """惰性获取 AgentTraceService。"""
    global _service
    if _service is not None:
        return _service
    try:
        from api.server import get_core
        core = get_core()
        core._ensure_initialized()
        _service = core._agent_trace_service
    except Exception:
        pass
    if _service is None:
        raise HTTPException(status_code=503, detail="Trace module not initialized")
    return _service


@router.get("/{message_id}")
async def get_agent_trace(message_id: str):
    """获取一条消息的完整 Agent 执行追踪。

    Returns:
        AgentTraceService.get_complete_agent_trace 的返回值
        （found=False 或含三层链路的 dict）。
    """
    svc = _get_service()
    # get_complete_agent_trace 内部走 sync Repository → 用 to_thread 包裹
    result = await asyncio.to_thread(svc.get_complete_agent_trace, message_id)
    return result
```

**③ 注册路由** — `emily-core/api/server.py`（在 monitor/evolution 路由注册段附近）

```python
# Agent 追踪查询 API
from .routes import trace as trace_routes  # noqa: E402

app.include_router(trace_routes.router, prefix="/api/v1")
```

**④ 注入服务到路由**（可选，lazy 模式下非必需）— `__init__.py` `_init_monitor_module` 同级处或 `_ensure_initialized` 末尾：

```python
# 供 trace 路由直接注入（lazy fallback 也能工作，此步可省）
try:
    from api.routes.trace import set_trace_service
    set_trace_service(self._agent_trace_service)
except ImportError:
    pass  # 非 API 运行场景
```

### 2.4 约束对照

| 约束 | 遵循情况 |
|------|---------|
| 分层不可跳（#2） | API → EmilyCore → Service(AgentTraceService) → Repository → DB ✓ |
| Sync repo + asyncio.to_thread（#6） | `get_complete_agent_trace` 走 sync repo，路由层 `asyncio.to_thread` 包裹 ✓ |
| 业务内核独立（#1） | 路由在 `api/`，服务在 `emily_core/`，不 import astrbot ✓ |
| 路由模式一致性 | 参照 monitor.py 的 lazy + set_xxx_service 模式 ✓ |

### 2.5 验收标准

- [ ] `GET /api/v1/trace/{message_id}` 对不存在/无 trace 的 message_id 返回 `{"found": false}`
- [ ] 对有 trace 数据的 message_id 返回 `{"found": true, ...}` 含三层链路（reasoning + llm_interactions + tool_calls）
- [ ] emy-test 发消息 → 取 `messages.id` → curl trace 端点 → 返回完整链路
- [ ] 路由未初始化时返回 503（非 500）

## 3. Module D2：ChatArchiveService 接线

### 2.1 问题

`ChatArchiveService` 从未实例化，`core._chat_archive_service` 从未赋值。`chat_archive` 工具已注册但恒返回 `{"success": False, "error": "聊天存档服务未启用"}`（[project/__init__.py:31-32](../emily-core/emily_core/tools/project/__init__.py#L31-L32)）。

### 3.2 修复方案

在 EmilyCore 初始化时实例化 `ChatArchiveService()` 并存为 `self._chat_archive_service`。工具注册逻辑 [registry.py:233](../emily-core/emily_core/tools/registry.py#L233) `getattr(core, "_chat_archive_service", None)` 会自动拾取，**无需改工具代码**。

**前提已满足**：
- `ChatArchiveService.__init__(storage_root="")` 无必填依赖
- 工具调用的 `search_messages` / `get_conversation_history` 方法在服务中存在（已核对方法名一致）
- M1 修复后入站消息已落库，**有数据可查**

### 3.3 代码骨架

**文件**：`emily-core/emily_core/__init__.py`（`_ensure_initialized` 内，建议紧跟 D1 后）

```python
# ── 聊天归档服务（D2：接线，激活 chat_archive 工具）──
```

### 3.4 验收标准

## 4. Module D3：QueryApplication 清理

### 4.1 问题

`QueryApplication` 从未实例化（全项目 `.py` 无 `QueryApplication(` 调用）。其 `handle_query(route_result, ...)` 签名依赖 legacy `RouteResult` 类型——这是旧路由架构的产物，新 WorkItem 架构下无调用方能产出 `RouteResult`，**属架构演进遗留，非"漏接线"**。

### 4.2 修复方案：删除

`QueryService` 已直接被使用（[__init__.py:367](../emily-core/emily_core/__init__.py#L367) + [registry.py:65](../emily-core/emily_core/tools/registry.py#L65)），Query 查询是简单 CRUD，不需要 Application 层编排。删除 `QueryApplication` 消除死代码。

### 4.3 代码改动

| # | 文件 | 改动 |
|---|------|------|
| 1 | [application/query_app.py](../emily-core/emily_core/application/query_app.py) | 整文件删除 |
| 2 | [application/__init__.py:12,19](../emily-core/emily_core/application/__init__.py#L12) | 删除 `from .query_app import QueryApplication` 和 `"QueryApplication"` 导出 |

### 4.4 注意事项

- 删除前确认 `RouteResult` / `QueryCommand` / `HandlerResult` 是否还有其他使用方。若仅 `QueryApplication` 使用，一并标记为 legacy（本计划不强制清理这些 adapter 类型，避免范围蔓延）
- `QueryService` 直接使用虽跳过 Application 层，但属可接受的简化（Query 无复杂编排需求），**不强制补 Application 包装**

### 4.5 验收标准

- [ ] 删除后 `emily-core` 容器正常启动，无 ImportError
- [ ] 查询类工具（query_data 等）功能不受影响
- [ ] `from emily_core.application import QueryApplication` 抛 ImportError（确认已移除）

## 8. 风险与回滚

| 风险 | 等级 | 缓解/回滚 |
|------|------|----------|
| D1 trace API 暴露敏感数据（LLM prompt/token） | 中 | 端点仅限内网（127.0.0.1:18080）；如需加鉴权可接 AuthHook 模式 |
| D2 `ChatArchiveService` 查询方法有隐藏 bug | 低 | M1 前一直没数据，从未被验证过；接线后先手动 curl 测 3 个 action |
| D3 误删仍被引用的类 | 极低 | 已核实 `QueryApplication(` 零调用；删除后容器启动即验证 |
| D4 monitor 路由有未发现的前置依赖 | 低 | 路由文件已完整，仅缺注册；注册失败不影响其他模块 |
| `AgentTraceService` 写入方法残留（M4 后无用） | 极低 | D1 仅接线查询方法；写入方法（`create_reasoning_log` 等）保留不删，避免破坏 import，日后可标记 deprecated |

### 回滚策略

- D1/D2 各自独立 commit（新增实例化 + 路由文件），回滚即 revert
- D3 删除操作独立 commit，回滚即恢复文件
- D4 单行注册，回滚即删行
- **无 DB schema 变更，零数据风险**

## 9. 后续建议（非本计划范围）

2. **legacy adapter 类型盘点**：`RouteResult` / `QueryCommand` / `HandlerResult` 等 adapter 类型可能随 `QueryApplication` 一起成为 legacy，建议单独盘点
3. **统一"服务初始化 + 路由注册"清单**：本次发现 monitor 路由漏注册，建议建立 `server.py include_router` 与 `services/` 目录的对照检查，防止"服务初始化了但路由没注册"或反向情况
