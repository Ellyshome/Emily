### 1.2 怎么做
1. **接线读取（核心一步）**：在 [session_data_fetcher.py](file:///d:/app/Emily/emily-core/emily_core/session/session_data_fetcher.py#L176) 第 1 步处，取到 `user` 后改为：

2. **注入长度保护**：对最终 `long_term_memory` 截断到 2000 字符，超限打 INFO 日志。
3. **补端到端断言**：`save_memory` 写入 → `SessionDataFetcher.fetch()` 返回的 snapshot 含该条目。
4. **文档对齐**：更新 `user_memory_service.py` 模块头注释为实际语义（文件优先、DB 兜底）。

- **2000 字符上限**：记忆条目随时间累积，防止变量区撑爆稳定前缀之外的提示词空间。

### 1.4 关键前置核对（修正 PRD 假设）

## 3. 修复项 C：图检查点持久化（MemorySaver → Postgres）

### 3.1 缺陷确认（已复验）
- [graph.py:13](file:///d:/app/Emily/emily-core/emily_core/workitem/langgraph_engine/graph.py#L13) 导入 `MemorySaver`，[graph.py:110](file:///d:/app/Emily/emily-core/emily_core/workitem/langgraph_engine/graph.py#L110) `compile(checkpointer=MemorySaver())`。
- [scheduler.py:338](file:///d:/app/Emily/emily-core/emily_core/workitem/scheduler.py#L338) 以 `pipeline_run_id` 作 `thread_id`，resume 走 `Command(resume=...)`（[:340-344](file:///d:/app/Emily/emily-core/emily_core/workitem/scheduler.py#L340-L344)），[_check_interrupt](file:///d:/app/Emily/emily-core/emily_core/workitem/scheduler.py#L370-L387) 用 `get_state` 读快照。
- 结论：进程重启后断点丢失，`WAITING_FOR_INPUT` 的 WI 永久卡死；内存还随 `pipeline_run_id` 无界增长。

### 3.2 怎么做
1. **加依赖**：`emily-core/requirements.txt` 增 `langgraph-checkpoint-postgres`（版本以 pip 与 langgraph 1.x 解析为准）。
2. **新建 checkpointer 工厂**：`workitem/langgraph_engine/checkpointer.py` → `build_checkpointer(config)`：
   - `config.database_url` 可连（默认参数连 `emily-postgres`）→ `AsyncPostgresSaver.from_conn_string(...)`；
   - 连接失败或显式 `langgraph_checkpointer="memory"` → 回退 `MemorySaver()` + WARNING，不阻断启动。
3. **建表迁移**：启动建图处（[`_build_pipeline_bus`](file:///d:/app/Emily/emily-core/emily_core/__init__.py#L464-L491)）调用 `await checkpointer.setup()`（幂等建表）。
4. **替换 compile**：`graph.py:110` 改为 `gs.compile(checkpointer=build_checkpointer(config))`，同步更新 :111 日志文案。
5. **终态清理**：WI 进入 `done/failed` 后 `adelete_thread(thread_id)`（try/except 包裹，失败仅告警），防 `checkpoints` 表无界增长。
6. **重启恢复巡检**：启动扫描 DB 中 `WAITING_FOR_INPUT` 的 WI，对"检查点不存在"者标记失败/待人工，避免用户回复撞 resume 异常。
7. **配置开关**：新增 `langgraph_checkpointer: str = "postgres" | "memory"`，并加入 bootstrap `env_map`（`EMILY_LANGGRAPH_CHECKPOINTER`）。

### 3.3 为什么
- **选 Postgres 复用现有 `emily-postgres`**（[docker-compose-minimal.yml:61-69](file:///d:/app/Emily/docker-compose-minimal.yml#L61-L69)）：与主库同生命周期，运维零新增组件；异步 API 与现有 `ainvoke` 匹配。SQLite 会引入第二存储介质与容器挂卷成本，不选。
- **保留 MemorySaver 回退**：Postgres 不可达时服务仍可启动（PRD 验收 §4），避免单点导致启动崩溃。
- **必须做终态清理**：否则每次运行都留一份 thread，等同把内存泄漏搬进数据库。

### 3.4 关键前置核对（修正 PRD / 旧结论）
- **旧阻塞项已消解，无需自定义 serializer**：`.claude/plans/LangGraph执行引擎替换_非完美项分析_V1.md` G1 记录"BusContext 不可 msgpack 序列化"，但 [state.py](file:///d:/app/Emily/emily-core/emily_core/workitem/langgraph_engine/state.py#L1-L31) 已重构为"纯可序列化 State + BusContext 走 contextvars"，该阻塞**已不存在**，PostgresSaver 可直接上。落地前仍须跑一次 `ainvoke` 确认无序列化异常。
- **contextvars 不跨进程，resume 依赖 scheduler 重建 BusContext**：好在 [scheduler.py:247](file:///d:/app/Emily/emily-core/emily_core/workitem/scheduler.py#L247) 每次执行都新建 BusContext、[:313](file:///d:/app/Emily/emily-core/emily_core/workitem/scheduler.py#L313) 在 `ainvoke` 前 `set_bus_context`，断点续跑时上下文来自 DB 重建，机制成立。
  - **但需核对**：resume 时重建的 BusContext 可能不含 `sop_text`，而 [_make_agent_loop_entry](file:///d:/app/Emily/emily-core/emily_core/workitem/langgraph_engine/graph.py#L160) 读 `ctx.get("sop_text","")`；断点位于 tool_node、恢复后回到 agent_node 时可能丢 SOP 上下文，需在实施时验证并决定是否补齐。
- **新增传递依赖**：`langgraph-checkpoint-postgres` 依赖 psycopg3，而项目现有的是 `psycopg2-binary`（[requirements.txt:9](file:///d:/app/Emily/emily-core/requirements.txt#L9)），安装会引入 `psycopg`，需在容器重建后确认共存无冲突。

### 3.5 验证
- `scripts/repro_checkpoint_persistence.py`：Phase A 挂起 → 新进程 `--resume` 续跑成功（修复前退出码 1，修复后 0）。
- 生产链路：`ask_user` 挂起 → `docker restart emily-core` → 用户回复 → 从断点续跑至终态，且已执行工具不重复执行。
- 无重启场景 resume 行为与现状一致（回归）；Postgres 不可达仍可启动；终态检查点被清理。

### 3.6 风险与回滚
- 风险：checkpoint 写入给主库增流量（每超级步一次）；`emily-postgres` 单点故障会阻断图中段。
- 回滚：`langgraph_checkpointer=memory` 立即回到现状；代码回滚为还原 compile 行 + 移除新模块。
