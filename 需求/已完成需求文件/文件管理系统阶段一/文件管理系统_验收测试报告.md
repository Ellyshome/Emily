## 三、测试发现与经验

### 3.1 LLM SOP 引擎局限性

`--managed --llm` 模式运行 Emily 完整的 SOP 引擎，LLM 收到消息后优先匹配已有 SOP（如"文件归档"），而非直接调用新注册的工具。这意味着：

- **新工具若没有对应 SOP，在 managed 模式下不会被 LLM 自主调用**
- 可用的 workaround：使用 `--message "tool_name param=value"` 格式引导 LLM（对 send_file 有效）
- 建议：为新工具配最小 SOP YAML，或使用 `--no-llm` + 直接 tool call 模式进行底层测试

### 3.2 emy-test SSE 客户端路径兼容性

send_file 成功后，SSE `file_send` 事件中的 `local_path` 被解析为 dict 而非字符串，导致客户端报错。这是测试工具的问题，不影响服务端功能验证。

### 3.3 跨操作系统文件 URL

`--file` 参数生成的 `file:///D:/temp/...` URL 在 Linux 容器中不可达。已在 SKILL.md 中添加注意事项，推荐测试文件放入 `emily-data/attachments/` 共享目录。

### 3.4 环境重置后 file_no 变化

`file_no` 在数据库重置后日期部分会更新（`FIL-20260725-xxxx` → `FIL-20260726-xxxx`）。`setup_test_env.ps1` 中的 `Invoke-SeedFileAccess` 和测试计划均已改为按排序位置动态选择，不再硬编码。
