## 修复方案

### 修复一：Agent 回复持久化 + 查询修正（问题2）

**现状**：
- [create_outbound()](file:///d:/app/Emily/emily-core/emily_core/repositories/message_repo.py#L317-L353) 创建出站消息时 `sender_user_id` 字段未填充
- [get_recent_by_user_id()](file:///d:/app/Emily/emily-core/emily_core/repositories/message_repo.py#L456-L489) 按 `sender_user_id == user_id` 过滤，查不到 agent 回复

**方案A（推荐）：修改 get_recent_by_user_id，按会话关联查询**

不走 `sender_user_id` 过滤，改为通过 Conversation 关联获取完整对话（用户消息 + agent 回复）。

```python
# message_repo.py - get_recent_by_user_id 改为按 conversation 关联查询

@staticmethod
def get_recent_by_user_id(user_id: str, limit: int = 20) -> list[dict]:
    """获取用户最近的完整对话（含用户消息 + Agent 回复），按时间正序。"""
    with get_session() as session:
        # 1. 找到该用户最近活跃的会话
        recent_msg = (
            session.query(Message.conversation_id)
            .filter(Message.sender_user_id == user_id)
            .order_by(Message.created_at.desc())
            .limit(1)
            .first()
        )
        if not recent_msg:
            return []

        # 2. 查该会话的完整消息（用户 + Agent）
        rows = (
            session.query(
                Message.content,
                Message.created_at,
                Message.direction,
                Message.sender_name,
                Message.sender_user_id,
            )
            .filter(Message.conversation_id == recent_msg.conversation_id)
            .order_by(Message.created_at.desc())
            .limit(limit * 2)  # 用户+Agent各一半
            .all()
        )

        turns = []
        for row in reversed(rows):
            if row.direction in ("user_to_agent", "inbound"):
                role = "user"
            else:
                role = "assistant"
            turns.append({
                "role": role,
                "time": row.created_at or "",
                "content": row.content or "",
                "sender_name": row.sender_name or "",
            })
        return turns
```

**方案A 优点**：不需要改动 outbound 写入逻辑，后端改动最小。
**方案A 风险**：如果用户同时在多个会话中发言，只会取最近一个会话的消息。若需跨会话，可扩为取多个 conversation_id。

**方案B（备选）：在 create_outbound 时填充 sender_user_id**

在 `create_outbound()` 调用处传入接收方 user_id 作为 `sender_user_id`。这需要修改 `create_outbound` 的调用方传参，改动面更大。

> **推荐方案A**。

### 修复三：session.md 模板重构（问题3 + 问题4）

**现状** [session.md](file:///d:/app/Emily/emily-data/prompts/session.md#L41-L42)：
```
### 对话记忆
{conversation_summary}
```

**新模板设计**：

```markdown
### 对话记忆

以下是你与该用户的历史交互信息，请理解其结构后合理使用：

#### 长期记忆（用户背景）
{user_memory}

#### 往期对话归纳（跨会话摘要，由系统自动归档生成）
{conversation_summary}

#### 近期对话（见消息列表中的历史消息，按时间正序排列）
系统会将最近的对话记录作为独立消息附在本提示之后。
- 角色为 "user" 的是用户发言
- 角色为 "assistant" 的是你的历史回复
- 近期对话可能有上下文断裂，优先参考上方"往期对话归纳"
```

**变更要点**：
1. 加入 `{user_memory}` 占位（该变量已在 `get_prompt_variables()` 中定义但未在模板中使用）
2. 用层级标题区分"长期记忆"和"往期归纳"
3. 添加元说明告知 AI 近期对话以独立消息形式注入，并告知优先级
4. 说明 user/assistant 角色的含义

**注意事项**：
- 如果三项均为空，该整段替换为 `（无历史记录）`
- 模板字符数增幅约 200 字，在当前整体 3000+ 字中占比可控
