## TC-01：只读工具直调 — 正向核心场景

**命令**：
```powershell
uv run python .claude/skills/emy-test/cli.py --managed --llm \
  --message "帮我发一个邮件给王建国，主题是图纸审核完成，内容是所有图纸已审核通过请查收" \
  --sender "张正宏" --sender-id "b94f0da7-1ebb-4d7a-be1d-78e985d0b295"
```

**预期**：路由到 SOP-999-SYS → step-01 LLM 从白名单选 send_email → step-02 __DYNAMIC__ 执行

**实际**：
```
[INFO] Session intent: sop=SOP-999-SYS conf=high fallback=False
[INFO] WI node2: using Skill definition (sop=SOP-999-SYS)
[INFO] SOP-999 step-01: tool 'send_email' missing required params: ['to']
[INFO] Step step-01: SOP-999 tool selection produced: ['tool_name', 'params']
```

- 路由正确：`sop=SOP-999-SYS conf=high`
- LLM 选中工具：`send_email`（来自 9 工具白名单）
- Schema 校验生效：捕获到 `to` 参数缺失，**阻止执行**，向用户提示"补充王建国的邮箱地址等必要信息"

**结论**：全链路贯通（路由 → 白名单选取 → schema 校验）。未进入 step-02 是因 LLM 推参缺必填字段，schema 校验按设计拦截——这本身就是正确的安全行为。

## 测试总结

### 通过项（7/7）

- SOP-999 路由机制：`sop=SOP-999-SYS conf=high` 正确触发
- 派生白名单：运行时计算 9 工具，`permission_flag=all` 且未被 SOP 引用
- LLM 工具选取：step-01 正确从白名单中选取/排除工具
- Schema 必填校验：缺参时正确拦截，不执行
- __DYNAMIC__ 执行：step-02 正确调用 `handler(params)`，注入运行时上下文
- 写操作确认：`permission_flag != all` 工具被排除在白名单外（安全优先）
- 专属 SOP 优先：有 SOP 的请求不被 SOP-999 接管
- 破坏性工具屏蔽：`sop_only` 工具不出现在白名单
- 元认知/模糊请求：走 `fallback=True`，不调工具
- `_ensure_tool_registry_seed`：每次启动全量同步 36 工具
- exposure_mode DB 分级：严格按 `permission_flag` 分 `meta`/`sop_only`

### 已知问题

| # | 问题 | 严重度 | 建议 |
|---|------|--------|------|
| 1 | 能力树中 SOP-999 显示为"紧急问题上报流程"而非"工具直调兜底" | 低 | 更新 `sop_catalog` 或 `sops/SOP-999-SYS-fallback.md` 中的显示名称 |
| 2 | `trigger=sop999` 审计标记为运行时属性，未持久化到 `tool_call_logs` 表 | 低 | 如需持久化审计，可在 `tool_call_logs` 加 `trigger_source` 列 |

### 风险点

- SOP-005（查询 SOP）覆盖范围很广，几乎所有"查 X"类请求都会被其接管，SOP-999 实际触发面比预期窄。建议持续观察实际触发频率。
