# 12 内核编排专项

> **本类目标**：验证编排内核本身的硬约束——唯一编排形态、状态可序列化、领域对象不进状态、端口可降级、事件同源，以及**常驻回归语料**是否可用。本类**大部分用例可离线执行**，是内核重构后最快的回归入口。
> **用例数**：26　|　**编号前缀**：`FR-O*`、`KRN-*`、`GOLD-*`、`SES-TC*`
> **执行通道**：C（内核离线回放）+ D（语料回放）+ 静态检索
> **来源**：`LangGraph编排内核化_功能复现测试用例_V1.md` O 组；`scripts/session_graph_replay.py`；`emily-data/golden/session_loop_cases.yaml`

## 二、常驻回归语料（`KRN-*`，11 条）★离线可跑，最快回归入口

> **执行**：`docker exec -e PYTHONPATH=/app -w /app emily-core python /app/scripts/session_graph_replay.py`
> **判定**：脚本末尾输出「共 11 项，通过 11，失败 0」→ 全过；退出码非 0 即失败。

| 编号 | 回放项（脚本内名称） | 目标特性 | 预期 | 对应实现 |
|------|-------------------|---------|------|---------|
| KRN-01 | 快速短路零模型调用 | 问候类不进模型 | `reply=="您好"` 且 `llm=0` | `fast_responder` 短路 |
| KRN-02 | 工具回环产出最终回复 | 一次工具调用后收口 | 回复 == 桩文本（`已查到记录`） | 图内 execute⇄summarize 回环 |
| KRN-03 | 迭代上限收敛为可读收尾 | 有界循环 | 达上限返回 `CAP_REPLY`，不抛异常 | `max_iterations` |
| KRN-04 | 门禁拒绝时不执行能力 | fail-closed 门禁 | `exec==[]` 且回复为拒绝说明 | `gate_evaluator` |
| KRN-05 | 挂起以提问收尾 | 能力需补参 | 回复 == 提问文案，且存在 pending | `suspend_factory` |
| KRN-06 | 挂起可续接并产出最终回复 | 续接闭环 | 续接后回复 == `已登记完成` | `resume_graph` |
| KRN-07 | 计划层内并行且分两层完成 | 层内并行/层间顺序 | 同层两区间**重叠**；3 步全部 done | `plan_subgraph` |
| KRN-08 | 事件端口产出进度且同源 | 事件单通道 | ≥2 条 `progress`，且文案来自节点映射 | `build_event_port` |
| KRN-09 | 端口装配可降级 | 端口缺失不报错 | `ports.describe()["events"]==False` | `build_ports(core=None)` |
| KRN-10 | 状态可序列化 | 收口状态合规 | `violations == []` | `validate_state_serializable` |
| KRN-11 | 契约校验拦截缺参与未声明参数 | 入计划前拦截 | 问题清单**同时**含「缺少必填参数」与「未声明参数」 | `validate_steps` |

## 三、golden 语料回放（`GOLD-*`，5 条）

> **语料文件**：`emily-data/golden/session_loop_cases.yaml`（四类断言分组：`capability_hit` / `permission_block` / `suspend_resume` / `archive_completeness`）
> **执行**：
> ```powershell
> # 先干跑校验语料可用
> uv run python scripts/golden_session_loop.py --corpus emily-data/golden/session_loop_cases.yaml --path new --dry-run
> # 真实回放（会写库，需授权窗口）
> uv run python scripts/golden_session_loop.py --corpus emily-data/golden/session_loop_cases.yaml --path new --report emily-data/golden/report_new.json
> ```

| 编号 | 用例 ID | 分组 | 消息 | 预期 |
|------|--------|------|------|------|
| GOLD-01 | chitchat-hello | chitchat | 「你好」 | `reply_contains: ["你好"]` |
| GOLD-02 | chitchat-thanks | chitchat | 「谢谢」 | `reply_contains: ["不客气"]` |
| GOLD-03 | sop-record-event | business | 「帮我记录事件：科技城5号楼铺装完成了25平米，验收通过。」 | `capability_hit: ["SOP-002-REC"]` + `archive_completeness: true` |
| GOLD-04 | suspend-record-event | business | 「帮我记一下事件」→ 续接「科技城5号楼铺装完成了25平米，验收通过。」 | `suspend_resume.capability: "SOP-002-REC"` |
| GOLD-05 | permission-delete-event | permission | 「帮我把上一条事件记录删掉。」（他公司 L3 用户） | `permission_block: true` + `must_not_call: ["delete_event","record_event"]` |

> 语料中的 `sender_id` 必须是 `users` 表**真实 UUID**；伪造会新建访客用户并导致断言全假。

## 五、执行命令参考

```powershell

uv run python scripts/golden_session_loop.py --corpus emily-data/golden/session_loop_cases.yaml --path new --dry-run
```

## 六、备注

- **本类是回归首选**：内核重构、编排图调整、契约 schema 变更后，先跑 `KRN-*`（离线秒级），再跑 `GOLD-*`（真实链路）。
- 语料目前仅 5 例，覆盖偏薄；建议以 01/02/03/04 类中的可自动化用例为骨架逐步扩充语料条目。
