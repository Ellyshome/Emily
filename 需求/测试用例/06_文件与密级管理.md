## 三、密级规则用例（`CONF-*`，10 条）★本类重点

> **两条业务规则**（2026-09-12 落地）：
> **规则 1**：上传文件默认「内部」（`confidentiality=1`），上传人可在上传时自选密级。
> **规则 2**：密级调整仅限 **上传者本人** 或 **L5/L6 管理员**；`uploaded_by` 为空时仅 L5/L6 可改；密级变动后**即时重算**可见性。

| 编号 | 目标特性 | 操作 | 预期（判定标准） | 断言 |
|------|---------|------|----------------|------|
| CONF-01 | 上传**默认内部** | `POST /api/v1/console/upload`，**不传** `confidentiality` | 响应 `confidentiality=1`；DB `files.confidentiality=1` | db_effect |
| CONF-02 | 上传人**自选密级**生效 | 上传时传 `confidentiality=0`（再测 `=2`） | 响应与 DB 均为所传值（0 或 2） | db_effect |
| CONF-03 | 上传密级**非法值归一** | 上传时传 `confidentiality=9` | 归一为 **1（内部）**，不报错、不落非法值 | db_effect |
| CONF-04 | **上传者本人**可调密级 + 审计留痕 | `POST /api/v1/console/file-confidentiality`，体 `{"file_id":"<id>","confidentiality":2,"operator_id":"<上传者uuid>"}` | 返回 `success=true` 与 `old/new`；DB 密级变更；`files.change_log` **追加一条** `{field:"confidentiality", old, new, operator, at}` | db_effect |
| CONF-05 | **L5 管理员**可调他人文件密级 | 同上，`operator_id` = L5 用户 | `success=true`，DB 密级变更 | db_effect |
| CONF-06 | **L6 管理员**可调他人文件密级 + 机密原生可见 | 同上，`operator_id` = L6 用户；随后 L6 查询该机密文件 | 调整成功；L6 检索/列表**可见**该机密文件 | db_effect, permission_block（反向） |
| CONF-07 | **非上传者且非管理员被拒** | 同上，`operator_id` = 非上传者 L3 / L4 用户 | 返回 `permission_denied`（提示"仅上传人本人或 L5/L6 管理员可调整文件密级"）；**DB 密级不变**；`change_log` 无新增 | permission_block, db_effect |
| CONF-08 | `uploaded_by` 为空时仅 L5/L6 可改 | 取一条 `uploaded_by` 为空的文件：先由 L3 调（应拒绝），再由 L5 或 L6 调（应通过） | L3 → `permission_denied`；L5/L6 → `success=true` | permission_block |
| CONF-09 | 密级变动**即时重算**可见性 | 将同节点可见文件由 `1` 改为 `2` → 用同节点 L3 用户查询该文件 → 再由 L6 查询 → 改回 `1` 再查 | 改 2 后：L3 **不可见**、L6 **可见**；改回 1 后：L3 **恢复可见**（`session_accessible_files` 已重建，无残留窗口） | db_effect, permission_block |
| CONF-10 | 三级密级语义对照 | 用 L1 / L3 / L5 / L6 分别检索同一组（公开/内部/机密）文件 | L1 只见公开；L2~L5 见公开+内部；机密仅**上传者 / 显式授权 / L6** 可见 | permission_block, db_effect |

### 密级值域约定

| 值 | 名称 | 可见规则 |
|----|------|---------|
| 0 | 公开 | 参与该节点/项目企业的用户可见 |
| 1 | 内部（**默认**） | 同上，密级上界 = 内部 |
| 2 | 机密（**白名单制**） | 仅 ①上传者自传 ②`session_accessible_files.access_type='explicit'` 显式授权 ③L6 全局兜底 |

> **注意**：L5 属于"管理员"但**原生不见机密**——L5 把文件改成机密后自己也看不到，此为**已确认可接受**的行为，不计缺陷。

## 四、执行命令参考

```powershell
# 上传（默认内部）
curl -s -X POST http://localhost:18080/api/v1/console/upload `
  -F "user_id=<上传者uuid>" -F "file=@emily-data\files\范例文件1.xls"

# 上传并自选密级=机密
curl -s -X POST http://localhost:18080/api/v1/console/upload `
  -F "user_id=<上传者uuid>" -F "confidentiality=2" -F "file=@emily-data\files\范例文件1.xls"

# 调整密级
curl -s -X POST http://localhost:18080/api/v1/console/file-confidentiality `
  -H "Content-Type: application/json" `
  -d '{"file_id":"<id>","confidentiality":2,"operator_id":"<uuid>"}'

# 库核对
docker exec emily-postgres psql -U emily -d emily -c "SELECT file_no,filename,confidentiality,uploaded_by FROM files ORDER BY created_at DESC LIMIT 5;"
docker exec emily-postgres psql -U emily -d emily -c "SELECT change_log FROM files WHERE file_no='<file_no>';"
docker exec emily-postgres psql -U emily -d emily -c "SELECT count(*) FROM session_accessible_files;"
```

## 五、数据层注意事项

1. **列级默认值**：ORM 层默认已改为 `1`（`models.py`）。**数据库列 schema 默认值可能仍为 0**；若存在绕开 ORM 的直接 `INSERT`，需补一条 `ALTER TABLE files ALTER COLUMN confidentiality SET DEFAULT 1;`。
2. **消息附件入库路径**：`file_storage_service.py` 的消息附件入库**不显式传密级**，继承 ORM 默认 `1`（内部），且无 `uploaded_by` → 按 `CONF-08` 只有 L5/L6 能改其密级，符合规则。
3. **测试数据清理**：`FILE-M4-*` 与 `CONF-*` 会写库，执行后按下表清理。

```sql
-- 清理 M4-T2 新建版本文件（按当天 file_no 前缀）
DELETE FROM files WHERE file_no LIKE 'FIL-<YYYYMMDD>-%' AND version = 'V2.0';
-- 还原 M4-T3 软删除
UPDATE files SET is_deleted = false WHERE file_no = '<FILE_18>';
-- 还原被 CONF 用例改动的密级（按需）
UPDATE files SET confidentiality = 1 WHERE file_no IN ('<file_no_1>','<file_no_2>');
```
