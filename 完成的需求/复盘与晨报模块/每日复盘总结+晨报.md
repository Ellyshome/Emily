# 每日总结复盘，与晨报
给调度机增加默认任务，每天调度机有一项任务

## 关于总结复盘问题
- 希望emliy是一个可以自进化的项目，通过每日复盘总结，观察项目运作与业务推进，总结实际规律并保存下来。
- 保存下来的成果具体应该是什么？（具体保存成什么？工作笔记？观察日志？还是其他什么东西）
- 这些成果如何作用到emliy项目本身？真正完成进化。
- 业务进化与系统进化可以分成两个系统分别推进，应有系统管理员统一把握

## 关于晨报问题
- 希望所有实际参与项目的用户，每天早晨开展工作前能有收到一份清晰的晨报，列表清楚当前的工作计划，与工作进度情况，让用户做到对任务有清晰的认知，避免遗忘。
- 根据需求，推导晨报应具备的信息
- 晨报是否需要根据服务用户的负责内容不同，而输出不同结构的内容？
    - 如甲方管理人员收到的内容，与纯参建人员收到的信息是否应有结构条目的差别。

# 总结复盘模块
- 每天0:00触发任务：总结复盘
- 扫描前一天0-24时进入的所有信息，形成本日信息汇总，信息包括：
    - 业务类的：对话记录、节点进度更新
    - 系统类的：警告/报错 log
- 调用llm、信息汇总+复盘要求prompt输出‘XX日期-业务复盘报告’与‘XX日期-系统复盘报告’
- 业务复盘报告输入条件：
    - 数据库-用户全量通话记录
    - 文档库-项目日志
    - 脚本当前节点树进程快照
    - 文档库-当前证照文件列表
- 业务复盘报告输出成果：
    - 过去一天各节点的任务推进情况
    - 是否有节点变动，如果有：
        - 是否是节点延误，如果是，原因是什么，是否有借鉴意义
        - 是否是节点新增成果要求，是否提前漏填，是否有借鉴意义
        - 是否有新节点启动
        - 是否有节点闭合，若是
            - 对节点进行关闭和总结
- 报告保存在日志文档库中。
- 两分报告作为附件同当日晨报发送给系统管理员

# 晨报模块
- 每日总结复盘完成后，根据业务复盘报告，与当前正运作节点的参与用户列表，对每个用户撰写各自晨报。
- 晨报内容应包含：口语化的问候+日期信息+用户当前参与节点的进度简报，

## 晨报结构
问候 + 日期 — 口语化问候，根据星期变化
节点进度 — 用户负责的 IN_PROGRESS 节点 + 进度变化
待办任务 — WAITING/SUBMITTED/RETURNED 的 PlanTaskInstance
昨日动态 — NodeEvent 操作记录
关注事项 — 截止临近/超期风险
收尾语 — 根据紧急数动态生成
