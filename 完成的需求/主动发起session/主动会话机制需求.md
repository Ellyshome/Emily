# 主动发起会话机制需求文档

## 1. 背景与目标

### 1.1 背景
当前系统中：
- 计划任务通知通过 `OutboundEventBus` 直接发送，用户不在线则丢失
- 缺少持久化的主动消息机制
- 各模块（计划任务、协同待办、权限系统）各自实现通知逻辑，不统一

### 1.2 目标
建立统一的**主动发起会话**机制，实现：
- 主动消息持久化（不丢失）
- 复用现有 SessionAgent 能力（可多轮交互）
- 自动存档留痕（完整对话记录）
- 各业务模块统一接入入口

---

## 2. 核心概念

### 2.1 主动会话
系统主动向用户发起的对话，区别于用户主动发起的对话。

### 2.2 触发源
需要主动触达用户的业务场景：
- 计划任务：超时提醒、升级通知
- 协同待办：待办提醒、审批通知
- 权限系统：权限申请、异常数据审批
- 其他业务模块

---

## 3. 架构设计（方案 B：独立调度器）

### 3.1 整体架构

```
┌──────────────────────────────────────────────────────────────┐
│  业务模块层                                                   │
│  ┌───────────┐  ┌─────────────┐  ┌─────────────────┐         │
│  │ 计划任务   │  │ 协同待办模块  │  │ 权限系统等其他模块  │         │
│  └─────┬─────┘  └──────┬──────┘  └────────┬────────┘         │
└────────┼───────────────────┼──────────────────────┼───────────┘
         ↓                   ↓                      ↓
┌──────────────────────────────────────────────────────────────┐
│  全局状态机（SM）层                                           │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  INITIATIVE_SESSION 节点（主动会话事件）                │  │
│  │  { target_user, prompt, trigger_type, priority, ... } │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────┬────────────────────────────┘
                                  ↓
┌──────────────────────────────────────────────────────────────┐
│  InitiativeSessionScheduler（独立调度器）                    │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  asyncio 后台循环 → 扫描 PENDING 节点 → 拉起 Session  │  │
│  └───────────────────────────────────────────────────────┘  │
└─────────────────────────────────┬────────────────────────────┘
                                  ↓
┌──────────────────────────────────────────────────────────────┐
│  Session 层（复用现有架构）                                    │
│  ┌───────────────────────────────────────────────────────┐  │
│  │  普通 Session → 注入初始 prompt → SessionAgent 执行     │  │
│  │  → 自动存档 → 更新 SM 节点状态                          │  │
│  └───────────────────────────────────────────────────────┘  │
└──────────────────────────────────────────────────────────────┘
```

### 3.2 调度器定位
- **名称**：`InitiativeSessionScheduler`
- **级别**：与 `PlanTaskScheduler` 同级，EmilyCore 内独立运行
- **职责**：专门负责主动会话的调度与拉起

## 4. 数据模型：SM 节点扩展

### 4.1 节点类型
新增节点类型：`INITIATIVE_SESSION`

### 4.2 节点字段

| 字段名 | 类型 | 必填 | 说明 |
|--------|------|------|------|
| `node_type` | String | ✅ | 固定值：`"INITIATIVE_SESSION"` |
| `target_user_id` | String | ✅ | 目标用户 ID |
| `initiative_prompt` | String | ✅ | SessionAgent 初始任务指令 |
| `trigger_type` | String | ✅ | 触发类型：`IMMEDIATE` / `SCHEDULED` |
| `scheduled_at` | String | ✅ | 计划执行时间（ISO8601），IMMEDIATE 为当前时间 |
| `priority` | String | ✅ | `HIGH` / `NORMAL` / `LOW` |
| `source_module` | String | ✅ | 来源模块：`plan_task` / `agent_issue` / `permission` |
| `source_id` | String | ✅ | 来源业务 ID（如待办 ID、任务实例 ID） |
| `session_id` | String | ❌ | 拉起的 Session ID（执行后填充） |
| `status` | String | ✅ | 状态：`PENDING` / `PICKED` / `COMPLETED` / `FAILED` |
| `executed_at` | String | ❌ | 执行时间 |
| `fail_reason` | String | ❌ | 失败原因 |

---

## 5. 核心流程

### 5.1 完整生命周期

```
1. 业务模块 → 创建 INITIATIVE_SESSION 节点（状态：PENDING）
         ↓
2. InitiativeSessionScheduler 轮询 → 发现满足条件的 PENDING 节点
         ↓
3. 更新节点状态 → PICKED（记录 picked_at）
         ↓
4. 调用 SessionPoolManager 创建主动会话
         ↓
5. SessionAgent 执行 initial_prompt 指定的告知任务
         ↓
6. 对话自动存档（复用现有机制）
         ↓
7. 回调更新节点状态 → COMPLETED（记录 session_id、executed_at）
```

### 5.2 调度器执行逻辑

```
调度循环 tick：
  1. 查询所有 status = PENDING 且 scheduled_at <= now 的节点
  2. 按 priority 排序（HIGH 优先）
  3. 对每个节点：
     a. 状态更新为 PICKED（防止重复执行）
     b. 调用 SessionPool 创建主动会话
     c. 成功 → 更新为 COMPLETED
     d. 失败 → 更新为 FAILED，记录 fail_reason
```

## 6. 接口设计

### 6.1 业务模块接入接口（SM Service）

```python
# StateMachineService 新增方法

async def create_initiative_session(
    self,
    target_user_id: str,
    initiative_prompt: str,
    trigger_type: str = "IMMEDIATE",
    scheduled_at: str | None = None,
    priority: str = "NORMAL",
    source_module: str = "",
    source_id: str = "",
) -> str:
    """
    创建主动会话事件
    
    Args:
        target_user_id: 目标用户ID
        initiative_prompt: SessionAgent初始任务指令
        trigger_type: IMMEDIATE / SCHEDULED
        scheduled_at: 计划执行时间（SCHEDULED时必填）
        priority: HIGH / NORMAL / LOW
        source_module: 来源模块标识
        source_id: 来源业务ID
    
    Returns:
        sm_node_id: 状态机节点ID
    """
```

### 6.2 Session 池扩展接口

```python
# SessionPoolManager 新增方法

async def create_initiative_session(
    self,
    user_id: str,
    initial_prompt: str,
    sm_node_id: str,
) -> str:
    """
    创建主动发起的会话
    
    Args:
        user_id: 目标用户ID
        initial_prompt: SessionAgent的初始任务指令
        sm_node_id: 关联的状态机节点ID
    
    Returns:
        session_id: 新创建的会话ID
    """
```

## 7. 与现有模块集成示例

### 7.1 计划任务模块集成

```python
# plan_task_scheduler.py 中

async def _handle_overdue_tasks(self, now_iso: str):
    for inst in overdue_instances:
        # 不再直接发消息，改为创建主动会话事件
        await self._sm_service.create_initiative_session(
            target_user_id=inst.executor_id,
            initiative_prompt=f"请提醒用户：任务「{inst.title}」已超时，请尽快提交成果。",
            trigger_type="IMMEDIATE",
            priority="HIGH",
            source_module="plan_task",
            source_id=inst.id,
        )
```

### 7.2 协同待办模块集成

```python
# agent_issue_service.py 中

async def create_approval_issue(self, ...):
```

## 8. EmilyCore 初始化调整

```python
# 在 EmilyCore._ensure_initialized() 中新增

def _init_initiative_session_module(self) -> None:
    """初始化主动会话调度器。"""
    try:
        from .services.initiative_session_scheduler import (
            InitiativeSessionScheduler
        )
        
        self._initiative_session_scheduler = InitiativeSessionScheduler(
            sm_service=self._sm_service,
            session_pool=self._session_pool,
            config=self.config,
        )
        
        # 启动后台调度循环
        import asyncio
        asyncio.ensure_future(self._initiative_session_scheduler.start())
        
        logger.info("InitiativeSessionScheduler started")
    except Exception as e:
        logger.warning("InitiativeSessionScheduler init failed: %s", e)
        self._initiative_session_scheduler = None
```

## 9. 非功能要求

| 项 | 要求 |
|----|------|
| 调度间隔 | 默认 30 秒，可配置 |
| 单次 tick 处理量 | 最多处理 50 个节点（防止阻塞） |
| 幂等性 | 同一节点不会被重复拉起（PICKED 状态锁） |
| 异常容错 | 单个节点处理失败不影响其他节点 |
