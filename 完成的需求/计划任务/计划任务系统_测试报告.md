## 四、发现的Bug与修复

测试过程中发现并修复了以下问题：

| # | 问题 | 影响 | 修复 |
|---|------|------|------|
| B1 | `plan_task_instances.status` VARCHAR(20) 放不下 `ANOMALY_PENDING_REVIEW`（22字符） | 用例C创建失败，DataError | ALTER COLUMN 扩为 VARCHAR(30) |
| B2 | `plan_task_instances.anomaly_reason` 无长度限制但在 PG 中默认过小 | 中文异常原因被截断 | 设 VARCHAR(500) |
| B3 | `PlanTaskInstanceRepo.create()` 中 `template_id=""` 空字符串违反 FK 约束 | 一次性任务创建失败 | 空字符串转 None |
| B4 | `users.permission_level` 全部为默认值0 | 鉴权检测无法触发 | Python 脚本批量设置权限等级 |

> 注：B1-B3 建议后续修改 models.py 中的 Column 定义为带长度参数的版本，避免新部署环境重蹈覆辙。B1 和 B2 的 models.py 已同步修复。


## 五、Pipeline BUS 集成层状态

通过 `emy-test` 技能发送消息后，系统能够：
- 正确识别 SOP-009-REC（计划任务创建意图）

但 Pipeline BUS 的 executor 节点因 `executor_mode` 默认为 `mock`，导致实际执行落入 MockExecutor 而非 RealExecutor。将 `executor_mode` 改为 `"real"` 后，仍有深层集成问题（query_tool 的 query_service 为 None），需要进一步修复 Pipeline BUS 的工具注册/依赖注入机制。

**当前结论**：Service/Application 层业务逻辑 100% 验证通过，Pipeline BUS 集成通道待后续调试打通。
